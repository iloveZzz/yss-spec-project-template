# 高保真原型与正式前端的接续

## 原型交给前端

高保真 UI 原型用于前端实现时，以实际原型和采用的规格为依据，在本次结论或已有交接中写下相关信息。有适用的自检或复核记录时直接引用。据实注明未执行的检查，局部交接只覆盖本次涉及的页面和状态。

- **依据和范围。** 给出选定 Spec、交互说明、设计规范、原型入口及采用的版本或工作树内容。用页面、角色、任务、状态和 FR/AC 定位结论，说明实际操作、视觉观察和未验证的部分。
- **需要保留的体验。** 指明已确认的用户流程、业务条件、反馈与恢复、键盘和焦点行为，以及信息层级、关键布局、视觉识别和响应式约定。区分已确认的设计决定与原型中用于表达设计的具体控件和样式。
- **关键场景的复验依据。** 按风险选取影响验收的场景，引用原 FR/AC 或章节。写清原型的实际入口、进入和重置场景的方法、角色、初始状态与数据、动作顺序、预期结果及应保留的数据，再记录实际观察结果。已有验收或复核记录足够复验时，直接引用。
- **差异与演示边界。** 指明未覆盖的状态、未解决的规则冲突及其影响。标出模拟数据、固定延迟、内存保存、场景切换等演示方式，注明真实接口、身份或持久化的验证范围。分别说明当前实际读到的材料及接收方能否访问。访问未知时注明，无法访问时在允许共享的范围内给出材料版本、关键依据和最短复验步骤。

例如，客户编辑弹层的 AC 要求保存失败保留输入、成功后关闭并返回焦点。复核记录实际触发的失败与重试，同时注明原型的保存结果来自场景模拟。前端接续时，使用目标工程的弹层、表单、服务与请求状态兑现同一行为，并以实际实现另行验证。

## 正式前端回写原型

任务需要用正式前端校准原型时，可以直接从当前产物和有效决定开始。已有适用的复核或交接记录就复用。仅委托对照或审查时，在当前结论记录发现和建议。

只读对照可操作无业务副作用的路径、复用已有证据或使用本次范围内的隔离模拟。保存、退款等会改变共享或真实业务数据的动作，须由本次任务明确授权，并在适用且获授权的测试环境中使用获授权的数据。缺少授权或证据时，报告可观察的结果与具体未验证范围。

1. **选定可对照的材料。** 定位本次实际运行的正式前端入口、环境及可核实的部署版本、构建或工作树内容，再定位采用的原型入口、版本、交互说明和对应 FR/AC 或章节。核对有效的业务和交互决定。只能看到源码、旧版本或静态页面时，写清实际可读部分和证据缺口。
2. **在可比条件下复验。** 对照相同角色、起始状态、代表数据和动作，视觉差异采用可比的视口及状态。沿适用的成功、拒绝、失败恢复或状态变化路径，分别记录实际看到的操作反馈、最终结果和不变项。说明每端接入的真实服务或模拟方式、数据变化可观察到哪一层，以及因权限、环境或数据所限未执行的部分。
3. **按依据和授权处理差异。** 组件、布局或技术适配仍兑现已确认的体验、业务条件和验收时，保留适配。正式前端偏离明确的规则或体验承诺时，指出缺陷并在前端修复授权内改动。若正式前端中的体验变更已有有效确认，按授权增量调整对应的原型和交互说明。影响业务规则或验收的变更由 Spec 侧在授权范围内更新原 FR/AC，范围外的改动列为建议。运行现状和模拟结果仅作为观察证据。缺少必要证据时标出待核实项。确有待定取舍时请业务方沿原问题决定，暂缓依赖该证据或决定的修改。

将对照结果及处理依据记入当前结论或有权更新的现有任务、交接记录，引用采用版本、原 FR/AC、复验步骤、观察结果和限制。修改后在相应产物复验受影响路径，报告实际结果及剩余差异。
