# 非技术规格方法

适用于已核验的 matt-spec-v1 Spec 工程；普通未治理草稿也可复用内容方法，但不能声称已经受管初始化或发布。

读取当前目标、已有材料、已确认决定及 tracker 规格。存在 Context 时使用稳定词汇；缺失不阻断普通综合，不自动创建 Context、ADR 或 Plan。只读请求仅分析。

事实缺口调用 yss-research；业务决定缺口调用 grilling；词义、责任歧义调用 domain-modeling。复用有效确认，独立已授权工作继续，不把建议当确认。多个来源冲突时先调查，不静默改变范围。

按 `.template-spec/templates/spec-template.md` 的非技术结构或当前任务适用结构整理问题、目标、场景、规则、边界、异常、非目标和验收。验收是可观察结果，不预先指定技术测试 seam、模块、API、数据库或实现任务。保持“全部/仅当/至少”等量词与来源一致，未定值留未决项。

AI 判断当前产品问题能否用文字解决，必要时再使用流程、状态、低保真或原型；只补高风险部分。不确定时调查或澄清，不默认构建最高档原型。实际产物执行对应检查，未运行不能声称交互验证通过。设计发现回流规则与 AC，关键问题未解决时仅报告草稿和阻断。

保存/发布遵循 [tracker 操作](spec-tracker.md)。实际审批按 [用户决定](user-decisions.md) 的新 Spec 分支：不额外加阶段确认；有真实审批要求才绑定实际展示内容与用户回复。中途可在授权范围保存或发布明确草稿，不暗示已批准。

自检当前来源、范围、规则与 AC 是否一致，检查成功、拒绝、边界、状态变化和恢复是否按影响覆盖。非关键延期项标明影响与条件，关键未决项阻断完成。使用 i-have-adhd 辅助当前文档表达，不改变事实。

返回主规格引用、实际工作与检查、适用决定、未决项及下游限制。下游读取引用自行承担技术与实现；不计算实施准入，不创建 PR、交接包或自动关闭 Issue。
