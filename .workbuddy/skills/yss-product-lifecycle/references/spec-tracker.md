# Spec tracker 操作

唯一配置为 `.template-spec/agents/issue-tracker.md` frontmatter 的 tracker。platform 选择 local-markdown/github/gitlab；本地 root 必需，GitHub repository 为 owner/repo，GitLab host 为明确 HTTPS 实例、project 为完整项目路径。远程需要保存本地草稿、恢复或批准材料时配置 root。已有合法配置复用，不从 Git remote 静默改平台或账号。

用户显式交接时，PR/MR 文件可保存标明来源与读取时点的 Issue 内容快照，Issue 仍是权威。快照不自动回写或跟踪 Issue；来源变化时由接收方核对当前内容，不以 PR 状态替代批准。

读取用户指定路径或 URL；已有明确定位直接更新，不能按同标题另建。新远程创建前生成随机稳定标识（UUID），在正文和按需 publication.md 保存目标与标识；记录仅用于发布恢复，不作为读取/起草资格。已有简单本地文件不要求额外记录。

优先使用可用连接器；不足时使用已配置 gh/glab。工具能力先查帮助，GitLab 保留实例信息，不假设 gitlab.com。正文发布使用对应 Issue 的正文接口，不新建 HTTP 引擎。

创建/更新前核实有效目标授权，读取当前正文和评论。更新前复读并比较基线，发现并发变更先综合，不用本地旧稿覆盖。平台有条件写入时使用；否则说明读取/写入之间仍有竞争窗口，无法安全更新时停止受影响覆盖。发布后读取实际结果核对内容，退出 0 不单独证明完成。

创建超时、定位未保存等未知结果先按目标/稳定标识查询，核实未创建前不重发。多个匹配报告冲突。平台不能可靠查询时保留未知，不凭猜测重试。失败不自动改投其他 tracker；本地准备完成与远程发布完成分别报告。

批准绑定实际展示内容及设计；动态 URL 不构成版本。无可读历史时仅为实际审批保存不可覆盖快照及原始决定来源。下游无法访问材料时明确缺口，不能声称交付完整。修改实质规则时同次更新正文及当前稿审批说明，旧批准仅适用旧版本，保留原记录。

权限缺失、核对失败、写入部分成功逐项报告；继续独立已授权准备。提交、推送、远程评论、关闭条目、分配人员及启动下游不由“发布 Spec”隐含授权。
