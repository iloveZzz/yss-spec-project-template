# 附件提交校验 · 原型与交互说明

采用同目录教学 v1，[Spec](spec.md) 为业务权威；[场景数据](scenarios.json) 为可复现输入，[页面](AttachmentSubmission.vue) 与[校验](model.ts) 表达该规则。2026-11-09 建立，全部本地模拟。运行与来源清单见 [README](README.md)。

## 任务与页面覆盖

| 页面 / 区域 | 入口与出口 | 任务、权限及规则 | 制作范围 | 实际验证 |
|---|---|---|---|---|
| 申请列表 | primary 起点、详情返回 | 经办人显示本人团队内一项；观察者本团队两项，EX-R01 | 可操作 | 见下文实际检查 |
| 申请详情与表单 | 列表“查看”或场景初始记录；返回列表 | 归属只读、标题/备注编辑、附件齐备、保存/提交，EX-R02–07 | 可操作 | 见下文实际检查 |
| 只读与范围拒绝 | readonly、out-of-scope，或提交成功 | 只读可理解；范围外不显示字段，EX-R01/02 | 可操作 | 见下文实际检查 |
| 未保存确认 | 修改后返回；留在原页、Escape 或放弃 | 正式值/编辑值分离、关闭回焦，EX-R08 | 可操作 | 见下文实际检查 |
| 场景选择与重置 | 壳内选择器、重置 | 恢复输入、正式值、错误、次数，EX-R09 | 可操作 | 见下文实际检查 |

列表与详情是同一业务入口的两种视图，消费同一份本地正式数据；不是互不联动的两张示意页面。附件操作不是文件上传。

## 初始数据

每个场景的实际值在 scenarios.json 的 `scenarios[id].initial_data`。REQ-001 为 T-001/U-001 自有草稿，标题“季度采购资料申请”、备注“保留原始说明”；所需材料按顺序为报价单、采购说明。REQ-002 为同团队他人记录，REQ-003 为其他团队记录。

经办人 U-001/T-001 的列表只有 REQ-001；观察者 U-004/T-001 可见 REQ-001、REQ-002。只读场景不得通过编辑值绕过动作校验。范围外场景直接尝试 REQ-003，只显示拒绝，不输出其标题、备注等详情字段。

## 可复现场景

下列相对链接以组装后的浏览器首页为基准，均使用 `#scenario=<id>`；为便于复制，这里以代码列出地址。切换与刷新重新初始化；页面业务规则沿 Spec，不由 hash 暗定。

| 场景 / AC | 入口与初始差异 | 顺序操作 | 预期反馈、变化与不变项 |
|---|---|---|---|
| primary / EX-AC01/04 | `/#scenario=primary`，列表起点、缺两附件 | 查看 REQ-001 → 改标题和备注 → 保存 → 返回列表 → 再查看 → 勾齐 → 提交 → 返回 | 保存即更新正式标题、不要求附件；无 dirty 误报；提交后只读、列表已提交 |
| missing-attachments / EX-AC03 | `/#scenario=missing-attachments`，详情初始缺两附件 | 提交 → 勾报价单提交 → 勾采购说明提交 | 依次列两项、一项、成功；每次检查现值，标题备注不丢，拒绝不改正式值 |
| readonly / EX-AC07 | `/#scenario=readonly`，观察者详情 | 查看只读原因、字段和按钮 → 返回列表 | 编辑与写动作禁用；列表两项；数据不变 |
| out-of-scope / EX-AC07 | `/#scenario=out-of-scope`，尝试范围外记录 | 观察拒绝 → 返回列表 | 不显示详情字段和敏感内容；返回只见自己的记录 |
| submit-failure / EX-AC02/05 | `/#scenario=submit-failure`，附件已齐全 | 标题清空白提交 → 改为“保留输入验证”及备注 → 提交 → 重试 | 无效不消耗次数；首次有效提交失败、草稿且输入保留；第二次成功 |
| requirements-failure / EX-AC06 | `/#scenario=requirements-failure`，清单首次失败 | 改备注 → 提交 → 重试读取 → 提交 → 补齐再提交 | 不以空清单放行；读取恢复后先列缺项，输入保留；补齐成功 |
| dirty-leave / EX-AC09/04 | `/#scenario=dirty-leave`，详情起点 | 改标题/备注/勾选 → 返回并留在原页 → 返回并 Escape → 返回并放弃；重进再修改保存返回 | 前两次输入保留；放弃不改正式值；保存后返回不出现确认 |

每个场景的重置方法相同：打开壳内“评审工具：场景与辅助显示”，点击“重置场景”。预期恢复该场景 JSON 中的正式值、初始详情/列表、编辑输入、勾选、错误及有效提交次数。submit-failure 重置后第一次有效提交应再次失败；requirements-failure 重置后再次显示读取失败。

错误入口：`/#scenario=unknown`、`/#scenario=primary&scenario=readonly` 必须显示入口错误，不能显示正常业务数据。当前壳显示“工作区入口错误 / 未知或缺失的场景，请检查评审链接。”标题为空白的保存拒绝可在 primary 详情附加操作；已提交后的重复提交由只读界面及动作校验拒绝。

## 变更与回流

改变角色范围、校验、失败、返回或重置语义时，同步 Spec 的 EX-R/EX-AC、scenarios.json、页面及本说明。只改排版时核对相关显示条件；实际检查标明本次采用的工作树/版本和具体范围。
