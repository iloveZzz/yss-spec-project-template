# 配置决定

只问当前写入所需、且用户或已有配置尚未确定的内容。推荐项放在问题前，肯定回答表示接受推荐；已有决定不再询问。

- tracker 文件由目标工程维护。沿用已有有效配置，用户明确要求修改时再改。尚未配置时采用用户明确选择的 `github`、`gitlab` 或 `local-markdown` 目标。完整新工程已核实唯一 GitHub 或 GitLab 代码托管项目时，可使用该项目的 Issues 并报告。`tracker: {}` 和旧 GitHub 空 `repository` 占位均表示尚未配置。多个候选或目标不明时，只澄清本次所需目标，平台登录默认仓、模板仓和未经确认的 fork 都不用于推断。
- GitHub 使用 `repository: owner/repo`，GitLab 使用 HTTPS `host` 和包含上级组的完整 `project`。用户当前明确的 URL、仓库或实例用于本次动作，与配置不同时说明差异并保留持久配置。访问失败时报告所选目标的实际错误，动作仍需对应授权。
- Local Markdown 沿用已选 `root`，`.work` 是新工程根目录示例。需要写入且目标待确认时，先完成当前可做的分析，待用户明确目录后再写入。
- triage 已安装且需要配置标签时，复用既有表；无表时采用 [三条默认标签](../triage-labels.md)，用户已明确偏好就不另问。不自动创建远程标签。
- 根 `CONTEXT.md` 是已有业务词汇的唯一位置；ADR 沿用根 `docs/adr/`。仅在用户要求记录稳定词汇/决定时由 domain-modeling 处理。大小写、嵌套或重复词汇文件有冲突时保留原文，只暂停受影响词汇写入；不阻断其他配置。

不把业务决定变成工具安装调查；可从仓库和工具帮助查明的事实自行读取。unsupported tracker 说明当前能力边界，不写入不支持的平台。
