# 增量摄取

处理用户点名或任务已授权的来源，搜索命中不自动等于摄取许可。写作涉及页面粒度、实体、证据或人工内容时读取 [写作方法](writing.md)。

## 摄取与综合

1. 读取来源、已有索引或等价导航及相关页面，核对本次可读资料与写入范围。缺少索引时从现有目录和页面定位。
2. 区分新增事实、条件、例外、反例、分歧和重复信息。同源转载追溯共同出处，来源摘要和生成答案保留派生身份。
3. 核对实体身份后合入已有对象与主题，更新整体认识、适用范围、分歧和开放问题。有独立读取价值时再建页面。
4. 给关键结论附实际证据位置，更新必要导航，沿已有约定简记实质变化。
5. 回读正文与链接，报告实际修改、冲突及未覆盖内容。无实质信息变化时保持文件稳定。

综合前核对时间、版本、对象和适用范围。演变保留前后有效条件，真实分歧保留双方证据。只读请求仅给候选，普通更新只涉及实际受影响的授权页面。

必要快照仅在本次范围保存，标明外部或工作树来源、版本与获取时间。原始业务文档和代码沿用其所属仓的维护职责。

更新前复读目标，发现并发变化先整合，无法安全区分时暂停受影响写入。人工正文按写作方法保护，来源冲突保留双方证据。

代码结论注明仓库/commit；含未提交修改时注明文件、工作树状态及实际读取时间，不把它归给 HEAD。变动的偏好/决定记录确认日期与来源。外部快照未经在线回源不能称当前有效。

## 来源变化与失效传播

分别核对来源身份、位置和内容版本。同路径或 URL 的实质内容变化按更新处理，原、新位置的内容或版本连续且有移动依据时维护同一来源。

| 情况 | 处理 |
| --- | --- |
| 内容更正 | 核对受更正片段影响的主张并更新 |
| 版本替代 | 保留新旧适用范围、替代依据与历史解释 |
| 正式撤回 | 重评引用主张，检查其他独立支撑 |
| 暂时不可访问 | 记录核验限制，只说明可读快照支持的范围 |
| 用户要求删除或遗忘 | 按实际授权处理原件、摘要、综合、索引及已知派生副本 |
| 仅移除来源文件 | 依据已知意图区分整理、事实变化或明确删除，只有影响当前动作的关键歧义才询问 |

沿来源链接、摘要和相关引用继续核对已知派生层，直到受影响页面已处理或受限位置已明确。例如原件支持摘要、摘要支持主题、主题支持保存答案时，各层均需重评。循环引用沿实际来源去重，核对到已检查页面后继续处理其他依赖，记录当前覆盖范围。

逐项核对剩余支撑的独立性、版本、适用范围和有效时间。共享内容根据剩余证据重新综合，失去唯一依据的授权正文撤下或标明待核实。新版撤回后，恢复旧版当前效力需要有效依据，旧版已过期时保留历史范围，当前结论待核实。

普通修订保留旧来源与替代说明。清除敏感内容时，范围内摘要和变更记录使用必要脱敏表述。Git 历史、远端及外部索引按各自位置和权限处理，仅报告实际处理结果。

受保护旧主张失效时，保留人工正文，在已有且获授权的来源页、生成区域或导航处记录定位到该主张的失效说明。缺少可写位置或依赖越出范围时报告受限位置，继续完成可安全处理部分。后续查询按 [查询方法](query.md) 沿链核验当前依据。

直接维护 Markdown，沿用已有 schema、manifest 或历史记录。只有实际授权包含对应迁移或删除时才调整这些资产。

Wiki 已启用 QMD 时，将已知文档快照、向量和运行缓存纳入来源变化盘点，按 [QMD 维护方法](qmd.md) 在对应授权范围更新或清除。搜索结果停用与实际派生内容清除分别核对，原文改写后重新读取当前正文。

## 保存、整理与恢复

用户要求保存研究成果时，先核对结论、原始依据和推断性质，优先合入已有主题。只保存对应授权内容与必要导航，普通查询保持只读。

根据实际重复、篇幅和阅读用途决定合并、拆分或归档，保护人工正文。来源或页面移动时核对原、新位置和内容版本，按页面所在目录重算相对出链，同时更新受影响入链、锚点与既有 wikilink。相同文件名的不同目标按身份消歧，整理后重复摄取继续复用已有对象。

恢复中断摄取前复读已写页面、索引或等价导航与已有记录，识别已完成修改和遗漏，核对新出现的人工编辑后续办。复用已完成内容，只补受影响部分，报告完成、冲突及受限位置。
