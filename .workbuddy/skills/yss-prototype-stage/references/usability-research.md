# 按问题选择用户研究

准备材料写入现有研究证据与 `design-qa.md`：问题、目标人群及纳入条件、无提示任务、固定场景、观察表、结果限制与待决事项。流程设计参考 [GOV.UK moderated usability testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)。

| 项目 | 可执行记录 |
|---|---|
| 问题 | 哪个具体决策缺证据？例如同名选项是否导致负责人选错 |
| 参与者 | 实际承担任务的角色、经验、辅助技术/语言条件；排除与利益冲突理由 |
| 任务 | 给目的与业务上下文，不给按钮名、路径或正确答案；记录完成标准与终止条件 |
| 主持 | 统一说明本地模拟范围、同意方式及记录用途；中性追问，不提示操作 |
| 观察 | 匿名参与者 ID、版本/包摘要、任务、成功/放弃、错误、恢复、求助及原话出处；时间仅在统一计时下比较 |
| 结论 | 区分直接观察、解释和建议；样本/招募偏差、场景简化、未覆盖人群及未执行项 |

教学任务：“找到闰日登记且由 U-002 负责的资料，修改日期后决定不采用修改。”预设数据来自组合查询 fixture；成功条件是负责人编号正确、结果正确、取消保持原范围。观察栏初始填“未执行”，不能填写模型想象的用户表现。

## 后续真实效果试点交接（本轮不执行）

| 任务 | 共同输入 | 观察指标 |
|---|---|---|
| 查询维护 | 同一 Spec/角色、同名 ID、空/失败/禁用选项、包含边界的固定日期和重置起点 | 正确率、误选、错误恢复、提示次数、完成时间 |
| 复杂表单 | 同一字段/校验、权限、跨页草稿和失败重试场景 | 草稿丢失、输入与已选值混淆、错误定位、放弃率 |
| 审批恢复 | 同一权限矩阵、部分失败和并发恢复来源 | 错误操作、重试范围、恢复结果与状态理解 |
