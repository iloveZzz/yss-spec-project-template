# Git 接入与 Skills 共享

适用于工程 Git 接入、团队共享已安装方法、从新 clone 继续使用 YSS。完整初始化工程的 Git、remote 和 Issue 配置先读本包 [工程初始化与协作配置](project-onboarding.md)；本文负责共享与续办。普通技能调用无需先做迁移；操作沿用当前任务授权，不自动提交、推送或修改关联仓。

## 确认工程边界

Profile 选择能力，project/skills 选择安装范围，scaffold 生成源码；三者都不独立决定 Git 仓库边界。

- 先核实真实 Git 根、remote、worktree 和已有内容。已有独立仓沿用身份；monorepo 子工程沿用父仓，不因安装 Backend/Frontend 而创建嵌套 `.git`。
- 完整初始化独立新工程时，将缺失的本地 Git、已确认 remote 与 tracker 纳入 Agent 接入动作；仅安装 CLI 或补装技能不创建业务仓。CLI 的 init/attach/scaffold 本身仍不执行 Git 初始化、remote 设置或提交。
- 已有 `.git` 的目录不满足 init 的空目录要求，使用 attach；scaffold 已生成源码的目录同样使用 attach skills。受管项目继续使用 sync。
- remote 使用已核实的真实工程地址；没有 remote 或暂时未知时明确注明。新建前先核实远程是否已有内容，非空远程优先复用 checkout/clone 后接入。tracker 的首次目标选择与既有配置保护按初始化参考处理，不从 remote 变更自动迁移。地图中的路径只用于定位，实际工作树在本次任务核实。

一个 YSS 安装根只使用一个 Profile，`skills` 也不能把多个 Profile 合并进同一收据。一个产品 Home 可以关联多个 Backend、Web、Mobile 和共享组件工程；优先采用并列目录，各工程加入其所属 Git 仓，Home 只保存自身资料与导航。

同一 Git 仓有多个工程时，用“仓库身份 + 仓内子路径”定位，例如 `spec/`、`services/customer-api/`、`services/order-api/`、`apps/web/`。这些不重叠目录可以分别安装，Git 根作为容器。已有父子安装根不会自动共享锁或仲裁所有权：分别核对收据中的受管物理路径，不得让父子根管理同一文件；无法证明隔离时顺序同步。Git/submodule 边界保护不等于普通子目录隔离，不为接入自动迁移已有布局。

## 保存可继续维护的工程快照

项目自建技能留在所属工程，YSS 受管技能沿原安装来源维护。Home 通过地图读取目标版本，不收走工程技能的维护权，也不进行双向覆盖。

| 材料 | 共享方式 |
| --- | --- |
| 项目自建技能 | 将完整技能目录及必要引用资源纳入所属仓库，避免与受管技能重名 |
| YSS 受管资料 | 按安装收据和实际引用核对技能、宿主入口及配套资源，包含所需 `.template-spec` 文件；不能只提交 `SKILL.md` |
| `.yss/project.json` | 与工程快照一起保存有效收据；它记录 Profile、安装范围、来源与相对路径基线，不手改摘要或所有权 |
| `.yss/scaffold.json` | 存在时保留生成来源，不能代替项目安装收据 |
| CLI/Bundle 来源 | 在已有 README 或安装说明记录实际 `version --json` 的版本、源码和 Bundle 来源；同版本号不保证同一内容 |
| `.yss/lock`、`.yss/transactions/` | 留作本机运行时与恢复资料，不纳入新的团队共享快照 |

提交前检查实际 Git 忽略结果和待提交内容，确认必要资源与收据没有遗漏；不通过强制添加将凭据、本机配置或恢复材料混入快照。工具安装使用的 `.yss/tool.json` 属于独立工具目录，不复制到项目。

新 clone 使用同一 CLI/Bundle 的行为与“使用当前最新版重建”分别判断。默认技能和依赖会随 Bundle 重算，需要重现旧安装时保留实际来源，不仅记录版本号。项目专属内容未被收据或本次 Bundle 选择时，sync 不接管；以后发生同路径冲突时仍按原保护处理。

## 排除本机运行时资料

在工程安装根的 `.gitignore` 中保留以下规则，不整体忽略 `.yss/` 或技能目录：

```gitignore
/.yss/lock
/.yss/transactions/
```

monorepo 中规则相对该 `.gitignore` 所在目录生效，不假设父仓根规则覆盖所有子工程。已有全局或项目规则若忽略整个 `.yss/`，先核对共享目标与收据可见性，不能声称补两行就完成恢复配置。

Frontend 已有 `.gitignore` 是 user-owned，sync 不会覆盖它。只有本次授权包含项目配置时，才读取原文并增量补足缺失规则，保留全部定制；其他受管忽略文件继续遵守其实际所有权与同步冲突处理。

新增忽略规则不会停止跟踪已有文件。已跟踪的锁或事务只报告范围，不自动去跟踪、重写历史或删除本机资料。发现未完成事务，先按当前 doctor/recover 能力处理；不能删除 `.yss`、锁或事务来绕过保护。只有完整安装才作为可共享的基线。

## 从新 clone 继续维护

先核实目录和程序来源，再用同一已核验程序检查：

```text
<程序绝对路径> version --json
<程序绝对路径> doctor --root <工程绝对路径> --json
<程序绝对路径> skills list --root <工程绝对路径> --json
<程序绝对路径> sync --root <工程绝对路径> --dry-run --json
```

doctor 按现有收据检查文件，不比较新 Bundle；同来源、完整且未改动的工程还需通过 sync 预览核实 unchanged。实际同步只在当前授权内执行。存在定制时按真实差异处理，不要求通过覆盖来获得“零差异”。

缺项目收据时保留文件并报告无法继续受管同步；残留控制目录可能先报格式错误。不重新 attach 强占已有技能，不从文件内容猜造收据。缺引用资源、存在同步冲突或未完成事务时，分别说明原因，不把文件存在等同于恢复完整。文件模式和换行差异按实际 Git 配置核查，不静默归一化所有用户文件。

## 从 Home 选择工程技能

地图的资料入口指向目标仓规则、实际技能目录和来源说明即可；按需读取技能名称、描述与路径，再读取适用正文及相对资源。`yss skills list` 描述受管选择，不能替代项目自建技能目录的发现。

按目标工程适用版本、Home 适用共享版本、来源可核实的宿主版本选择；同名时明确目标仓、工作树及技能路径，不把其他 Profile 或全局版本混用。命令使用目标工程 cwd，子任务也携带目标位置和规则来源；已有跨仓方法继续适用。

显式读取可将指令型技能作为任务上下文，但不代表宿主已原生注册。切 shell 目录、增加可写目录或派出子 Agent 均不能证明重新加载；技能依赖的专用工具、插件和宿主元数据另行确认。保持原技能目录和资源引用，不通过将受管目录软链接到另一仓来规避同步边界。

技能资源以 `SKILL.md` 所在目录为基准，工程命令以目标工程为 cwd。工程可以固定不同技能版本，普通任务不自动升级到全局最新；读取外部技能后仍需显式核对目标 AGENTS 和局部规则。远程、容器或云环境在执行端解析路径；缺少挂载或访问权限就说明缺口，不能回退另一 checkout。

## 在多个工程间续办

Home 汇总目标与结果；Spec 保存业务规则和原型，实际 Backend 或契约仓保存生产 API，工程保存实现和验证。先查真实调用关系再确定影响范围，不因地图列有 Mobile 就一并修改，也不在 Home 复制另一份权威 OpenAPI。

在当前聊天或已有实施说明中保留必要的目标、工程/worktree、允许路径、输入版本、已做事项、证据、剩余依赖和下一步即可，不新建状态系统。输入包含未提交差异和相关未跟踪内容依据，不能只记 HEAD。中断后先核实当前工作树、输入和运行现场；A 版成果保留“A 版已验证”的事实，任务采用 B 时只重做受影响部分，技能版本变化也一样处理。

契约明确且路径、运行资源可隔离时可并行；共享 OpenAPI、生成客户端、根锁文件、共享组件由一人负责整合。宿主没有子 Agent 就串行，不自动启动其它宿主进程。分工至少携带目标、实际工程、输入、技能路径、允许范围与回报要求；技术问题回工程，新的业务取舍反馈 Spec。

worktree 不隔离端口、数据库、输出目录和运行中的程序。检查被测服务身份和来源，使用独立资源；清理前核实归属，只关闭或删除本任务创建的对象。mock、构建成功、单仓完成分别报告，不能替代整体所需的集成证据。只有本次含发布任务时才补兼容窗口、各仓发布顺序和失败责任；多仓提交不是原子发布，不自动回滚其他仓。
