# 验证与 review

目的：证明本次范围实际成立，不用固定数量门禁代替判断。先看项目真实 scripts、测试组织与 CI；命令名不是行为保证，`lint` 可能带 `--fix`。

## 高保真还原的完成判定

按当前文件与本次选定设计核对三类证据：

| 证据 | 成立条件 |
| --- | --- |
| 工程 | 本次适用的结构、类型、静态检查及必要测试通过；沿用项目组件和数据边界，没有通过关闭规则绕过问题 |
| 视觉 | 在可比条件下实际对照来源与实现，覆盖受影响的页面区域、弹层和布局尺寸；记录差异及处理结果 |
| 交互 | 实际操作受影响的核心任务及相关异常/恢复状态，确认可操作性、输入保留、键盘和焦点行为；逻辑单测不能替代浏览器路径 |

核心任务失效、输入丢失、主要布局或主题不符、关键操作不可达均属于未解决前不能报告还原完成的偏差。缺少浏览器、有效设计输入或用户明确限制运行时，继续完成不依赖该条件的工作，报告“源码已实现，相关还原验证未完成”并列明缺口，不把未执行写成通过。局部文案任务可报告该项源码修改完成，不能外推为整页还原完成。

缺少生产接口但上述三类证据已在明确模拟范围内成立时，可报告“前端已还原（模拟运行，待联调）”；真实服务和持久化仍需各自证据。使用当前范围内已取得的有效结果，不要求为了交付表述重跑一次全套检查。

新建或调整工具链、请求模拟、浏览器回归时读 [质量工具](quality-tooling.md)：ESLint 无写入检查、MSW 网络边界、Playwright/axe 与人工检查各自负责不同证据；不因新增工具扩大每次任务的检查范围。可用的 vue-testing-best-practices 仅作专题辅助，以安装版本和官方资料核对。

## 按变更选择证据

| 改动 | 最小有用检查 | 不能据此声称 |
|---|---|---|
| 文案 / spacing / token | 受影响画面和弹层的浏览器对比；必要构建 | 未看的其他主题、视口都一致 |
| Vue 逻辑 / composable | 类型检查；实际行为或边界的小测试；受影响路径操作 | 纯函数测试证明焦点/布局正确 |
| 查询 / 写入 / 缓存 | 旧响应、失败保留、重复提交、身份清理等实际相关回归 | 模拟 service 证明真实服务已联调 |
| 路由 / 权限 | 直达、刷新、前进后退及相关未登录/403路径 | 按钮隐藏证明后端授权安全 |
| 新工程 / 依赖 / 构建配置 | 锁文件可安装、类型/已有静态检查、代表测试、生产构建、实际启动 | dev server 可打开等于部署已成功 |
| 发布路径 / 资源配置 | 在适当预览环境检查 base、深链回退、资源与更新错误 | 本地 preview 证明真实网关配置正确 |
| OpenAPI / 生成客户端 | 实际生成、类型检查、契约差异及生成函数经过 transport 的响应/错误/取消测试 | 生成 DTO 或模拟接口证明生产服务符合契约 |

遵守目标工程必需检查；若与当前范围明显冲突，说明具体原因，不擅自关闭。无既有测试工具的新工程，按风险选择 Vitest + Vue Test Utils 做逻辑/组件验证，浏览器端使用项目已有设施或可用浏览器；不为纯文案改动引入整套测试依赖。

复用现有命令与场景，按变化选择有意义的检查。例如 `build` 已依次执行结构和类型检查时，同一文件状态下不再单独重复；修复后重跑失败项及受影响检查。技能维护、只读审查和文档改动不自动触发应用全量测试，也不默认新建 CI、视觉平台或检查脚本。

新分支、状态机、解析器、竞态及安全边界留下可重复的最小测试或断言；修复缺陷时确认检查能识别原问题。避免只断言实现细节、测试文案是否包含关键词或为覆盖率制造无价值用例。

## 代表路径

按实际涉及的行为选取，不机械全跑：

- 列表：初次加载、空结果、失败恢复、筛选/翻页归零、连续查询后旧响应不覆盖新数据。
- 编辑：校验失败、保存失败保留草稿、成功后同步、双击不重复提交、取消与焦点恢复。
- 身份：登录过期、403、退出或切租户后旧缓存/旧响应不再显示；写入结果不明不报成功。
- 视图：代表桌面与设计要求的窄屏、长内容、弹层主题、键盘可达、焦点可见。

以断言和具体动作记录结果。例如：“请求 B 先成功、请求 A 后成功，列表仍为 B”比“竞态已处理”更有价值。未操作的路径保持未验证。

## Review 方法

用户明确要求独立 review 时，使用可用的独立评审者读取当前成果及必要原始输入；没有独立评审能力就说明限制。其余任务按实际需要自审或委派，不把评审、角色或批准记录作为统一交付前置。只请求 review 时保持只读，不自行进入修复。

评审覆盖两个相互补充的视角：

1. **设计与行为**：从规则追踪到页面和真实操作，检查关键状态、设计保持项、主题链、可访问性、模拟范围。不能只看一张默认截图。
2. **工程与边界**：读受影响调用链、状态生命周期、请求与缓存、认证、错误恢复、生成/手写边界、依赖锁与配置。确认改动没有遗留旧调用者或扩散无关改动。

仅报告可解释影响的问题，附文件/行号、触发条件、预期与实际、严重性及最小修复建议。按以下顺序处理：数据丢失或越权/串租户 → 主要行为失效 → 关键设计偏差与可访问性 → 可维护性。建议性偏好单列，不能伪装缺陷。

修复确认的问题后，只重跑受影响的检查及项目必需项；最终 review 绑定修正后的文件。不能把旧版通过结果套在后续改动上。无发现时记录已读/已执行范围与未检查项，不承诺“没有任何问题”。

## 交付表述

交付包含应用源码、实际安装/运行命令、现有设计/规则映射、真实验证结果和未完成边界。可合并在已有 README 或回复中，不强制报告文件。

- **已执行**：命令或浏览器动作、目标版本/当前文件、结果；“构建通过”“类型检查通过”“测试通过”分别陈述。
- **模拟**：哪些数据与动作是 fixture/mock、是否持久化、重置方式和真实接入缺口。不能把演示成功写为业务验收通过。
- **未执行 / 风险**：缺少接口、浏览器或环境时说明受限范围；没有实际生产证据不声称已部署或上线。

性能检查以实际需要为准。构建 chunk 大小、压缩估算、浏览器网络传输和交互延迟是不同指标；无阈值的统计不能称为预算门禁。大列表先确认数据量与瓶颈，再决定分页或虚拟化。
