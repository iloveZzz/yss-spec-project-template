# 模板维护流程

`template-source` 模式（见 [[仓库身份与路由]]）使用模板维护流程管理模板自身的演进，不默认生成具体产品的 Spec、原型、OpenAPI 或垂直切片 Ticket。

标准流程为：影响面分析 → 修改对应单一事实来源 → 同步技能投影和派生文档 → 执行压力场景与 `scripts/verify-template` → 独立审查和 Git checkpoint。影响面分析决定修改哪些权威资产：`AGENTS.md`、`CONTEXT.md`、生命周期映射、裁剪指南或 `skills-lock.json`。

硬门禁包括：创建、修改或退役 skill 时使用 `maintaining-skills`，并按 L1 / L2 / L3 执行对应验证与审查；`.agents/skills` 是跨 Agent 共享技能的权威内容，各平台目录中的共享技能是生成投影，禁止分别手工修改（见 [[技能投影与锁定]]）；`scripts/verify-template` 是模板发布阻断门禁（见 [[模板发布门禁与验证]]）。

模板与外部 `create-yss-spec` 的跨仓库契约未完成集成验证时，不得声称可发布；发布顺序与责任边界以 raw 源 `create-yss-spec-contract.md` 为准（见 [[实现仓库与跨仓库契约]]）。模板改动后需运行 `scripts/sync-skills`、`scripts/update-skill-lock` 与 `scripts/verify-template`。
