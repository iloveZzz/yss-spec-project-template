# 仓库身份与路由

仓库身份由根目录 `yss-project.yaml` 显式声明，只包含 `schema_version` 与 `repository_mode` 两个字段，是 CLI 与 Agent 共享的稳定契约（ADR-0002）。`repository_mode` 有两种合法取值：`template-source`（模板源仓库）与 `project-instance`（模板实例仓库）。

`template-source` 模式使用模板维护流程：影响面分析 → 修改单一事实来源 → 同步技能投影与派生文档 → 执行压力场景与 `scripts/verify-template` → 独立审查与 Git checkpoint。该模式不默认生成具体产品的 Spec、原型、OpenAPI 或垂直切片 Ticket（详见 [[模板维护流程]] 与 [[模板发布门禁与验证]]）。

`project-instance` 模式按产品研发生命周期分诊任务（见 [[产品研发生命周期]]）：入口分诊 → 机会与 Discovery → 业务 / Spec / 功能架构 → 产品设计与需求冻结 → 系统 / 数据架构与工程契约设计审查 → 契约冻结与 Ticket 正式化 → 垂直切片与 TDD 实现 → 验证发布与复盘。

文件缺失、schema 版本不支持或模式值非法时，必须停止路由并执行迁移检查，不得根据目录、Git 远程或占位符猜测身份。外部 `create-yss-spec` CLI 从模板初始化仓库时必须将模式改写为 `project-instance`，这一跨仓库契约的细节见 raw 源 `create-yss-spec-contract.md`。仓库身份判定是 Agent 的首要步骤，直接影响后续所有流程选择（见 [[Agent入口规则]]）。
