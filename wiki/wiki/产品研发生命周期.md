# 产品研发生命周期

`project-instance` 仓库按产品研发生命周期分诊任务。日常骨架为：入口分诊 → 机会与 Discovery → 业务 / Spec / 功能架构 → 产品设计与需求冻结 → 系统 / 数据架构与工程契约设计审查 → 契约冻结与 Ticket 正式化 → 垂直切片与 TDD 实现 → 验证发布与复盘。

任务开始时先根据影响面判断是小改动、中等变更还是新模块 / 高风险变更，定位最近可信阶段，再执行对应活动。整个生命周期由 [[条件强制门禁]] 中的 21 个条件强制门禁约束：命中触发条件时必须完成，未命中时只记录 `not-applicable` 及原因，不生成空文档。

新功能或较大变更先用 `grill-with-docs` 澄清需求，再用 `to-spec` 形成 Spec 基线（见 [[Spec基线]]）。只要进入 Spec 基线，必须产出产品总体设计或功能架构；涉及 UI 与主流程、导航、权限、异常 / 恢复状态或 API 反推时，构成产品设计影响并强制 [[产品设计影响与原型]] 流程。API 契约变更先形成 OpenAPI 3.1 Draft，经必要的工程基线、系统 / 数据架构和设计审查后 Freeze（见 [[OpenAPI契约]]）。

契约冻结完成后，使用 `to-tickets` 将需求拆成可独立验证的窄垂直切片 Ticket（见 [[垂直切片Ticket]]），禁止只按 Adapter / Application / Domain / Infrastructure 横向拆分。每个功能先建立功能父 Ticket 汇总阶段证据（见 [[Ticket与流程状态]]）。生命周期各阶段资产与门禁的权威映射以生命周期资产映射为准。
