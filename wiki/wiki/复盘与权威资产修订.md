# 复盘与权威资产修订

发布后或阶段性完成后做复盘判断：出现架构返工、验证返工、IMPORTANT / CRITICAL review finding 或人工确认延期时，落简体中文复盘并修订权威资产。

复盘输入包括验证证据、审查报告、Ticket 证据与 Git checkpoint 记录（见 [[Fresh验证与独立审查]] 与 [[Ticket与流程状态]]）。复盘输出按 `docs/templates/retro-report-template.md` 记录，发现的问题回流到对应单一事实来源：流程语义问题修订生命周期映射或裁剪指南，词汇问题修订 `CONTEXT.md`，决策问题沉淀 ADR，技能问题进入 `writing-skills` 修订流程（见 [[模板维护流程]] 与 [[条件强制门禁]]）。

复盘修订遵循影响面分析与条件强制门禁：命中触发条件才生成对应资产，未命中记录 `not-applicable`（见 [[影响面分诊与流程裁剪]]）。复盘发现的跨仓库问题（如 `create-yss-spec` 契约偏差）须同步到外部仓库责任边界（见 [[实现仓库与跨仓库契约]]）。

复盘是模板维护流程的最后一步，也是下一次迭代影响面分析的输入，形成持续改进闭环。
