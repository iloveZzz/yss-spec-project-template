# 模板发布门禁与验证

`scripts/verify-template` 是模板发布阻断门禁，模板源发布前必须通过结构、技能同步、流程语义和压力场景验证集合；不等同于只检查文件存在、Markdown 链接或 YAML 语法。

`verify-template` 验证五类压力场景（生命周期、YSS Router、YSS UI、Matt × YSS 集成等），由 `scripts/verify-lifecycle-scenarios`、`scripts/verify-yss-router-scenarios`、`scripts/verify-yss-ui-scenarios`、`scripts/verify-matt-yss-integration-scenarios` 等脚本支撑。模板与外部 `create-yss-spec` 的跨仓库契约未完成集成验证时，不得声称可发布（见 [[模板维护流程]] 与 [[实现仓库与跨仓库契约]]）。

模板维护硬门禁还包括：修改 skill、`AGENTS.md`、流程规则或模板时，必须使用 `writing-skills` 的 RED / GREEN / REFACTOR 思路，保留基线失败、压力场景和修订后验证证据；共享技能投影禁止分别手工修改（见 [[技能投影与锁定]]）。

任何"完成 / 可合并 / 可发布"结论必须基于 fresh verification（见 [[Fresh验证与独立审查]]），不接受"之前跑过"或实现者自述。模板发布前还需同步技能投影与派生文档、更新 `skills-lock.json`，并完成独立审查和 Git checkpoint。
