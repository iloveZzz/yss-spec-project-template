# 模板发布门禁与验证

`scripts/verify-template` 是模板源发布阻断门禁。按 `CONTEXT.md`，模板发布门禁是结构、技能同步、流程语义和压力场景验证的集合，不是只检查文件存在、Markdown 链接或 YAML 语法。通过时输出 `模板发布校验通过`。

Quickstart 要求：`template-source` 修改流程、技能或模板后，执行 `scripts/sync-skills`、`scripts/update-skill-lock` 和 `scripts/verify-template`（见 [[模板维护流程]]、[[技能投影与锁定]] 与 [[模板总览]]）。创建、修改或退役 skill 时使用 `maintaining-skills`，并先按 `docs/process/harness-process-tailoring.md` 判定 L1 / L2 / L3；只有 L3 必须保留完整基线失败、压力场景、修订后验证和正式独立审查证据。发布候选固定按 L3 聚合验证，但不追溯补造每个既有 L1 / L2 修改的独立 RED。

身份为 `template-source` 时，脚本先跑 `.template-source/scripts/evidence-index --check`、`pnpm --dir .template-source/tooling/node test` 与 `check:vendor`，再执行投影 / 锁文件 `--check`、生命周期注册表校验和全部 `scripts/verify-*` 场景脚本。技能清单、来源、版本、哈希和投影目标以 `skills-lock.json` 为准；当前 `mattpocock/skills` 的 `revision` 为 `0ab1b63a410a03d3627979a109c8695de27af954`，不以 README 中可能过期的 hash 覆盖锁文件。

模板与外部 `create-yss-spec` 的跨仓库契约未完成集成验证时，不得声称可发布（见 [[实现仓库与跨仓库契约]] 与 [[仓库身份与路由]]）。公开发布投影前的顺序为：同步 canonical projections → 更新 lock → `scripts/verify-template` → 导出并检查 → 独立审查 → 在 `yss-spec-dev-skills` 提交人工 PR。

任何「完成 / 可合并 / 可发布」结论必须基于 fresh verification（见 [[Fresh验证与独立审查]]），不接受「之前跑过」或实现者自述。`gate.release-ready` 的证据是 `evidence.fresh-verification` 与 `evidence.checkpoint-and-rollback`。Git checkpoint 只包含本轮明确范围；获得用户授权后才提交或推送（见 [[Agent入口规则]]）。
