# 影响面分诊与流程裁剪

Harness 流程裁剪指南定义了影响面触发与 `not-applicable` 的判定规则：不是所有变更都走完整生命周期，而是根据影响面裁剪流程深度。

分诊维度包括：小改动（如孤立文案、token、颜色、间距等无行为变化的视觉修复）、中等变更（单个契约或模块内调整）与新模块 / 高风险变更（跨层、跨仓库或破坏性契约变化）。任务开始时先做影响面分析，定位最近可信阶段，再决定执行哪些活动与门禁（见 [[条件强制门禁]]）。

典型裁剪规则：只有 UI 变化触及主流程、导航、权限体验、异常 / 恢复状态、状态流转或 API 反推时，才构成产品设计影响并强制 [[产品设计影响与原型]] 流程；文案、token、颜色和孤立视觉修复记录 `not-applicable`。全新产品、全新模块和低风险调整不生成 Spec Delta（见 [[SpecDelta]]）。未定义关键流程清单时，不得声称 E2E 覆盖率达到 100%（见 [[Fresh验证与独立审查]]）。

裁剪不是省略质量：被裁剪的环节仍需记录 `not-applicable` 及原因，保证追踪证据完整。
