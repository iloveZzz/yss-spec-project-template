# Slice Implementation Contract

Slice Implementation Contract 是进入实现前由 `yss-router` 根据冻结资产和垂直切片编译、再由生命周期编排器批准的实现合同。合同至少包含 Common、Frontend、Backend、Contract 和 Cross-repo 子合同，以及工作单元、TDD 模式、允许写路径、禁止模式、证据和验证命令。

Router 只能生成合同草案，不能自行批准合同或设置 `ready-for-agent`；批准与持久化由生命周期编排器完成（见 [[YSS路由与合同编译]] 与 [[Ticket与流程状态]]）。Backend 子合同保留额外强约束，至少包含 `required_skills`、`allowed_write_paths`、`forbidden_patterns`、`expected_evidence_files`、`seam_deferred`、`verification_commands` 六个字段。

合同将系统 / 数据架构、ADR、工程基线、OpenAPI Freeze 与风险 / 回滚约束转译为 Build Architecture Checklist（见 [[OpenAPI契约]]）。核心 YSS skills 必须消费批准合同并返回 YSS Skill Execution Result；路径越界、证据缺失、未执行验证、`drift`、`violation` 或 `new_impacts` 阻断继续实现或触发重路由。

合同编译依赖已冻结的 Spec 与垂直切片（见 [[Spec基线]] 与 [[垂直切片Ticket]]），跨仓库切片还需补充 Cross-repo 子合同（见 [[实现仓库与跨仓库契约]]）。实现者自报 `implemented` 不构成最终通过，必须由 Router、生命周期编排器和独立 Reviewer 复核（见 [[Fresh验证与独立审查]]）。
