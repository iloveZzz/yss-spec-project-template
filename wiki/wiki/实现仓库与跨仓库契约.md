# 实现仓库与跨仓库契约

当前仓库默认是研发管理仓库（Harness），前端、后端和其他运行时代码优先位于独立实现仓库；只有用户明确选择当前仓库承载实现代码时，才按需创建 `apps/backend/` 与 `apps/frontend/`，不得自行新建其他顶层业务代码目录。

进入实现前必须：确认受影响的 frontend / backend 工程是 `existing`、`required` 还是 `initialized`，并登记实现仓库、分支、CI、验证命令和回滚点；无可复用工程时，先确认外部目标仓库或输出目录，再分别使用 `yss-ddd-scaffold-generator` / `yss-frontend-scaffold-generator`，不因当前仓库缺少 frontend / backend 目录而绕过脚手架路由。实现仓库接入规则见 `docs/process/implementation-repo-integration.md`（见 [[YSS路由与合同编译]]）。

跨仓库契约变更需要两个或多个独立仓库协同实现、验证和按顺序发布。任一参与仓库未完成契约对齐和集成验证时，不得单独声称整体可发布。模板与外部 `create-yss-spec` CLI 的跨仓库契约（身份转换、升级迁移、集成测试、发布顺序）见 raw 源 `create-yss-spec-contract.md`，建议技能为 `cross-repo-implementation-routing`（见 [[模板维护流程]]）。

Ticket、Spec 和阶段证据按用户选择或当前主远程路由到 GitHub / GitLab；平台不可用时生成本地待发布草案，不自动改投其他平台（见 [[Ticket与流程状态]]）。
