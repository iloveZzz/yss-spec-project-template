# 复盘报告：<功能名称>

## 做得好的地方

引用本次实际结果与证据，说明哪些做法值得保留；不把预期收益写成已实现。

## 需要改进的地方

记录触发条件、实际影响与证据，区分事实、已确认机制和待验证假设；说明返工或漏检为何未被既有检查发现。检查是否存在、是否接入本次执行路径、是否实际执行分别说明，不把“有检查”写成“本次已检查”。

## 改进动作

引用既有待办 / 工作项；在其权威记录中登记负责人、解决时点、验证方法、关闭条件与关闭证据。本节说明动作如何解决上述问题，不另外维护一套进度；未分派写未登记。只有计划、建议或尚未执行的验证时保持待处理，不能关闭行动。

## 沉淀去向

列出需修订的事实源、Skill / 模板 / 校验场景及关联行动，说明每项采取以下哪种处置及理由：

- 既有检查未接线或漏执行：优先修复接入与执行路径，引用修订位置及本次实际执行证据。
- 重复出现、可机械判定的不变量缺少检查：确认既有检查未覆盖后，增加最小检查，以失败反例证明能检测目标情形，并记录修订后的实际验证结果。
- 无法机械判定：说明人工验证的方法、判断依据和结果记录位置，按关联行动的关闭条件留证。
- 机制或适用范围尚未确认：登记待验证假设与验证方法，不把单次现象直接写成通用禁令。

关闭时引用实际修订与验证结果；检查已存在、方法已提出或文档已起草本身不构成关闭证据。事实源、Skill、模板和检查只在各自权威位置修订，本节引用其去向。
