# 运行记录与证据留存

运行工具把普通执行记录保存到仓库外的 SQLite 和日志目录。checkpoint、合同、批准、用户原始决定、迁移回执及恢复事务继续使用现有文件作为权威。查询索引和历史通过记录只能帮助定位证据；阶段流转、实现和交付仍执行当前合同要求的 Fresh Verification。

## 存储位置与运行方式

受影响工具要求 Node `>=22.13 <27`，使用内置 `node:sqlite`，不安装原生驱动。低于最低版本或达到 27 时，在创建目标目录、数据库或日志前拒绝执行；`off` 模式也遵守工具的 Node 基线。

默认目录为 `~/.yss-harness/runtime/<workspace-id>/`，其中 `workspace-id` 是项目根目录真实路径的 SHA-256。不同 worktree 分开保存。`YSS_RUNTIME_HOME` 可指定仓外绝对目录，CI 优先使用 `RUNNER_TEMP`。目录本身及符号链接解析后的目标均不得进入项目或已登记子仓。

支持运行存储的执行入口接受 `--runtime-store sqlite|off`。试点使用显式模式；验证及分发闭合后，新版本默认使用 `sqlite`。`off` 回到原文件执行路径，用于受控回退。已有实例通过升级计划接入，不自动迁移业务文件。

运行由创建它的存储会话登记终止；其它连接不能通过 `finish` 接管运行或覆写报告。进程中断后保留待恢复状态，历史状态不能据此转成当前验证通过。

| 内容 | 保存方式与用途 |
|---|---|
| 运行摘要、命令结果、事件 | SQLite 保存输入摘要、实际退出码、耗时和终止原因 |
| checkpoint 查询索引 | 绑定源文件路径和当前摘要；源文件变化后索引过期，不能改变门禁结果 |
| stdout / stderr | 执行时流式写日志文件，正文不逐段进入数据库 |
| 重复运行输入清单 | 以原字节 SHA-256 去重并压缩，数据库登记对象引用 |
| 正式验证材料 | 独立文件包，保留原报告与 `run:` 格式，并登记永久保护 |

数据库文件名为 `runtime.sqlite`。SQLite 使用短事务、`journal_mode=DELETE`、`synchronous=FULL` 和 5 秒锁等待。事务资产中的完整输入、恢复备份仍保留原字节，不替换为运行对象引用。Fresh Verification 的源码扫描范围保持不变；如果以后消费仓外对象作为输入，必须显式绑定对象摘要。

模板 runner 在同一短事务中保存一次实际命令结果、日志索引和对应完成事件；复用执行仍单独登记各查询位置的事件，通过 command_id 引用首个实际命令，避免在事件中重复保存命令及日志路径。文件摘要与序列化在事务前完成，事务失败回滚全部登记，命令及已有日志不重跑或删除。首次登记失败后的复用事件保留脱敏命令和日志路径，不能引用不存在的命令记录。

命令结果保留原有 runner 状态，并追加 actual_exit_code、actual_exit_signal 和 actual_exit_code_observed。超时、取消的包装状态不替代子进程实际退出观察；未执行或启动失败的实际退出码为 null，信号终止保留实际信号。普通退出 130 仍按实际失败处理，不能仅凭数字判为取消。

## 执行与证据

运行登记完成后执行命令，保存实际结果并形成报告。命令执行成功和运行存储成功分别记录；数据库故障不得改写实际命令退出码，也不得重跑已经执行的命令。已有日志继续保留，报告给出存储异常。无法形成完整验证报告时，不能宣布验证通过。

模板验证未指定 `--report-dir` 时保存普通运行记录；显式报告目录自动保护。发布验证保护内部完整验证报告。只读分诊继续保存独立运行包并保护整个包，`run:` 仍解析到真实文件。`project-ci check` 的 stdout JSON 和原退出码保持兼容，可选择登记运行。

导出包带相对路径和摘要清单，能够在没有原数据库的环境核验。新阅读入口消费该清单；旧报告字段和历史已批准材料继续兼容，不重新序列化历史材料。

## 管理入口

统一使用 `scripts/runtime-store`。精确参数可通过 `scripts/runtime-store --help` 查询；查询和验证的 `--plan` 不创建数据库或运行文件。

| 命令 | 行为 |
|---|---|
| `inspect` | 查询运行、存储量、保护原因和过期候选 |
| `inventory` | 只读盘点存量机器文件，报告分类、大小、重复内容和归档候选 |
| `export` | 导出指定运行的报告、日志、输入和摘要清单，登记永久保护 |
| `plan-gc` | 生成可审阅的清理计划，不删除文件 |
| `apply-gc` | 按计划重验引用、占用与输入摘要后清理 |
| `backup` | 创建一致性数据库快照及恢复所需文件 |
| `restore` | 从备份恢复，拒绝覆盖不同内容的目标 |

常用操作如下；输出、计划与备份目录均选择仓外绝对路径：

```bash
scripts/runtime-store inspect --root <项目根> --json
scripts/runtime-store inventory --root <项目根> --json
scripts/runtime-store export --root <项目根> --run <运行ID> --output <新的仓外目录>
scripts/runtime-store inspect --source <导出包目录>
scripts/runtime-store plan-gc --root <项目根> > <仓外计划.json>
scripts/runtime-store apply-gc --root <项目根> --plan <仓外计划.json>
scripts/runtime-store backup --root <项目根> --output <新的仓外备份目录>
scripts/runtime-store restore --root <项目根> --source <仓外备份目录>
```

数据库版本由迁移记录管理，升级前备份；未知版本和不符合初始化条件的已有数据库拒绝写入。备份等待运行占用解除后创建独立一致性快照，并保存相关文件摘要；恢复核对所属工作区和摘要，已有不同内容不覆盖。派生索引可以从仍保留的权威文件重建，未导出的运行事件依赖备份恢复。

备份保存运行存储目录及一致性数据库快照。登记在其它仓外目录的正式报告列为 `external_dependencies`，保留其路径和摘要；恢复结果的 `formal_evidence_complete` 表示这些外部材料是否仍完整。需要脱离原环境携带正式证据时，应先使用 `export` 生成独立包，再通过 `inspect --source` 校验并解析相对日志路径。备份不会搬迁或覆盖原正式报告。

## 留存与显式清理

普通成功运行从结束时间起保留 7 天；失败、超时和取消运行保留 30 天。只有显式执行 `apply-gc` 才删除过期日志。清理后保留精简摘要及“日志已过期”标记，查询者不能将其作为完整证据。

清理须同时满足：运行已结束且过期、没有保护记录或正式引用、没有进程占用、引用扫描完整。未知分类、未解析动态引用、待恢复运行和运行中记录均保留。计划生成后输入发生变化时，执行拒绝该计划。共享输入对象只有在全部引用都具备清理资格时才删除。正式导出材料不适用 7 / 30 天留存期。

文件占用探测不可用或结果不完整时，清理资格保持不确定并保留文件。macOS / Linux 使用 `lsof`，Windows 使用独占文件探测。清理中断记录 `gc-pending`；恢复清理由重新执行 `plan-gc` 生成计划，再显式执行 `apply-gc`，重新检查引用、保护、占用和剩余原字节。普通启动不会自动继续删除。

执行清理时应保持正式引用和日志读写的静止窗口；需要作为正式材料使用的运行先执行 `export` 登记保护。SQLite 事务能协调本存储的登记、保护与对象引用，任意外部文件写者和日志读取进程不共享该锁，因此删前复核不能提供跨进程文件系统的原子快照。无法建立静止窗口时只运行 `plan-gc`，保留候选。

历史合同、批准、checkpoint、回执和维护证据只参与 `inventory`。盘点列出的归档候选不授予删除或迁移权限；历史整理需要独立的范围授权及当前验证。
