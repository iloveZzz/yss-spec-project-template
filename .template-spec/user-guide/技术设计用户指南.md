# 技术设计用户指南

技术设计把已明确的业务行为落实到真实工程的职责、调用、数据、接口和失败处理。用户可以直接要求方案评估、数据库分析、API 设计或完整研发，Agent 按当前请求选择必要深度并复用已有工程。

本文以 CLI 3.8.0、Template 5.8.0 的职责为基线。当前主干 `536f6eee` 进一步补充来源采用依据、运行入口和新会话接续方法，具体使用范围以实际安装技能为准。团队流程见[用户手册](用户手册.md)，演示练习见[培训材料](培训材料.md)，已有项目输入见[既有成果复用](阶段接入与产物复用使用手册.md)。

## 先给出行为与工程

| 输入 | 用户已有材料 | Agent 核实与补充 |
| --- | --- | --- |
| 目标与验收 | 明确请求、Spec、业务票或已有 FR/AC | 当前可观察行为、边界与真正未决的业务选择 |
| 业务语言 | 项目根 CONTEXT、规则与已确认决定 | 词义、责任与现有实现的差异 |
| 产品设计 | 选定原型、交互说明、状态与模拟范围 | 需要真实服务承接的动作和结果 |
| 工程事实 | 仓库、目录、代码、POM、配置、已有设计 | 实际架构、版本、调用方、数据库和外部依赖 |
| 本次范围 | 只给设计、完成实现、补测试或维护文档 | 可写路径、验证环境与外部动作授权 |

事实缺失先调查，影响业务结果的选择交给业务方。目标、规则和版本已有依据时直接沿用。设计内容保存在项目已有说明或当前任务中，复杂行为再展开图表和详细接口。

```text
为[业务行为]设计技术方案。规格采用[位置及版本]，工程使用[目录]。
请读取当前架构、调用方、POM、数据和接口，说明职责、事务、权限、
并发与失败恢复，以及验证办法。本次只交付设计，业务结果取舍再定点询问。
```

## 按问题选择设计深度

| 当前问题 | Agent 展开的内容 | 常见输出 |
| --- | --- | --- |
| 模块或外部系统如何协作 | 边界、职责、依赖方向、运行约束 | 当前行为涉及的架构说明和必要关系图 |
| 一个行为怎样落地 | 调用路径、数据与API、事务、兼容性及恢复 | 同一份技术方案中的关键决定与影响 |
| 复杂规则怎样实现 | 对象责任、状态、关键接口、映射和异常 | 可实现的详细设计及对应验证要点 |
| 一个局部缺陷怎样修 | 根因、受影响调用方、最小修改及回归 | 当前任务中的修复说明和实际结果 |

只有方案存在实质差异时才比较备选。性能、容量和恢复目标缺少测量依据时，保留假设及验证方法。只读设计请求交付设计，已授权实现任务继续完成受影响代码和验证。后端方法由目标工程中的 `yss-technical-design` 提供，能力衔接见[Profile 技能地图](../agents/profile-skills.md)。

## 沿用实际 DDD 或 MVC 架构

| 责任 | DDD 工程 | MVC 工程 |
| --- | --- | --- |
| 业务规则 | Domain 维护领域行为、不变量、状态与聚合责任 | 既有 Service 维护用例规则和状态行为 |
| 事务与协作 | Application 编排用例、事务和跨聚合协作 | Service 管理事务、幂等与依赖协作 |
| 持久化与外部系统 | Infrastructure 实现 Repository、Gateway 等实际端口 | Repository 与已有外部适配器负责数据访问和集成 |
| HTTP 边界 | Controller 处理请求、校验、身份、响应和映射 | Controller 沿现有请求响应边界处理 |
| 查询与展示 | 根据查询路径组织分页、投影和展示模型 | 沿既有查询与 Service/Repository 约定组织 |
| 设计技能 | `yss-technical-design`，聚合内部按需用 `yss-tactical-design` | `yss-technical-design`，用例实现采用 `yss-application` 的 MVC 方法 |

新工程根据真实业务和部署约束选择架构，再使用对应脚手架。已有工程沿用当前分层、包名和版本。脚手架选项与平台默认组合见[Backend 与脚手架](cli/tutorial-backend.md)。YSS 4、Boot 4 和 Java 17 的新建默认组合仍需在目标工程执行相应构建、运行和依赖验证，具体部署结果按实际环境报告。

```text
在[现有MVC工程]实现[明确行为]，保持当前 Controller/Service/Repository 结构。
请核对 Service 的规则、事务和幂等边界，处理相关调用方并运行有意义的回归。
```

```text
在[现有DDD工程]设计并实现[聚合行为]，采用[规则位置]。
请核实聚合责任、不变量、外部端口和事务边界，保留当前分层与版本，
验证成功、拒绝、重复执行及本次相关并发路径。
```

## 数据库、API 与前后端各承担什么

| 责任方 | 负责内容 | 输出及交接 |
| --- | --- | --- |
| Spec 与产品设计 | 目标、概念关系、信息含义、必填/唯一性、权限、状态、异常与验收 | 业务规格、选定高保真原型和交互说明 |
| 后端技术设计 | 实际模块、事务、一致性、数据模型、API、兼容性和外部依赖 | 工程内技术方案、契约、实现及验证 |
| 数据库分析 | 结构审查、只读元信息、表字段索引设计、说明书及可审阅 DDL | 有来源的发现、设计取舍和实际文件检查 |
| 前端应用 | 选定体验、状态与资源还原，真实 API 消费和请求错误处理 | 应用源码、工程/视觉/交互证据及联调状态 |
| 集成负责人 | 共享契约、生成客户端和跨仓依赖整合 | 当前版本的逐仓结果及必要集成证据 |

### 数据库任务

向 Agent 指明已有 DDL、模型或授权数据库目标，以及审查、设计或生成说明书的目的。Agent 先核实业务关系，再使用 `database-analysis-docs` 处理结构和文件。

新设计默认表达逻辑关系，记录关联数量和维护责任，保留必要的主键、非空与唯一性，主键 ID 默认由写入方提供。已有库按真实结构记录。多格式持续维护时可采用同源 JSON，单份分析可直接维护 Markdown。连接采集读取授权范围的系统目录与对象定义，DDL 执行和迁移另按对应动作授权处理。

```text
审查[DDL或模型位置]是否支持[规则位置]，只读分析。
请核对关系、必填、唯一性、状态和查询索引依据，区分现状与建议，
给出来源、具体影响和待决定事项。需要SQL时先确认目标方言与版本。
```

### API 与前端任务

实际后端或契约仓维护生产 API。设计需说明参数、返回、错误、权限、分页及已有消费者兼容性。前端读取该权威版本，按实际任务生成或接入客户端。原型模型保留模拟用途，API 缺失时前端交付说明已完成部分和待联调路径。

```text
为[业务行为]完善[契约位置]并接入[前端工程]。
请核对当前调用方、权限、错误、分页及兼容性，统一transport和生成边界，
完成已授权的两仓修改，分别报告契约检查、模拟验证和真实联调结果。
```

## 数据变化、失败与发布顺序

涉及存量数据时，先读取数据库版本、schema、已有迁移和应用读写路径。方案说明历史空值、重复值、非法状态和字段转换的处理依据，沿用工程已有迁移方式。

需要新旧实例并存时，按实际依赖安排兼容结构、应用发布、分批回填、读写切换和旧结构清理。说明并发写入、断点重跑、中止条件与恢复动作。应用回退核对当前数据和 schema 的可读性，数据恢复写明实际备份前提与影响。

跨仓发布任务由各仓提供当前版本、兼容窗口、发布顺序和失败责任。具体部署环境与执行授权在当前任务核实，未知恢复能力保持待验证。设计中的指标、日志与健康信号沿用已有设施，再按实际缺口提出补充。

## 如何判断设计与实现完成

| 结果 | 查看什么依据 |
| --- | --- |
| 设计已完成本次范围 | 行为、职责、关键决定、依赖、验证办法和未决影响均可定位 |
| 源码已实现 | 本次目标涉及的代码、调用方、配置和兼容处理已完成 |
| 构建或测试已通过 | 实际命令、目标模块、发现并执行的测试、结果文件与跳过项 |
| 运行路径已验证 | 服务身份、输入、动作、可见结果、必要副作用及清理结果 |
| 联调或部署已完成 | 对应环境和当前版本的实际集成、部署与业务可用证据 |

后端命令优先使用工程根 `./mvnw`，测试阶段与 Profile 根据实际 POM 选择。真实数据库隔离、锁、权限、外部服务和数据恢复各有自己的验证范围。只读 review 输出有位置、条件和影响的发现，修复按已有研发授权继续。

当前主干 `536f6eee` 增强了项目验证入口接续。新会话先从已有技能、README、运行说明和用例恢复启动、就绪、代表正常异常路径、证据及清理方法，核实服务工作树和资源归属后继续。来源冲突时保留实际采用正文和必要资源依据，具体接续方法见[既有成果复用](阶段接入与产物复用使用手册.md)。

交付按实际请求返回设计或代码位置、采用版本、关键取舍、已执行检查及未完成项。完整研发交付按需更新已有构建部署说明，提交、PR/MR、部署与发行沿各自动作授权执行。
