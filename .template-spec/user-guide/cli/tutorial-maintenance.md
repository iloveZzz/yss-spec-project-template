# 维护与恢复

本页以 Rust CLI `3.8.0` 与内嵌 Template `5.8.0` 为操作基线。维护前核对 `yss version` 和目标命令帮助，沿用当前安装根、Profile 及有效收据。

## 更新受管项目

```text
yss doctor --root <受管项目目录> --json
yss skills list --root <受管项目目录>
yss sync --root <受管项目目录> --dry-run
yss sync --root <受管项目目录>
yss skills ensure <技能名> --root <受管项目目录>
```

sync 更新当前 Bundle 的受管模板和技能，skills ensure 补装所选技能及依赖，upgrade 更新程序本身。选择其中符合任务的一项，程序升级后需要项目资源更新时再运行 sync。

文件处理使用原安装摘要作基线。来源未变化时保留本地修改和删除，来源与本地同时变化时整次报告冲突。未知文件即使内容相同也由原所有者维护。受管文件退役时只删除未改动版本，已改动文件产生冲突。user-owned 与 protected 文件保留。先阅读诊断列出的具体路径和双方差异，确定采用内容后再执行同一操作，保留与本次无关的工作。

sync 默认沿用原安装范围，需要转换时显式指定 `--installation project|skills`。收据中的 Profile 保持原身份。新技能视图与保留的 canonical 技能定制不一致时也会报告冲突，须先核对采用的版本。技能文件存在、来源正确与宿主已经加载分别核验。

## 恢复项目或工具事务

```text
yss doctor --root <项目或工具目录> --json
yss recover --root <项目或工具目录> --dry-run
yss recover --root <项目或工具目录>
```

未完成事务经完整预检后恢复，已提交事务只重试安全清理。中断后又被用户修改的文件可能与恢复基线冲突，保留现场并按具体路径核对。recover 的处理对象是事务状态，已完成操作需要按其实际数据和版本安排恢复。

Windows 升级可能因旧进程占用程序而报告 cleanup pending。退出占用进程后，用 recover 重试清理。若中断后主入口暂缺，从已校验的发行归档取得独立新程序，再对原工具根运行 recover。实际磁盘目标、当前运行程序和清理状态分别核对。

完整有效且私有材料已清理的 committed 事务，在目录身份变化后可保留为只读历史。doctor 的 retainedHistory 会列出这些 ID，恢复时保持其原状。损坏记录、未完成事务或有残留的目录继续按诊断处理。

## 共享工程与续办

工程共享时保留完整技能、宿主入口、必要引用和 `.yss/project.json`，有生成收据时一并保留 `.yss/scaffold.json`。项目 `.yss/lock` 和 `.yss/transactions/` 属于本机运行与恢复资料，按项目实际 Git 状态处理，保留未完成事务现场。

新 clone 先核实程序与 Bundle 来源，再执行 doctor、skills list 和 sync 预览。同版本号也须核对实际 Bundle。项目自建技能由该工程维护，用户级技能沿其原安装来源更新。跨工程续办还需核实真实工作树、选定输入和运行资源。

## 工作台个人数据

工作台使用独立个人目录，启动信息会显示实际路径。自定义目录通过 `workbench --data-dir <绝对路径>` 传入，同一任务的查询、登记和答复沿用该目录。

个人数据目录位于项目和 Git 工作树之外，使用核实过的真实绝对路径。训练 Home 与工作台数据可放在同一临时父目录的两个独立子目录。

当前数据保存于 `workbench.sqlite3`。旧 JSON v1/v2/v3 的纯查询保持只读，首次启动新版工作台或执行写入命令时，先按原字节 SHA-256 备份，再迁入 SQLite，即使业务写入最后没有状态变化也会完成迁移。迁移保留记录、ID、revision、历史和隐藏任务，随后 `state.json` 用作存储标记。

备份和恢复按以下顺序操作。

1. 退出工作台，确认其进程已停止。
2. 复制整个个人数据目录，包括数据库、state.json 和尚存日志。
3. 恢复时保持工作台退出，将同一份完整备份恢复到选定目录。
4. 用匹配的新版程序启动该目录，核对 Spec、答复、确认和历史。

异常退出产生的 SQLite 日志由新版工作台启动时恢复。preparing 标记表示迁移尚需续接，纯查询会提示启动新版工作台。文件损坏、缺失或标记冲突时保留现场，核对完整备份与程序版本。逻辑状态仍限 16 MiB，查询仍读取完整内存快照，容量按实际限制使用。

迁移后的目录由新版程序管理。确需使用旧程序时，先完整保留当前目录，再核验升级前 JSON 备份摘要，将其复制为另一独立目录的 state.json，并用旧版已有的 data-dir 参数指向该目录。升级前备份只含当时记录，迁移后的修改保存在原 SQLite 目录。

## 模板与 CLI 维护人员

模板仓维护文档、技能及分发声明，CLI 使用 Rust/Cargo 构建。构建、打包与发布按 CLI 仓当前说明和对应动作授权执行，实际验证结果随版本说明。项目接入使用实际 CLI 命令，仓库中的历史脚本和流程记录按其原版本阅读。
