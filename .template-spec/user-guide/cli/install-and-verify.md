# 安装、接管、升级与恢复

本文描述正在整理的新 CLI 接口，尚未作为正式发行发布。先运行已安装程序的 `yss version` 和 `yss help`，仅使用该版本实际支持的命令；旧发行版不因模板更新而获得新接口。

首次安装交给 Agent：选择用户授权的版本与平台，从官方发行说明确认资产名称、SHA-256 和安装位置；在临时目录安全展开，核对二进制实际帮助，再放入独立工具目录并配置 PATH。没有可用发行版时报告这一事实；不要把未发布构建称为正式版，不调用旧插件或仓内安装脚本。

新接口中，新建用 `init`，普通已有工程用 `attach`，已有受管工程用 `sync`。先选择 `--profile spec|backend`；`--installation project` 安装项目入口与资料，`--installation skills` 只装技能及所需入口。先用同一条命令加 `--dry-run` 检查影响，再按已有授权直接执行原命令。同步转换安装内容时查看 `sync --help` 的实际开关，不手改安装元数据。

程序升级与项目同步分别操作。在线使用 `yss upgrade --to <版本> --tool-root <工具目录>`；离线使用 `yss upgrade --artifact <归档> --sha256 <SHA-256> --tool-root <工具目录>`。两者均可加 `--dry-run`，不生成保存计划。升级后核对 `version`，项目需要更新时再执行 `sync`。

发生中断先保留现场，用 `doctor` 和 `recover --help` 识别未完成事务并按实际支持范围恢复。冲突或来源不符时保留用户文件，不能删除状态、改身份或强制覆盖来伪造成功。旧实例和旧插件没有自动兼容承诺；先检查实际帮助与错误，再决定在副本或新目录处理。
