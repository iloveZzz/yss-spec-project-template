# 错误处理

先读取当前 CLI 返回的错误码、中文消息及路径上下文，再核对 `yss version` 和目标命令帮助。普通错误输出到 stderr，`--json` 的错误位于 error 字段。成功退出码为 0，参数错误为 2，其他失败或取消为 1。

| 错误或现象 | 处理 |
| --- | --- |
| ARGUMENT、未知命令或参数 | 核对实际版本和对应命令帮助，按已支持参数重试 |
| NOT_READY、缺少安装收据 | 核对目标目录身份与原安装，新普通项目用 attach，已有安装保留原收据 |
| CONFLICT | 阅读列出的文件和基线差异，保留现场，确定采用内容后重试 |
| UNSAFE_PATH | 核对绝对/相对路径、符号链接、已有目标、子模块及工作树边界 |
| DIGEST_MISMATCH、VERSION_CONFLICT | 核对发行来源、精确版本、target、归档摘要及实际程序 |
| LOCKED、CONCURRENT_CHANGE | 核对正在运行的进程或任务，结束相关写入后重新读取状态 |
| RECOVERY_REQUIRED | 用 doctor 查看项目或工具目录，再按 recover 帮助处理未完成事务 |
| NETWORK、NOT_READY 的在线来源错误 | 核对已选来源、CA、读取权限和 Release 状态，使用已授权来源重试 |
| 工作台返回旧 revision 冲突 | 刷新最新状态，核对双方内容，再重新提交本次修改 |
| 工作台迁移或存储标记错误 | 退出工作台，保留完整个人数据目录，按备份和迁移状态处理 |

文件、收据、锁和事务资料保留真实状态。失败后的操作、实际完成部分和待恢复事项分别说明。完整步骤见 [维护与恢复](tutorial-maintenance.md)。
