## 1. 已确认的目标

用户要求原型设计尽量应用 shadcn 组件，避免自行用原生 HTML 控件替代；明确移除独立 HTML 的轻量原型路线，改为低保真草稿。用户选择方案 A：低保真草稿同样使用 Vue + shadcn-vue，之后完善同一份原型，不另建一套 HTML 实现。

用户同时报告 Form、Input、Select 的黑边出现在**点击或展开之后**。这是已确认的触发描述，尚未实际复现，不能将缺 Token、CSS 覆盖或焦点环叠加写成已经证实的根因。

延续 [Spec 技能整合设计](2026-11-01-spec-skills-integration-design.md)：完整产品 Spec 包含规格、原型及说明，研发负责技术设计和实现。低保真降低视觉细节，不取消核心流程、状态和异常行为；Spec 是否完成仍依据交付内容及实际检查，不自动要求每项任务都升到高保真。

## 2. Approaches

| 方案 | 做法 | 取舍与决定 |
|---|---|---|
| **A：同一 Vue + shadcn-vue 路线** | 低保真草稿与完善后的原型共用组件、状态和场景；按阶段调整视觉与内容精度 | 减少重复实现，早期就能验证交互；草稿也需现行 Vue 运行环境。**用户已选择。** |
| B：先静态线框，再做交互原型 | 草稿以静态线框/流程图确认结构，再另做 Vue 交互页面 | 早期更轻，但交互需重新实现，静态草稿不能证明行为。未选择。 |

以下组件对应关系、资源落点及复核范围是本设计的实施建议，供用户审阅，不冒充用户逐项指定。

## 3. 组件使用规则

### 3.1 有对应组件就使用实际组件

产品页面、低保真草稿、嵌入式评审工具和随包候选比较工具使用同一规则：已有可用的 shadcn-vue 控件必须直接使用，不因“临时”“简单”或“仅评审工具”改成原生交互控件，也不只给原生控件加一层相似 CSS 后称为 shadcn。

| 用途 | 采用方式 |
|---|---|
| 按钮与动作 | Button，明确提交与非提交行为 |
| 文本输入、长文本 | Input、Textarea |
| 有限选择、搜索选择 | Select；确需搜索时沿用 Combobox |
| 勾选、布尔设置 | Checkbox；不要为一次替换引入新状态系统 |
| 字段组织、标签与错误 | Field、Label/FieldLabel、FieldDescription、FieldError；按实际语义组合 |
| 复合输入 | InputGroup，外层负责边框与焦点，内部控件不重复画框 |
| 展开、折叠评审工具 | Collapsible + Button；使用已登记固定版本 |
| 弹层、确认、菜单 | 现有 Dialog、AlertDialog、Sheet、DropdownMenu 等对应组件 |

原生 `form`、`main`、`section`、`div`、标题、列表、链接、iframe、SVG 等结构与语义标签仍可使用。shadcn 组件内部渲染的 input/button、隐藏输入也正常保留；检查对象是作者侧可见控件及其真实导入，不禁止浏览器 DOM 标签。文件选择等浏览器能力应通过适用组件使用，不发明无效替代控件。

没有对应组件时，优先组合现有组件；确需原生特殊能力，应在具体产物说明中写清限制，不保留独立 HTML 轻量路线作为通用 fallback。若用户未来明确指定其他实现，遵循该次明确范围，不能由 Agent 自行推定例外。

不为“Form”这个名称新增表单库或验证框架；保留现有输入校验、错误关联、提交保护和无障碍语义。

## 4. 低保真草稿的定义与资源

草稿用于确认任务组织、信息层级、字段、动作、规则与状态。视觉采用简单表面、克制装饰和代表内容；仍能区分可操作、禁用、错误、选择和焦点。不能通过全局灰度滤镜隐藏状态含义，也不把草稿变成纯组件陈列。

草稿与完善版使用同一 Vue 页面、shadcn 控件、业务数据及场景合同。制作深度由作者按任务选择，不新增给最终用户的“低保真/高保真”开关，不引入第二套构建器、路由器或业务状态源。确认后的产品原型在原有源文件上完善，不承诺实验代码可直接用于生产。

### 4.1 随包示例的调整

- 移除 `assets/offline-html/`、`assets/native-workbench/` 和 `assets/low-fidelity-exercise/` 的独立原生 HTML 实现；更新当前导航和资源说明，不保留旧路径别名、跳转或迁移脚本。

## 5. 点击和展开后的黑边处理

### 5.1 先复现，按实际样式来源修复

复用当前组件状态展示与实际分步表单/查询示例，在现行固定依赖下观察 Input、Textarea、InputGroup、SelectTrigger、SelectContent。分别执行鼠标点击、Tab 聚焦、Enter/Space/方向键展开、选择、Escape 关闭和焦点返回，并保留普通与错误字段的观察。

检查产生黑边的具体元素与状态：border、outline、box-shadow、Tailwind ring、focus/focus-visible、data-state/open 以及弹层 Teleport 后的主题变量。检查真正的计算样式、CSS 层级和载入顺序，不以源码里存在 border-input 或颜色变量证明最终呈现正确。

当前共有项目 Token、shadcn 映射、原型布局和页面微调样式；应在现有主题适配层修复实际根因。`prototype-theme.css` 只消费 Token，不能当作完整 Token 定义。变量需覆盖文档根和 Teleport 弹层，缺失时补齐实际依赖，不靠全局 `outline: none`、全部 `border: 0` 或逐页 `!important` 掩盖。

若固定样本没有复现用户描述，记录已检查的浏览器、样本、状态及限制；继续完成组件规则与已验证状态，不能凭推测修改 CSS 或宣称用户见过的黑边已经修好。

### 5.2 统一的状态要求

| 状态 | 预期 |
|---|---|
| 默认 | 使用当前设计的输入边框 Token；默认浅色基线是细灰边，不出现变量失效导致的黑色回退 |
| Hover | 依当前主题反馈；不以加粗黑框表达悬停 |
| 点击/键盘聚焦 | 边框与焦点提示使用明确的主题角色；保留一个清晰的外部焦点提示，不重复叠加 outline 与 ring/shadow |
| Select 展开 | 触发器、浮层外框和选项高亮各自使用对应语义；不让浮层继承默认黑色轮廓或局部容器外丢失 Token |
| 错误及错误+聚焦 | 保持错误边框、提示文字和错误关联；聚焦/悬停不能把错误状态覆盖成普通主题色 |
| 禁用/只读 | 状态明确且可解释；禁用控件不打开、不提交；只读内容仍可读，不用移除边界掩饰状态 |
| InputGroup | 外层提供边框及焦点提示，内层输入无第二重描边；键盘焦点仍可辨认 |

颜色遵循实际项目 DESIGN/Token，示例默认值不强行覆盖已有设计。对比度、焦点、错误关联按实际呈现检查，不能只因“没有黑边”就宣布无障碍通过。
