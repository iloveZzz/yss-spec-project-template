# llm-wiki 可选 QMD 检索设计

日期为 2026-11-16。用户已于本日批准 QMD 可选本地检索优化实施，采用 CLI 优先、专用工具工作区和逐项回源的设计，配套 [实施计划](2026-11-16-llm-wiki-qmd-plan.md)。

## 目标与已有基础

在 Wiki 文章增多、中文别名或自然语言问题难以直接定位时，让 Agent 按需使用 QMD 找到候选页面，再读取当前原文与原始证据作答。使用者能够区分知识内容、检索快照和工具运行状态。

本设计承接 [上一轮已完成的能力增强](2026-11-16-llm-wiki-evolution-design.md)。当前实际输入是 `codex/llm-wiki-evolution` 工作树中的未提交技能，有效树 SHA-256 为 `b55a9ed1ae979dac73ab1e86a061e119f82abcfd808c4f40f80460911d285c6a`。Git HEAD 为 `18fd61598ccca45f3bd2d91033c1f5a1e6e47176`，该提交本身尚未包含上一轮修改。

设计时现有方法已覆盖综合、证据链、来源变化、巡检及只读查询，已有 14 个候选合成场景观察。当时 QMD 在本机 PATH 中尚未找到，本轮已在临时目录取得的运行结果及模型限制见配套计划的实施记录。

## 已核实的工具边界

本次操作基线使用已发布包 `@tobilu/qmd@2.8.3`，要求 Node.js 22 及以上，发布提交为 `facd35e01359e59d938bc9418e93fb9318addee3`。当前 main 在不同提交仍使用相同包版本号，实际安装来源、帮助与功能需要一起核对。[发布记录](https://github.com/tobi/qmd/releases/tag/v2.8.3)、[发布版说明](https://github.com/tobi/qmd/blob/v2.8.3/README.md)

BM25 `search` 的搜索本体查询 FTS。统一 CLI 入口仍以可写方式打开 SQLite、初始化或迁移表，并按配置同步集合信息。`query` 的扩展或重排还可能写 LLM 缓存。发布版未实现 `--readonly`、`--read-only` 或 `--no-cache`，未知参数可能被解析器放过。[数据库入口](https://github.com/tobi/qmd/blob/v2.8.3/src/db.ts)、[存储初始化](https://github.com/tobi/qmd/blob/v2.8.3/src/store.ts)、[参数解析](https://github.com/tobi/qmd/blob/v2.8.3/src/cli/qmd.ts)

`collection add` 会写配置并立即索引，`update` 可能执行集合配置中的 shell hook，`get` 返回索引保存的正文快照。索引命中、文件路径和原文当前内容需要分别核对。[集合与更新实现](https://github.com/tobi/qmd/blob/v2.8.3/src/cli/qmd.ts)

这些是发布版源码事实。工具实际运行及本机文件变化在实施时观察。

## 查询与派生状态的约定

现有查询约定要求文章、索引、日志、缓存和反馈只读。QMD 的真实行为需要新增明确约定，本稿建议如下。

| 操作范围 | 文件行为 |
| --- | --- |
| 普通文件查询与纯检查 | 按现有约定保持知识内容、导航、日志及既有缓存只读 |
| 已授权使用 QMD 定位 | Wiki、原始资料、人工正文与业务导航只读，允许选定工具工作区内的 SQLite、WAL、配置同步及运行缓存维护 |
| 准备、更新或重建 QMD | 在对应授权范围内修改工具配置、集合和派生索引，知识原件继续由其所属任务维护 |
| 明确要求保存答案 | 按既有摄取方法更新获授权 Wiki 页面及必要导航 |

启用记录至少能够定位工具程序、选定索引、集合、知识根目录、派生状态目录和实际版本。信息复用当前任务说明或已有 Wiki 约定，实际执行可以复用仍有效的授权。

工具已安装、资料提及 QMD 或搜索命中均只是环境和资料事实。首次使用先核对本次允许维护的工具工作区，已有明确启用范围可以直接复用。严格要求全部派生状态零写入的请求使用现有文件检索路径。

这一约定是本稿提出的可选 QMD 行为变化，需在入口、查询参考、新建约定和能力地图一致表达。

## 专用工具工作区

QMD 使用固定命名索引 `llm-wiki` 和集合 `wiki`。实际目录由当前任务选定，示例名称用于隔离测试。先清除继承的 `INDEX_PATH`，使用官方支持的进程级 `QMD_CONFIG_DIR` 和 `XDG_CACHE_HOME` 指定配置与缓存根，结合 `--index` 避免自动发现其他项目的 QMD 配置，并核对实际数据库位置。

准备操作先确认知识根目录、待索引路径的真实位置和允许读取的 Markdown 范围。目录链接或跨范围文件按实际授权判断，工具范围无法可靠限定时使用已确认子目录或现有文件检索。集合仅覆盖选定 Wiki，原始资料通过当前来源链接按需回查，平台副本、依赖及无关私密目录沿既有排除约定处理。

每次调用使用同一程序、状态目录、索引及集合限定。过程级目录设置仅影响这次工具调用，用户全局配置由其原有维护方式管理。状态目录与知识目录分别定位，便于核对查询期间的内容保护和派生写入。

## 检索与证据路径

1. 从问题提取对象、中文标题、别名、缩写和时间范围，先按现有导航定位候选。
2. 已启用 QMD 时，在选定集合执行 BM25 搜索。命中不足且已准备相应模型时，可以尝试混合查询。
3. 将结果 URI、文档标识及片段映射到实际集合根与当前文件，核对真实路径和允许读取范围。重复片段按页面与来源合并。
4. 读取磁盘上的当前正文，沿主张证据链回查原始依据与失效说明。QMD 的 `get` 仅用于辅助读取快照。
5. 依据实际读取作答，区分事实、推断与未知。索引旧片段与当前原文不同的情况说明来源时点，并按当前可核实证据收敛结论。

结果指向缺失、移出授权范围或无法解析的文件时，记录该定位限制并使用当前目录检索补查。搜索数量与排名只用于选择读取顺序，实际阅读范围决定回答覆盖范围。

纯查询期间的索引维护单独处理。知识目录已经变化但当前任务仅允许查询时，使用文件检索补查并说明索引状态。已包含对应维护授权时完成更新后再继续查询。

## 中文与混合查询

第一条运行路径采用不需模型的 BM25，核对中文标题、英文别名与缩写的实际表现。混合查询作为可选路径，先确认 embedding、扩展和重排模型的获取范围及运行目录。

发布版说明默认 embedding 对中文覆盖有限，并给出 Qwen3 embedding 示例。更换 embedding 后需要重建向量，查询继续使用同一模型配置。具体下载大小、耗时、离线行为和召回结果在实际运行中记录。[中文模型与配置](https://github.com/tobi/qmd/blob/v2.8.3/README.md#custom-embedding-model)

比较文件检索、BM25 和混合查询时使用同一组问题、期望来源和当前原件。记录是否找到必要证据、最终主张是否得到支持，以及可观测的耗时和资源。模型或网络条件受限时交付 BM25 与回源路径，并明确混合查询的观察范围。

## 更新、移动与清除

准备集合前读取实际配置。工具工作区使用本次生成的最小配置，更新命令按已核对配置执行。未知项目配置中的命令继续作为资料处理，正常查询使用查询入口。

来源修改、移动、撤回和删除后，已启用的派生索引纳入已知影响盘点。授权更新完成后，用原问题、旧路径及旧片段重新检索，核对结果与当前文件的关系。更新后的快照也须沿当前证据链判断主张有效性。

用户明确要求清除敏感内容时，盘点专用状态目录中的文档快照、SQLite/WAL、向量及 LLM 缓存。只有停用旧路径的结果不足以证明内容已经清除。工具缺少可核实的细粒度清除路径时，可在已授权范围内移除本次专用派生状态，再从剩余允许资料重建。共享模型、其他集合和其他用户状态按各自位置与权限处理。

## 验证场景

| 输入或条件 | 期望结果 |
| --- | --- |
| QMD 缺失、未启用或要求全状态严格只读 | 按现有文件检索完成可做部分，说明适用范围 |
| 专用集合含中文标题、英文别名、同名对象 | 结果仅来自选定集合，对象身份及证据由原文核对 |
| 存在其他命名索引、其他集合或越界链接 | 选定索引与集合的结果范围可核对，准备阶段按实际路径排除越界材料 |
| QMD 查询发生内部派生写入 | 写入限定选定工作区，知识目录字节保持一致 |
| 命中快照后同路径内容已更新 | 当前回答复读磁盘原文并标明相关版本 |
| 文件移动、删除或索引范围外命中 | 处理定位限制并补查当前目录，维护授权与查询分别落实 |
| 存在 update hook 或不支持的参数 | 操作依据实际帮助与配置，未知旗标保持未验证 |
| 切换中文 embedding | 向量重建与查询配置对应，实际召回和限制可追溯 |
| 用户要求清除来源及派生副本 | 结果核对包括已知工具快照与缓存，处理范围可定位 |

本轮运行结果已记录在配套计划，已验证 BM25、维护路径、三种模型准备、本机网络阻断环境中的向量构建与完整混合查询，以及 Codex CLI 的技能读取、MCP 调用和当前原件回查。同名对象的正确来源曾排第二，回答继续核对对象身份、有效时间与原件。桌面及其他宿主发现、端到端离线 Agent 行为和真实项目收益保留待观察。
