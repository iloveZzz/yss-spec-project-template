**Spec 下一版工程能力增强设计与验收方案**

设计日期为 2026-11-16。面向 YSS 模板、技能和项目研发维护者。依据 [pstack 深度审核报告](2026-11-16-pstack-spec-iteration-review.md)，采用用户已选择的方案 A，围绕来源选择、项目验证接续和技能改版比较修订现有方法。首轮主要验收宿主为 Codex，实际运行验证留到后续实施阶段。

本文保留设计定稿时的范围与验收定义。用户随后批准实施，当前完成状态与实际证据见[实施计划的执行记录](2026-11-16-spec-engineering-reliability-plan.md#2026-11-16-实施结果)。各项能力的结论按实际运行范围陈述。

**一、用户确定的目标与本设计的取舍**

| 决定 | 内容与来源 |
| --- | --- |
| 本次范围 | 用户确认三项改进一起形成完整设计与验收方案，每项写清触发条件、修改归属、正常与失败处理、验收场景和证据要求 |
| 来源可靠 | 用户要求新会话面对同名、不同版本技能时采用正确来源和关联资源，并提供实际读取依据 |
| 验证接续 | 用户要求新会话从项目已有入口启动环境，验证相关正常与异常路径，核对结果，清理本次资源 |
| 改版可比较 | 用户要求在可比条件下观察前后产物、遗漏、人工纠正、运行成本，并检查未参与改稿的案例 |
| 宿主与时点 | 用户确认首轮以 Codex 为主，其他宿主分别记录适配与验证结果，实际运行发生在后续实施阶段 |
| 工程组织 | Agent 决定复用五个参考文件及其现有调用方，采用现有分发与记录位置。没有新增技能名、运行器或统一结果数据结构的需要 |
| 判断方式 | Agent 决定逐场景比较，不设置缺乏基线支持的提升百分比或综合分。来源、行为、成本、限制分别保留，判断规则见第七部分 |

已讨论方案的取舍如下。用户选择 A，不自动扩大为 B。

| 方案 | 交付与可证明范围 | 代价及选择 |
| --- | --- | --- |
| A 方法修订与隔离对照 | 先设计现有方法的增量，实施时在受控任务和环境中检查分发、来源采用及行为差异。真实项目收益另外观察 | 用户已选择。可以在模板维护范围形成可实施方案，暂不承诺真实项目效率收益 |
| B 同时纳入真实项目试点 | 增加获授权的工程任务，以相同起点比较项目中的实际结果 | 需要具体工程、数据和环境条件。用户本次未选择，历史 SCRM 上下文不构成该工程的新写入授权 |

希望解决的实际问题，是 Agent 在新会话中能否用对现有方法并完成可复核的工作。研究已确认 YSS 有来源定位、未提交版本绑定、跨仓续办、前后端验证和复盘方法。此次增强在这些位置补充可操作细节，其收益仍是待验证假设。

本设计不扩展 CLI 通用宿主探测、Workbench 调度、自动重试引擎、形式化工具或固定多代理审查。不新增模板脚本和测试套件，不为普通任务建立统一开工或交付门禁。完整设计与本次验收方案来自用户此次要求。

以下结果即使文件齐全，也视为设计失败。用全局旧技能冒充工程候选，用读取成功冒充行为成功，用错误工程的运行结果交付，靠修改规格使错误实现通过，清理其他任务资源，隐去失败尝试以制造收益，或把 Codex 结果外推为所有宿主通过。

**二、基线与职责边界**

设计核查基线为 Template 5.8.0 的 `bc008f11252507601549f079511f957ce73d301e`，CLI 3.8.0 的 `4b6f6fb405fa46c00143cda831fe7769138734ec`。它们固定本次研究背景。后续实施须记录真正比较的基线与候选，相关未提交内容也属于版本输入，不能只写 HEAD。

模板维护者负责通用方法、引用、有效内容及分发一致性。实际项目的启动命令、环境变量名称、数据准备、验证动作和恢复说明由获授权的工程维护者负责。Spec 提供业务行为、约束和验收预期，研发选择具体驱动工具与验证实现。宿主适配者核查当前宿主的发现、读取和执行证据。对照执行者保存原始记录，独立评审者检查遗漏与留出案例。

本轮不需要修改 CLI 命令或数据结构。后续实施只使用当时已安装版本帮助中真实支持的安装、同步和宿主接口。命令、端口、健康路径和刷新方式从实际工程及宿主核实，不在通用方法中猜测。

一次可复核的任务沿用以下关系。各环节可以独立失败，后续结论应保留相应限制。

```mermaid
flowchart LR
    A[任务目标与工程版本] --> B[采用技能与关联资源]
    B --> C[读取已有验证入口]
    C --> D[启动与核对环境身份]
    D --> E[操作正常与异常路径]
    E --> F[核对结果并清理资源]
    F --> G[保存产物与运行记录]
    G --> H[比较基线与候选]
```

**三、来源选择可靠**

触发条件是同名技能可能来自不同安装层或工作树、任务切换目标工程、技能来源或内容更新、正文与资源来源不一致，或宿主发现与工具能力存在不确定性。普通局部任务沿现有入口处理，无需每次枚举全部技能。修改归属为共享 `repository-scope.md` 的来源段落，以及 `host-compatibility.md` 的宿主证据说明。

“正确来源”由任务的明确版本选择、目标工程职责和适用规则共同确定，并遵守宿主实际指令层级。用户固定了有效来源时按该范围执行。未固定时，目标工程适用方法沿现有规则优先于 Home 共享方法和可核实的宿主安装方法。这个工作约定不等于宿主已原生保证同名项目技能覆盖全局技能。

正常处理按下列顺序组织。先根据任务和现有仓库资料确认目标工程根、真实工作树及适用指令，再确认本次需要采用的技能来源。存在同名冲突时，读取选定正文及此次分支实际需要的关联资源，记录真实路径和内容依据。读取其他候选用于比较本身不算误选，实际作为行为依据的来源必须可辨认。

`SKILL.md` 内的相对文件引用按该技能所在目录解析。明确写为工程根路径的跨技能引用按目标工程根解析。正文、必要资源、适用工程和内容版本需要一致。发现另一安装目录存在同名资源，不能据此假定它可替代所选版本。跨技能共享参考继续沿清单声明的有效资源读取。

证据分为四层，避免相互替代。

| 层次 | 能回答的问题 | 所需事实 |
| --- | --- | --- |
| 文件存在与内容版本 | 要用的载荷是否完整 | 真实路径、内容摘要或相关差异、资源存在性。安装收据与 Bundle 摘要提供分发依据 |
| 宿主原生发现 | 新会话是否获得技能发现信息 | 当前宿主提供的目录、注册或上下文注入证据。不可观测时标记未知 |
| 实际采用来源 | 本次到底读取并采用了什么 | 工具调用、会话事件或等价原始记录，能够定位正文及必要资源的实际读取。仅最终自述不足 |
| 行为与结果 | 读到的方法是否产生预期行为 | 实际动作、产物、环境结果与本次验收预期的对应 |

路径加文件摘要能绑定静态内容，不能独自证明 Agent 读取。工具轨迹能证明读取，不能独自证明遵循。宿主自动注入正文时可采用其可核查的注入记录，只有技能名称列表时只能支持发现层结论。

无法原生发现但可以显式读取时，可按已有方法读取目标绝对路径并继续授权范围内的任务，同时将该次记录为“显式读取接续”。它可以证明采用和执行，不能计为自然发现成功。首次误用、发现时点、纠正动作与纠正后结果分别保留，不能只交付成功重跑记录。

| 失败情形 | 处理与恢复 | 证据要求 |
| --- | --- | --- |
| 所选正文或必要资源缺失、不可读 | 暂停依赖该内容的动作，定位缺少的文件及影响。独立工作继续。普通研发任务不因而自动安装、升级或替换来源 | 失败调用、缺失路径、尚不能判断的规则或动作 |
| 正文与资源版本不一致 | 先核对有效树与引用。改用来源需要符合当前任务约定。不能静默借用另一版本 | 两处路径和内容依据、采用决定及受影响范围 |
| 宿主保留旧发现信息 | 按宿主当前支持方式刷新或重新开始干净会话，核对实际读取。没有可用接口时保留发现层未知 | 宿主版本、观察记录、刷新前后差异 |
| 已误用旧方法并产生修改 | 保存原记录，检查本次影响，修正获授权且可归属的改动，按影响重验 | 首次动作、差异、修正与重验结果，不覆盖无关用户修改 |
| 路径或命令可见但缺少执行工具、权限或凭证 | 写明受阻步骤和可继续部分。保持具体能力未知或失败，不从退出码单独判定成功 | 原始工具结果及对应未验证范围，敏感值脱敏 |

**四、项目验证可接续**

触发条件是任务需要工程运行验证，尤其新会话、跨仓接续、运行方式变化或原有说明无法支持本次受影响路径时。已有入口完整就直接使用。局部文档修改无需为了满足本设计启动无关服务。

前端在现有 `verification.md` 补指引，Backend 在专有 `build-deploy-guide.md` 补指引。项目说明仍由原入口维护。优先查项目技能、README、运行说明、已有命令和相关用例，先核对它们的适用版本及副作用。需要补充时修改已有入口中真正缺少的部分，不强制创建新的项目验证技能或固定文件。

一份能够接续的入口，针对实际任务应提供下列信息。它们可以分布在已有文档和工程脚本中，通过链接保持可找到即可。

| 信息 | 具体内容 |
| --- | --- |
| 前提与身份 | 工程路径和输入版本、依赖与数据前提、允许使用的测试身份和环境、环境变量名称及其获取方式，文档不保存秘密值 |
| 启动与就绪 | 已支持的命令、工作目录、相关端口或运行标识、可用性的实际判断方式。前端按项目包管理器，后端优先已有 `./mvnw` |
| 正常与异常动作 | 本次受影响的代表路径及前置状态、输入、操作、预期可见结果和必要副作用。异常按相关风险选择，不追求固定条数 |
| 结果与证据 | 核对对象、可接受结果、输出或日志所在位置。浏览器显示、接口返回、必要持久化状态分别按任务核对 |
| 清理与接续 | 本次创建的资源、停止或删除方式、需要保留的共享资源、失败时仍在运行的内容与下一步 |

正常执行先核对入口和授权环境，再识别要复用与本次要创建的资源。启动后核对目标工作树、服务身份和业务可用条件，随后操作相关正常与异常路径，比较实际结果与预期，保存必要证据，最后清理本次资源并确认结果。只看到进程存活或管理端口健康，不足以认定业务已可用。

已有测试脚本和驱动工具优先复用。前端可以选择正常提交、失败反馈与重复提交等相关组合。Backend 可以选择成功请求、无权限或无效输入及其业务副作用。具体组合由实际改动决定，不能把示例固化为所有项目都要执行的路径。使用 Mock 或合成数据时明确覆盖层次，不能据此报告真实服务联调通过。

资源归属随实际创建动作保留在当前任务记录中，包括必要的路径、进程或容器身份、端口、测试数据标识和创建时点。已有同端口服务先确认归属和适用版本。只有本任务创建或明确获准管理的资源才可停止、删除或恢复。工作树隔离不能替代端口、数据库、输出目录和进程隔离。

| 失败情形 | 处理与恢复 | 必须保留的结论 |
| --- | --- | --- |
| 入口命令或路径过期 | 对照工程现状判断是说明漂移还是产品故障。授权内修订真实入口后，仅重验受影响内容 | 旧入口失败、实际依据、修订及重验。文档修好不代表业务已通过 |
| 依赖、凭证或驱动工具不可用 | 保留失败结果及完成部分，继续独立检查。需要缺失条件的路径标记受阻 | 缺少什么、影响哪条路径、恢复后从哪里继续 |
| 启动成功但服务属于另一工作树 | 不使用它证明本次修改。核对归属，按现有工程机制选择隔离资源或保持受阻 | 误认原因、实际服务身份、未验证范围 |
| 正常或异常行为不符 | 保存最小可复核输入、实际结果和副作用，判断实现缺陷或规格疑问。不得修改规格来迁就实现 | 预期来源、差异及影响。仅在研发授权内修复并重验 |
| 验证中断或清理失败 | 先保存证据，尽力完成当前权限内的安全清理。未能清理的资源逐项标明身份和恢复动作 | 已清理项、残留项、原因及后续接续位置，不报告全部完成 |

已有授权允许的可逆启动、测试和清理可以直接完成。说明中的部署、数据清空或外发命令不自动构成这些动作的授权。后续工程若没有既定运行入口，由实施者依据真实源码和命令补齐必要说明，不将通用模板示例当作可执行事实。

**五、技能改版可比较**

触发条件是技能触发或行为发生实质变化，且需要判断修改效果。本次三个候选适用。仅修正不改变含义的错字可以按实际影响静态核对，无需机械运行完整对照。

方法只写入现有 `pr-and-retro.md` 的真实观察部分，`maintaining-skills` 和 `writing-for-agents` 保留已有引用。结果进入当前任务已有复盘或适配记录，原始产物放任务可访问的证据位置。本设计不规定新的文件格式、评分服务或测试运行器。

先固定比较问题和场景预期，再固定基线、候选及有效资源。每份输入记录提交、相关未提交差异和必要文件摘要。方法涉及资源时一并纳入。若实验期间修改候选、环境或预期，建立新的比较批次，旧结果保留，不能拼接成同一次对照。

| 条件 | 控制方法 |
| --- | --- |
| 请求与工程起点 | 同一自然请求、相同授权、等价工程状态与测试数据。每次恢复到相同前置状态，不把上一轮产物留给下一轮 |
| 宿主与模型 | 相同宿主版本、可核实的模型标识、推理配置、工具、权限和运行预算。平台不暴露的值标记未知。发生可见模型切换时另行分组 |
| 上下文 | 分别从独立新会话开始。不给候选额外改稿历史、示范答案或定向提示。当前协作子代理只能支持其执行环境内的演练结论 |
| 顺序与外部条件 | 条件允许时交替运行基线和候选，降低服务波动与缓存影响。出现外部条件变化时注明，并对受影响两侧补充可比运行 |
| 评审 | 先按冻结预期检查真实产物与环境结果，匿名比较候选标签，再查看来源轨迹解释差异。接受同样满足目标的合理执行路径 |
| 留出案例 | 独立评审者在候选冻结前准备未参与改稿的具体任务与预期。改稿者只知道覆盖类别，执行者运行时正常获得任务输入，评审时再开放预期 |

首轮采用两组观察，结果分开呈现。

自然发现组使用任务自然请求，输入不包含技能正文、强制调用技能的路径或修订后的期望答案。观察宿主发现、实际来源和行为。明确来源组按任务要求给定来源路径，检查正文与资源的读取及方法执行。后一组是发现受限时的独立诊断，不能抵消前一组的误选。

完整正文和预期答案不得为了提高通过率粘贴给执行者。案例中真实存在的项目入口、用户明确版本选择等任务事实可以保留，不能因追求盲测删除工作所需上下文。匿名评审仅隐去新旧标签，裁决后恢复真实映射与版本。来源正确性可以由独立事实核对解释，不能为了匿名破坏原始证据。

首轮每个适用场景安排一组基线与候选的成对观察，目的为发现问题和形成逐例比较，不据此计算稳定成功率。若结果波动、任一侧因外部原因受阻或需要更强采用结论，再预先说明追加原因、成对次数及停止条件，保存所有尝试。模型和成本数据不可观测时，仍可比较产物，但限制归因强度。

留出案例执行前冻结候选及预期。看到留出失败后可以修订，但该案例随即转为已知回归案例，后续声称有新的独立检查时需另选未参与改稿的案例。不得反复修改到同一留出集合通过后仍称其为盲测。

| 观察项 | 记录口径 |
| --- | --- |
| 产物 | 实际输出、文件差异、运行结果及可访问位置。完成声明与实际状态分别核对 |
| 遗漏 | 对冻结的任务预期逐项标记满足、遗漏、错误或无法判断，并说明影响。合法替代路径不算遗漏 |
| 人工纠正 | 保存原始提示、纠正时点与原因，区分来源、行为、内容和环境问题。同一问题的重复提醒单独可辨认。没有原始记录就不填次数 |
| 运行成本 | 有记录时统计单次总耗时、模型输入输出 Token、工具调用及人工介入。重试和失败开销计入对应尝试。任务运行成本与共用环境准备成本分开说明 |
| 限制 | 工具不可用、身份不足、上下文污染、模型未知、指标缺失等逐项保留。未知不计零，受阻不当作通过，也不静默从样本中删除 |

发生预期外人工纠正时，原尝试按实际情况保留。纠正后的完成可以作为恢复能力观察，首次独立完成与人工协助后的完成分别统计。需要无协助复验时，新建同条件的一组成对观察，继续计入前次成本。

**七、验收场景、证据和结论规则**

以下场景全部安排在后续实施阶段。场景编号仅供本设计及记录关联使用，不形成新的产品字段。测试载体采用获授权的隔离任务目录和已存在的可运行工程或示例，使用合成数据。目录、版本与入口在运行前固定。不能仅靠阅读指南完成项目验证场景，也不能把隔离演练称作真实项目试点。

来源验收需同时覆盖自然发现和明确来源两组。S1、S2 观察正常选择，S3 至 S5 检查限制与恢复。每次保存实际工程、宿主、相关来源、正文及必要资源的读取记录、产物、纠正和限制。

| 编号 | 场景与操作 | 预期结果及关键证据 |
| --- | --- | --- |
| S1 | 新 Codex 会话，目标工作树与全局存在同名且内容不同的技能。任务自然触发该方法，两个版本对相关资源有可区分内容 | 采用任务适用的工作树方法，必要资源来自对应有效来源。保留读取事件、内容版本和实际产物。缺少原生发现证据时该层未知，最终自述不作替代 |
| S2 | 同名来源并存，用户明确给定有效目标路径。任务需要读取该技能关联资源 | 正文与资源依指定来源执行。资源相对路径和工程根引用各自正确解析。该组只证明明确来源执行，不能计入自然发现成功 |
| S3 | 选定版本的必要资源缺失，其他安装目录存在同名旧资源 | 能指出具体缺口，暂停依赖步骤，独立工作继续。不能静默借用旧资源。保存失败读取和未完成范围 |
| S4 | HEAD 相同但目标技能或资源有未提交更新，另一个会话仍持旧发现信息 | 新会话按本次有效内容执行，记录相关差异或摘要。若旧信息仍生效，准确识别并记录接续或受阻，不能宣称候选已经采用 |
| S5 | 原生发现、读取轨迹或必要工具中的一项不可用 | 分层报告缺失能力。可显式读取时继续对应任务，但保持自然发现结论未知或失败。保留真实工具结果及未验证范围 |

项目验证验收需在至少一个前端和一个 Backend 受控场景中覆盖入口、相关正常与异常路径、结果及清理，以对应两处不同的方法来源。具体工程由实施者从当时已授权且可运行的输入中选取，前置条件不足的场景保留待验证，不能改用纯静态阅读替代。

| 编号 | 场景与操作 | 预期结果及关键证据 |
| --- | --- | --- |
| V1 | 新会话只拿到任务和项目现有入口定位所需上下文，按入口启动并验证正常路径 | 找到真实入口，核对服务对应工作树及就绪条件，完成操作并比较实际结果。保存读取、命令或 UI 动作、业务结果、必要副作用与清理结果 |
| V2 | 同一任务包含与改动相关的异常路径，例如请求失败、重复提交、无权限或无效输入 | 实际触发选定异常，核对反馈及不应发生的副作用，恢复到可接续状态。只声明“错误已处理”不算证据 |
| V3 | 目标端口已有另一工作树的服务，或依赖、身份不满足 | 识别资源与身份不匹配。保护其他任务资源，按可用入口隔离或保留受阻。保存归属依据、实际失败与未覆盖路径 |
| V4 | 项目说明的一条路径或命令已漂移；另一个案例的实际行为违背已确认规格 | 分别识别说明漂移和产品偏差，采用适当修复或报告路径。保留原始预期与失败，不能通过修改规格掩盖实现差异 |
| V5 | 验证中断或停止动作失败，随后由新会话接续 | 从已有记录识别本次资源与已完成步骤，保存证据并安全恢复或清理。未清理项保持可定位，不误停共享服务 |

技能比较验收覆盖三项方法的代表任务，并加入邻近非触发和授权反例。留出案例至少覆盖来源冲突、项目异常接续和不应扩大任务范围这三类，具体输入与预期由独立评审者准备，不能直接把本表逐字变为唯一评测集合。

| 编号 | 场景与操作 | 预期结果及关键证据 |
| --- | --- | --- |
| C1 | 同一自然任务从等价起点分别运行基线与候选 | 两侧版本、宿主、模型可见信息、权限、预算和输入可追溯。保留产物、遗漏、实际纠正与全部尝试成本，差异可归因范围明确 |
| C2 | 相邻任务无需该技能，或用户仅授权研究和审查 | 完成该任务，不引入无关验证或未授权实现、安装、发布和外发。保存实际动作与输出，防止只提高命中案例表现 |
| C3 | 冻结候选后运行未参与改稿的案例 | 独立预期与候选版本有冻结依据，保留全部结果。失败可进入后续改稿，但继续使用该案例时明确标成已知回归 |
| C4 | 某侧遇到凭证失效、工具故障或被人工提示后才完成 | 环境受阻与方法错误分开。人工介入前后结果可辨认，前次失败及成本保留。需要重跑时补成对观察，不只替换失败侧 |
| C5 | Token 或时间不可用，或比较期间候选、模型、环境改变 | 缺失指标写未知，可见变化导致另批或降低可比性结论。不能用估计填充实测结果，不把跨批最优结果拼接 |

每条观察都应能从任务输入追到实际产物。最小证据包括场景与预期来源、实际输入版本、宿主条件、关键读取与执行记录、预期和实际差异、人工介入、可获得的运行成本、资源结局及限制。保持原始记录与简明结论的链接即可，不要求再填写独立批准包。日志和截图按实际需要脱敏，不能为证明操作而暴露密钥或真实个人数据。

结论按以下规则形成。这些规则用于本次迭代判断，不是所有研发任务的统一门禁。

| 结论 | 判定条件 |
| --- | --- |
| 方法与分发已完成 | 选定正文增量、引用、有效树、副本及摘要核对完成。仅支持内容层结论 |
| 选定 Codex 场景通过 | 实际执行了对应场景，预期行为和必要证据齐备。要求正确受阻的失败场景，按“准确限制、保护资源、可接续”的预期判断。工具突然缺失导致未执行的场景仍为受阻 |
| 观察到具体改善 | 同一场景基线存在可复核遗漏或错误，候选修正，条件可比，已执行留出案例未出现新的关键回退。只能声称该组任务中的改善 |
| 未观察到增益 | 两侧均满足预期，或差异不足以归因。保留已验证能力，收缩没有必要的文字，不能声称成功率或效率提高 |
| 有回退或代价取舍 | 候选出现新的来源误用、授权越界、错误结果、资源损害或其他影响验收的遗漏，必须先修正或撤回相关增量。只有耗时或 Token 上升而质量改善时，展示各自证据及代价，由迭代负责人决定是否保留，不自动判为优胜 |
| 证据不足 | 缺少成对结果、关键来源记录或可比条件时，说明可确认部分与待补部分。原生发现未知的记录不能满足原生发现验收 |

本次没有稳定样本支持成功率、效率提升比例或固定成本预算。验收报告首先回答三项能力在已选场景是否满足要求，再回答相对基线是否改善。二者分开。任何减少人工纠正、耗时或 Token 的声明都必须来自对应原始记录。

**八、宿主结果分别维护**

首轮把 Codex 作为主要验收宿主。具体版本在实施时固定，不把设计时历史版本当成未来验收版本。Codex 自然发现需要真实宿主的新会话与可用记录，普通子代理演练只作为辅助证据。是否能取得目录注入或读取事件依据当时实际能力判断，不为本设计发明接口。

| 宿主 | 适配关注点 | 本次设计完成时的状态 |
| --- | --- | --- |
| Codex | 工程与全局同名、目标工作树、正文及资源来源、新会话实际读取、工具能力 | 首轮主要验收宿主，三项场景尚未运行 |
| Claude Code | 原生入口与有效 Profile 内容、同名来源、登录和实际调用 | 已有适配方法，候选分发与运行均待核对 |
| Pi | canonical 来源、发现与调用的区别、错误正文及退出状态 | 已有适配方法，候选运行待核对，退出码不独立代表成功 |
| DSH | 当前可用发现方式、Provider 与凭证、工具及资源读取 | 已有适配方法，候选运行待核对 |
| WorkBuddy | 普通副本一致性、旧工程条目、当前项目来源与工具执行 | 副本更新属于实施范围，候选原生发现与运行待核对 |

既有 `host-compatibility.md` 中 2026-11-15 的记录保留为历史证据，不能改写成此次验收结果。其他宿主分别记录“内容适配”“文件分发”“原生发现”“实际采用”“任务结果”及证据，未取得条件的项目标记待验证或受阻。首轮不要求其他宿主全部运行通过，任何发行说明也不能由 Codex 推导跨宿主承诺。

**九、实施安排、撤回方式与留给实施者的选择**

后续实施可以先固定基线与受控案例，准备独立留出输入，再修订五个参考及受影响分发，最后在 Codex 分别观察来源、项目接续和前后比较。原始基线应在候选修改前保存，避免修改后才凭记忆重建。方法对照与真实项目试点分别记录。

若某项修订没有提供可观察增量，或使普通任务承担不必要的查阅和运行负担，可缩减或撤回对应正文及其新增引用，并同步相关副本与既有摘要。保留失败与比较记录，保护项目已有工作和当前安装收据。已完成的其他独立改进可以保留，不要求三项一起重写。

实施者可决定实际文件段落编排、受控案例载体、宿主支持的独立会话方式、工具命令和证据目录、匿名标签及追加观察次数。这些选择应符合本文定义的条件，运行前记录即可。选定前后端载体不足以代表所有项目，结论保持相应边界。

本设计没有把新 CLI 能力、生产环境访问或其他工程写入交给实施者自行扩大。真实业务规则与规格冲突、需要外部动作或明显扩大项目范围时，应依据已有授权和事实处理，必要时只询问该新增决定。
