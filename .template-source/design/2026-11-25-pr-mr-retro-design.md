# YSS PR/MR 描述与 Agent 会话复盘修复设计

2026-11-25。面向 YSS 模板和技能维护者，记录设计与实施结果。

在现有 `yss-write-docs` 和 `yss-deliver-pr-mr` 上做两处修复。让实际 PR/MR 交付复用已有写作方法，并让 Agent 会话复盘根据可读取的证据提出经过核实的改进。现有技能名、调用方式和默认选集继续适用。方案只涉及技能正文、共享参考、分发与导航，沿用现有 CLI 和宿主能力。

YSS 已吸收 Matt 的 PR 和复盘方法。实施前，交付技能的正文步骤和资源清单缺少共用 PR/MR 方法的直接引用，复盘方法也缺少 Agent 会话的取证和候选建议核实步骤。对照基线为 Template 5.17.1 `00e88457` 与 Matt `d6539114`。[YSS 适配记录](../../.template-spec/agents/matt-skills-adaptation.md) · [Matt `pr`](https://github.com/mattpocock/skills/blob/d65391149dbb5fe76478e76fa8d5122b2aa5a70e/skills/engineering/pr/SKILL.md) · [Matt `retro`](https://github.com/mattpocock/skills/blob/d65391149dbb5fe76478e76fa8d5122b2aa5a70e/skills/engineering/retro/SKILL.md)

## PR/MR 正文与交付

| 用户任务 | 入口 | 结果 |
| --- | --- | --- |
| 仅起草或改写 PR/MR 描述 | `yss-write-docs` | 根据可读材料交付正文草稿，沿用共享 PR/MR 写作方法。目标仓明确且可读取时，采用其模板及相关差异 |
| 明确要求通过 PR/MR 交付选定材料 | `yss-deliver-pr-mr` | 核对目标、材料、授权和实际文件变更。起草或更新正文时读取同一写作方法的 PR/MR 章节，按现有规则执行并回读 |
| 查询状态、审查差异或跟进已有反馈 | 当前任务对应入口 | 按现有方法处理。只有请求涉及撰写正文时才读取 PR/MR 写作方法 |

### 正文处理

1. 仅起草正文时，用户提供的改动摘要、验证结果或已有正文可以作为输入。目标仓尚未确定或实际差异不可读时，按材料起草，注明会影响判断的未知差异、版本或验证范围。选定目标仓后再使用其可读模板和相关差异，当前工作目录本身不足以确定目标仓。[现有写作入口](../../.agents/skills/yss-write-docs/SKILL.md#执行)
2. 真实交付以目标仓实际差异为依据。选定的项目版 `yss-deliver-pr-mr` 从同一有效工程根读取 `.agents/skills/yss-write-docs/references/pr-and-retro.md` 的 PR/MR 章节。跨仓交付时，目标仓提供模板、差异和授权规则，技能参考来自这次实际采用的技能来源。独立公开包读取自己的包内相对引用。
3. 按目标模板和获准段落的用途写相关变化、受众与验证。新建正文且目标仓无适用模板时，可将简要变化放在开头。更新已有正文只改获准内容，其余字节保持原样，包括首段、标题和相邻段落。用户只授权更新验证段时，在该段写实际验证和覆盖范围。简单材料交付给出文件、来源、未决项和接收方下一步。有复杂状态、权限或流程变化时，按需选短表、局部 diff 或同条件截图。验证证据对应实际候选和具体行为，保留失败、未运行和未覆盖项。缺少 Before 时说明旧行为的来源或复现限制。
4. 有数据、权限、公开接口、配置或跨仓影响时，在模板允许且获准的段落写清受影响对象、恢复条件和验证状态。若授权范围或模板没有合适位置，把对应说明留在交付反馈中。代码回退、已写入的数据和已发生的外部副作用分别按证据判断。信息不足时保留待确认项。
5. 共享参考不可读时，依据实际目标仓模板和现有交付正文规则完成可支持的部分，并记录缺失的资源。真实交付的每次写入都须核实目标、授权、将公开的差异及原正文保护范围。无法核实的动作按现有规则暂停。出现 head 或正文竞争时，先回读当前状态再判断哪些证据和修改仍适用。[交付正文与并发规则](../../.agents/skills/yss-deliver-pr-mr/SKILL.md#发布并核对) · [共用写作方法](../../.agents/skills/yss-write-docs/references/pr-and-retro.md#pr--mr-描述)

## Agent 会话复盘

`yss-write-docs` 的现有参考新增「Agent 会话复盘」用法。用户明确要求复盘 Agent 工作时，默认复盘当前会话。指定历史会话时，按已提供的 ID、链接或能无歧义确定的对象定位。普通项目复盘和当前任务中有证据的返工回看继续使用既有方法。目标确实歧义时，只核实会改变结论的会话身份。

### 取证与建议

1. 先用已可见并能归属目标会话的回合、工具结果、日志、变更或用户提供的片段。当前或指定历史会话被压缩、截断或缺失时，只在相关缺口影响判断、目标会话身份可以核实、宿主提供可授权使用的只读记录入口时，补读同一会话的必要回合或工具输出。入口不可用、记录不可达或身份无法核实时，按现有可归属材料说明已覆盖的范围和具体缺口。指定会话不可读时，其结论仍以能归属该会话的材料为限。
2. 保留能追溯的首次失败、最终结果和可观察影响。子代理汇总只能证明主会话看到的内容，独立执行、调用次数和耗时需要对应原始记录。读取的历史消息和工具输出作为复盘证据，修改、提交及权限调整以当前任务的实际授权为准。
3. 对候选做一次与成本相称的核对，判断机制是否成立、是否已有办法、是否产生了实际影响。现有检查可用而未被执行时，先核实调用路径和原有结果。机制待确认时可提出补证建议，并标明它是待验证假设。按实际后果和证据强度排序，合并同一机制产生的重复建议。
4. 对成立的建议给出事件位置、实际影响、原因依据、最小改动位置和下一次复验信号。导航问题优先修正已有入口，机械错误先检查现有校验的覆盖和接入，判断问题落到现有审查约定，工具或信息访问问题以可观察的阻碍为依据。证据充分且没有成立项时，报告「未发现值得处理的改进项」。材料不足时，已确认的局部发现和未覆盖的判断可以同时报告。按需引用原始证据，避免用全文、敏感输出或估算数字充当依据。[YSS 复盘方法](../../.agents/skills/yss-write-docs/references/pr-and-retro.md#复盘中的改进与沉淀) · [现有模板的沉淀去向](../../.template-spec/templates/retro-report-template.md#沉淀去向) · [Matt 上游反馈 #1173](https://github.com/mattpocock/skills/issues/1173)

## 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 新建普通 Spec 交付，目标仓有 PR/MR 模板 | 可观察到本地共享参考被读取，正文采用目标仓模板，保留文件来源和接收方下一步。跨仓时分别读取采用的技能来源和目标仓模板 |
| 更新含权限或数据变更的已有 MR，用户只授权改验证段 | 用前后正文核对，首段、模板固定内容及其他段落逐字保留。验证段标明具体候选、实际场景及 Before 或恢复验证的缺口。需另行说明的影响和恢复条件出现在交付反馈中 |
| 有实质风险的交付，已授权写入风险及验证内容 | 在目标模板支持的位置写明受影响对象、恢复条件、仍不可恢复的副作用及证据缺口，正文保持模板结构 |
| 只有改动摘要和验证片段，用户只要求 PR 草稿 | 根据所给材料完成草稿，标明实际差异或版本未核实的范围。检查无 Git 或平台写入，工作目录中的模板和差异也未被当作目标仓证据 |
| 交付时共用参考缺失，或发现 head / 正文已变 | 资源缺失时继续有依据的工作并报告缺口。只在确认目标、授权和待写内容时写入。发现 head 或正文变化时暂停受影响的写入，回读并核实哪些证据与动作仍适用 |
| 当前长会话的可见上下文只含重试成功，首次失败仅在可读的受控回放中 | 读取轨迹指向目标会话的必要片段。报告可定位的首次失败、实际影响和最终结果，并给出有依据的最小改进及复验方式 |
| 同一合成用例中，宿主无法补读中段 | 保留可证的最终结果，明确中段未覆盖，原因和影响保留为未知。读取轨迹没有指向其他会话，报告不把该用例判成完整零发现 |
| 指定历史会话不可访问，但用户附有可归属片段 | 输出该片段能支持的局部结论及其覆盖边界，当前会话内容没有被混入 |
| 只有子代理汇总，用户仅要求复盘 | 结论标明汇总来源与证据限制，工具次数、耗时和独立执行事实仍待核实。观察文件差异和工具调用，确认复盘没有产生写入、提交或权限修改 |
| 记录完整且顺利的会话与普通项目复盘 | 顺利会话允许给出零改进项，普通项目复盘依然可按现有用法产出 |
| 项目分发和单项公开包 | 依下节区分资源声明验证和默认安装验证，核对平台副本和 Backend 有效摘要。独立公开投影在只有交付技能的临时环境可读，内容能回溯到共享源 |

### 分发验证

1. 用现有 `yss-bundle` 生成临时候选归档，记录 `manifest.json` 的模板来源信息和归档摘要。对三个 Profile 的两种安装范围，从同一归档在内存构造最小选集。只以 `yss-deliver-pr-mr` 为起点递归解析 `skillDependencies`，合并该安装范围的 `base`、闭包内技能文件及 `skillReferences`，排除默认选集。归档保留原始默认配置。
2. 正例检查交付入口及共享参考均在最小视图，`yss-write-docs` 的独立入口未被选入。核对参考对象的摘要和内容与候选源一致。负例在内存副本中仅移除交付技能对该参考的声明，重算六种视图。交付入口应继续存在，共享参考应从视图消失。这组检查用于证明资源由交付技能声明带入。
3. 正常安装另用内嵌同一候选归档的 CLI，在临时目录核对实际 `bundleDigest`、默认选集、落盘的交付入口与共享参考。现有 `ensure` 会合并默认与显式技能，适用于正常安装路径。最小视图在归档上做静态核对，实际宿主读取在行为场景中观察。[模板维护与分发约定](../agents/skills-maintenance.md)

### 行为对照

实施时固定实际基线与候选。用相同的自然请求、输入、权限和可比项目起点，在独立 Codex 新会话中对照普通交付、风险交付、返工复盘与证据不足场景。保留一个独立准备的补充案例，核对实际读取路径、产物、遗漏、人工纠正及已有记录可支持的运行成本。长会话分支可用合成回放验证，真实宿主补读只在有授权且有实际读取轨迹时记录。GitHub 和 GitLab 的外部写入边界可用本地材料或受控演练观察，按实际覆盖报告。其他宿主按分发与实际行为分别记录。

以可定位的共用方法读取、关键事实保真和有依据的改进建议作为本次结果。若静态资源闭包成立但新会话未采用规则，检查入口措辞与读取顺序。若候选仅增加正文长度或复盘噪音，收缩对应改动并定向复验。现有任务记录足以保存结果。[既有改版观察方法](../../.agents/skills/yss-write-docs/references/pr-and-retro.md#技能行为改版的对照)

## 实施结果

共享参考、交付入口、三份技能地图和六处资源声明已更新。WorkBuddy 的两个技能文件与共享源逐字节一致，Claude 链接和实际安装副本已核对，Backend 两个有效树摘要已重算。[交付入口](../../.agents/skills/yss-deliver-pr-mr/SKILL.md#发布并核对) · [共用方法](../../.agents/skills/yss-write-docs/references/pr-and-retro.md)

- **分发。** 使用工作树生成候选 Bundle，SHA-256 为 `2ee3ebaff4232a316abaab8c8d992c6d68fcf7c8a118ade887ae3863a8010bfc`。三种 Profile 的两种安装范围均通过资源声明正例和移除声明的负例。用内嵌该归档的临时 CLI 同步六个临时实例，并在空目录新装一份 Spec `skills`。默认技能数分别为 Spec 18、Backend 43、Frontend 20，三个宿主目录的落盘字节与源一致。独立公开包的包内引用和许可证通过本地投影核对。
- **PR/MR 行为。** 首轮受限 MR 保留了段外字节，但把恢复操作写入了只获准修改的验证段。收紧规则后，复验逐字节保留验证段外内容，恢复操作和外部副作用进入正文外的交付反馈。只给摘要的草稿能交付并说明 Git 差异待核。模拟参考缺失或 head 与正文变化时，Agent 按可确认材料继续起草或暂停受影响的更新。
- **会话复盘。** 首轮可读回放读到了早期失败，未打开被引用的现行导航。明确核对现行材料后，复验实际读取导航并给出复验信号。回放不可读时保留已知结果和覆盖缺口，子代理仅有汇总时保留未核实项，完整顺利会话能给出零改进项。
- **观察范围。** Codex CLI 0.172.0 共执行 24 个独立只读会话，含九组首轮成对观察及最终候选定向复验。工具轨迹显示本地文件的实际读取，所有场景的工作区哈希保持一致。平台响应和会话补读使用合成输入。真实 GitHub/GitLab 写入、桌面宿主的技能发现和真实历史会话补读仍待对应环境验证。样本支持上述场景结果，整体质量和成本变化仍需更多数据。

## 跨 Profile 整合

`pr` 成为三个 Profile 的默认入口。`retro` 在 Spec 默认安装，Backend 和 Frontend 可按需用 `yss skills ensure retro` 补装。入口共用同一份方法，两个安装范围分别分发必要参考。默认数为 Spec 20、Backend 44、Frontend 21，可用数为 67、57、26。[技能地图](../../.template-spec/agents/profile-skills.md) · [PR 正文入口](../../.agents/skills/pr/SKILL.md) · [会话复盘入口](../../.agents/skills/retro/SKILL.md)

- **分发核对。** 候选 Bundle SHA-256 为 `0724424904a28796acb9770362ff5aab6461ebcc0985e3c32f6d4a77e5ad3ec6`。归档与内嵌该候选的临时 CLI 在六种安装组合上的预览一致。临时 Spec 实例实际同步从 18 项增至 20 项，两个入口均已落盘。
- **Frontend 案例。** 在空目录新装 Frontend `skills` 后，`pr` 随默认集安装，`retro` 处于可选未安装状态。以「退款表单提交失败后保留备注并允许重试」为合成输入，同一 Node 状态测试改前退出 1，改后退出 0。`pr` 读取已安装的入口、共享参考和真实测试记录，沿临时工程模板生成正文，保留浏览器联调未验证的范围。
- **按需复盘。** 运行 `yss skills ensure retro` 后，Frontend 的默认集仍为 21 项，`retro` 作为显式选装落盘。复盘读取本地入口和同一共享参考，定位首轮验证漏掉备注断言的问题，并建议在现有用例同时核对备注和重试状态。两个 Codex CLI 只读会话均保留临时工程文件字节。会话证据来自本地合成记录，验证覆盖状态函数与技能调用。
