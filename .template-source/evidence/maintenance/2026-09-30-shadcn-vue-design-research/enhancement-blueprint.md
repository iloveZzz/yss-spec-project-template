# YSS 高保真 Skills 与 design 修订蓝图

状态：研究建议，尚未修改现行能力。依据见主简报 claim-001～013。默认保留 React/shadcn 原型和原生轻量路线，生产 Vue/YSS 合同不变。

## 工作包一：先把规范和预览修到一致

1. **根 DESIGN.md 正文**：将原型默认命名紧凑变体、窄屏普通控件和生产默认主题分开说明。继续引用现有 `button-compact`、`card-compact` 和普通变体，不重写色板/字体，不用生产compact算法改变原型正文大小。保持旧批准资产与局部修改的密度约定。
2. **`.template-spec/design/design.md` 与 README**：删除互相冲突的默认密度描述，统一导航；把原型作者、生产映射和历史来源分成清晰适用范围。已有Token接入/计算样式检查改为当前能力说明，保留真正未完成的暗色待办。
3. **`.template-source/design/preview.*`**：修复Token加载路径，消费生成变量，减少独立硬编码；明确预览模式及其来源。纯展示按钮标明边界或禁用并说明；需要演示的筛选/详情/恢复采用确定性场景，不能出现按钮改名但行为未改。
4. **profile同步**：通过 `.template-source/profile-skill-sync.json` 登记 preview.js 依赖，使用仓库同步脚本更新 design/frontend profile。检查产出根中的真实资源，不用主仓通过代替分发通过。
5. **证据模板注释**：说明原型compact是选择根规范命名变体，不必等同于消费生产 `tokens.compact.json` 的完整算法结果；视觉主题名、实际Token摘要和截图一致。沿用既有schema，不新增批准状态。

验收：规范与默认构建行为一致；明亮/紧凑/comfortable按已声明能力分别核验；暗色未完成派生和浏览器检查时不声称可用。主仓及两个profile的预览资源零缺失、无console错误、筛选/重置/浮层行为与展示声明一致。复制到独立目录时按既有导出机制包含实际依赖。

## 工作包二：增强三个现有 Skill 的方法

| 归属 | 增强内容 | 不扩张的边界 |
|---|---|---|
| `yss-prototype-stage` | 任务→页面配方→当前可用组件的选择导航；新增组件的固定源码、依赖、许可、离线与状态核验；复用现有五类业务模式 | 不把上游CLI执行策略直接引入所有项目，不在原型消费生产组件事实；不把研究中的候选写成已可用 |
| `yss-design-system` | 页面骨架、信息分组、密度、反馈位置、主题映射；正反例说明具体改善及代价 | 根DESIGN仍是视觉权威；语法偏好不是新门禁；不把完整应用壳强加给局部修改 |
| `prototype-review` | 在原有低保真评审和六轴QA中补组件误用、任务连续操作、窄屏命中区域与焦点核验 | 保留行为缺陷、视觉观察、偏好建议的区分；不凭库名授予无障碍通过 |

复用上游Skill的选择方法、语义角色和组合示例；不继承其默认 `@latest`、自动registry探索、preset覆盖或与本仓不同的主题改写规则。代码层适配留在作者工具和本地主题层，Skill正文保持简短。

## 工作包三：小批组件接入与业务模式深化

第一批按采用矩阵接入字段、反馈、详情和结构组件。每次更新先验证同一固定React revision是否包含候选；如果需要升级revision，单独形成来源差异与回归范围，不混入组件小改。

- 查询：工具栏展示当前筛选、结果和选择状态；次要行操作收进菜单，主要动作保持直接可见；详情承接窄屏次要字段。
- 表单：字段分组、说明/错误关系、步骤状态、返回保留输入、错误聚焦、提交失败和重试连成完整任务。
- 审批：不可操作原因、已处理与剩余事项、部分失败反馈形成稳定结构。
- 冲突：保留现有“草稿保留—确认放弃—完整服务端快照替换—再次保存”语义，只改呈现不偷偷改规则。
- 分析：指标/筛选/明细保持同源；新图表仅在任务需要时加入。没有图表Token角色时先补规范，不复制官方颜色。

新组件主题适配需检查嵌套控件。当前主题中针对input、button、浮层的规则可能与InputGroup/Sheet等默认样式叠加；必须用计算样式确认边框、间距、字号和高度，不以编译成功替代。

作者配置继续使用现有字段，例如：

```json
{
  "schema_version": 1,
  "title": "资料维护",
  "entry": "./page.tsx",
  "scenarios": "./scenarios.json",
  "density": "compact"
}
```

不要求新建另一份组件批准manifest。上游原文件继续由现有registry manifest记录；本地适配差异和实际依赖闭包接入现有build provenance。Sidebar等含hook的组件需显式扩展受控来源解析范围，不能放宽为任意路径/依赖。

## 工作包四：验收与同步

| 检查 | 具体完成条件 |
|---|---|
| 规范 | 当前DESIGN/Token摘要一致；选定密度实际计算样式正确；旧资产只读 |
| 任务与场景 | 场景切换/重复重置/候选切换清空临时状态；保留共同初始数据；未知场景仍明确失败 |
| 浮层/菜单 | 标题和名称可读；打开、取消、提交、Escape、焦点返回正确；窄屏不遮挡关键动作 |
| 字段/列表 | 错误关联和定位；选择/分页/筛选状态准确；空、权限、错误有区别；无效操作有原因 |
| 紧凑布局 | 1440×900与390×844实际关键流程；命中区域及相邻间距；200%缩放；减少动效的计算样式 |
| 离线/来源 | 独立目录file://断网运行；新增依赖/资源完整且固定；来源摘要、许可、越界/符号链接/远程依赖拒绝仍有效 |
| 兼容与分发 | H1/H2、原生路线、比较v2和legacy只读、Evidence v4、Visual Baseline v1；权威源→投影/锁→profile→受影响CLI快照 |

继续执行既有测试和 `verify-template-fast`，按实际影响升级；PR/main/发布边界用各自验证。不能用本研究包校验通过代替实现验证，也不能沿用此前未闭合的全仓验证结论。

若后续希望证明质量收益，先冻结本轮方法增量和共同工程基础，再另行确认/绑定已有试点授权及预算。当前没有新增真实Agent启动计划，不自动重开此前停止的校准。可比结果才送用户匿名视觉确认；工程通过、任务质量和用户偏好分别结论。
