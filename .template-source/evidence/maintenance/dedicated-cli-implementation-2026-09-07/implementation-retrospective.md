# 专职 CLI 实现复盘

本轮维护的是 template-source 工具链，强度 L3。已确认设计 v1.1.0 和提问者“确认，开始实施”为实施依据；未创建产品生命周期资产。

独立检查发现恢复路径可绕过旧实例身份和嵌套 Git 边界，以及入口路径尾分隔符影响包内目录保护、全局升级识别。根因是正常应用入口已检查的条件没有在恢复入口重新核验，且入口路径归一化不统一。修复将身份、gitlink、嵌套仓库和备份摘要预检置于恢复写入之前，并在主入口统一规范化包根路径。保留 SIGKILL、磁盘失败、恢复期间目录变化与实际 bin 入口测试，防止只验证正常路径。

真实包验收曾因调用不存在的 verify-repository-mode 和测试夹具覆盖 profile 来源字段失败。实际身份命令为 scripts/repository-mode；夹具现保留完整 profile。包级合同用预览核验资产，完整生成在实际 tgz 安装后执行一次，并由接力验证复用；失败记录不计作通过。

现有设计 CLI 的测试会修改同一模板快照，并发执行可互相干扰，已把套件设为串行。三个旧 CLI 的测试与打包分阶段执行，来源均锁定完整提交。

完整模板有 6155 个文件。持久化事务逐文件落盘使首次创建在本机需要数分钟，属于已观察到的性能限制；本版保留恢复证据完整性，后续优化须继续覆盖断电/中断恢复行为。

npm 分发与 GitHub 提交分开记录。当前 npm 身份检查返回 E401，未发布新 npm 包；旧 scripts/instantiate-harness 继续保留，待新包公开可安装并验收后才启用退役提示。新 CLI 不兼容该旧入口生成的实例。
