# Slice v3 第二轮优化与验证收敛

本轮状态：`implementation-ready`，限定 Slice 合同和直接消费者。未提交、推送或发布。YAML 仍是唯一权威合同，批准继续绑定原始字节。

## 已交付

- **减少审批返工**：新草案声明冻结 Ticket 需求版本。模板、状态说明和审阅视图区分冻结时状态与当前执行状态；进度、验收结果和重路由记录使用已有 tracker / 任务包。修改需求仍触发摘要失效，旧合同不自动改绑。
- **按影响准备材料**：从已发布生命周期架构审查触发条件计算适用性，绑定注册表和裁剪依据；低风险单仓可不提供未触发的架构审查材料。未知影响、未知规则版本和必要材料缺失阻断。既有 UI 基线核验原始源码、构建、截图与 API 证据，新 UI 变化不能借此绕过设计材料。
- **汇总缺口**：来源发现与独立检查一次返回多个 blocker，含稳定错误码、字段、来源、责任类别和恢复动作。依赖未满足的下游标记未执行；来源索引区分 Ticket、checkpoint、仓库登记与 Agent 细化。阻断草案可显示绑定当前 YAML 摘要的诊断，但不能批准、派发或执行。
- **跨仓执行**：消费现有多项目准备结果和逐仓工程批准，文件事实仍集中在 basis。逐仓编译后合并一次冻结能力和 Skill 集；编译依据在调用中变化时阻断。工作单元必须选择唯一工程，执行上下文和技术设计子进程传递该选择。写范围、验证 cwd、联合验证依赖、变更文件与证据逐仓核验；同名路径不能串仓。交付与回滚顺序必须完整。
- **阅读与核验效率**：审阅固定展示目标、范围、验收、取舍、风险和待决定事项，缺说明明确标记；验收不重复展示。任务视图保留共同约束和所选工程上下文。差异附原字节证据，区分范围、验收、授权、工程细化与格式，不推断批准可沿用。视图复用一次读取和规范化结果；执行边界仍重新读取，外部不能提供伪造缓存。

Slice schema 保持 v3；v2 和没有新增声明的旧 v3 保留原规则。新行为通过显式新草案启用，不继承旧批准。没有改造其他合同结构或新增管理系统。

## 接收端边界

主模板支持本轮跨仓准备、批准、派发和结果核验。后端 / 前端接收端保留单仓 v3 读取能力；对不支持的来源多项目准备协议明确阻断，不能套用各 Profile 本地裁剪规则，也不能替换原编译依据和批准绑定。相关拒绝场景已纳入回归；并未宣称所有专职接收端都能执行新跨仓合同。

## 可复现成本测量

同一 MVC 夹具、同一份权威 YAML 的合同及来源读取调用从 **27 次降至 12 次**，登记文件多个别名的读取从 **6 次降至 1 次**。优化前使用本轮开始时保存的读取实现，基线代码和摘要保留为只读证据；这不是完整旧版本的性能基准。[测量数据](metrics.json)、[基线读取实现](read-baseline-source.json)

准备报告保存实测准备耗时；未实际观测的补材料轮次、人工确认次数保持 null。已有确认延续的合成场景新增确认次数为零。真实 MVC 切片的准备、审查与执行耗时留到下一次已授权实施中采集，未把夹具耗时写成真实工时收益。
