# Plan → Spec 入口维护者自检

日期：2026-09-10。`template-source`，L3（生命周期门禁、跨仓合同与聚合行为变更）。按 `maintaining-skills` 默认停在 `implementation-ready`，不冻结候选、不自动发起独立审查，不提交或推送。

## 已确认边界

用户确认按推荐继续：Plan 未通过时不得进入正式 Spec 起草；无依赖的独立调研可继续。自动加载检查项不等于自动批准；非关键延期和未命中门禁须有证据、原因及真实用户确认。主模板与战略子项目一起修复，保持战略子项目的业务方案交接终点。

## 根因与修复

- 原 `validateNextRoute` 在无状态时返回 allowed；机会调研到 Spec 还可绕过仅绑定需求规划工作单元的用户决定检查。新增反例在修复前实际返回 allowed 并失败。
- 原工作单元查询不自动加载 Plan 阶段门禁、`planning` 或 `grill_exit`，且主模板编排图遗漏 Plan 路由。现在 Plan / Spec 阶段或相关工作单元查询均加载全量 pending 检查和 Plan 门禁。
- 注册表 `stage.plan.spec_entry` 持有检查项与条件门禁映射，覆盖不完整时阻断。统一校验器被流转、任务包派发及 checkpoint 恢复消费；完成态 Spec 结果也必须携带入口证据。显式 `to-spec` 按主控 Skill 回交相同入口。
- 审阅包绑定当前功能、正文、Context、注册表、调和记录、逐项证据、影响面、未决问题和会签资产。复用现有 `plan-conclusion`，先展示再取得真实回复，不新增批准阶段。
- 关键问题和可执行阻塞不能延期；非关键延期必须有原因、责任人、解决点、接收方和证据。命中门禁校验会签与用户回复；未命中门禁的 N/A 理由纳入同一审阅快照。缺项、摘要漂移、错误范围及无回复均阻断。
- `.agents/skills` 是修改源，投影和锁由脚本生成。两个 CLI 快照同步，并在新建实例上实际检查 pending 投影与无状态阻断。

## 反证与边界

覆盖无状态、空状态、缺检查项、pending、必需检查 N/A、缺证据、缺影响面、缺门禁、命中门禁伪 N/A、空原因、关键问题延期、可执行阻塞延期、缺延期交接、无回复、过期依据、错误范围、Context 缺失、旧审阅批准、直接 Spec 任务和 checkpoint 恢复绕过。正向覆盖当前真实回复来源、用户确认的非关键延期、命中门禁以及未命中门禁。

首轮主模板全量检查识别出旧 Matt 集成测试将无 Plan 审阅的 Spec 完成结果当作有效样例；修复测试夹具，补充完整合成 Plan 审阅，不移除正向测试或放宽入口。合成回复仅存在于测试临时目录，不是本次产品批准。

检查器保证结构、证据摘要和回复绑定，不证明业务判断绝对正确，也不是身份签名系统。主控仍须核查影响面及未决项分类，不能为放行而填 false。任意绕开 Agent 流程直接编辑文件不是此校验器的安全边界。

本次是流程与校验器维护，不适用产品行为 TDD、产品 Spec / Ticket 或产品 Context 调和；以可执行回归和模板根词汇校验替代。完整新鲜验证结果见相邻 checkpoint，未通过前不声明完成。

已保留先前 Plan 迁移及其他用户修改，尤其 `submodules/create-yss-harness-dev` 不属本轮范围。回退应仅逆向本轮差异，不能整仓 reset 覆盖既有未提交工作。未修改历史冻结证据。
