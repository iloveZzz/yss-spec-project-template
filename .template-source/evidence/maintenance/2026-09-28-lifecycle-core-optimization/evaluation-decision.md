# 对照评测试点结论

本轮交付正确性修复，**不推广 focused 为默认阅读方式**。全部轨迹已审阅；API 与 UI 在 Agent 隔离环境中未完成，不能满足全量目标行为和恢复效率采纳条件。原默认 `legacy` 保留，focused 仅显式选择。

共启动 16 次会话，累计执行窗口 2,126.81 秒（约 35.4 分钟），未超过 20 次／60 分钟上限。基线 8 次、候选 8 次；每组两个 UI 恢复会话因前置步骤失败而未启动。没有把它们记作成功或零成本。

| 任务 | 基线，两次重复 | 冻结候选，两次重复 | 语义复核 |
| --- | --- | --- | --- |
| 正式研究收尾 | 0/2，旧路由阻断 | 2/2，真实复验后合法终止 | 来源摘要和实际路由调用可复查，研究文件未改写 |
| API 与证据 | 0/2 完整通过 | 0/2 完整通过 | 两侧本地监听均报 EPERM；均拒绝替换日志。候选实际调用新证据校验器并得到 evidence-digest-mismatch |
| UI 两步恢复 | 0/2 完整通过 | 0/2 完整通过 | Chrome 启动 SIGABRT／EPERM，未产生页面、截图或 console；第二步均未执行 |
| 跨仓漂移 | 2/2 | 2/2 | 两侧均重算两个仓库同名文件摘要，正确阻止复用 repo-b 旧证据 |

自动判定从 2/8 通过变为 4/8，通过数增加来自研究路由修复。全部 16 个已执行会话的最终文件写范围检查通过；轨迹中未观察到错误放行。该检查不能证明不存在瞬时或外部写入，且恢复未执行，因此不能宣称重复副作用验证全面通过。

仅对双方均完成目标行为的两个跨仓样本比较：

| 重复 | 输入 token，基线 → 候选 | 总工具调用，基线 → 候选 | 耗时秒，基线 → 候选 |
| --- | --- | --- | --- |
| 1 | 233,266 → 221,105 | 12 → 12 | 86.81 → 57.98 |
| 2 | 277,636 → 141,844 | 13 → 5 | 106.78 → 72.03 |

这是两个样本的观测值；总工具调用不等于恢复调用，恢复指标仍为未知。suite 未强制启用 focused 布局，不能将变化归因于任务裁剪；缓存和模型执行路径也有影响。总体 token 含失败路径，不作为收益指标。费用未知，不宣称统计显著或固定收益比例。

单独的合成任务视图实验中，3 项验收、当前任务命中 1 项时，正文从 10,701 字节变为 10,976 字节；24 项验收、命中 1 项时，从 12,249 变为 11,243 字节。新恢复说明有固定开销，裁剪收益依赖任务规模；该结果不能替代 Agent token／恢复验证。

候选来源保持冻结。后续确定性检查修正了路由的 `not_applicable_reason` 和 Skill 8KiB 入口预算，并同步说明与锁；差异记录在 `post-evaluation-snapshot-delta.json`。最终源码不冒充已重跑 Agent。全部失败、未执行步骤和预算记录保持原样。

下一次效率试点需先提供能执行本地 API 与真实浏览器的同一受控运行时，并在固定提示中明确选择待测布局；再对最终冻结源码完成两步恢复。此处仅记录后续条件，本轮未追加会话、安装适配器或改变运行时权限。
