## 自检结果

- 生命周期继续统筹门禁与批准，通用技能负责技术设计，编译器只起草实现合同。新技术分析入口、资产依赖、状态说明、架构模板及用户手册保持一致。
- DDD 专项技能保留；MVC 分支不要求战略 DDD、聚合、值对象或 Gateway。技能注册表限定专项能力的架构族，MVC 不加载 yss-domain。
- 新工程的架构决定绑定当前文件摘要与真实用户决定；既有工程绑定登记，不通过目录或合同自述重选架构。
- v2 合同共同头绑定输入、架构与规则承接，分支 Schema 由共同字段和专项 Schema 确定性生成。旧 v1 合同要求显式 legacy-ddd，既有 DDD 规则继续回归。
- 新增 artifact.technical-design 和 evidence.technical-design-review，旧 DDD ID 保留原义；更新技术分析工作单元描述和语义基线，没有新增阶段或批准门禁。
- 规则/场景承接支持 MVC 用例和 DDD 对象，按切片验证延期、冲突、未知依赖、成功/失败测试及输入漂移。编译器在编译及 freshness 检查重验当前设计。
- 所有共享技能只修改 .agents/skills，投影和锁经脚本生成；没有手工维护并列副本。
