# 审批与会签提效维护记录

本轮按会话中三轮已确认方案实施。仓库身份为 `template-source`，维护强度为 L3（生命周期门禁、授权边界、核心校验）。工作区开始时干净。本轮不包含提交、推送、CLI 固定版本发布或生产操作。

## 已落地的行为

- 普通功能默认一个推进负责人和一个独立审查者。Standards、Spec、UI 是检查维度，不是默认审查人数；能力缺口、结论冲突和外部制度要求才增加专家。
- Plan、Spec、设计、工程契约继续保留适用检查；有明确范围授权时通过 `continuation_ref` 复用原始用户回复，独立审查绑定当前资产、差异和验证证据。
- 原授权明确列出边界、资产引用、范围和七类决定依据。原始依据保持不可变；当前候选可以变化，但须由独立审查说明前后差异与等价性。检查器验证声明及来源，不自动判断自然语言语义。实施延续另对原授权与当前切片的仓库、写路径进行精确比较，重算摘要也不能扩大写权限。
- 范围扩大、验收/契约/授权/风险/质量/对外承诺变化、无回复、撤回、自审、证据过期和缺失均不放行。非阻断建议带待办去向，不要求再批准。
- 外部制度未知时不允许自动延续；已登记制度逐一验证当前范围和指定真人回复。通用模板不推定客户、公司或审计没有要求。
- 相邻专业检查支持一份 `review-bundle`，每项保留当前对象、范围和结论；总体批准不能掩盖失败项。
- 历史原始回复继续可读且严格核验，不会被自动扩展成更大授权。Git、发布和生产授权仍独立。

## 同步与兼容范围

已更新主模板事实源、生命周期与原型/代码审查 Skill、生成投影、Skill 锁、生命周期派生视图、任务包与 checkpoint 入口。共享校验依赖及代码审查适配同步到设计、后端、前端三个 Agent 工作区，并保留它们已有的专职责任边界。

三个接收端已验证可核验主模板携带的源授权延续，并在原始回复缺失时拒绝。它们本地生命周期未登记的新 capability 边界仍拒绝延续，不自动获得主模板的新权限。固定提交来源的 CLI 快照未重建/发布；本轮分发锁为 `working-tree`。

## 验证与限制

验证结果见本目录的实际日志及 verification.json。重点覆盖无重复用户回复的正例，以及越界、撤回、实质变化、降低质量、缺证据、自审和外部审批缺失的反例。维护采用 self-check，没有把实施者自检描述为独立审查。

## 复盘

人员策略与 Skill 执行方式必须同步：只调整角色表会留下 code-review 固定双 Agent 的隐性成本。本轮已同步修改。初次回归暴露的入口文本预算、旧测试角色和测试工作目录问题已修复；这些是迁移适配问题，不能通过放宽校验掩盖。

稳定 ID 仍指向原有批准边界，没有新增/复用其他含义的 ID；按已确认政策更新触发说明和语义快照。实际效果尚需在真实项目观察人工中断次数、审查等待、返工和缺陷逃逸，当前测试不构成生产效率提升百分比。
