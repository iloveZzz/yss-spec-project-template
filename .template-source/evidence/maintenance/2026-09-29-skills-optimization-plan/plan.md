# Skills 全面优化计划

状态：v1 已定稿，Q1–Q7 全部确认，定稿日期为 2026-09-29。本文是模板维护执行计划；本次授权为澄清和形成计划，尚未启动实施、真实模型评测、提交、推送或发布。后续实施以用户明确的推进指令为入口。

## 目标与依据

覆盖主模板与三个 Agent profile 的全部 canonical 技能，核对并优化调用策略、触发描述、正文组织、环境依赖、资源完整性和分发适配。基础设施复用现有注册表、锁、生成投影、同步脚本和评测器。全面覆盖要求每个入口有处置结论；具体修改须有问题或收益依据。

研究输入为 [跨平台 Skills 研究报告](../2026-09-28-cross-platform-skills-research/skills-research-brief.md) 与 [证据台账](../2026-09-28-cross-platform-skills-research/skills-evidence.yaml)。2026-09-29 核对主仓 HEAD 仍为 `e1503a536b92b3e0a74182632f0690cc5601de62`。研究清单包含 213 个入口实例，其中主仓 77、backend 59、design 23、frontend 54；跨仓重复项不是不同技能。实施前重新绑定源码和清单，不将研究阶段的验证复用为实施通过证据。

### W1：调用合同的具体落点

修改范围为 `.template-spec/agents/yss-skill-registry.yaml`、受影响 canonical 的 `agents/openai.yaml`/正文、`scripts/lib/skill-registry.mjs`、`scripts/lib/skill-supply-chain.mjs` 及对应测试和 profile 适配。

注册表保持治理意图权威，运行时元数据由同一意图生成或校验。区分发现、自动选用、显式调用、内部依赖和动作授权；不以 `instance_default_discoverable` 替代 invocation。宿主无法等价表达内部调用等规则时，登记能力缺口并验证有效的适配方式，禁止静默丢失限制。

验收至少包括：拟提交信息不执行 Git；已授权的指定范围提交不被误拦；普通任务不选中内部 core；公共提交入口仍能消费 core；自动文档辅助与用户禁止辅助都正确；维护任务授权不得扩大到无关项目；每个 profile 保留其有效差异。

### W2：发现与冲突处理

计划新增只读发现入口及宿主适配模块，具体文件名由 W0 根据现有工具目录确定，属于新增实现而非当前已有命令。输出包含 runtime/version、工作目录、配置来源、名称、来源路径、完整资源摘要、声明策略、已观测生效策略及观测方法。

同时记录 `observed`、`inferred`、`unknown`，未知值不能自动填成宿主默认。先在干净 fixture 验证 canonical、符号链接、实体投影、同名不同内容、用户级同名与子目录启动，再做当前项目只读观察。真实来源不能可靠判断时，不伪造探针成功；阻断受影响关键技能的验证通过。

相同内容重复不默认阻断；内容相同还须比较依赖闭包和生效策略。无关用户级技能不影响当前任务通过；本任务实际选中未经登记的不同来源则阻断。修复优先限定到受影响的项目分发配置，旧客户端兼容性未知时保留投影并登记缺口。

### W3：评测覆盖与判分

修改范围为 `.template-source/scripts/skills-agent-eval.py`、其说明文档、`.template-source/scripts/tests/test_skills_agent_eval.py` 及新增场景数据。沿用原始轨迹、产物断言、写范围、预算、异常和未完成记录；增加宿主适配时保留原始事件，归一化结果不能丢失错误和工具调用。

Codex 对每个经 W0 确认的有效技能组至少覆盖自然语言正例、近邻负例；显式入口、内部依赖、生命周期及动作授权另覆盖对应的调用/拒绝/恢复场景。内部 core 的正例是公共入口正确消费它，不能为了全覆盖直接自动调用 core。环境或依赖不同的 profile 单独运行差异场景。

Cursor/Pi 覆盖真实发现、显式与隐式调用、内部依赖限制、同名冲突、提交咨询与实际授权、生命周期恢复、前后端路由及各端特有行为。宿主没有某能力时验证明确回退，并保持该能力未支持的声明；不得以降级场景通过代替完整能力通过。

每次基线/候选比较固定场景、模型、推理档位、运行时及依赖；模型以当前可用配置确定并记录，不擅自切换供应商或新增付费账号。跨宿主可能使用不同模型，故只在同一宿主配置内比较旧/新，不能把客户端差异直接归因于 Skill 优化。

执行错误、未完成、自动断言和语义复核分别记录。关键约束及声明必须通过的场景逐项通过；不以平均通过率掩盖未授权写入或关键来源冲突。修正判分器时保留原因和摘要，对两侧统一重评分；重跑使用新输出目录，不删除失败样本。

### W4：全量内容与依赖优化顺序

按公共合同与技能依赖拓扑推进，以下为工作组织顺序，不授予额外生命周期所有权：

1. 通用辅助与已确认调用差异：提交辅助、文档写作、工作区、来源刷新。
2. 通用工程与审查：`code-review`、`wayfinder`、`archify`、诊断、TDD、研究等。
3. 生命周期与设计/契约：生命周期、Plan/Spec/Ticket 兼容入口、设计、原型、编译器及 OpenAPI。
4. 后端专项：架构/领域/应用/持久化/控制器、组件与脚手架。
5. 前端专项：UI、API、Formily、表格/树、主题、页面生成与脚手架。
6. profile 本地技能与适配差异收尾；它们的前置规则变化时须提前联动，不等最后才发现冲突。

每项审查：触发是否能与近邻区分；入口是否保留必要判断和拒绝条件；正文是否重复根治理；条件资料是否按需加载且可达；脚本是否承担确定性工作；资源/工具/项目环境是否说明；缺失前提是否有明确出口；对外导出是否完整。`compatibility` 可用于表达环境前提，但依赖清单仍由既有 registry/lock 管理，不重复维护。

成本改造比较同一任务的实际文件读取、可观测字节、模型报告 token、耗时和产物质量。冷/热缓存及缺失遥测单独标记，不混作零。初次差异小或噪声大时按预算补配对复测，收益不能稳定解释则撤回纯成本变化；不以字符减少、少于 500 行或删除必要约束作为通过依据。

### W5：同步、兼容与 CLI 集成

维护 `.template-source/profile-skill-sync.json`、命中的 `.template-source/profile-skill-patches/`、三个 Agent 仓的本地权威内容及分发配置。先核对上游来源与适配依据，再生成投影与锁；不得把源仓绝对路径写入公开技能包。

每个生成器覆盖最小新建、按需 ensure、已安装更新、存在用户定制的冲突、退役兼容入口与再次执行无新增变化；按实际影响裁剪未涉及的产品组合并留理由。测试只使用临时实例，不替用户迁移既有工程。

工作树来源的本地包/fixture 可用于内循环，但不构成固定来源集成或可发布证明。最终模板/Agent 提交与 CLI 快照固定到真实 SHA 后，才能执行固定版本集成。此阶段若尚无提交授权，保留本地验证成果并明确标记交付前置未满足。

真实 Codex 评测使用下列已有入口，所有变量由 W0/W3a 产物解析为绝对路径/固定配置，不让用户手填事实。`TURN_CAP`、`SECONDS_CAP` 只是分配到单进程的剩余预算，调用方必须累计基线、候选、其他宿主及失败重试。

```bash
python3 .template-source/scripts/skills-agent-eval.py \
  --source "$FROZEN_SOURCE" --scenarios "$SCENARIO_FILE" \
  --output "$RESULT_DIR" --variant "$VARIANT" \
  --codex "$CODEX_BIN" --model "$EVAL_MODEL" \
```

需要比较方差或高风险复测时使用独立新批次，不能把单次通过写成稳定概率。Cursor/Pi 使用 W3a 实现且经过本地验证的入口，不在计划中假称现有 runner 已兼容。

## 已确认的评测资源控制方案

按已确认的 Q7，先做有上限的校准，再依据实际数据一次性确认剩余全量预算：

- 首批最多 **24 次 Agent 启动尝试、45 分钟 Agent 执行窗口、单次 300 秒**，按先到上限停止；跨基线/候选及失败重试累计，不按进程重置。准备与判分耗时另报，不承诺全部工作 45 分钟结束。
- 从已审阅场景中选 6 类典型任务，安排基线/候选配对与必要重复；若含多步场景，以实际 turn 数计入 24 次，不能按场景数绕过上限。保持三个宿主的必要能力预检，环境失败未解决时不批量启动。
- 24 次与 45 分钟是已确认的控制上限，不是对覆盖充分性、实际时长或费用的预测。到限保留未完成项；记录真实 tokens、耗时、错误和剩余覆盖量。
- 校准后依据有效技能组数、场景步骤、宿主差异和复测需求给出总调用量/时长及能核实的费用估算，取得一次总预算决定后，在该范围内按批自动推进；只有超限或实质范围变化才再决定。
- 没有可核验费率或账单时费用为未知，不用 turn 数冒充费用上限；不新增购买、订阅或付费服务。当前仍只编写计划，不启动模型运行。

任何已确认预算达到上限后均停止启动新运行，保留未完成状态；不得通过裁掉已确认覆盖面来制造完成。校准样本若覆盖不足，应先报告实测缺口，不自行扩大上限。

## 回滚与完成标准

W0 保存每个相关仓库的起点 SHA、原始工作区差异和本批输入/输出清单；未提交的用户工作单独保全。回滚只针对本批允许路径及已确认的原始字节，不使用 reset/clean/自动 stash。生成产物通过恢复相应 canonical/config 后重新生成，并复核摘要。

正文优化按技能族独立回滚；registry 与宿主元数据必须一起回滚，避免只退一侧；profile 适配与对应子仓内容一起核对；CLI 回到已验证的模板/Agent 固定来源组合，不随意混用旧包新锁。失败评测和撤回理由继续保留。

实施完成要求：逐项执行表无未处置入口；确定的不一致与适用测试失败已关闭；完整资源与环境前提可核验；Q5 的真实覆盖及语义复核齐备；Q4 冲突可解释且无阻断项；纯成本改造满足 Q6 或已撤回；投影/锁/profile 适用验证通过。缺宿主、凭据或观测能力不能记为通过，也不能跳过已确认覆盖后宣称全面完成。

固定来源集成、Git 交付、发布就绪和实际发布分别报告状态。本轮形成计划的完成条件为 Q1–Q7 决策明确、工作批次与验收/回滚可执行、未验证事实与后续授权边界已写明，不要求现在实施这些工作。
