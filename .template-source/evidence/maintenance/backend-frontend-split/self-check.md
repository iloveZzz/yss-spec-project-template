- 后端、前端专职模板各有 profile、派发范围、编排技能和本地实例化入口。前端使用新增 frontend-engineering-design 工作单元，保留旧 DDD ID 的原始语义，不将其用作前端工程设计的别名。
- 共享角色身份与来源技能仍保留，执行和最小编译闭包按本端 profile 限制；对端只读输入评审不赋予实现权限。
- 原通用研发 profile 保持原行为；create-yss-harness-dev 原有 template.snapshot.json 的 6 行差异未修改。专职初始化拒绝已有目录，不提供原地 sync 或自动迁移。
- 两个公开仓库已由 GitHub 初始化，作为真实 160000 gitlink 挂载，main 分支附加。模板代码尚未提交或推送；当前 gitlink 的初始化提交不能代表本地实现已发布。

## 已检查的关键行为

接收同时验证战略、后端及源批准；目录/ZIP 可在源仓移除后读取。前端映射将已规划用例记为 mapped，不能冒充已实现。接收记录及用例文件均绑定字节摘要；后端包绑定冻结接口、已批准 Slice Contract、提交、构建、部署、测试数据和验证记录。

每次正式启动/恢复均重新检查已知基线、映射与真实服务的五类身份；旧成功输出和 accepted/verified 字段不能放行。输入通过后编译器只返回 draft；写代码仍须持久化且已批准的当前 Slice Contract 和既有就绪条件。

缺输入、损坏包、错误批准、缺少成功/失败场景、跨切片、部署/数据变化、服务失败、已导入新版、用例字节漂移、profile/metadata 失配及跨端派发均有拒绝路径。正式生成绑定不可变提交及源文件树摘要；工作树测试显式标为非发布快照。

## 验证与局限

逐仓命令、UTC 时间、耗时、退出码与日志见本目录 *-verification.json/log。主模板完整核验同时运行新的交付场景和生成实例跨仓接力；dev、backend、frontend 的核验 profile 也已纳入新场景。

这些场景使用明确标注的合成业务 fixture 和独立 HTTP 测试进程。它们验证流程机制，不能当作真实产品后端部署、前端视觉验收或整体业务验收。版本探测只证明当前服务身份可达，业务正确性仍依赖同版后端测试和产品端到端证据。不能观测未同步的源仓最新变更。

未进行正式候选冻结、独立审查或发布；maintaining-skills 的 L3 日常目标为 implementation-ready。代码提交/推送须后续授权，并先形成可获取子仓提交再更新父仓 gitlink。

## 本轮返工与修正

旧校验器包含通用四角色、DDD 主路由和通用 CLI 的固定断言。拆分时同步修正专职 profile 的路由、编译、角色边界、实例入口与对应反例；前端新增稳定 ID，避免覆盖旧 DDD ID 的语义。更新技能边界生成文件后重新同步投影与 lock。新仓的 vendor 检查在安装已有锁文件依赖后重跑；未改依赖版本。

后续新增专职 profile 时，应以 profile、实际执行入口、分发实例和负向场景共同确认闭环；仅复制文档或改仓库名不足以支持新的职责。
