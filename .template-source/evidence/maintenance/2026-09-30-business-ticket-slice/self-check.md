# 业务 Ticket 与实现 Slice 衔接维护者自查

这是实施者自查，不是独立审查或产品批准。范围为用户批准的 L3 模板维护；不包含实例迁移、Git 交付或发布。

| 风险 | 当前实现与证据 |
|---|---|
| Spec 没有后续交付单元 | 生命周期和显式 to-spec 产出业务草案；Spec 退出与 checkpoint 均要求可读集合。没有工程仍可进行业务检查。 |
| 战略/战术职责混合 | to-tickets 先选输出类型；Design 只校准业务票，研发再细化 Slice。实现正式化仍保留工程准备和批准。 |
| 入口自相矛盾 | 删除兼容入口中的独立实现票简版模板，统一引用共享业务/实现模板；不再在末尾用例外覆盖前文默认工程拆分。 |
| Design 不能进入正式化工作 | 草案可以进入该工作单元；只有退出至技术分析/战略交接时要求正式化。新增拒绝与通过断言。 |
| 有效但错误的 Spec 批准 | 正式化必须绑定同一 Spec，或当前已批准审阅包中的精确来源摘要；另一个 Spec 的有效批准被拒绝。 |
| 内容类型冒充 | 原始 Markdown frontmatter / YAML 内容受检；放入 issues/ 不会把业务票或阶段工作项变成实现票。 |
| 覆盖/依赖失真 | 精确 FR/AC 对应、重复 ID、悬空定位、依赖环、延期依据、审查摘要和来源漂移均有检查。专业语义标为未评估。 |
| 一业务票多 Slice | 汇总原始 AC 到 Slice 的映射；covered 不代表实现完成或获批。 |
| 提前借用 Plan 批准 | 新 Handoff 能力将最终业务集合绑定当前战略交接批准；测试拒绝旧 Plan 门禁映射。 |
| 包不可独立读取 | 导出完整来源闭包；CONTEXT.md 在只读包中读取固定快照别名，导入报告指向真实文件，源仓不隐式回退。 |
| 降格/混用协议 | Slice v2 保留诊断读取，新规则的当前实现要求 v3；旧工具真实执行拒绝未知新能力。未伪造历史批准。 |
| 迁移误改用户资产 | 新初始化启用 business_ticket_version: 1；旧配置缺失保持 legacy-unassessed，同步不补写；定制文件保留且变更可见。 |
| 工作区并发/已有改动 | 主仓和 7 个子仓初始差异已备份；只对字节等于本轮旧源的脏 profile 目标执行受 before_sha256 保护的同步。其他已有修改保留。 |

正向编译同时验证默认自动填充与显式原始 AC 绑定，精确定位验收表中的 ID；重复提及同一 ID 不再造成歧义。定向测试 33 项通过；标准权限/阶段拒绝运行记录另存 counterexamples。分发与完整回归结果以 verification.md 及外部原始日志为准。测试数据为合成 fixture，不能作为 dataingest 产品批准或真实 Agent 行为/效率证据。
