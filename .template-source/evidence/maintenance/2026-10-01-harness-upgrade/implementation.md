# YSS 实例升级技能与迁移执行器

本轮实现范围为 `yss-harness-upgrade`、共享迁移协议、四类 CLI 适配及分发。仓库身份为 `template-source`；产品 Spec、Ticket、Slice 批准与本次维护无关（not-applicable：未改变产品需求或批准状态）。维护强度 L3：涉及生成语义、跨仓分发和迁移权限边界。没有提交、推送、发布或迁移真实项目。

## 实现结果

- canonical Skill 位于 `.agents/skills/yss-harness-upgrade`；入口保持轻量，冲突规则和家族差异放在协议与引用中。新增实例默认携带该技能；旧实例可以先读取固定 CLI 包内的 `resources/upgrade-skill`，不必先覆盖项目安装技能。
- 四个 CLI 统一提供 `migrate plan|apply|status|recover|rollback`。复用原有受管文件、布局迁移、退出分发及实例验证规则；原 sync/update/upgrade 入口保留。
- 计划绑定执行器、内置模板、项目/Git 输入、候选操作和冲突决议。apply 在固定执行器下重建候选，拒绝重签篡改、输入漂移和跨家族接管。CLI 版本检查包含正式版和预发布优先级，不允许降级。
- 普通升级归档原文件、计划及回执；布局迁移、prune 和显式冲突决议还保存项目内容副本。归档在项目外且不自动清理；依赖、Git 内部数据、索引缓存和事务状态不在内容副本内。
- WAL 事务覆盖文件、生成锁与 metadata；支持进程中断恢复及最近升级回退。回退前完整检查所有原件与升级后文件，保护后续修改。主 CLI 的旧事务入口与迁移互斥，未完成迁移必须先 recover。
- 主 CLI 为明确接受的定制分别记录模板摘要和定制摘要，保持上游基线独立；同版本重新规划不会反复提示已确认的冲突，后续手改或新模板差异重新决议。
- `scripts/sync-harness-upgrade` 生成三个 profile 的注册记录、协议及局部编排入口。Skill 投影、锁和四份 CLI vendor/resources/snapshot 使用仓库生成器维护。

## 维护者自检

已检查计划重新生成、受管范围、路径保护、Git 状态保留、原件摘要验证、事务中断状态和新旧入口互斥。修复了合并后重复冲突、回执落盘中断后状态收敛、备份临时文件命名，以及预发布版本比较。独立审查未执行，本记录不冒充独立审查。

新增命令仅在隔离夹具与开发安装包上执行。业务文件、tracker、批准和合同延续其原有归属；升级技能不替用户作出新的语义决定，也不授予发布或实现资格。

## 验证证据与边界

最终结果见相邻 `verification.json` 与日志。共享核心覆盖真实写入、SIGKILL、并发修改、恢复、归档损坏、重签计划、路径保护及幂等。主 CLI 单独覆盖自定义合并、重复规划、回退和旧入口锁。

`agent/` 保存真实 Codex read-only 调用、任务包、输入摘要与五类提示输出，确认升级路由、业务升级排除、布局冲突、中断恢复和回退手改判断。该评估只有一次五场景判断，不是完整自主迁移 E2E 或效率统计；不得将机械测试结果替代真实 Agent 行为结论。

开发 tarball 使用 `npm pack --ignore-scripts` 并离线安装，只用于本轮 WORKTREE 集成。正式 prepack 的 committed-source 门禁没有取消；未做 npm 发布。共享工作区存在本轮之外的大量变更，整仓核验结果单列，不能把冻结包通过说成整个工作区可发布。
