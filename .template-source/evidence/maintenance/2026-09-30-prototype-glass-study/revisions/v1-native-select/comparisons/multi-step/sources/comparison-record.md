# 标准精修与轻玻璃外观对照

## 本轮决定与范围

用户经 grilling 两轮选择全部推荐：企业精修＋可选轻玻璃；保留颜色、字号、控件高度、圆角；优先查询列表与表单；先制作可运行对照，再决定规范与 Skill 固化。本记录为维护区视觉研究，非产品批准、生产代码或通用主题发布。

仅新增本目录。根 DESIGN.md、Token、Skill 权威源与其他已有修改保持只读。本轮没有新增生命周期门禁、生产组件库或真实 Agent 试点。两个候选共享同一份 React 页面逻辑、内容及场景数据，仅 data-appearance 的材质选择不同。桌面选择现有 compact、窄屏普通变体，保留系统字体和已有圆角。

## 保持项与改进

查询：同一份三条虚构资料、两条一页、即时关键词和状态筛选、编号排序、跨页选择、详情 Sheet、只读和空态。未实现导出继续禁用；无批量写入业务，选择数量仅用于展示，不增加处理规则。
表单：同一份两步输入、必填校验、返回保留、第一次提交失败后重试成功、本地模拟。仅增加步骤指示、帮助与提交区域布局。
共同精修：标题与分组、查询状态、选中提示、表单进度、菜单和浮层阴影。既有原型作为来源快照保存在 evidence/source-baseline；未重新定义既有业务规则。
差异轴：标准精修使用实色控制区域；轻玻璃仅顶部控制区、表单操作区、详情底部操作区和菜单启用半透明与模糊。内容、错误、输入、表格、详情正文保持实色。

## 待验证问题与事前标准

1. 同内容、状态、视口下，操作区是否更易区分，且内容可读性不退步？
2. 切换候选后恢复同一场景初态；表单草稿、错误、选择和浮层不继承。
3. 桌面 1440×900、窄屏 390×844 无页面水平溢出；控件高度与字体仍来自当前 Token。
4. 查询/分页/详情、表单错误定位/返回保留/失败重试、键盘菜单/Escape/焦点返回无回归。
5. 减少透明后恢复实色；减少动效后无过渡与动画。模糊不可用时以实色显示。
6. 独立目录断网 file:// 可运行；console 无新增异常。工程验证不代表视觉质量已获用户确认。

## 共同操作脚本

查询正常场景：筛选“季度”→重置筛选→选择 M-001→下一页→返回上一页→从更多菜单打开详情→Escape 返回→切换候选，验证筛选与选择归零。可另选空数据、加载、只读场景。
表单保存失败场景：空名称点下一步，检查焦点→输入名称和说明→下一步→输入负责人→上一步确认保留→再次下一步→确认提交失败→重试提交成功→重置，验证恢复空表单。
材质：滚动页面使内容经过顶部控制区，观察分离程度；查询打开更多菜单；表单观察底部操作区；在页尾评审工具勾选“减少透明效果”。

## 试验参数与选择代价

所有颜色、字号、控件高度、间距和圆角消费已有 Token。玻璃 86% 表面不透明度、模糊使用 spacing 对应值、两级轻阴影仅为本研究的材质参数，集中在 authoring/refinement.css；不是已批准 Token，也未添加到 DESIGN.md。无需背景图片、渐变或新字体。
标准外观视觉稳定、渲染简单；轻玻璃在背景经过时更有层次，但需要额外对比度、降级及渲染性能检查。本轮不测量普遍效率提升，不宣称复刻 Apple 原生 Liquid Glass。没有图片或复杂背景时差异应当克制。
官方原则依据：https://developer.apple.com/design/human-interface-guidelines/materials 与 https://developer.apple.com/videos/play/wwdc2025/219/ 。仅借鉴导航/控制层与内容层分离原则，不接入平台原生 API。

## 选择结论

待当前用户视觉评阅；两个候选均未被宣布为胜出方案。标准仍为本研究的默认入口，轻玻璃为可选对照。是否固化到 DESIGN.md / Skills 留待看过样例后的决定。
