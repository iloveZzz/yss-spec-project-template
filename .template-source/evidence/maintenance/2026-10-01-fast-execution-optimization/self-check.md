# 维护者自检

本轮为 L3 模板维护。只更改核验依赖、模板源测试准备与测试调度，不改变项目实例的批准、Slice 合同、Fresh Verification 或发布规则。自检不能替代下列实际验证结果；最终结果集中记录在验收报告与 checkpoint。

| 关注点 | 实现与验证方式 |
|---|---|
| 已知漏检 | Schema 与 validation phase 进入核心升级清单；business-ticket 源码命中业务票测试；实际替换为全部接受的 Schema 实现，选中的拒绝行为测试必须失败，恢复后通过。 |
| 未知输入 | 保留未知路径升级完整验证；未扩大 selection 裁剪清单。 |
| 原有断言 | 消费测试只替换初始构建步骤，保留原有业务、搬移、篡改、越界断言；构建专项测试仍执行两次独立真实构建。 |
| 产物完整性 | 发布和消费绑定源码摘要、CLI pins、snapshot 与 Node/Python 指纹；逐项核验文件类型、权限与内容，复制后再核验原产物和输入。 |
| 复制隔离 | 每个消费测试独立复制目录；禁止符号链接和特殊文件，不使用硬链接。分别验证修改互不影响与两个进程同时消费。 |
| 调度范围 | 四个精确文件路径允许最多两个 worker；未知文件以及同名但不同路径的文件继续串行；每个 Node test 进程内部使用 test-concurrency=1。 |
| 失败传播 | 实际进程失败、连续失败、恢复、超时、取消和孙进程终止反例；保留非零退出码及 stdout/stderr。 |
| 清理边界 | 准备与测试进程的 TMPDIR/TMP/TEMP 指向本次拥有的目录，测试文件之间隔离；取消后由外层回收。只移除本次 mkdtemp 创建的目录；外部报告目录保留，不清理其他运行的目录。 |
| 单文件入口 | 无共享上下文时直接执行原构建回调；不依赖上次运行留下的产物。 |
| 模式回退 | legacy 保留原准备与串行路径；release 强制 legacy；concurrency=1 向内部传播。默认切换取决于全部验收结果。 |
| 计时与覆盖 | 准备、构建、复制、测试文件、清理分段记录；性能用外层完整进程墙钟时间，并按测试身份和执行次数比较，不仅比较总数。 |

采样期间不在被测副本上编辑文件，不并行运行另一套重型验证。性能重放的限定变更集仅用于同场景比较；交付验证必须使用本轮完整实际改动。首次/重复场景均无跨运行产物缓存，OS 页缓存未受控。

当前验证平台为 macOS ARM64，结果不外推为 Windows/Linux 的性能或进程树终止保证。收益范围仅为声明的完整 fast 内循环，不代表整个 SDD 研发流程等比例提速。

最终结果：冻结副本完整验证通过；正式首次档 21 对通过，69 次有效运行后用户主动停止。重复档及输入变化档未完成，default_mode=legacy；详见 results.md。共享主工作区的并行修改保持原样，未宣称完整集成或可发布。
