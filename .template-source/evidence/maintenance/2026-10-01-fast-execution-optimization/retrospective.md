# 本轮缺陷复盘

本轮先修补可复现的检查依赖漏检，再建立 legacy 基线。Schema 全接受反例必须由被选中的真实测试发现，不能只断言计划里出现某个组名；嵌套 Node 测试进程还需移除 `NODE_TEST_CONTEXT`，避免测试未真正运行却返回成功。

进程监督初版的取消路径会遗留孙进程；修复进程组终止后，实际 wrapper 探针又发现测试自行创建的临时目录残留。最终将准备与每个测试执行的 TMPDIR/TMP/TEMP 放入本次拥有的目录，由外层统一回收，并保留报告目录。两次 RED/GREEN 都归档，早期样本不充当最终版本证据。

完整性检查最初只使用 0777 权限掩码，会漏掉特殊权限位；反例失败后改为 07777。构建计时最初把 spawn 的 null status 当作成功；修复后记录失败、原始退出码及 signal。基准控制器也用真实子进程验证了中断时恢复输入、释放锁和回收子进程。本次人工 SIGTERM 后确认恢复与释放，保持退出码 130，未补写不存在的外层时间。

隔离副本的完整验证曾因缺少 ignored CLI snapshot 及 Vue authoring toolchain 失败。按官方固定版本准备方式补齐环境后重新完整运行通过，未改弱 gate。失败和未执行项留在归档，并在 `superseded-runs.json` 说明原因。

模板运行时的 Fresh Verification 与性能接受是两个结论。首次档达到目标，但用户中止后重复档不足、输入变化档未开始，因此继续保持 legacy 默认。没有把开发阶段 3 对结果或部分正式样本用来代替完整验收；共享主工作区的并行改动也不纳入本轮冻结副本的通过声明。
