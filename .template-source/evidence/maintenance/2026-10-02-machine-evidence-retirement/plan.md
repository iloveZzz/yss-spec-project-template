3. 原件缺失或仍等于本批预期状态时，从归档恢复到原路径；若该路径已被后续任务修改或占用，停止覆盖，保留两份材料并交回主控处理。
4. 消费者迁移失败时回退本批修改并恢复输入。只反向应用本轮精确差异，不回退其它任务的改动、HEAD 或 index。
5. 对恢复材料重新做摘要与读取验证；旧批准保持历史身份，不因恢复而自动成为当前批准。

删除当前文件不会缩小既有 Git 历史。Git 历史重写及永久销毁归档不在本计划范围；如需减少克隆体积，应另行分析分发、协作和可恢复性并取得授权。

## 9. 启动前待落实项与交付物

| 待落实项 | 解决时点 | 处理方式 |
|---|---|---|
| 实施范围授权、执行者与精确写路径 | P0 启动前 | 引用后续用户指令，登记本批边界 |
| 持久归档位置、访问责任与共享获取方式 | P1 写归档前 | 采用可恢复位置；无法取得持续访问时保留原文件 |
| 当前引用、历史消费者及任务是否仍在使用 | 每批移除前 | 执行者调查；未知项延后，不直接转为已退役 |
| 是否改动 Skill、分发或跨仓消费者 | P0 及每次发现新影响时 | 按实际影响重新分级并同步相关来源 |
| 项目保留期或审计要求 | 永久删除或自动到期策略制定前 | 本计划仅完整归档，不制定销毁策略 |

后续实施交付物保持精简：一份批次处置记录、一份可恢复原件归档及成员清单、一份仓内归档索引、必要消费者改动和实际验证日志引用。原始大报告集中保留，不为每个阅读入口再复制。

本轮计划文档的验收只检查事实、数值、引用、执行顺序、停止条件、验证和回滚是否明确。实施结果、收益和发布状态待后续执行产生证据后再填写。
