# 本轮验证返工复盘

## 校准前置检查不足

预检证明了依赖可离线构建，却没有覆盖“构建后写设计说明，再按评测器实际 node -e 方式评分”的完整顺序。结果暴露两项问题：design.md 与 DESIGN.md 在 macOS 碰撞；旧模块入口把缺失 argv 当作文件路径。

修复已落实到 CLI 入口及回归测试，覆盖真实路径、路径别名、node -e、stdin 导入。后续 fixture 说明改为 design-notes.md，构建后写说明再校验当前 DESIGN/Token 的确定性流程已通过。原始 Agent 产物与失败没有修补，按停止条件仅启动一次，不用剩余预算重试。

## 浏览器范围不能由一次 smoke 代替

WebKit 的文件导航与点击焦点行为和 Chromium 不同。仅检查页面出现，未必能发现高密度表格方向键和弹窗焦点返回问题。

现在工作台脚本支持双引擎，两条路线检查完整重载后的名称、负责人、版本与再次保存；实际触发按钮用于恢复焦点。WebKit 无法在 offline=true 下打开 file:// 的环境差异被明确记录，验证采用阻断 HTTP(S) 并断言零请求。200% 缩放通过浏览器原生 API 实测。

## 保持证据边界

原工作区的无关文档尾部空格保留原样，本轮在源码匹配的隔离工作树取得 fast 证据。分发是 working-tree 快照，未声称固定提交可发布。正式六组对照未启动、没有当前用户视觉确认，工程通过不能替代设计收益。
