# 跨仓“提交申请”样板试点（仅模板维护测试）

## 范围与执行

`run-lifecycle-cross-repo-pilot` 在隔离临时目录创建管理、后端、前端三个 `project-instance` 样板。管理样板来自本地 `create-yss-spec` 工作树快照，后端和前端样板分别来自本地专职 Harness CLI。样板写入一个“材料完整可提交，缺项拒绝”的 Spec、Java 服务与测试、Vue 单文件组件与请求逻辑测试。所有批准数据均为 **test-data-only**，不能作为真实产品批准或发布证据。临时仓在结束后清理，命令、退出码、耗时、标准输出和标准错误保存在 `cross-repo-pilot-v4/`。

| 步骤 | 观察值 | 结果 |
|---|---:|---|
| 管理样板初始化 | 956 ms | 通过 |
| 后端样板初始化 | 30,787 ms | 通过 |
| 前端样板初始化 | 37,937 ms | 通过 |
| 后端 `./mvnw -o validate/test/package` | 640 / 1,603 / 1,417 ms | 全部退出码 0；两个业务测试通过 |
| 前端 `pnpm install/test/build` | 3,384 / 236 / 239 ms | 全部退出码 0；两个行为测试及 Vue SFC 编译通过 |
| 同三仓战略/后端交付、导入和前端接收 | 50,012 ms | 10 个场景通过 |

完整观察与源文件 SHA-256 见 `cross-repo-pilot-v4/report.json`。上述耗时含当前机器和依赖缓存条件，不推断效率提升。后端包摘要绑定本次 Maven 生成的 JAR；接收时的版本探针使用测试服务，源提交标识为合成值，因此本试点不是生产部署认证。

## 错误注入与恢复

| 注入 | 拒收位置 | 恢复 |
|---|---|---|
| 修改已批准 Spec 字节但保留旧摘要 | 战略交付导出 | 恢复 Spec 原字节后导出通过。 |
| 错误包摘要或增添未登记包文件 | 前端接收核验、包开启 | 恢复原接收数据或原包后通过。 |
| 缺失已完成的前端接收记录 | 前端输入核验、合同编译与实现入口 | 补齐调和、预检、成功/失败用例和接收记录后通过；输入就绪仍不授予实现批准。 |
| 将 OpenAPI 批准绑定改为旧摘要 | 后端交付检查 | 恢复原批准记录后导出通过。 |

测试还覆盖旧接收版本、真实版本探针不符、测试数据摘要不符、服务不可用与缺少场景。`scripts/verify-frontend-delivery-scenarios` 保存了逐项断言和运行轨迹；状态服务文件使用原子替换，避免并行验证时读到半写入 JSON。

Java 样板是刻意缩小的行为样本，真实 YSS Spring 平台兼容、真实后端部署、浏览器视觉还原和正式 Slice 批准不由此证明。生成的前端 Harness 自带的通用 `node --test` 会扫到一个缺失 `yss-technical-design` 夹具的历史测试；本试点仅执行新增切片的 `pnpm test` 指向 `src/submit.test.js`。该历史问题保留为分发待办，不计入切片通过证据。
