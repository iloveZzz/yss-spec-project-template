# 影响面分诊与流程裁剪

先核验当前身份和唯一日常 / 正式路径政策；正式路径与模板维护再按变更规模、实际影响选择最近可信阶段。它减少未触发的工作，保留已经命中的条件强制门禁；目录或文件存在不能证明阶段通过。

## 判定顺序

1. 读取当前治理仓根 `yss-project.yaml` 与唯一 `CONTEXT.md`；身份异常停止受影响写入并检查迁移，只读调查不创建阶段资产。
2. 项目实例按 `request_triage.delivery_path` 与支持的 `yss lifecycle route` 核验同一任务、实际实现仓及完整基线；缺事实先调查。
3. 合格日常任务只更新同一记录；已有正式绑定、新风险或政策排除影响恢复 `governed`。
4. 正式任务及模板维护再判断变更规模和 UI、API、数据、后端、前端、跨仓库、高风险影响，核验可复用批准、证据与依赖，从最近可信阶段恢复。

注册表中的 `artifact.impact-assessment` 每次变更触发，记录受影响仓库、资产、风险和接入阶段。生命周期结构以注册表为准，裁剪指南解释入口与证据边界，见 [[仓库身份与路由]] 与 [[条件强制门禁]]。

## 正式路径与模板维护的裁剪矩阵

| 类型 | 默认入口 | 必需工作 |
|---|---|---|
| 模板源维护 | 影响面分析 | 修改单一事实源、必要投影同步、分级证据与 Fresh Verification |
| 小改动 | 入口分诊 | 影响面、主 tracker 同步、本轮验证；未触发时不生成 Spec、架构、原型或切片 |
| 中等变更 | 最近可信 Spec / 架构阶段 | Spec、功能架构、适用工程审查、父 Ticket 和切片 |
| 全新产品 / 模块 | Plan | Plan、Spec、产品总体设计、功能架构、适用设计 / 契约审查、父 Ticket 和切片 |
| 高风险变更 | 既有冻结基线 | Spec Delta、架构 / 数据 / 工程审查、契约复核、切片和回滚设计 |

未命中的 UI、数据或 API 门禁记录 `not-applicable` 及原因，不生成空文档。跨仓库变化绑定实现仓库、分支、CI、验证命令、发布顺序和回滚点。模板源只维护可复用资产，产品 Spec、原型、OpenAPI 和运行时代码按模板维护边界处理，见 [[模板维护流程]]。

## 风险与专业检查

安全 / 权限不单独分诊。需求或冻结资产未明确改变相关行为时，不额外登记或解释安全不适用；明确改变时写入普通业务与工程资产，按实际 UI、API、Backend、Data、High-risk 影响触发现有检查。SQL、DDL、迁移及上传 / 下载按数据或 API 影响路由，不自动升级安全专项。

专业能力和补充只读 Skill 从角色表及检查策略编译。普通功能默认一个推进负责人和一个独立审查者；角色表的候选能力不是全员签字名单。无依赖检查可并行，相邻检查可组合执行并逐项留结论，实施者不能替代独立审查者。

首轮覆盖全部适用检查。修复后比较旧候选与当前候选，定位受影响结论、行为和直接 / 传递依赖，再定向复审并重新绑定证据。未受影响项需有可读取比较依据；摘要变化、UI 影响或 `new_impacts` 不自动触发全轴复审，未知影响先调查并阻断依赖事项。

已有用户授权明确覆盖当前范围时，按用户决定协议核验延续。业务范围、关键规则、验收标准、契约承诺、授权边界、风险接受或对外承诺实质变化时，展示可审阅差异后取得新决定。缺专业结论由主控派发并等待，验证失败先修复或重新路由；仅缺真实决定、新授权或不可自主取得的必要输入时暂停依赖工作。

合格日常任务记录范围、验收、工程 / 基线、适用 Skills、实际测试、独立审查与回滚，跨会话更新同一 Ticket/PR；不为日常任务补阶段 checkpoint。只读问答、状态查询和定位只返回来源、结论及缺口。

## 回写与恢复

正式路径的集中 checkpoint 记录范围、变更文件、受影响仓库、实际验证命令和结果、阻塞、审查点、Ticket 状态及下一步。项目实例批准或流转前核验 `context_reconciliation`，缺权威上下文只能 `blocked` 或 `reroute`。

质量标准在工程基线定义一次，由合同、执行结果、审查和发布核验复用。命中高风险时保留在途反证，缺反证或残余风险未处理仍阻断。延期 seam 写风险、责任人、后续 Ticket、验证计划和目标版本或发布日期。完成结论见 [[Fresh验证与独立审查]]。
