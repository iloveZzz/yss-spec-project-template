# 模板发布门禁与验证

模板验证入口按维护影响面与交付边界选择。快速检查支持日常实现，完整 `scripts/verify-template` 支持 main 与发布前核验，Fresh Verification 是结论依据。

内循环运行 `scripts/verify-template-fast`；PR 运行 `scripts/verify-template-candidate`；main 与正式发布前运行不可裁剪的 `scripts/verify-template`。快速入口按 Git 影响面选择检查，未映射路径或核心验证资产变化时 fail-safe 升级为完整验证，来源仍为当前工作树，用于 `implementation-ready`。显式 candidate / release 入口要求已提交来源。candidate 的名称不表示必须冻结候选或派发独立审查。

共享技能变更先在 `.agents/skills` 修改权威内容，使用 `maintaining-skills`，运行 `scripts/sync-skills` 与 `scripts/update-skill-lock`。验证核对仓库身份与流程资产、投影和完整技能树哈希、过时路径与用语、流程压力场景、Markdown 相对链接、示例 OpenAPI 解析以及 Git diff 空白错误。

L1/L2/L3 由维护强度策略计算。L3 日常采用维护者自检，正式发布另执行完整门禁；不会仅因等级而新增候选冻结或正式独立审查。缺验证、机器失败或关键证据缺失仍阻断。新维护 checkpoint 使用 schema v2，保留分级理由、实际验证和目标状态。

日常维护默认达到 `implementation-ready`。自检路径 `release-ready` 使用 release profile，并绑定本轮 `scripts/verify-template` 的 final-release-verification；这一状态不代表实际发布授权。外部 `create-yss-spec` 固定版本集成和兼容性未闭合时，不得声称可发布。

公开 Skill 发布另按 Skills 维护说明完成单向导出：同步 canonical 投影、更新锁文件、完整验证、导出并检查、独立审查，再向 `yss-spec-dev-skills` 提交人工 PR。Git 提交、推送及发布仍按用户授权执行。

模板维护候选保存在当前工作区的仓外 `maintenance:candidates/<id>/`，原子捕获为 `candidate-manifest.yaml`、`candidate.bin` 与 `tracked.diff`。新 manifest schema v2 声明 `reference_base: bundle` 及工作区身份，stream/diff 使用包内相对引用，保持原候选字节流和摘要。维护验证记录的 `maintenance:` 引用绑定 `evidence_digest`；项目实例与 Slice 的外部路径权限不随之扩展。

入口定位见 [[仓库身份与路由]]；维护过程见 [[模板维护流程]]；验证和独立审查边界见 [[Fresh验证与独立审查]]。
