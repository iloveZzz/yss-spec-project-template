# 切片实现合同

Slice Implementation Contract 将冻结上游依据、实施范围、Skill、工作单元和验证要求绑定到当前切片。实现合同编译器生成草案，生命周期批准并持久化后，正式切片才能消费。

本合同用于正式 `governed` 切片。已由唯一政策和支持的 CLI 核验为 `daily` 的任务使用同一 Ticket/PR 的验收、工程基线、适用 Skills、实际测试、独立审查和回滚证据，不先编译正式 Slice；该分支不豁免已有正式合同，也不改变正式就绪校验器。

## 版本与批准

新切片使用 Slice v3，将上游依据、实施范围、冻结 Skill、工作单元及验证要求单点保存，仅展开适用专项约束；v2 保留历史读取。Backend 子合同仍承担额外强约束。

正式切片只消费已批准、已持久化且当前的合同。实现合同编译器只起草，不批准、不设置 `ready-for-agent`、不宣布完成；`gate.slice-contract-approved` 的合同批准也不代替就绪计算。

`check.slice-ready-for-agent` 绑定合同批准和 Fresh Verification 证据。切片拆分以已正式化业务 Ticket、冻结 Spec、设计、契约、当前实现仓库准备及阻塞关系为输入，生命周期复算后才允许进入 `ready-for-agent`。

## 实施输入与工作范围

实现前登记实际仓库、项目根、分支、CI、验证命令与回滚点，再编译最小 Skill 集与当前合同。正式工作单元输入当前合同和允许写路径，输出前后端实现、TDD 与 YSS Skill Execution Result。

UI 切片在实现就绪前须有已校验的前端实现计划，实现后补还原验证，覆盖截图或视觉回归、状态交互、console warning 及实际 `pnpm` 退出码。前端验证优先 `pnpm`，后端优先项目根 `./mvnw`；缺少时记录受控例外与实际命令。

新工程脚手架仅在架构决策已确认且当前、Project Scaffold Contract schema v4 已持久化并获批准时无交互运行，只生成机械骨架。既有工程不能重选或覆盖，架构转换单独立项；业务切片继续受自己的批准合同约束。

## 偏离与结果核验

路径越界、证据缺失、验证未执行、`drift`、`violation` 或 `new_impacts` 时停止实现并重新路由。`seam-deferred` 登记风险、责任人、后续 Ticket、验证计划和目标版本或发布日期。

YSS Skill Execution Result 记录合同版本、变更文件、证据、实际验证、延期 seam、偏离和新增影响。实现者自报 `implemented` 需要合同编译器、生命周期和独立 Reviewer 复核；完成结论仍以当前 Fresh Verification 为依据。
