# 切片实现合同

Slice Implementation Contract 是阶段 7 进入实现前的实现合同：由 `yss-implementation-contract-compiler` 根据冻结资产和 [[垂直切片Ticket]] 编译草案，再由生命周期编排器批准并持久化。正式垂直切片必须消费已批准、已持久化且版本当前的合同。实现合同编译器 只生成草案，不得输出 `approved`、`ready-for-agent` 或 `completed`。

实现合同编译器 先读 [[Spec基线]]、切片 Ticket、需求冻结、适用的原型确认、[[OpenAPI契约]] Freeze 或无 API 影响、系统 / 数据架构、Design Review、Build Architecture Checklist、实现仓库和验证命令。输入缺失、未批准或 `stale` 时输出 `blocked`，交回 `yss-product-lifecycle`。编译结果只能是 `draft`、`blocked` 或 `ready-for-lifecycle-review`，见 [[YSS路由与合同编译]] 与 [[Ticket与流程状态]]。

合同根为 schema v2，含 `readiness`、`resolution`、Common、Frontend、Backend、Contract、Cross-repo 子合同及 `work_units`。`resolution` 同时冻结 `required_capabilities`、`required_skills`、`recipe_ids`、显式 conditions、原因链和 Registry/Compiler digest；任一 digest 漂移都必须标记 `stale`。Common 收影响面、项目根、允许写路径、证据、验证命令、人审点和重编译触发器。Frontend 在适用时绑定批准原型与状态矩阵；Contract 记录 API Freeze 或 no-impact；Cross-repo 记录参与仓库、交付顺序、集成验证和回滚顺序。Backend 必须逐项填写 `component_impacts`、`application_boundary`、`transaction_boundary`、`persistence_strategy`、`seam_deferred` 等字段；端到端后端切片必须包含 Application。

`scaffold_status=required` 时，先由 实现合同编译器 按脚手架 schema 编译 `controlled-generation` 合同草案，经生命周期编排器批准并持久化后再生成机械骨架。脚手架合同在 实现合同编译器 阶段只能是 `draft` / `ready-for-lifecycle-review` / `blocked`，只覆盖业务代码前的工程骨架，不能替代随后的 Slice Implementation Contract。骨架完成后业务行为回到 实现合同编译器，按 `behavior-tdd` 逐单元实现；打印命令或单项 `./mvnw validate` 不能代替合同批准。

路径越界、证据缺失、未执行验证、`drift`、`violation` 或 `new_impacts` 时停止实现并重新编译。专项 skill 必须消费当前批准合同并返回 `YSS Skill Execution Result` v2；编译器只验证结果与合同的一致性，最终阶段状态与 `ready-for-agent` 仍由生命周期持有。`seam-deferred` 只能显式记录风险、责任人、后续 Ticket、验证计划和目标版本或发布日期。
