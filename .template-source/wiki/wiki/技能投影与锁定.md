# 技能投影与锁定

共享 Skill 的权威内容位于 `.agents/skills`。各 Agent root 中的同名技能由此生成，投影不作为并列来源，也不分别手工维护。

`skills-lock.json` 持有技能清单、来源、上游哈希、有效目录树哈希和投影目标。`upstreamHash` 记录可追溯的未适配上游内容，`effectiveHash` 记录当前完整技能目录树，`targets` 记录应投影的 Agent roots。平台专属技能保留在所属 root，并进入锁文件的 `platform` 分组。锁定技能名包括 `maintaining-skills`、`llm-wiki` 与 `code-review`；技能名派生摘录不携带目录树 hash 或来源版本。

技能注册表与锁文件各持一类事实：active 注册表负责身份、capability、任务模式、类型化依赖、分层、别名与默认可发现性；锁文件负责来源和投影完整性。生命周期与实现合同编译器只消费通过注册表校验的 canonical 技能。

新增共享技能先显式登记 `scripts/update-skill-lock --add=<skill-name>`；平台专属技能用 `--add-platform=<root>:<skill-name>`。修改权威内容后运行 `scripts/sync-skills` 与 `scripts/update-skill-lock`，再分别用 `--check` 核验。工作区偶然出现的未跟踪目录不会自动进入发布清单。投影允许指向权威目录的符号链接或完整同步副本，检查器验证目标或目录哈希。

专职 Profile 通过 `.template-source/profile-skill-sync.json` 登记跨仓消费关系。先 `--dry-run` 再 `--apply`，CI 使用 `--check`；未登记入口、不同于预期的未提交目标改动、来源漂移或无法重放的补丁会阻断写入。Design 保留原同步与其四个上游技能的所有权；Backend / Frontend 的 `materialization: generated` 只在本地生成完整共享技能、投影与 Frontend 平台包，不直接编辑生成目录。

模板维护以 `--update-source-lock` 显式更新两端来源锁；有相关未提交源码时锁为 `working-tree`，仅用于本地维护。独立准备及正式组合构建只接受 `committed`，绑定固定 Spec 来源和可重放适配；缺来源、错误提交、漂移、越界、用户修改或未知占用均拒绝覆盖，失败恢复本次触及文件，相同输入重放不写入。

受影响子项目同步投影与锁文件；普通本地 Skill 交付不自行升级 CLI 或扩大为发布任务。涉及正式 CLI 分发时再按固定来源合同重建快照，验证期间保持同一快照输入。固定交付先共享源、再两端来源锁、再 CLI 来源锁与完整资产，最后更新父仓 gitlink；提交、推送及发布按各自授权执行。

公开发布通过 `yss-public-skills.json` 和导出器生成 `iloveZzz/yss-spec-dev-skills` 的单向投影。共享内容的维护按 [[模板维护流程]]，验证入口见 [[模板发布门禁与验证]]。
