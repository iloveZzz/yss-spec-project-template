# 模板总览

YSS Spec Project Template 是 Matt Pocock Engineering Skills × YSS × OpenAPI 驱动的研发文档模板。它默认作为 Harness / 研发管理仓库，保存流程、契约模板、Agent skills 和协作约定；前后端运行时代码默认放在已登记的独立实现仓库。

## 从身份开始

每次任务先读取根 `yss-project.yaml`。当前声明为 `schema_version: 1`、`repository_mode: template-source`，因此走 [[模板维护流程]]，不生成具体产品的 Spec、原型、OpenAPI 或垂直切片 Ticket。产品实例声明为 `project-instance`，先按当前主控合同的唯一 `request_triage.delivery_path` 政策与支持的 CLI 核验 `daily / governed / needs-info`，再按相应路径推进，见 [[产品研发生命周期]]。身份缺失、非法或 schema 不支持时停止受影响写入并进行迁移检查；细则见 [[仓库身份与路由]]。

进入独立子仓后由子仓入口解释本地身份、工具与流程，共同授权、用户工作保护和允许写范围继续有效。CLI 源码仓与 `skillUtils` 工具包按已声明身份维护，不补造产品治理文件。只读调查不创建 Ticket、checkpoint、批准或启动回归。

## 当前资产的职责

| 资产 | 用途 |
|---|---|
| `AGENTS.md` | Agent 入口、硬门禁和禁止事项 |
| `CONTEXT.md` | 每仓唯一的业务词汇表与流程语汇 |
| `.template-spec/` | 可复用流程、门禁、契约和文档模板 |
| `.template-source/` | 模板源专属现行维护与分发资产，不进入实例；运行历史存仓外 |
| `.agents/skills/` | 共享 Skill 的权威内容 |
| `.codex/`、`.cursor/`、`.pi/` | Skill 投影与平台专属能力 |
| `scripts/` | 合同与流程验证工具 |
| `docs/` | 项目实例按需创建的 Plan、Spec、设计、Ticket 与交付证据 |

生命周期结构事实由 `.template-spec/process/lifecycle-registry.yaml` 定义；Markdown 地图只是派生阅读视图。影响面和维护强度由裁剪指南及 `maintenance-intensity.yaml` 定义。Skill 来源、版本、投影和路由由 `skills-lock.json` 与技能注册表定义。阅读入口只引用这些权威资产，不能另起一套规则。

根 `CONTEXT.md` 只沉淀已确认的稳定语言。业务术语使用 PascalCase `英文标识`，其稳定身份为 `<ContextId>/<EnglishIdentifier>`；流程术语的英文标识填 `—`。模板源不放虚构产品业务行，见 [[Agent入口规则]]。

## 修改与验证

共享 Skill 在 `.agents/skills` 修改后，通过 `scripts/sync-skills` 与 `scripts/update-skill-lock` 更新投影和锁文件，见 [[技能投影与锁定]]。模板维护先按 L1 / L2 判定影响，内循环使用 `scripts/verify-template-fast`；未知路径、缺输入映射或非法依赖先修正计划，不自动全量。日常仅完成变化行为及直接 / 传递消费者的必要检查，报告 `limited`；PR 候选使用 `scripts/verify-template-candidate --base <完整 SHA>`，main 集成与正式发布另按现行覆盖、baseline、资格与回退合同运行 `scripts/verify-template`，见 [[模板发布门禁与验证]]。

运行时代码按 [[实现仓库与跨仓库契约]] 接入。用户明确选择 Harness 内布局时，默认使用 `apps/backend/<project>`、`apps/frontend/<project>`；其他真实工程布局按当前项目根和批准写范围登记。子模块须核验真实 gitlink；目录名称本身不授予写权限，容器根不能代替具体工程根。前端验证优先 `pnpm`，后端优先项目根 `./mvnw`。

[[LLM Wiki]] 是源材料的阅读层，不能替代权威源。本仓 Wiki 位于 `.template-source/wiki`，不属于产品实例分发面；维护日志、审查候选与历史证据存到仓外运行目录。CLI 选型、初始化及升级从用户手册进入；GitHub 能力、npm 发布版本和实例快照分别核对，不凭仓库内容推定已发布。
