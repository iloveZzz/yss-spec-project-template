# 仓库身份与路由

仓库身份以根 `yss-project.yaml` 为准。Agent 先核验身份，再选择模板维护或产品研发路线；文件缺失、schema 不支持或模式非法时停止受影响写入并进入迁移检查，不根据目录、Git remote 或占位符猜测。

## 两条入口

| 身份 | 路线与边界 |
|---|---|
| `template-source` | 按影响面维护可复用模板、工具与治理资产；不生成具体产品的 Spec、原型、OpenAPI 或垂直切片 Ticket |
| `project-instance` | 先核验当前任务的日常 / 正式路径资格；合格日常任务维护同一 Ticket/PR，正式任务从最近可信阶段恢复并执行命中的工作单元和门禁 |

当前根清单是 `schema_version: 1`、`repository_mode: template-source`。本仓默认走 [[模板维护流程]]；产品实例按最近可信阶段消费 [[影响面分诊与流程裁剪]] 与 [[产品研发生命周期]]。Wiki 是阅读视图，当前规则仍以根入口及其引用的事实来源为准。

路径以当前治理仓根解释。独立子仓以本地入口解释工具和身份，共同授权、用户工作保护及允许写范围继续有效；CLI 源码仓和 `skillUtils` 工具包不补造 `yss-project.yaml` 或产品 `CONTEXT.md`。只读调查不建立阶段资产。

项目实例使用支持能力的 `yss lifecycle route`，绑定同一任务、实际实现仓和完整基线 SHA。政策启用且资格已证明的 Spec、Backend、Frontend 可用 `daily`；旧 CLI、缺政策、Profile 未启用或资格未证明时先调查。已有正式任务不得因标签变更降级，无关正式资产也不阻断合格日常任务。

## 统一 CLI 的身份与资产合同

Spec、Design、Backend、Frontend 使用同一固定 `yss` 二进制，三个 Agent 模板源继续维护。运行前核验实际二进制 SHA-256、统一 CLI 版本 / 源码 SHA、协议、模板提交、Bundle 和 manifest 摘要；旧 CLI 版本只表示历史迁移基线。验证脚本显式使用固定二进制及来源目录，不从 PATH 或旧 gitlink 猜版本。

`init` 不带 `--plan` 时直接初始化；审阅路线使用 `--plan --out <新计划>`，之后用 `--apply --plan-file <计划>` 应用。普通已有工程使用 `attach`，原生实例升级使用 `sync`，两者默认预演。旧实例先显式生成 `migrate plan`，再通过 `migrate apply` 写入，不能删除身份文件后伪装成普通工程接管。

原生身份与受管基线保存在 `.yss.json`。保存计划绑定实际项目根、Profile、协议、固定 Bundle 来源、输入、变更字节及权限。唯一根 `CONTEXT.md`、业务资产、用户 `.github`、Git HEAD/index/gitlink、文件类型与权限受保护；用户修改或不能证明来源的旧基线进入冲突，不自动覆盖。项目实现仓挂载仍须符合 [[Agent入口规则]]。

## 同步、插件绑定与恢复

目标模板来自固定二进制内的 Bundle；apply 不查询 `latest`，不执行计划提供的外部脚本。公开 `bundle export` 可导出完整资产及 manifest。资源补装用 `assets ensure` / `skills ensure` 的保存计划与显式应用；必要能力的 `UNPORTED`、输入漂移或缺失证据阻断对应切换。

后端交付插件绑定 `spec`，产品设计插件绑定 `design`。已绑定旧实例使用对应插件 `project-migration-plan` / `project-migration-apply`；原生来源升级使用 `project-upgrade-plan` / `project-upgrade-apply`，使身份、基线与 binding 纳入同一事务。直接 `yss sync` 更换来源而缺少匹配的新 binding 返回 `BINDING_REQUIRED`；既有身份与 binding 失配返回 `BINDING_CONFLICT`。同一来源的资源补装保护原 binding 的字节和权限。

原生事务位于 `.yss/transactions/`。普通 `recover` / `rollback` 默认只读，各加 `--apply` 才恢复 / 回退；`migrate recover` / `migrate rollback` 是显式写入子命令，不要求 `--apply`。旧未完成事务以 `LEGACY_INTERRUPTED` 拒绝迁移，先由对应仓外固定旧执行器恢复。apply 后、首次 rollback 前发生用户修改时返回 `CONCURRENT`，保留现场；成功回退后的重复回退保持幂等。

迁移后核验身份、Profile、Context、受管基线、Skill 锁与投影、插件 binding 和适用实例治理，再按相同选项重新规划以确认无重复变更。成功须同时观察实际退出 0、`status=ok`、`code=OK`；局部升级成功不等于产品批准或发行就绪。真实业务工程先在隔离副本验证。固定源码、适用平台发行资格、完整模板门禁及发行清单闭合后，提交、推送、发布、npm 弃用与旧仓归档仍分别按授权执行；历史版本保留，不执行 unpublish。

## 历史合同的适用边界

`create-yss-spec-repository-mode-contract.md` 已标为 historical / superseded，下文旧包参数、旧 metadata、`--force` / `--prune` 与旧发布步骤属于历史执行器合同，不能作为统一 `yss` 的操作说明。历史原文继续用于旧实例恢复的来源核对；现行命令与保护规则以统一指南和模板实例升级协议为准。
