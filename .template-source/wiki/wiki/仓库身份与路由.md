# 仓库身份与路由

仓库身份只由根目录 `yss-project.yaml` 声明。该清单是 CLI 与 Agent 共享的稳定契约，只含 `schema_version` 与 `repository_mode`，不写入项目名称、团队规模或 Tracker。`repository_mode` 仅有两个合法值：`template-source`（模板源仓库）与 `project-instance`（模板实例仓库）。

文件缺失、schema 版本不支持或模式值非法时，必须停止路由并执行迁移检查；不得根据目录、Git 远程或占位符猜测身份。当前仓库 live 值为 `schema_version: 1`、`repository_mode: template-source`，因此默认走 [[模板维护流程]]，不按具体产品生成 Spec、原型、OpenAPI 或垂直切片 Ticket。总览见 [[模板总览]]。

`template-source` 按「影响面 → 单一事实来源 → 投影 / 派生资产 → 分级证据」维护，发布阻断门禁是 `scripts/verify-template`（见 [[模板发布门禁与验证]]）。`project-instance` 先用 `docs/process/harness-process-tailoring.md` 判定变更类型、影响面和最近可信阶段（见 [[影响面分诊与流程裁剪]]），再按 `docs/process/lifecycle-registry.yaml` 执行命中的工作单元和条件门禁，进入 [[产品研发生命周期]]。

外部 `create-yss-spec` 创建或接管的产品仓库必须写入 `repository_mode: project-instance`；合法 `template-source` 可在 attach 时转换为 `project-instance`，合法 `project-instance` 保留并校验，非法身份在写入前阻断。CLI 快照等于 Git 跟踪树减去根目录 `.template-source/`；源仓库 LLM Wiki 编译树与模板维护审查留在治理区，不进入新项目。CLI 只管理 manifest 声明的研发管理资产，不接管前后端运行时代码、业务目录、用户文件或 `.git`。

当前仓库默认是研发管理仓库，运行时代码优先位于已登记的独立实现仓库（见 [[实现仓库与跨仓库契约]]）。只有用户明确选择本仓库承载实现代码时，才使用 `apps/backend/<project>/` 或 `apps/frontend/<project>/`；`app/backend/`、`app/frontend/` 及其子路径禁止作为工程输出。身份判定是每个任务的第一步，后续硬门禁见 [[Agent入口规则]]。
