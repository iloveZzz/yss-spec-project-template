# 仓库身份与路由

仓库身份以根 `yss-project.yaml` 为准。Agent 先核验身份，再选择模板维护或产品研发路线；文件缺失、schema 不支持或模式非法时停止并进入迁移检查，不根据目录、Git remote 或占位符猜测。

## 两条入口

| 身份 | 路线与边界 |
|---|---|
| `template-source` | 按影响面维护可复用模板、工具与治理资产；不生成具体产品的 Spec、原型、OpenAPI 或垂直切片 Ticket |
| `project-instance` | 按影响面与最近可信阶段进入产品研发生命周期，执行命中的工作单元和门禁 |

当前根清单是 `schema_version: 1`、`repository_mode: template-source`。本仓默认走 [[模板维护流程]]；产品实例先读裁剪指南，再由生命周期编排器消费注册表，见 [[影响面分诊与流程裁剪]] 与 [[产品研发生命周期]]。

## CLI 的身份与资产合同

`create-yss-spec` 初始化或接管产品仓库时，写入 `schema_version: 1`、`repository_mode: project-instance`。`attach` 必须显式选择 dry-run 或 apply；已经有 `.yss-template.json` 时拒绝接管并提示 `sync`。合法模板源可转换为实例，合法实例保留并校验，非法身份在写入前阻断。

CLI 只管理 manifest 声明的研发管理资产。运行时代码、业务目录、用户文件、`.git`，以及 `.gitmodules`、gitlink 和已挂载的实现仓工作树，都属于用户资产。`attach` / `sync` 不得创建、覆盖或删除这些实现仓资产。

模板快照由显式分发 allowlist 构建。`.template-source/**`、源仓库 ADR、源仓库 Wiki 编译树和其他未登记资源不进入快照；新增顶层文件未命中 allowlist 时也不进入。README 仅在初始化时生成，随后由项目维护；根 `.gitignore` 持续同步只更新公共规则区。快照以完整 40 位 `templateCommit` 绑定来源。

## 同步、冲突与恢复

`sync` 使用 CLI 包内快照。“最新”指所执行的已发布 CLI 所携带的快照，不在运行时拉取模板仓库。普通同步新增缺失资产、更新未被本地修改的受管文件，并报告冲突和退出分发的文件。`--force` 只能处理受管 conflict，不能绕过 unsafe 或迁移冲突。

`sync --prune` 是显式清理入口：只删除内容仍等于旧 baseline 且仍由模板拥有的退出分发文件，删除前备份。存在本地修改、缺 baseline、路径类型异常或属于项目的文件必须保留并报告。普通同步不删除这些文件。

初始化及成功同步后，目标实例必须实际执行：

```bash
scripts/sync-skills --check
scripts/update-skill-lock --check
scripts/verify-project-instance
```

任一同步后门禁失败，回滚本次文件变更并保持旧 metadata。模板与 CLI 的共同验证、固定版本集成和发布证据未闭合，或来源仍为浮动 ref / WORKTREE 时，不能宣称整体可发布；发布动作仍按授权执行。Agent 的后续写权限与实现合同见 [[Agent入口规则]]。
