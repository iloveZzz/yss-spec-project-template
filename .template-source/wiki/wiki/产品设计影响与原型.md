# 产品设计影响与原型

UI 影响不等于产品设计影响。UI 影响是会改变用户可见页面、导航、交互流程、状态呈现或权限体验的功能影响；纯后端、API、批处理或数据变更不自动构成 UI 影响。产品设计影响更窄：只有 UI 变化触及主流程、导航、权限体验、异常 / 恢复、状态流转或 API 反推时，才需要页面流、状态矩阵和原型校准。

文案、token、颜色、间距和无行为变化的孤立视觉修复属于 UI 影响，但不自动构成产品设计影响。未命中时按 [[影响面分诊与流程裁剪]] 记录 `not-applicable` 及原因，不生成空的设计包。[[Spec基线]] 模板也约定：只有存在 UI 影响时，才强制低保真页面草图、状态矩阵、高保真 HTML 原型和用户确认；否则同样记 `not-applicable`。两条判定要同时看，不能把「有一点可见变化」直接升级成完整产品设计流程。

命中产品设计影响时，生命周期在 `stage.product-design` 产出交互说明和低保真原型；存在状态流转、异常或恢复时再补状态矩阵；需要视觉与交互校准时再做高保真 HTML 原型。`work-unit.prototype-design` 的完成条件是原型评审、高保真验证和用户确认门禁均通过。对应门禁为 `gate.prototype-reviewed`、`gate.prototype-verified`、`gate.user-confirmation`，证据分别是独立评审结论、`antd` CLI 与浏览器验证、用户确认记录，见 [[条件强制门禁]]。

高保真 HTML 原型是低保真评审通过后、在浏览器中审查真实视觉密度、交互状态和页面流的产品设计资产。它不等于生产前端，也不替代 OpenAPI、Spec 校准或垂直切片。UI 设计、原型、组件或主题先走 `yss-design-system`，再走 `yss-prototype-stage`；Codex 再路由 `product-design:index`，其他 Agent 交付等价合同资产。产出前后用 `antd` CLI 记录 Ant Design v6 与浏览器验证事实，技能入口见 [[YSS工程技能体系]]。`high-fidelity-html-prototype` 已退役，不再作为 Router alias、默认发现入口或独立物理技能；迁移路径见 `docs/agents/skill-migrations.md`，不得创建同名兼容目录。

Visual Baseline Contract 是为生产前端还原冻结页面、视口、交互状态、参考图像和允许差异的可验收合同。它不是单张原型截图，也不是绝对像素匹配；每条基线必须能定位到同一视口和同一状态再复验。UI 影响切片在提升 `ready-for-agent` 前还要有前端实现还原计划，合并或发布前做还原验证，见 [[垂直切片Ticket]] 与 [[Fresh验证与独立审查]]。校准结论回写 Spec，并作为 [[OpenAPI契约]] Draft 的交互输入；有 UI 且用户未确认前，不得进入 OpenAPI Draft 评审。整段工作挂在 [[产品研发生命周期]]，不越过需求冻结直接写生产页面。
