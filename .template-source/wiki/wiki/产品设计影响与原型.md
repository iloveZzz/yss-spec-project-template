# 产品设计影响与原型

UI 影响是否需要产品设计流程，由主流程、导航、权限体验、异常或恢复、状态流转及 API 反推的风险决定。命中产品设计影响时，用低保真、状态矩阵与 H1/H2 原型回答当前设计问题，并把生产还原要求交接给实现阶段。

## 影响面判断

UI 影响包括用户可见页面、导航、交互流程、状态呈现和权限体验的变化；纯后端、API、批处理或数据变更不自动构成 UI 影响。文案、token、颜色、间距和无行为变化的孤立视觉修复虽有 UI 影响，也不自动构成产品设计影响。

产品设计影响触及主流程、导航、权限体验、异常或恢复、状态流转或 API 反推，需要页面流、状态矩阵和原型校准。未命中的门禁记录带原因的 `not-applicable`，不生成空文档。

## 原型工作单元

`yss-prototype-stage` 持有产品设计合同，调用设计系统、独立评审以及 H1/H2 适配器；原型不使用 `yss-ui`。真实组件事实用于前端实现计划、已批准实现和还原验证。

`work-unit.prototype-design-v2` 输入 Spec、产品设计影响和状态矩阵，输出交互说明、低保真、状态矩阵、H1/H2 原型交付物、Design QA、档位验证和前端实现交接事项；同步校准业务 Ticket 并保留稳定 ID。

低保真评审通过后按当前决策风险选择 H1 `visual-review` 或 H2 `flow-review`，并在浏览器复验。新原型交付物验证采用 schema v4，包含共同证据、Visual Baseline Bundle、浏览器、Design QA、无障碍及档位验证。

原型交付物是产品设计资产，生产前端、OpenAPI、Spec 校准和垂直切片继续各自履行合同。真实 YSS/AntDV 组件验证属于实现计划与还原验证，不另设第三种原型档位。

原型的持久反馈、偏好与决定写入生成的目标原型仓 `AGENTS.md` 或当前已授权设计资产，并遵守目标写范围。修改共享原型模板或运行时 Skill 投影须有明确模板维护任务，用户对当前原型的反馈不会自动扩大到共享源。

## 批准与生产交接

`check.prototype-reviewed` 核验低保真页面、流程、状态或 API 反推的独立评审；`check.prototype-verified` 核验 H1/H2 原型的视觉或流程校准。`gate.product-design-approved` 汇总这两项检查，核验原批准或授权延续；新增体验取舍由用户决定。

Visual Baseline Contract 冻结生产还原的页面、视口、交互状态、参考图像和允许差异；每条基线要能在同一视口和状态复验。UI 切片进入 `ready-for-agent` 前需要已校验的前端实现计划，实现后还须截图或视觉回归、状态交互、console warning 和实际 `pnpm` 退出码。

需求基线见 [[Spec基线]]，API 行为见 [[OpenAPI契约]]，实现交接见 [[切片实现合同]]；UI 还原结果进入 [[Fresh验证与独立审查]]。
