# YSS Spec 技能入口

本目录安装了所选 YSS 技能及必要参考资源。使用简体中文，按用户当前目标和已有授权选择技能，不要求启用治理流程或补建项目文档。

- 技能位于 .agents/skills，宿主副本由安装记录管理；已有项目规则与业务约束继续适用。
- 需要了解默认技能、选择条件及跨 Profile 衔接时，按需读取 [技能地图](.template-spec/agents/profile-skills.md)；普通任务直接选择相关技能。
- Spec 默认包含 `handoff`：交接要点与提示词由 `yss-product-lifecycle` 整理；明确要求通过 PR/MR 交付选定规格、原型及交互说明时使用 `handoff`，按对应动作授权执行。
- 后端工程命令优先 ./mvnw，前端优先 pnpm。构建、测试和审查按当前任务需要开展，不作为统一前置。
- 保留权限、业务输入校验、错误处理和文件保护；不覆盖无关用户修改，不把子模块当普通目录。
- 使用 CLI 实际帮助中的安装与同步能力；支持本版时用 sync 更新、--dry-run 预览，skills ensure 补装指定技能。
- 提交、推送、部署和发布使用对应授权；说明实际结果与未执行事项，不声明未经验证的成功。

Spec 完整交付只包含业务规格、高保真交互原型及交互说明；核心操作可操作、纯展示可用高保真静态稿、无 UI 用业务逻辑或状态原型，覆盖范围按风险选择。低保真草稿不单独算完整交付。普通查询和局部修订只完成当前范围。

业务票仅在明确要求拆票时作为规格组织形式输出，不是第四类必交付物，Spec 的 to-tickets 只拆业务票。“确认 Spec”“准备交给研发”不自动拆票或生成物理库表、DDL/索引、生产 API 契约与实现切片。业务规则及有来源的技术事实可以表达，原型模拟不构成生产承诺。

免除流程审批不扩大任务范围；用户明确要求技术设计或开发时，按授权和可用研发能力作为研发任务承接并分别说明成果，不强制换仓、安装 profile 或新增审批。

`project` 与 `skills` 默认安装同一组 16 个 Spec 能力入口。预装不改变显式调用政策或外部动作授权；`implement`、`code-review` 可按需补装，不属于 Spec 默认集合。
