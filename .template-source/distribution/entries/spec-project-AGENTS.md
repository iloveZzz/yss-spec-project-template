# YSS Spec 项目入口

使用简体中文。按用户目标与已有授权直接开展工作，按需读取相关需求及根 CONTEXT.md。

- 优先使用适用的 YSS 技能；前端工程命令优先 pnpm，后端工程命令优先 ./mvnw。
- 技能位于 .agents/skills，规格与产品设计参考位于 .template-spec；宿主技能副本由安装记录管理。
- 不要求生命周期路由、阶段批准、checkpoint、检查计划或测试报告。免除流程审批不扩大当前任务范围；检查按实际需要开展。
- 保留权限、业务输入校验、错误处理与用户文件保护。提交、推送和发布使用对应授权。
- 使用已安装 CLI 的实际帮助。支持本版接口时，sync 更新文件，--dry-run 仅预览；doctor 查看差异，recover 处理未完成文件事务。
- 不覆盖无关工作。交付说明实际改动与未执行事项，不把生成或编译结果当作未执行的测试结果。

完整 Spec 只交付业务规格、高保真交互原型及交互说明，三类内容可共用文件。核心 UI 操作可操作，纯展示可用高保真静态稿，无 UI 用业务逻辑或状态原型；低保真草稿不单独算完整交付。普通查询、局部修订和模板维护只完成当前范围。

业务票仅在明确要求拆票时作为规格组织形式输出，不是第四类必交付物。“确认 Spec”“继续完善规格”“准备交给研发”不自动拆票，也不触发技术设计。Spec 的 to-tickets 只负责业务票。

保留业务概念、信息含义、唯一性等规则及有来源的技术事实；原型可使用演示代码与模拟数据，不将其升级为物理库表、DDL/索引、生产 API 契约、技术选型或实现切片。用户明确要求技术设计或开发时，按授权与可用研发能力作为研发任务承接并分别说明成果，不强制换仓、安装 profile 或新增审批。
