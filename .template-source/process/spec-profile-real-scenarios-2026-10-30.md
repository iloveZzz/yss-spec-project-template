## 简单规则：字段映射覆盖率

来源：[企业数据模型协作工作台 Issue #1](https://github.com/iloveZzz/yss-spec-project-template/issues/1)，摘取 FR-007 和覆盖率验收。提交评审整体覆盖率不得低于 80%；发布整体覆盖率不得低于 85%，且 P0 必填字段覆盖率不得低于 95%。整体覆盖率是范围内有效映射逻辑字段数除以范围内逻辑字段总数；P0 覆盖率按 P0 必填字段单独计算。

选择文字与边界表：本次只检查阈值及业务结果，数值和阻断规则可直接表述，没有发现必须操作界面才能回答的问题。整体工作台其他交互不因该局部结论而被判定无需设计。

| 实际范围举例 | 操作 | 应观察的结果 |
|---|---|---|
| 有效映射 79/100 | 提交评审 | 79% 低于 80%，阻断并说明原因 |
| 有效映射 80/100 | 提交评审 | 满足覆盖率条件；其他独立阻断项仍须检查 |
| 整体 84/100、P0 95/100 | 发布 | 整体不足 85%，阻断 |
| 整体 85/100、P0 94/100 | 发布 | P0 不足 95%，阻断 |
| 整体 85/100、P0 95/100 | 发布 | 满足两项覆盖率条件；不代表其他发布条件通过 |

原文使用“不低于”，因此阈值相等满足该项条件。零分母、精度及舍入方式在所读取片段中没有足够依据，不能自行写死；应向业务确认或继续查证。上述是 AI 基于真实需求完成的表达选择与例子检查，不是对业务系统的运行测试。

## 复杂交互：Excel 导入

来源：[Excel 导入物理模型草稿 Issue #4](https://github.com/iloveZzz/yss-spec-project-template/issues/4)。涉及上传、预览、问题处理、确认应用、取消、返回及重试；其中上传只产生预览，阻断项不得写入草稿，警告需用户确认。适合先用流程/状态表整理，再针对取消、返回、错误恢复等确有操作不确定性的部分使用局部可交互原型，而非为所有页面强制原型。

| 观察节点 | 行为与风险检查 |
|---|---|
| 上传和预览 | 只展示将生成的内容及问题；未确认时不能写入草稿 |
| 存在阻断项 | 显示问题和修正入口，不能应用 |
| 仅有警告 | 展示警告并取得明确确认后才能继续 |
| 取消或返回 | 明确是否保留预览及草稿；取消后不能沿用旧确认继续应用 |
| 失败及重试 | 显示失败并允许适用的重试；避免误以为已应用或丢失已有草稿 |

仅凭文字不能证明用户是否理解警告确认、返回与取消的区别或恢复路径；应实际操作局部原型并记录参与者、步骤与结果。此处尚未构建或运行原型，不能报告关键交互已验证。已有 Issue 的技术切片与 API 要求是历史下游内容，不作为新 Spec 的前置条件。

## 审批内容变化：证据与待验证项

Issue #1 文本含 `prototype_review: approved`，但其评论为空，未找到可还原当时内容的快照及原始人工批准；不能将其当作可复用的批准。历史标签和文档状态也不能替代批准。

若实际任务明确要求审批，应先展示可还原的当前规格并记录真实用户对明确范围的决定，再对两个真实修订验证：纯文字等义修正复用有效批准；关键阈值、覆盖范围或验收发生实质变化时，旧批准仅覆盖旧版，当前稿标明受影响部分待审批。上述是待执行的预期，并非已经发生的审批或变更。不可由 AI 模拟用户同意。

实际验收需要可运行宿主、明确的真实任务范围和可还原的原始人工批准与后续真实修改；没有这些条件时只能保留本次分析探针结论。
