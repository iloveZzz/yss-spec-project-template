# Matt 技能适配完整收口设计

本设计解决当前 YSS 独立技能与治理要求交叉、适配说明过期、退役技能数据依赖 JS 写法，以及分发资源和效果证据难以解释的问题。保留 template 与 CLI 已有架构，分批修正实际消费者，不重新建设技能发现、生命周期或评测系统。

用户已在本会话选择“完整收口，分批实施”。这一选择确认设计范围和组织方式；本文仍为待审阅设计，不代表具体技术方案已经批准，也不授权实现、提交、推送、发布或更新用户实例。本文是唯一跨仓主设计，CLI 不另写一份重复的流程规范。仓库忽略 docs/superpowers/，因此沿用模板源合同目录保存并登记索引；不修改忽略规则或强制提交文档。

## 1. 目标与成功条件

读者是维护 template、CLI 和技能分发的实施者。完成后应出现以下可观察行为：

| 编号 | 场景与目标行为 |
|---|---|
| R1 | 用户已明确授权、验收清楚的独立实现，在调用 TDD 后继续使用当前公开接口和验收，不重新要求生命周期资格、Tracker、Slice 或 checkpoint |
| R2 | 已有 daily、standard 或正式任务继续消费其当前合同；技能调用、文件就绪和普通草稿都不授予正式资格 |
| R3 | 同一技能入口、适配说明、必要参考、Spec/Backend 分发副本对适用条件表达一致 |
| R4 | 验证说明能解释所选测试可以发现什么、没有覆盖什么；人为制造失败时能证明修改实际生效 |
| R5 | 新 CLI 从结构化合同读取退役技能 ID，模板内部 JS 重构不再改变新合同下的识别结果；有效兼容别名、跨仓引用与本地退役物理技能明确区分；旧来源仍可解释 |
| R6 | 每个随独立技能安装的外部参考都有当前消费者或来源追溯依据；删除声明或文件不会造成缺引用、隐式治理或覆盖用户修改 |
| R7 | 后续 Matt 思想的采用状态可追溯；真实 Agent 选择与执行效果有观察记录，不用文件数、删行数或结构测试冒充提效 |

这些编号仅用于本文需求与验收对应，不是新增生命周期 ID、阶段或门禁。

不以固定比例减少文件、Token 或耗时作为本轮承诺。若资源仍有必要消费者，保留是正确结果；若没有可信的两侧运行数据，效果结论保持未证实。

### 2.2 本轮要解决的具体缺口

1. implement 的独立入口无需治理，行为变更却调用 TDD；TDD 目前只说明 daily 与 governed 的测试边界前提，缺少 standalone 和 standard 的清晰解释。
2. Matt 集成说明仍把 model-invoked 技能限定在生命周期工作单元，并以正式证据协议概括研究。该说明仍由 adaptationRef 和分发集合消费，存在指令歧义；尚未证明必然导致模型阻断。
3. CLI 的 retiredSkillIDs 用正则读取模板 JS 中的集合字面量和追加语句，数据合同依赖源码写法。
4. 固定模板中 Spec 初始技能外部参考路径并集为 270，Backend 为 186；Spec code-review 为 233，yss-research 为 238。这是 skillReferences 与引用组展开后的去重计数，不含技能内部文件和投影，也不代表运行时读取量。正式条件参考和真实脚本依赖交织，需要逐项解释。
5. 现有任务样例主要是执行者路线核对；完整的独立模型选择证据、确认次数和耗时数据仍不足。不能据此声明新设计已经提高效率。

本轮研究后新合入的安装 bootstrap、固定发行输入校验、升级来源匹配和目标对齐行为属于基线，不重做或撤销。

## 3. 方案比较与已选方向

| 方案 | 范围与收益 | 代价与限制 | 决定 |
|---|---|---|---|
| 聚焦修正 | 修 TDD/适配说明，补测试与诊断细节 | 跨仓数据耦合、资源归属和效果证据仍分散 | 未选 |
| 完整收口、分批实施 | 一份设计覆盖六项改进，分别交付技能、数据合同、资源和验证 | 需要保持模板与 CLI 的兼容顺序 | 用户已选择 |
| 全量同步 Matt 或替换既有体系 | 接近上游当前文本和组织方式 | 改变默认值、Context、授权与历史治理语义，缺乏对应收益证据 | 不进入实施方案 |

下文具体字段、兼容策略和样例组织是基于现有代码提出的技术设计，不冒充用户逐项指定。实施计划可以决定内部函数拆分和测试摆放，但不得改变这些可观察行为。

## 4. 职责与不变约束

| 责任 | 所有者 | 本轮处理 |
|---|---|---|
| 普通技能的方法、必要输入和条件加载 | template 的 canonical .agents/skills | 修正入口与必要参考，按实际调用链验证 |
| 阶段、身份、授权续用、正式合同 | template 现行治理资产 | 保持语义，只在命中分支消费 |
| 技能来源、退役数据、分发选择 | template 现有注册与分发合同 | 收敛数据来源，保持明确的版本与兼容路径 |

| 发现、自动选择、显式调用 | 实际宿主与调用元数据 | 不将文件投影正确推断为宿主已发现或已执行 |

以下行为不变：init/attach 默认 governed；skills 仍需显式选择；sync 保留已登记安装方式；转换安装方式仍走显式 migrate；已有保存计划不重新套默认值；Context 不改名；Spec/Backend 是本轮支持范围。

不增加第四种安装/交付模式、本地发现命令、任务状态库、审批表、动态资源依赖引擎或通用 JS 解析器。不调整 resolve 的 ready/missing/blocked、JSON envelope 或退出码含义，不把查询退出 0 当作就绪或批准。

提交、推送、发布、安装和真实外部写入继续按实际授权执行。独立复核依实际要求，不按检查轴强制安排人数。只编辑 canonical 技能，再通过既有生成器更新投影与锁。

## 5. 技能执行链与规则说明

### 5.1 TDD 按已经确定的任务分支消费输入

TDD 不承担身份判断或生命周期路由，不另建资格计算；消费调用者已经确定的分支、当前任务和验收。

| 分支 | 测试边界与验收来源 | 需要停止的情况 |
|---|---|---|
| standalone | 当前用户请求/Issue/Spec 中已有的验收、实际公开接口和工程标准 | 检查后仍缺影响行为的决定，或新范围超出授权；只停依赖该决定的工作 |
| daily | 同一 Ticket/PR 的验收、工程基线和现行路由结果 | 当前政策不支持、必要证据缺失或新影响被排除；回现有任务处理 |
| standard | 当前 Spec-lite、同一任务和仍有效的真实用户决定 | 相关依据改变、决定撤回或当前性无法核验；沿原协议处理 |
| governed 正式实现 | 当前批准且有效的 Slice 合同、公开边界和适用决定 | 合同失效、范围变化或必需输入缺失；不改走独立任务 |

standalone 的已知公开接口与已给验收可以直接形成测试，不要求用户再次确认内部 seam 名称。需要设计新接口且涉及真实业务取舍时，先调查，再集中询问缺失决定。允许技术性细节由实施者在已授权范围内决定并说明依据。

保持测试经公开接口验证行为、预期值来自独立依据、一次完成一条有意义的反馈循环。必要的范围内重构仍由实施者在绿色测试下完成；冻结审查者保持只读。

入口只保留上述分支选择和共通原则，治理细则使用当前拥有规则的参考，不在 TDD 中复制整套生命周期协议。不得把“仅缺本技能的说明”解释为已有正式任务可以绕过合同。

### 5.2 修正适配说明与路由中的重复规则

MATT-POCOCK-ENGINEERING-SKILLS.md 调整为适配导航和来源说明：区分普通、日常交付、正式治理与模板维护；说明 user-invoked/model-invoked 与执行授权是不同维度；指向当前实际入口，不重复维护执行协议。

研究条目明确默认聊天或用户要求的一份报告；只有显式审计研究或现有正式流程才消费 governed-research。审查条目明确无独立 Spec 时使用已有验收，确无依据则报告对应轴不可评价。

路由在要执行某技能，或要解释其前提和例外时读取当前实际入口；推荐列表可以用于定位，不独立决定跳过前提。仅列出可选入口不强制读取全部技能。显式调用限制不变，不能因读取源码就自动调用 user-invoked 技能。

检查本批触及参考中的过期上游名称和不可用入口；有现行本地所有者时改为该所有者，不重新引入上游 setup 或另一套通用审查流程。

### 5.3 测试覆盖说明与人为变异证据

对本次选择的关键测试边界，在当前任务或 PR 说明其能发现的错误和重要遗漏；不要求每个简单断言填写表格，也不新增证据 schema。缺少运行、环境不适用与已通过必须分开。

仅当实施者人为修改代码或 fixture 来制造失败时，比较修改前后字节，确认目标修改确实生效，并确认红灯来自目标症状。已有真实失败不为满足此条另造 mutation；不在真实用户工作树 reset、还原或覆盖原文件。隔离 fixture 的原始与修改后内容可作为证明。

诊断保留当前简单缺陷的直接路径；不增加固定假设数量、每轮重新确认或无关压力/性能实验。没有能覆盖真实问题的测试边界时，记录缺口，不用浅层测试冒充完整回归。

## 6. 退役技能的结构化合同

### 6.1 数据所有权

在现有 .template-spec/agents/yss-skill-registry.yaml 的 retirement_contract 内定义新版退役数据，不新建平行注册表。根技能注册表仍保持 schema_version 3；retirement_contract 使用独立 schema_version 2，新增 retired_ids 字符串数组。retired_id_source 固定为 .template-spec/agents/yss-skill-registry.yaml#/retirement_contract/retired_ids，仅作为核验标识，不是动态加载地址。保留现有 stages、deprecated_new_use、cleanup_statuses、hard_retirement_tombstone 和 failure_codes 字段及语义，扫描政策的来源说明同步更新。

根 registry 的 retired_ids 是本轮退役判断的唯一人工事实源。首次迁移保持旧查询和模板退役校验的完整有效集合；不能只抄 OBSOLETE 第一段而丢失追加 ID 或历史循环中的有效条目。按设计基线静态复算，根为 99 个唯一 ID：60 个初始项、17 个循环追加项、5 个单独追加项、17 个前端退役项；两处字符串拼接还原为 to-prd 和 to-issues。实施时以完整集合等价断言验证，数量相同不能代替集合相同。

Backend 当前为 82 项，本设计建议由根派生完整 99 项。新增的 17 个前端 ID 作为本地物理技能不得重新安装；已声明的跨仓引用按第 6.2 节单独解释，不一概返回退役错误。这些技能不会因此变为 Backend 可安装能力。既有受管文件仍保留或按明确迁移规则处理，不自动删除。此统一是设计建议，需随本文审阅，不宣称旧 Backend 已有相同行为。

校验要求：数组必须显式存在且元素全为字符串，ID 满足现有 ^[a-z0-9][a-z0-9-]*$ 规则且不重复；不得与本仓可安装的 canonical ID 冲突，包括共享、平台和实际指向本仓 canonical 内容的 external 项。source=cross-repo-reference 的外部引用与有效兼容 alias 可以同名，但不能据此重新分发退役物理目录。语法上允许空数组表达明确的空集合，但本次迁移必须保持上述完整 99 项，不能清空。集合内容和兼容投影必须一致。null、未知版本、未知子合同字段、错误类型或非法冲突都属于合同错误，不等同于“没有退役项”。排序只用于稳定输出，不作为运行时集合语义。

CLI 复用 internal/schema.Parse 的严格 YAML 读取能力，保留真实标量类型并拒绝重复键、alias、anchor 与显式 tag。新增严格字段校验只针对 retirement_contract，不能对仅声明部分注册表字段的旧 skillRegistry 直接启用全局 KnownFields，误拒其他合法字段。

### 6.2 消费与兼容

新 CLI 对 retirement_contract v2 直接读取结构化数据；声明 v2 但格式错误时拒绝相关技能解析/选择，不回退 JS，不从用户工程或网络寻找替代数据。v1 且来源标识仍为 scripts/lib/skill-supply-chain.mjs#OBSOLETE 的历史固定来源继续使用受限旧解析器，保留其集合和读取错误语义，不扩大支持的 JS 语法。子合同存在但为空、畸形或版本未知时拒绝。

本轮明确修正新消费者的兼容别名解析顺序，适用于其读取到的 v1/v2 来源，不改写历史记录。当前 root/Backend 都声明 research → yss-research，但 CLI 和部分 JS 入口在归一化前检查退役，而生命周期就绪入口先归一化。采用 registry 已声明的兼容意图：唯一别名先映射到本仓存在、未退役、未 deprecated 的 canonical，再做当前使用资格检查。别名不能指向别名、形成环、绕过 deprecated 或造成多目标歧义。未命中有效别名的原始退役 ID 仍拒绝；扫描物理目录和锁时始终用原始物理 ID，因此 .agents/skills/research 仍属退役目录。

对 source=cross-repo-reference 的记录，生命周期就绪查询保留 external-skill-required 等现有外部依赖语义，不按本地物理退役误判。CLI 的本地安装/resolve 不把这类外部能力纳入内置可安装集合，维持非内置选择的拒绝边界；查询诊断应明确其是外部引用。Backend 的 yss-ui、yss-formily、yss-frontend-scaffold-generator 三项属于此类。不得为通过无交集检查删掉这些引用。

withoutRetiredSkills 对可解析的兼容选择保留其 canonical 目标，继续走既有规范化和安装验证，不先按 alias 的旧物理名称丢弃。没有有效映射的已退役选择才按原机制移出目标选择，既有文件仍受独立删除规则保护。旧二进制保留原有 alias 行为；“能解析新生成集合”不表示获得此修正。

没有 retirement_contract 的已支持历史输入保持原调用者行为：resolve/ensure 仍沿用旧 reader 的成功或错误结果；迁移的 withoutRetiredSkills 在历史来源确实没有 JS 合同时保留原选择，不凭空推定退役。没有子合同不代表允许绕过原 registry、来源或 Bundle 校验。v2 必须在“缺 JS 就保留选择”的旧探针之前识别；兼容 JS 缺失不能掩盖 v2 数据或让畸形 v2 变成无合同。退役 ID 与当前树/锁冲突必须被校验拒绝，不允许通过现有“树仍存在就保留”分支掩盖冲突。

旧 CLI 不认识 nested 合同版本，不能假定它会在装载新模板时统一拒绝。因此兼容期保留旧 CLI 能读取的 JS 字面量形状，由模板生成链从 retired_ids 单向生成并检查；它是生成投影，不是第二份手工事实源。新 CLI 不依赖该投影；旧 CLI 的受支持范围由实际兼容用例证明。

必须区分：旧 CLI 代码装配新 Bundle 时，旧 reader 应能读取生成字面量；原旧二进制操作新来源实例时，仍会核对其自身固定 Bundle 与实例来源，可能返回 cli-snapshot-mismatch。兼容投影不取消该保护，也不证明旧二进制能管理新来源实例。若无兼容字面量，旧 reader 会在相关选择操作报合同缺失，而不是整个 Bundle 必然无法加载。

模板 Node 消费者与 CLI 对同一固定来源必须得到同一个集合。兼容文件保留原路径，使用一个带生成标记的 export const OBSOLETE = new Set(JSON 数组) 块；不使用字符串拼接或块外手工 add。首次迁移由实施补丁建立标记，之后生成器只更新该块。缺失/重复标记、手改生成块或生成期间输入漂移均拒绝覆盖。

复用 scripts/sync-skills 和 scripts/update-skill-lock 的现有生成链，在使用退役集合过滤前同步该块；--check 只比较、不写入。生成后同次操作必须使用新集合，不能因 Node 静态 import 缓存继续使用旧 Set。采用动态导入或更新同一导出集合的内部实现由实施者决定。

Backend 在 manage-profile-skills.mjs 的 composeProfileTree 之前，参照既有 daily-delivery 派生方式同步 overlay 的 retirement_contract 和兼容 JS 块，再组合与验证。不能只改临时组合树；其他 Backend 注册字段和模块逻辑不覆盖。普通查询不触发生成。

本批必须覆盖 supply-chain 的同步/锁、skill-registry、skill-retirement 扫描、skill-governance、lifecycle-context-query-core、backend skills audit，以及 CLI resolveSkillSelection 和 withoutRetiredSkills 两条消费链。仅修查询函数不算完成。

### 6.3 切换顺序

先交付能读 v1/v2 的 CLI 和模板校验能力，再由模板切换到 v2 并生成兼容投影，最后以真实固定模板来源装配 CLI Bundle。中间批次可以验证源码和本地候选，不能声称发行已携带新合同。

本轮不删除旧来源读取能力，也不确定其退役日期。只有另行确认受支持旧消费者已退出后，才能删除兼容投影或旧解析器。来源、摘要、Bundle/metadata、保存计划与授权保护继续沿用现有体系；不因新增嵌套数据版本重定义公共 CLI 协议。

## 7. 独立技能资源边界

### 7.1 本轮采用完整静态闭包

继续使用已有 skillReferences、referenceGroups 和 skillReferenceGroups。CLI 安装整棵已选技能目录以及声明的外部资源，不新增按运行时分支动态下载、条件资源字段或不同安装方式下偷偷改写技能正文的机制。

资源整理覆盖 Spec 初始八项、Backend 初始 implement/code-review，以及本轮实际触及的 TDD、诊断和对应专业依赖。对每个外部参考登记直接消费者、传递依赖或来源追溯用途；合并共享记录，复用现有适配说明/任务记录，不创建长期人工并行清单。

| 类别 | 处理规则 |
|---|---|
| 普通入口真正需要的通用说明 | 已有技能内所有者则引用它；仅一处使用且无治理语义的材料可内聚到所属技能，修复所有实际消费者 |
| 条件正式流程所需材料 | 当前共享技能仍可进入该分支时保留完整闭包，并明确加载条件；不能只因普通任务不读就删掉 |
| 可执行脚本的 import、schema、模板、数据文件 | 按执行链保留，修改消费者后才调整声明；不能用文档链接扫描代替脚本依赖检查 |
| adaptationRef 等来源依据 | 仍有锁或安装消费者时保留；不能只因正文没有链接就认定无用 |
| 无当前消费者的残留或重复材料 | 核实所有 Profile、公开导出和兼容消费者后移除；记录影响与迁移处理 |
| 无法证明用途的资源 | 保留并记录未决原因，不算已经精简，也不放宽完整性检查 |

Markdown 链接、行内路径、代码 import 和机器引用分别检查。不得把链接改成代码字体或删除链接来绕过闭包验证。无需为了减少目录数复制一套治理工具或把全部规则塞回 SKILL.md。

### 7.2 同步与删除

资源声明减少不等于用户磁盘立即减少。当前 sync 对缺少精确迁移规则的旧外部资源可能保留为 retired-preserved；技能树内文件删除也可能形成冲突。保持这些保护，不把旧资源全部自动删除。

确需回收受管残留时，使用现有迁移规则与保存计划：明确适用来源、删除目标及原基线；用户修改、占用、路径异常或规划后漂移仍按当前合同拒绝或要求决议。支持现有 keep-local 的位置继续允许保留；保留不能伪装成已删除。历史批准、任务、Context 与非受管用户文件不在清理范围。

本轮分别报告新安装目标集合、既有实例计划中的变化、应用后的实际残留。没有获得真实实例操作授权时只使用隔离 fixture 验证，不自动 sync 用户工程。

### 7.3 导出、投影与交付

canonical 修改通过现有生成器覆盖 Spec/Backend 组合、已声明运行时投影和锁。公开技能导出继续验证技能内链接、路径、来源和必需脚本；未包含治理的公开包不能声称具有正式治理执行能力。

现有 --skill 导出只复制所选技能，不自动补齐兄弟技能。对本轮触及的公开技能维持既有支持集合：已支持的单技能导出必须继续成功；依赖兄弟参考且此前不支持独立导出的入口继续明确拒绝，不因此扩大公开承诺。组合包须包含声明的必需兄弟技能。不得复制第二份共用写作规范或放宽出界/断链检查来让导出通过。

同一资源同时服务普通和正式消费者时保留单一正文来源。本轮不以 270/186 的下降作为验收条件；验收要求是分类有依据、普通路径无强制治理、所声明能力的完整闭包仍可用、用户文件保护不退化。

## 8. 上游采用记录与效果验证

### 8.1 采用记录

在现有 Matt 适配说明增加精简采用表：审阅的上游固定提交、变更主题、本地采纳/适配/不采纳、实际消费者、验证或未覆盖原因。原始 sourceRevision/upstreamHash 保持真实；选择性借鉴不改称整体同步。采用表只记录差异，执行规则仍由技能与现行合同拥有。

本轮采用测试能力/盲区说明、条件 mutation 生效检查和实际入口优先原则。保留 governed 默认、CONTEXT.md、条件独立复核和本地授权；不复制固定多 Agent、每次 seam 人工确认、自动提交/重置工作树或上游全部新入口。

### 8.2 行为场景

复用 skills-agent-eval.py 与现有说明。冻结设计基线和候选来源，在同一实际可用宿主、模型配置、工具及 fixture 下比较。首次范围以 Codex 为主，不把其结果扩展为其他宿主通过；其他宿主只核验本轮受影响的文件与元数据一致性，运行效果未测则保留 unknown。

| 场景 | 关键观察与验收 |
|---|---|
| 明确调用 implement，验收清楚的独立行为修复 | 已具备必要技能的无治理 fixture 能经 TDD 完成真实失败/修复验证；不创建治理资产，不重复索取已有决定 |
| 独立任务缺业务规则 | 先检查已有材料，只询问真正缺失的决定；不猜验收，不启动受影响写入 |
| 无独立 Spec 的审查 | 从用户请求取得验收；确无依据时明确对应轴不可评价；保持只读 |
| 无 Tracker 的普通研究 | 使用已提供的一手材料作答，不启动 setup、证据包或正式 Ticket |
| 相邻非触发请求 | 普通说明/格式任务不被引导到 TDD、正式研究或生命周期初始化 |
| 已有 daily/standard 且确认仍有效 | 复用当前依据；撤回或相关输入变化后按原协议处理，不从技能中发放资格 |
| 显式正式任务缺必要合同 | 阻断依赖动作，不创建替代普通稿绕过；有合法输入时仍加载适用正式参考 |
| 中断后的恢复 | 先读取现有改动、命令状态和结果；不重放未知副作用，不覆盖用户新增内容 |

测试显式入口时给出真实明确调用，不要求宿主隐式选择 user-invoked 技能。无身份 fixture 必须确实无身份；不能误用 runner 的默认来源复制，把治理文件带进去后声称测了独立工程。fixture 声明必要来源与允许写范围，缺源文件属于环境/场景失败，不归因于技能。

对本批新能力另外设置局部工程用例：人为变异确实生效、无效变异不能被当作有效红灯；退役合同的新旧兼容与畸形拒绝；资源引用完整性和同步保护。这些确定性边界不要求全部交给模型判断。

### 8.3 证据与完成含义

保留基线与候选的来源摘要、实际配置、工具轨迹、输出和失败；自动断言与语义复核分开。记录可核验的重复询问、额外治理资产、错误路由、关键参考读取、实际验收完成情况；耗时和 Token 仅取运行时实际提供值，缺失不填零。

执行计划确定有限场景批次、次数和预算，沿用 runner 的预算账本与退出语义。环境失败或预算耗尽记 incomplete；修复后只复跑受影响场景并保留原失败，不挑选最好样本。首次代表性场景用于定位行为差异，不作统计性的通用提效承诺。

关键行为场景失败必须分析并修正受影响设计/实现；无法运行则可以报告局部工程完成，但不能宣布整体行为验收完成。文档存在、metadata 正确和 Go 测试通过都不能替代模型行为证据；模型完成也不能替代工程测试或发行验收。
