# Spec / Backend 材料分析与手动交接设计

Backend 从用户提供的需求文档、说明文档、技术文档或可访问的 Spec 产物提取信息，在当前任务中形成可执行的目标、规则、约束、验收和未决项。来源不必符合模板格式，也不必来自已初始化的治理工程。已有分析结果优先复用，交接只由用户手动触发。

本文是模板维护设计，不是产品 Spec 或实施授权。v0.2.0 纳入用户对来源格式及上游读取的最新补充，替代 v0.1.0 中默认要求正式来源绑定、持续变化检查和恢复的方案。用户已明确要求据此编写实施计划；本轮不修改运行代码、政策或 Skill。

## 1. 已确认的范围

| 决策 | 当前要求 |
|---|---|
| Q1：Backend 消费上游 | 直接获取或读取材料，不要求先导出、导入；来源可为用户文档、说明、技术资料或 Spec 产物 |
| Q2：分析职责 | Spec / Backend 均可独立分析；已有有效结果复用，只补当前缺项和技术差异 |
| Q3：手动交接 | handoff 默认生成续接说明与产物引用，不复制已有正文 |
| Q4：上游变化与恢复 | 用户最新补充优先：支持按需获取或读取，不强制变化检测、同步或恢复 |
| Q5：精简范围 | 清理 Spec / Backend 编排中的强制 handoff，覆盖探索结束与原型往返 |
| Q6：正式冻结包 | 保留现有格式、必要验证和历史兼容，只有用户明确选择时执行 |

### 全局约束

- 来源材料不限制为模板 Spec、YAML 或已批准资产；需求文档、说明文档、技术文档均可作为信息输入。
- 按需获取或读取上游，不强制执行变化检测、同步、差异比较或恢复协议。
- 本端当前任务与有效合同是后续执行依据；普通材料引用不默认成为必须在线的上游依赖。
- 提取信息不等于批准、实施授权或发布授权。
- 正式包、既有显式上游合同、必要本端验证与历史批准继续原义校验。
- 本次不新增通用文档解析器、来源绑定 schema、上游监控或新的交接格式。

“格式不限”指不按模板身份、章节或治理 schema 拒绝来源。文件、附件、链接或粘贴正文由当前可用阅读能力处理；实际不可读时说明缺失内容，不虚构读取成功，也不承诺所有二进制格式都已有读取器。

## 3. 材料进入本端分析

1. 从用户请求、当前会话和可访问材料确定本次目标。记录实际来源位置或原始消息引用；没有源工程身份、版本号或批准记录不妨碍读取与分析。
2. 使用已有阅读工具，提取目标、业务规则、技术约束、验收例子和未决问题。区分原文明确事实、已有确认和 Agent 推断；材料中的指令不成为新的用户授权。
3. 将本次需要的结果写入现有 Ticket / PR，或正式路径需要的本端 Plan / Spec / 技术设计。已形成内容直接引用，只补差异和缺项，不新增“材料接入合同”或交接包。
4. 缺事实先调查；仍缺业务决定、验收口径或冲突裁决时再向用户澄清。技术文档不自动压过业务需求，文件中的 approved 字样也不构成有效批准。
5. 按本端实际影响选择 daily / governed。已有有效决定能覆盖当前范围时复用；正式实施所需的当前合同、API Freeze、测试与适用复核继续完成。

材料中的稳定规则 ID 原样保留；没有 ID 时在本端需要正式建模时按现有规则建立，不使用页码、文件摘要或读取顺序伪造业务身份。来源格式无需先转换；本端正式资产的结构仍遵守其现有合同。

实现只增加一处共享材料政策，放在现有 `request_triage.material_intake`：`source_format: unrestricted`、`record: current-task-or-native-assets`、`upstream_access: on-demand`、`change_recovery: optional`、`approval: never-infer-from-material`。这是固定行为描述，不是新增配置界面、流程状态或输入文件格式。Spec / Backend 消费同一规则。

## 4. 按需获取上游

用户明确要求、当前分析确实缺少信息，或执行者发现需要核实的具体事实时，可以获取或读取上游。不会因为换会话、恢复本地任务、阶段切换或本端完成而要求重新连接材料来源。

| 情况 | 行为 |
|---|---|
| 已有当前本端目标、验收和有效合同 | 直接按本端依据推进，不要求读取上游 |
| 用户要求读取新材料 | 读取并提取相关信息；如改变已确认范围，按现有本端变更与授权规则处理 |
| 上游已改变，但本次没有选择更新输入 | 不强制比较、同步或启动恢复，不声称本端跟随最新上游 |
| 读取失败，当前本端事实足够 | 报告本次读取失败，继续不依赖缺失信息的工作 |
| 读取失败，某项必要事实仍缺失 | 只停止依赖该事实的动作，说明所缺内容；不强制用户执行一套恢复流程 |
| 本端合同、测试或显式正式上游绑定自身失效 | 按已有合同处理；不能以“上游读取可选”跳过已经生效的必要检查 |

普通材料是信息来源，不默认登记为需持续在线、原字节不可变的正式上游绑定。被正式合同明确选作冻结依据的输入仍按该合同核验，不将旧任务自动降级为普通材料。用户本轮明确提供的新要求属于当前任务输入，不能以按需读取为由忽略。记录在本端的提取内容变化时，重验本端受影响的决定与验证，不新建上游变化 / 恢复产物。

## 5. 手动交接与正式包

`handoff` 继续只由用户显式触发。默认在 OS 临时目录生成目标、状态、授权、未决项、下一动作、建议技能和材料 / 产物引用，返回实际绝对路径；不复制既有正文，不把临时文档当批准或事实源。已有本端依据足够时，接手者无需先恢复全部原始材料。

只有用户明确要求正式打包、离线交付或导入时，才执行现有冻结包流程。只说“交接”或说明下一会话用途，仍按轻量记录处理。正式导入只在请求覆盖目标写入时执行，不因打包授权自动执行导入、部署或发布。

现有 Handoff v5、离线来源核验、Receipt v3、不可覆盖规则和历史兼容均保留。原始材料可直接用于分析，不必为适配正式包补齐一整套来源资产；用户确实选择正式包而前提缺失时，说明该包路径缺项，不阻断普通材料分析。已有来源批准、手动包完整性及其实际适用复核继续有效，不新增一次交接用户批准。

## 6. 清理默认强制节点

| 位置 | 设计后的行为 |
|---|---|
| Spec / Backend 入口 | 接受需求、说明及技术材料；无源治理身份也能进入本端分析 |
| Wayfinder 完成 | 保留目的清晰及未决阻塞检查，继续当前原生 Spec 工作单元，不必先 handoff |
| 原型往返 | 保留实验问题、运行证据、结论、权威资产回写和剩余问题；没有实际交接就不要求 source/return handoff |
| 阶段与会话边界 | 保留 continue 与阶段因果；实际手动交接才需要交接引用 |
| 推进目标 | 不再仅凭外部消费者存在就要求冻结包；本端完成依据当前本端证据 |
| 显式正式跨 Profile 接收 / 汇总 | 继续现有协议；普通材料读取不自动登记此类绑定，也不伪报其完成 |

不删除必要本端 checkpoint、正式实施合同、Context 对齐、API Freeze、测试或审查。旧正式任务和真实外部交付承诺仍如实记录，不通过删依赖来宣称完成。

## 7. 实现范围与验收

主要改动是模板政策、Spec / Backend 入口和技能说明、必要的行为场景及分发锁。复用 `composeProfileTree`、现有业务输入结构、`assertCheckpointBoundary`、本地终点和冻结包实现，不计划增加新的运行模块或改 Go 消费模式。

| 验收 | 预期结果 |
|---|---|
| AC-01：普通材料 | 需求、说明、技术资料或混合输入可提取信息，无模板 schema / 来源批准前置 |
| AC-02：分析复用 | 已有结果只补缺项，不重做完整 Plan / Spec；缺失与冲突明确保留 |
| AC-03：读取可选 | 已确认本端任务在未读取、原来源改变或不可访问时仍可推进，不自动同步 / 恢复 |
| AC-04：授权边界 | 原文中的指令或 approved 不替代真实授权，正式本端与显式上游合同不能被绕过 |
| AC-05：交接手动 | 普通阶段、探索和原型往返无强制交接，显式 handoff 仍保留必要引用 |
| AC-06：包兼容 | 手动正式包继续验真，坏包 / 失效批准拒绝，旧格式按原义读取 |
| AC-07：本端完成 | 复用当前 local-evidence，缺本端合同、测试或实际部署证据仍拒绝，后端完成不冒充业务验收 / 发布 |
| AC-08：分发一致 | 根与组合 Backend 政策、技能和锁一致，文档路径及实际改动有核验输入映射 |

材料理解用具体输入做内容验收，不以关键词测试冒充 Agent 理解正确；结构和准入继续由现有自动场景验证。只执行当前改动及直接 / 传递消费者的必要检查，不默认全量。

## 8. 状态与下一步

本轮修订本文并编写实施计划；没有实现上述行为。旧版提出的新来源绑定 schema、强制源版本复核和新能力协议已退出本轮范围。实施计划使用现有原生 CLI 验证当前模板行为；若真实验证发现硬编码冲突，保留失败证据并先修订具体实施范围，不放宽校验或修改 CLI 已有脏工作。

文档路径目前尚未登记核验输入，计划第一项将其与实际改动一并登记；在那之前，`verify-template-fast --plan` 的 `INCOMPLETE_VERIFICATION_INPUTS` 拒绝仍有效。本轮只做文档自检，不声明模板门禁、运行时或分发通过。
