# ADR-0008: 分离模板实例分发面与模板源治理区

## 状态

已接受

## 背景

`create-yss-spec` 通过模板源仓库的 Git 跟踪文件构建快照。模板源仓库同时保存 RED / GREEN 证据、研究记录、跨仓契约、发布路线、源仓库治理 ADR 和源仓库 LLM Wiki 编译树时，这些记录会被复制到每个新项目，增加上下文噪声，并可能让项目团队把模板维护过程误认为产品研发资产。

## 决策

`docs/` 定义为模板实例分发面，保留项目实例需要的生命周期规则、模板、用户指南和共享验证资产。`.nvmrc` 与根 `.gitignore` 同属分发面。`.template-source/` 定义为模板源治理区，保留模板维护证据、源仓库专属治理文件和源仓库 LLM Wiki 编译树（wiki-root 为 `.template-source/wiki`）；CLI 在根目录级别排除整个治理区。新 `project-instance` 不附带该编译树；用户需要本地知识库时在仓库根 `wiki/` 执行 `llm-wiki` `init`。

历史证据只移动归档，不删除。已有项目同步时，旧受管路径继续使用 `remove-report` 报告并保留物理文件，避免静默删除用户资料。模板源和模板实例的验证脚本根据 `yss-project.yaml` 的 `repository_mode` 选择源仓库专属检查或共享检查。

## 取舍

根目录排除比逐文件排除更能防止未来新增治理记录泄漏到实例，但要求验证脚本显式区分 `template-source` 和 `project-instance`，并使派生工作单元表只在模板源侧生成。保留归档证据增加模板源体积，却保留了发布审查和回滚所需的可追溯性。
