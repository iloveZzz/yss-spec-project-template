# 产品设计与逻辑原型的共同复核

先核对当前版本、规则来源、验收和产物位置。用户只要求局部审阅时限定该范围；缺规格时可指出可观察问题，但不能声称已经符合未知需求。

| 产物 | 可以核查的内容 | 不能据此声称 |
|---|---|---|
| 文字/流程/状态设计 | 主体、条件、量词、权限、转移、边界、异常和恢复是否明确，是否对应验收 | 页面已可用或交互已运行 |
| 线框/静态视觉 | 入口、信息层级、动作可见性、内容、必要状态与视觉约定 | 动态行为或真实接口通过 |
| 可操作 UI | 实际执行承诺任务，观察成功、取消、拒绝、失败恢复及适用显示/键盘条件 | 模拟后端等于真实服务、Agent 操作等于用户研究 |
| 逻辑状态原型 | 从已知输入执行动作，核对合法转移、拒绝结果、重复动作及重置 | 试验模块可直接生产或已证明性能/并发实现 |

有图解时按 [图解表达](../../i-have-adhd/references/visual-explanation.md) 核对重要转换的角色、触发、条件、结果及规则引用，区分业务状态与界面显示状态。图文矛盾、来源不明和待定规则分别指出，不因图形完整推断行为已确定；不增加必需图表或独立审查要求。

## 检查方式

沿真实用户任务检查入口、前提、动作、结果和退出，不只看孤立组件。权限、校验、状态冲突和失败恢复按当前风险选取；纯展示没有交互时不凭空要求动作路径。有交互承诺必须实际操作，缺浏览器或运行环境时记录未验证。

视觉检查以用户参考、项目规范或已说明设计目标为依据，包含内容密度、长文本、错误提示和当前范围的关键状态。按设备与风险实际检查窄屏、缩放、键盘、焦点、对比度或辅助技术，不要求所有项目执行同一组设备和报告。

产品 UI 的低保真草稿与完善版共用 Vue + shadcn-vue 组件和场景；低保真仍验证核心动作、失败保留、重试及重置。检查真实组件使用以及点击/展开后的边框、键盘焦点、错误关联、InputGroup 和 Portal 状态，具体见 [条件检查](component-qa.md)。

同一规则在 Spec、原型和说明中含义应一致。模拟动作必须标明，未实现入口不可假装有效。关键决定未知、权限或恢复语义冲突时报告草稿和缺口，不替业务方选择答案。

## 结果

每项发现写位置、依据、可观察影响和建议；区分阻碍当前验收的缺陷、规范差异、偏好与未来改进。记录实际检查、未执行项与工具限制；静态扫描、截图、构建成功不能替代动态行为或用户确认。

修正后只复查受影响部分；没有证据时不写通过。完整 Spec 是否已具备规格、原型和说明，由其交付范围判断，复核不另建审批系统。
