# 业务分析与方案判断

用于需求尚未形成可解释业务行为、方案有真实取舍或下游影响不明确的任务。读取当前目标、已有研究、Spec、实际业务材料和已确认决定；已有 CONTEXT.md 时沿用词汇，缺少文件不阻断分析，也不自动初始化治理。

按 [业务分析方法](references/business-analysis.md) 梳理角色、场景、范围、规则、状态、异常与可观察验收。复用稳定编号和既有决定；结果写回当前规格或其引用材料，不产生另一套规格。

事实不明先调查，业务选择未定才用 grilling 澄清，词义与责任含混用 domain-modeling。说明可继续部分与真正依赖未决决定的部分，不因局部缺口停止全部工作。

方案比较只针对真实取舍，写明依据、代价与重新考虑条件；无实质备选不凑数量。产品行为需体验时由产品设计或逻辑原型支持决定，不能用示意页面猜业务规则。

不选择技术架构、数据库、接口或实现分层，不要求实现仓、OpenAPI、阶段身份、固定集合或批准包。返回业务说明、验收缺口和待决定事项，真实对外发布与写入遵循已有授权。
