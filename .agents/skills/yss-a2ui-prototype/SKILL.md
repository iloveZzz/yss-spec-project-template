# A2UI 高保真原型

适用于明确指定 A2UI，或同一业务对象需要随用户意图增减、重排组件的原型。先找出一次操作前后**界面结构**的差异。仅修改固定页面的视觉、文案或状态时，用项目既有的 `yss-design-ui`；正式 Vue 应用交付由工程任务承接。

1. **确定用户要完成什么。** 沿用目标项目的规格归属、角色、任务、已有交互和设计基线。选一条有代表性的路径，写清入口、用户动作、第二种布局和可观察结果。权限或状态分支以现有业务决定为准。局部改稿按原授权落位。
2. **画清固定与动态区域。** 页面标题、导航、主题、断点和焦点管理由 Vue 宿主承担。把确实需要变化的部分做成一个 surface。列出每个画面需要的组件、展示顺序、文案层级、绑定字段和可触发动作。已有设计系统优先；可操作控件采用实际的 shadcn-vue 组件。
3. **组装可运行原型。** 复用同项目的 `.agents/skills/yss-design-ui` 及其固定版组件、主题与许可。按[装配与协议说明](references/authoring.md)把[起步素材](assets/starter/)接入原型。需要 SCRM 表单分区、带字数的备注、表单提示或阶段流转预览时，直接选用[SCRM 组件目录与示例](references/scrm-components.md)。替换示范业务数据、动作及页面文案，用同一条记录构造初始消息、布局增量与数据增量。需要更多组件时，同时补 catalog 约束、Vue 映射和操作验证。
4. **走通用户动作。** 让 Core 解析按钮事件和绑定，再由宿主按当前对象、角色和状态决定结果。按规格呈现反馈、拒绝或恢复。模拟来源在交互说明里标明。需要异步切换时，由宿主区分轮次并丢弃迟到结果。
5. **在浏览器复核并交付。** 从页面入口操作到结果，核对实际可见的组件增加或移除、绑定值和动作上下文。按设计检查窄屏、键盘和焦点，试一次无效消息后的恢复。返回原型入口、运行方式，以及“动作 → 实际画面 → 对应规则”的简短说明。明确实测的组件范围和仍未验证的路径。

示例调用：`使用 $yss-a2ui-prototype，根据现有活动报名规格制作高保真原型。从报名摘要进入入场指引，再返回同一条报名记录。`
