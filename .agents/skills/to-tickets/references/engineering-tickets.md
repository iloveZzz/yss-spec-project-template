# 工程票与可验收实现增量

用户明确要求研发拆分时读取；已授权的 `implement`、前端应用或 Backend 任务也可直接读取本方法组织实现。后者按原请求继续工作，不要求先拆票、创建父票或调用 `to-tickets`。方法不授予跨仓写入、外部建票、提交、推送或部署权限，拆票本身也不自动启动实现。

## 以实际来源与工程为依据

读取本次真正消费的需求、Spec、设计或 Issue，以及实际目标工程、技术栈和已有实现。保留原规则、FR/AC、稳定 ID 与已确认讨论；缺陷或直接需求已完整表达时，不补建 Spec、业务票或集合。文件是来源就引用文件，Issue 正文是来源就引用正文；已有工作项、工作树、分支和 PR/MR 先衔接，不另造平行票集。

记录真实仓库及必要路径、来源版本或读取时点。选定输入含未提交内容时据实标明，不用仓库 HEAD 代替实际读取内容。跨仓先核实工程身份与本次授权，来源仓可读不等于实现仓可写；无法核实的位置或依赖写明未知及影响，继续整理已有依据的范围，不编造路径、接口、负责人或版本。

前端承接选定的高保真设计、交互说明和实际接口来源，保留原验收及模拟边界；缺少关键输入时说明具体受影响行为。生产 API、数据结构和权限由真实契约及已确认决定支持，原型或 mock 不能作为生产承诺。必要技术设计由本次授权内的适用研发能力完成，Backend 继续使用自己的设计能力、架构约束和实现切片模板；本方法不把后端职责降为业务票分析。

## 按可观察结果划分

一票描述一个用户或调用方可观察、可验收的增量，贯通完成该行为实际命中的部分；纯前端或纯后端任务不为凑全链路新增另一侧工作。完整增量可包括成功、拒绝、异常和恢复，但只覆盖来源要求及实际影响，不机械一条 FR 一票。

组件、hooks、表、Controller/Service/Repository 和其他技术层是实现职责，不是默认拆票单位。只有独立完成条件清晰、真实依赖允许时，公共能力或基础改造才单独成票，写明消费者与可验证结果；不能把“写组件”“建表”“接接口”本身当成业务能力已完成。

保留来源中的量词、权限、边界和失败语义。未知 API 或未定业务选择不能写成确认事实；说明受影响范围、需要的决定和解除条件，继续处理不受影响部分。若本次只授权 mock 或界面实现，完成条件明确限定在该范围，真实集成仍列为未完成或下游依赖。

## 每票的必要内容

沿用项目已有适用模板和条目结构；没有模板时按下列内容组织，简单票可用一段，不为字段补造事实：

| 内容 | 写清什么 |
| --- | --- |
| 结果与范围 | 谁执行什么操作得到什么结果；覆盖行为、边界与非目标 |
| 来源与验收 | 实际路径或 URL、版本或读取时点，承接的 FR/AC 或原规则与完成条件 |
| 执行位置 | 实际仓库与必要子路径，已有工作树、分支、PR/MR 及本次责任边界 |
| 实现约束 | 实际需要的设计、界面、接口、数据与组件约束及其来源；不为表格增加模块或技术方案 |
| 验证方法 | 与本票验收相称的已有命令或观察方法；区分模拟、真实服务及尚未覆盖的行为 |
| 依赖与并行 | 所需产物或行为、解除条件、共享修改和运行资源的协调责任 |
| 完成终点 | 用户本次要求达到的位置，例如本地实现或已授权的 PR/MR、合并、部署；未要求的动作不加作门槛 |
| 当前结果 | 实际完成与验证、证据位置、未决项、未完成动作及实际保存状态 |

验收描述条件、动作和可观察结果，不以文件存在、构建成功或技术层全部改完替代来源验收。按变更风险选择必要验证，不新增统一测试套件、报告或阶段门禁；未执行、执行失败和验证通过分别报告。

## 依赖与可并行边界

只记录真实前提，展示顺序不等于依赖。写清下游需要哪项实际结果及如何确认；依赖票关闭、PR/MR 合并或子任务自报完成不能单独证明前提满足。无法独立验证的工作明确共同集成边界，不把中间批次写成独立可用。

按修改和运行冲突判断并行：共享接口、配置、POM、锁文件、生成输出、测试数据、数据库与端口需要明确协调责任；文件不同不代表可并行。接口契约一致且各自验收不依赖对方未完成行为时才适合并行，实际分派与集成由执行任务负责。机械重构按 expand → migrate → contract 组织，按实际可独立验证的范围划分。

## 保存与完成

涉及接收、恢复、读取或写入 tracker 时，按项目根读取 `.template-spec/agents/issue-tracker-operations.md`，沿用其定位、关系、并发更新、未知写入和续办方法。普通拆分分析在对话给出；保存、发布、评论、关系维护和关闭复用各自动作的有效授权，不因本方法被读取就自动写外部。

来源变化只调整受影响的增量、依赖和验收，保留仍有效的工作。实质业务取舍回到业务方，等义技术细化沿当前授权继续，不新设审批节点。

按本票原验收报告实际结果与缺口，分别说明 mock 可用、代码完成、真实联调、PR/MR 合并与业务验收。已有业务父票只聚合真实结果、证据和剩余覆盖；子票全关闭不自动满足父票验收，也不自动授权关闭父票。结果回到原工作项，规则变化回到原来源，不另建进度台账。
