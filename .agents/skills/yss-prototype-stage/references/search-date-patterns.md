# 搜索选择与日期范围

在选项较多、同名对象需要编号区分时选择 Combobox；少量固定选项继续使用 Select。日期条件包含起止日且只关心日历日时选择 RangeCalendar + Popover。先明确任务、数据和取消语义，再选择组件；本配方不覆盖远程搜索、多选、日期时间或时区转换。

## 行为与教学入口

`assets/vue-business-patterns/combined-query-standard.config.json` 演示组合查询；`owner-validity-standard.config.json` 演示负责人及有效期表单。`export-vue-patterns.mjs` 同时导出原五类模式、新变体、工作区及组件状态展示。全部是维护 fixture，不写入产品 Spec；参考日期固定为场景 JSON 的 `referenceDate`，不使用运行当天。

| 决策 | 本轮教学合同 | 实现交接必须明确 |
|---|---|---|
| 搜索和值 | 搜索词只过滤本地名称/编号；正式值为稳定 ID；同名不同 ID 可区分 | 选项来源、ID 类型、权限和历史失效 ID；不能把名称当主键 |
| 搜索状态 | 空结果、加载、失败重试、禁用和清空；失败保留词和值 | 哪些状态来自真实服务；恢复动作和错误码 |
| 键盘 | 上下键、Enter、Escape；组合输入期间 Enter 不选中；取消不覆盖旧值 | 中文输入法、目标浏览器和辅助技术检查 |
| 日期 | 纯 `YYYY-MM-DD`，起止均包含、同日合法、双空不限；单端、逆序、非法日期阻止应用并定位 | API 的日期格式、空值含义、区间端点；禁止隐式时间戳转换 |
| 日期草稿 | 浮层独立草稿；应用才提交；取消/Escape 保留原值；清空先改临时值 | 保存、筛选和浮层应用的三个边界 |
| 页面生命周期 | KeepAlive 保留已应用查询及表单草稿；关闭确认后重开初态；离页清理浮层 | 内存保留范围、刷新策略和逻辑焦点后继 |

新增能力由固定 revision 的原始组件承担语义。本地 SearchSelect/DateRange 承担业务状态，主题在独立映射层；不修改 vendor 源文件。`@internationalized/date` 使用锁定的 3.12.4，禁止用 `new Date('YYYY-MM-DD')` 绕入时区语义。

## 把设计疑问写成可观察任务

“用户是否理解日期？”改成：“找出 2024-02-29 当天由 U-001 负责的资料，再取消一次日期修改；记录最终结果和条件。”观察是否选错同名 ID、是否应用单端日期、取消后能否辨认原条件。任务不给按钮名或点击顺序；成功标准可复核，模拟执行不填成真实用户观察。

陌生角色、新主流程、复杂权限或恢复操作仍有未解问题时，进入 [条件式用户研究方法](usability-research.md)。业务范围仍由已有 Spec、交互说明和状态矩阵承载；研究材料不授予实现或批准资格。

## 验证

通过 [统一验证入口](prototype-verification.md) 运行来源/编译、原五类模式和新增浏览器场景。重点反例：文字假冒选择、非法 ID、重名误选、IME 误提交、未完成范围被应用、取消改值、失效触发器抢焦点。结果并入现有六轴 QA，不增加 schema 或批准字段。
