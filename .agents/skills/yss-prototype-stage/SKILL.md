# 按需产品设计

先说明当前不确定性，再选择最小必要表达：规则清晰用文字和验收；顺序/角色/状态复杂用流程或状态表；入口/内容关系不清用低保真；只有实际操作才能判断时构建可交互原型。视觉方向可用静态视觉稿。允许局部组合和随新证据调整，不按层级逐一升级，也不因有 UI 强制原型。

事实由 yss-research 调查，业务取舍用 grilling，词义问题用 domain-modeling。不要用原型猜业务决定。需要视觉一致性时调用 yss-design-system；使用 prototype-review 对实际产物复核。当前文档表达按需用 i-have-adhd。

流程检查主路径及适用失败、取消、重试和退出；低保真检查必要信息、入口、动作结果、权限与异常；原型实际操作承诺场景并检查恢复及适用显示/可访问性条件。没有运行不能称交互通过，截图不证明动态行为。工具不可用且关键问题依赖验证时，明确阻断。

现有 H1/H2 构建工具可在确有相应原型需要时使用，不是所有设计的必经链。不要求固定组件栈、独立审查、完整六轴归档、OpenAPI、端点映射或实现 Slice。生产实现与技术可行性留给下游。

发现回流 Spec 的规则与 AC，实质业务变化消费真实决定及适用审批；不新增产品设计批准节点。关键问题解决并完成相称检查后才报告当前范围完成。返回产物引用、选择依据、真实验证、模拟/未覆盖范围和剩余问题。
