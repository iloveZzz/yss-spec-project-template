# Spec tracker 规则

使用 tracker 接收、恢复、读取或发布 Spec 时，先读取项目根的 `.template-spec/agents/issue-tracker-operations.md`。目标定位、正文与关系读取、写入授权、并发处理和失败恢复沿用该共享方法；本文仅补充 Spec 来源、版本与交接规则。

同一需求保留一个主 Spec。规则来源是文件时，文件仍是权威来源，Issue 引用其实际路径与版本；规则直接来源于 Issue 时，才以对应 Issue 正文为权威。交互说明、原型和业务票关联同一来源，不因发布到 tracker 改换来源或复制第二份可独立修订的规格。当前执行状态在所选 tracker 维护，Spec 中的内容版本与真实确认记录不替代执行状态。

用户显式交接时，PR/MR 文件可保存标明来源、版本或读取时点的内容快照。快照不自动回写或跟踪原来源，也不接管来源权威；动态 URL 本身不构成固定版本。接收方在开始依赖工作和交付前按风险核对所用规则、AC 与相关原型的实质变化，不以 PR/MR 状态代替业务决定。

有真实确认或审批要求时，记录实际展示的范围、内容与设计版本，以及原始决定来源；无可读历史时，才为该次决定保留不可覆盖快照。实质规则变化沿原来源更新并标明影响，旧确认只适用原范围和版本，保留原记录。保存、登记、发布或交接都不自动产生批准，也不为已授权工作增设确认环节。

交接保留实际来源、采用版本或读取时点、原型模拟边界、规则与 AC、已知未决项和验证缺口。下游访问情况未核实时标为未知；材料不可读时说明影响并继续独立工作，不能声称交付完整。研发发现沿同一规则与 AC 返回；修订建议、实际回写和业务确认分别据实记录，业务完成仍以实际验收结果为依据。
