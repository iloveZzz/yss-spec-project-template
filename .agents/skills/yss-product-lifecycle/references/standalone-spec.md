# 普通规格起草

这是 life 与显式 `to-spec` 共用的起草方法，不是另一个技能入口。life 直接消费本参考，不隐式读取或调用 user-only 兼容技能。

1. 读取用户材料及当前已确认决定。已有根 `CONTEXT.md` 可读时使用其稳定词汇；缺少它不阻断普通稿，不创建词汇表或猜 ContextId。词义冲突与未决项保留在当前稿。
2. 按需读取 `../../i-have-adhd/references/document-writing.md` 的共用中文写作规则。按目标、使用者、范围与非目标、规则及验收、待确认项组织正文；没有适用治理模板时直接用 Markdown，不查找 Plan、Tracker 或阶段合同。
3. 用“主体在什么条件下做什么，系统产生什么可观察结果”写规则。将确认的每条规则与可测试验收对应，按影响覆盖成功、拒绝、边界与状态变化；未确认的阈值、异常结果和权限规则写待确认，不补造决定。
4. 复用已确认内容，只询问阻止当前交付的实质缺口；其他缺口明确标记，责任人和时点未知就写未知。实现细节只引用已确认约束，不提前决定架构、API Freeze 或实现任务。
5. 在实际授权范围内答复或保存到用户指定草稿路径。稿件只表示需求整理；不创建 business-tickets、issues、正式状态或批准，也不授予实现资格。
6. 对照原始输入检查规则、边界、非目标、未决项及验收是否完整一致，报告实际检查与未覆盖部分。正式化需另行核验正式分支的当前输入和真实决定。
