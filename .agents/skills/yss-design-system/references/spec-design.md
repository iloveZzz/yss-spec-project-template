# 按需设计规范

先确认当前产品问题：视觉层级、信息密度、表单反馈、操作可见性、状态提示或特定显示条件。已有模式能解决就复用，不要求为每个需求重建完整设计系统。

根 DESIGN.md 是项目已有视觉约定的主要来源；按实际主题与密度读取 `.template-spec/design/tokens/` 中相关 Token，不全量加载所有主题。引用关系或数值矛盾时明确指出，不能静默以偏好覆盖已有约定。没有基线时只提出解决当前问题所需的可审阅建议。

文字/流程不强制视觉稿。需要可见信息结构时可提供线框；只判断外观可用静态稿；必须操作才能判断时才制作相应原型。允许只为受影响局部补产物。所有形式都不要求预先定义生产组件、API 或实现代码。

检查与声明相称：静态稿核对内容层级、动作可见性和视觉约定；原型实际操作承诺路径，按当前风险检查窄屏、键盘、对比度等条件。未运行的检查明确未验证，不要求统一档位、固定六轴矩阵、完整证据归档或独立审批。

规范检查发现业务权限、异常、恢复或范围问题时回流 Spec 与 AC；真实取舍交给用户，默认诚实自检，独立复核只按实际要求。输出来源、范围、实际发现和未覆盖条件。
