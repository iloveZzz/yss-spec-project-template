# 接口语义与导出方法

## 只读审查与按需编辑

先确认本次请求范围；只读审查不改文件。逐 operation 对照当前需求、调用方与实现，检查路径/方法、operationId、参数来源、请求/响应、状态码和错误定位。OAS 3.1 文档不混入生命周期 frontmatter；需求涉及页面动作时核对动作与接口或明确非目标，不要求额外原型包。

- 按实际模型核对嵌套字段的类型、必填/null、默认值、枚举、格式与字段来源。共享 create/update schema 也要分别检查省略语义；凭据字段区分创建、更新、掩码回显、omit=保留和 clear，不机械要求所有 password 必填。
- 检查分页空结果、total、排序/分组白名单与边界；并发版本、幂等键、失败重试及错误结构以业务语义为准，不凭模板强加字段。
- YSS wrapper、PageQuery 和 wire 字段以 yss-dto 与目标序列化行为为依据，响应 data 使用具体 schema，不把 Java 泛型文字写作 OAS type。下载、流式、回调或其他既有协议按实际约定，不强套 wrapper。
- 不从 getter、Lombok 或单个注解直接推断 wire shape；计算字段和异常响应对照目标 mapper、真实实现或已有序列化观察。缺证据时说明无法判断，不要求先造 fixture 才能审查。
- 保留认证、授权、资源过滤和错误脱敏，检查本次变化对既有调用方的影响；公开 schema 不泄漏内部聚合、持久化结构、凭据或敏感信息。错误应能定位到实际模型、字段或行。

报告 operation/schema/property 的具体位置、触发条件、影响和依据；区分实际发现、待确认事实与建议。用户要求编辑时同步相关引用、示例及调用方，沿用已有需求与接口文档，不生成平行追踪矩阵或批准记录。

## 按需导出 JSON

YAML 与 JSON 表达同一接口；沿用项目可用转换能力，先读其实际帮助。项目已提供 Redocly 时可按需要使用 `pnpm exec redocly lint <yaml>` 或 `pnpm exec redocly bundle <yaml> --output <json> --ext json`；先确认参数支持，不为导出强制安装、全局升级工具或改锁文件。

- 保留可表示的内部 `$ref`；递归/循环模型不默认加 `--dereferenced`。合并 schema 时发现命名冲突应明确处理，不能静默覆盖或改变指向。
- 先检查引用的实际解析路径，包括符号链接；默认只读取本次 API 目录内相对文件。未授权的绝对路径、越界路径或远程 URL 不自动读取；已有明确共享组件范围可按其真实授权使用，不要求额外 Freeze 记录。
- 明确输入与输出位置，防止输出覆盖 YAML、无关用户文件或越过授权路径。生成前读取已有目标并保留用户内容；转换结果不能把失败、未解析引用或类型变化伪装成成功。
- 按实际需要核对解析、引用与字段语义；无工具或没有执行时说明未导出/未验证，不凭文件名声称 JSON 与 YAML 一致。仅审查时不运行有写入副作用的 bundle。
