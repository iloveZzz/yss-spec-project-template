# Skill 编写

## 主描述与菜单短描述

`SKILL.md` 的 `description` 帮助选择技能。用一句话写清用户在什么情况下需要它，以及它会完成什么。容易和相邻技能混淆时，补上能区分两者的条件。例如“在尚不存在的目录生成最小 Vue 3 工程”点明了脚手架的适用场景，已有页面的修复属于前端应用技能。操作步骤和完整的类名清单放在正文或参考资料中。

技能已有菜单短描述（`agents/openai.yaml` 中的 `interface.short_description`）时，用一个短句写出最有辨识度的动作或结果，让读者看名称和短描述就能选用。两处描述的职责和适用范围应一致。显式调用条件、提交或发布授权沿用技能原有约定。

同一字段出现中英文混写时，按该字段的主要语言整理。YSS 自有技能通常用简体中文，原生英文技能保留英文主描述，菜单短描述沿用现有界面语言。中文句子里的普通词用中文，如“只读审查”“组合式函数”。有助于识别任务的技术名称（如 Vue 3、OpenAPI）和需要直接输入的命令保留原写法。

| 场景 | 描述示例 |
|---|---|
| YSS 前端脚手架的主描述 | 新建 YSS 前端应用时，在尚不存在的目录生成最小 Vue 3 工程。 |
| 同一技能的菜单短描述 | 在全新目录生成最小 Vue 3 工程，按目标验证运行 |
| 原生英文技能的主描述 | Set up Git worktree isolation for concurrent work. |

## 元数据与分发

保留当前宿主支持的元数据、来源和许可证。显式调用与自动选择属于发现策略，不授予对外动作权限；不要因技能安装而假定已获提交或发布授权。

修改共享内容源后同步对应平台副本与清单。技能内可携带直接支撑生成或转换的确定性脚本；删除失效命令和重复流程，不新增安装包装脚本、通用测试套件、检查计划、审批或发布门禁。用可读的任务说明表达需要 Agent 完成的操作。

来源记录区分原始引入版本、比较版本和有效内容哈希；复用现有分发清单让适配说明随相关技能安装，不新增锁 schema。Backend 从共享源继承时保持来源信息，不能覆盖其专有内容或平台元数据。

跨技能按需读取方法时，声明相对项目根的 canonical 路径，并在适用安装模式的 skillReferences 中分发所需叶子资源；只读取参考不等于安装或调用整个技能。检查单项安装后的引用闭包，不能用全量预装掩盖缺失资源。结构核对不能替代实际宿主发现与行为观察。
