# 设计交接与还原

用于依据已有设计和原型，在目标应用实现已确认的体验。局部修改只处理相关页面。采用已有充分输入，可在原说明或任务回复中记录本次接续。

## 找到真正的基线

优先读取用户指定材料及目标项目已有说明；按需要补齐以下信息，可以用链接代替复制：

| 输入 | 要读取的事实 | 工程使用方式 |
|---|---|---|
| 业务规格 / 交互说明 | 字段含义、操作条件、权限、状态转换、错误恢复、验收例子 | 决定行为；不能根据一张截图发明业务规则 |
| `DESIGN.md` / 设计稿 | 信息层级、关键布局、密度、字体、色彩、断点、明确的设计决定 | 决定需兑现的视觉约定和对比基准，按目标工程主题落地 |
| 可运行原型 | 页面入口、核心流程、可操作状态与已知模拟 | 核对用户体验、可达性和应覆盖的状态 |
| 已有 `prototype-review` 结论 | 复核采用的版本、页面和 FR/AC、已验证的交互、已知差异及演示边界 | 用于明确本次落地与复测范围，回看原依据解决冲突 |
| 原型源码、CSS 与资源 | 设计意图、依赖、实际资源、变量和值源、许可 | 理解原型画面，按工程约定选择经核对的资产和通用组件 |
| 组件来源 / manifest / 锁文件 | 本地修改、来源版本、依赖与许可 | 判断兼容；保留已有来源清单，不虚构摘要或版本 |
| 服务资料 | 已确认 API、认证方式、分页/错误/权限语义 | 真实接入的依据；缺失时标为接口待确认 |

已有复核结论时，按项目根的 `.agents/skills/prototype-review/references/frontend-handoff.md` 核对其版本、证据和适用范围。应用技能随包取得这份参考。需要检查新原型或变化内容时，可按任务用 `prototype-review` 做针对性复核。用户只要求实现且已有充分依据时，直接接续原规格、设计与已有结论。

任务来自 Issue 时，读取当前正文、讨论、AC、已有子项及依赖，再沿原始链接核对源 Spec、原型和接口的当前内容。Issue 中的摘要不能替代这些来源；需要定位、恢复或更新关系时，按项目根读取 `.template-spec/agents/issue-tracker-operations.md`。遇到来源变化或不一致，只标出影响本次实现的差异，不把旧票摘要补写成另一份权威规格。

区分提交中的基线与包含用户未提交改动的工作树。若采用工作树设计，记录实际文件及当前改动情况，不能只写 HEAD 作为完整依据。复制到隔离目录时包含实际依赖的未提交资源；禁止重置、覆盖或清理原产物。

本次选定的规格与交互说明约束行为，原型与设计规范提供确认过的体验及画面对照。目标工程的目录、组件、语义主题、响应式规则、状态和服务约定决定如何实现。保留已确认的业务流程、结构和关键视觉决定。未指定的控件变体、间距、断点细节与加载反馈按目标工程规范适配。已有排序、分页、错误处理等行为先核对当前调用者及规则，涉及冲突时列明影响。实际采用的设计输入用于还原对比，历史截图用于其原有工程回归。

文字规则与画面冲突时指出具体冲突；只有会改变业务或已选视觉方向的未决问题需要用户决定，其他页面和无关部分继续实施。任务已明确要求的变更无需再次审批。输入确实缺失时只标明受影响状态，不发明规则、不把整个工程一并停下。

## 轻量映射

每个受影响的核心任务至少能追溯到设计、实现和检查。可以写在既有 README 或 PR 描述，不强制独立文件。

在已明确的研发请求中，Spec、原型或已有 Issue 的实现范围确需细化时，按项目根读取 `.agents/skills/to-tickets/references/engineering-tickets.md`。按可验收行为组织前端工作项，说明页面/状态、来源链接、AC、真实接口依赖及验证方式；已有工作项的定位、关系与写回沿用 `.template-spec/agents/issue-tracker-operations.md`，复用已有子项，不按组件或文件数量机械拆票。先在当前任务中明确实现范围，只有获得对应远程写入授权后才持久化为 Issue。该叶子资源可独立读取，不要求安装或调用完整 `to-tickets`、补建票或重新取得实现资格；小改动直接实施。

按本次范围列出实际需要的默认态、弹层打开态、编辑/校验态、提交结果与恢复动作；只检查有设计依据或由本次工程行为产生的状态。一个弹层的默认截图不能代替取消、失败保留输入与关闭回焦的验证。

| 设计 / 规则与复核依据 | 页面、状态与实现责任 | 数据或演示边界 | 如何验证 |
|---|---|---|---|
| 客户列表换条件后查询，空结果可清除条件。复核里的转圈由定时器模拟 | 项目表格保留已授权旧行及布局，查询 composable 按最新意图控制局部 Spinner、关联动作与重试 | 使用查询 service。后端未提供时由可控 fixture 模拟响应和失败 | 逆序响应时显示最新结果，换条件失败后可重试，空结果与失败可区分 |
| 编辑弹层保存失败保留输入，成功才关闭。按原型复核的失败场景核对 | 用本地 Dialog、目标工程的字段校验和请求状态实现，按回执更新草稿和列表 | 使用真实写入契约，或在隔离的模拟边界复现回执 | 实际触发失败和重试，核对字段保留、成功关闭、列表更新及焦点返回 |

实际项目使用实际路径、设计链接和检查结果替换例子。没有运行的检查写“未执行”，不能把“如何验证”当已取得证据。

交付或更新已有父票时，沿 AC 链接对应实现、PR/MR 和实际验证，分别说明前端行为已实现、已实测及待联调范围。真实 API 尚未接入或未实际联调时，保留该限制；不能因 mock 通过或关联后端票已完成而关闭尚未验证的跨端验收。源 Spec 和原型继续承载业务与设计细节，工程进展只补充实现事实与差异。

## 按目标工程实现

- 用目标工程页面框架和本地 shadcn-vue 组件重建页面结构、控件和样式。保留确认过的视觉意图，把原型配色、尺寸、排版和响应式约定映射到项目 tokens、组件变体和布局规则。涉及已确认的业务或关键视觉冲突时，说明影响，回到原依据处理。本地适配只覆盖当前范围。
- 原型源码用来理解行为。可按需采用经确认的图标、图片、字体、设计值或兼容的独立通用组件，核对许可、依赖、props、emits、slots 与主题。项目已有等价组件时复用现有实现。整页原型、演示 CSS、业务组件、数据模拟和原型路由不直接进入生产页面。
- 用项目路由表、schemas、业务组件、hooks 和 service 承担各自职责。身份、权限、分页、上传、错误及持久化以真实契约为依据。接口缺失时保留明确的接入缺口，将随机数据、固定成功、内存保存、场景切换器和演示路由隔离在预览或模拟设施中。
- 涉及等待与异步反馈时，使用 `yss-frontend-loading` 从真实路由、请求和回执推导状态，核对旧数据能否保留、动作何时禁用、迟到结果归属、失败如何重试及焦点落点。原型的定时器或场景开关用于理解示例。原型缺少的必要运行状态按工程与服务事实补齐。

兑现原规则中适用的取消、重试、禁用原因、加载、错误与空状态。按实际业务决定是否需要未保存离开提示、删除确认或部分成功反馈。

## 主题与组件链

1. 找到真实 token 定义及其消费者。YSS 原型常见链为 `tokens.css`（值）→ `prototype-theme.css`（布局/密度）与 `theme.css`（shadcn 语义映射）；文件名以实际项目为准。只复制消费变量的 CSS 不算完成主题。
   若拿到的资产只有映射文件，继续从原型实际 CSS 入口、项目 `DESIGN.md` 或设计技能的 `assets/DESIGN.md` 找到值源。按本页实际需要映射到目标工程，记录采用值的来源和覆盖范围。找不到关键设计值时标出缺口，未指定的细节应用项目主题。
2. 同一语义 token 保持一个权威定义，必要适配发生在语义映射层。按已确认的视觉约定和目标工程主题检查字号、行高、控件高度、表格密度、圆角、阴影与焦点环。需要修改全局主题时核对本次授权和受影响页面。
3. 定义和主题作用域覆盖 Teleport：放在文档根或弹层实际祖先，核对 Dialog、Popover、Select、Tooltip。放在 `.app` 或 SFC `scoped` 内不保证传送到 `body` 的内容继承变量。
4. 检查 Tailwind 主版本、CSS layers/导入顺序、语义类映射、动画依赖与扫描范围；跨 package 组件或动态拼接 class 可能构建成功但没有样式。使用实际可扫描类或该版本支持的明确来源配置。
5. `components/ui` 是项目持有的源码。已有组件先复用；新增组件按目标版本和来源取得其完整依赖闭包。CLI 不覆盖已定制组件；组件 API、Reka 和图标 import 以实际版本为准。
6. 交互控件直接使用已有 shadcn-vue 对应组件。允许语义布局标签、链接和组件内部原生 DOM；不以“长得像”的原生按钮/输入替换组件契约。不为 Form 名称自动引入新表单库。

## 实际还原检查

先在相同视口、缩放、数据、主题和状态下比较设计与实现；稳定异步数据和动画后截图，并记录对应的来源画面与实现画面。字体、浏览器或操作系统不同造成的比较限制应说明。已有自动截图设施才复用，不为单次局部任务建设一套视觉平台。

先核对旧快照的来源、状态和覆盖范围。迁移前工程的快照只证明相对该工程基线的回归，不能替代与本次选定原型的对比；实现截图不能自证还原。不得通过更新基线、遮罩核心控件、扩大容差或跳过失败用例掩盖偏差。任务已明确改变设计时，可在对照新依据后更新受影响基线，说明变化依据与范围，不新增例行审批。

- 默认画面检查层级、对齐、列宽、密度、文本截断及资源；弹层单独检查主题、尺寸、定位和滚动。
- 按设计目标验证窄屏/断点、长文本、溢出和页面滚动，不把整页截图相似误当所有尺寸通过。
- 操作关键路径：键盘到达、标签/可访问名称、焦点进入与返回、取消/提交、失败保留输入。仅组件自带 ARIA 不证明页面可访问。
- 差异记录说明设计依据、实际结果、适配原因和影响。区分符合目标工程规范的适配与偏离已确认体验的问题。重要业务未决项回到业务说明。
