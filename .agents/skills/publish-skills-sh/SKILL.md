# 发布技能到 skills.sh

将用户选定的技能形成便携包，交付到指定 GitHub 分发仓，再验证公网安装和页面内容。复用源仓导出器、Skills CLI 和目标仓的发布工具，按实际能力执行。

## 1. 固定范围与授权

- 确认源技能路径或 ID 清单、目标 `owner/repo`、目标分支或 PR 策略、公开范围及许可证兼容性。复用本会话已确认的发布映射；缺少目标、公开范围或许可依据时询问用户。
- “整理、导出、校验技能”只授权制包与本地验收。“发布指定技能”在目标和范围已确认后授权该分发仓的提交、推送及适用的发布步骤，无需再次索取相同授权。
- 授权只覆盖所选技能及必要的分发声明，不扩展到其他技能、整个源仓、源仓提交、CLI 发版或 npm 发布。遇到仓库要求的额外审批，先形成可审查候选，再按规则处理。
- 读取源仓和目标仓规则，记录 HEAD、索引与脏文件。保留无关修改；目标待写文件已有修改时先展示差异并确定合并方式，不能直接覆盖、重置或清理。

## 2. 形成便携包

识别为 YSS 模板源时，先读 [YSS 导出适配](references/yss-export.md)，消费既有公开清单与导出限制。其他源优先用已有导出器；没有导出器时，只整理选定技能和其必要资源。

- 在仓外建立候选目录，核对 `SKILL.md` 的 `name`、`description`、技能命名和文件权限；必需引用与脚本依赖须能在包内解析，条件外部依赖须写明入口与缺失处理。
- 检查私有路径、凭据、内部资料及许可证；发现不可公开内容时修正候选或缩小范围，不能以删掉必要引用冒充便携。
- 分别记录源文件和导出文件的完整清单、原始字节摘要、必要权限及聚合摘要。注明源仓、基线提交和 `source_state`；允许真实标记 `working-tree`，不得把未提交内容声称为固定提交来源。
- 导出加工会改变正文，源摘要与导出摘要可不同。导出后重新核对源输入；来源漂移使该候选失效，重新制包和验收。

## 3. 对齐分发仓

按目标仓既有目录结构同步所选技能、README、安装命令及已有来源记录。目标已有 Claude Code 插件或 Changesets 时，同步声明与版本，采用其校验和版本策略；没有时不新增发布框架。

更名时更新活动入口、技能选择器和链接，保留 Git 历史；旧 URL 尚存在不能当作活动别名。只暂存本次授权的路径，保留无关工作树和索引内容。

## 4. 本地验收

记录使用的 Skills CLI 版本，先核对命令能力。以下为命令形状；按现有入口或固定版本运行，不假设本机已安装 `skills`。

```sh
skills add <候选目录> --list
skills add <候选目录> --skill <所选ID> --agent codex --copy --yes
```

第二条在仓外临时工程执行，多技能逐项选择，不能用 `--all` 扩大范围。核对发现结果、安装目录的完整清单、摘要与必要权限，执行目标仓已有检查。发现与安装使用不同参数，按 CLI 实际支持情况选择 JSON 输出。纯本地检查可关闭遥测，保留用户已有设置。

## 5. 提交与推送

确认源输入仍与候选绑定，目标待写内容仍符合合并方案，本地验收通过且存在发布授权后，提交、推送指定分发仓。按其分支或 PR 策略交付；创建 PR 时返回链接，不能将未合并 PR 声称为默认分支已发布。

失败时保留候选、差异和检查证据。不能用强推、扩大暂存范围或跳过检查来完成发布。

## 6. 公网验收与结果

- 确认远端提交与预期 SHA 一致，核对该提交适用的 CI 实际状态；在隔离临时工程从远端安装所选技能，比较完整文件清单、导出摘要与必要权限。
- 检查 skills.sh 对应页面的技能名称和本次最新正文。HTTP 200、旧页面存在、标题正确或 CI 仍在运行，都不能证明本次更新完成。
- skills.sh 根据安装遥测自动收录 GitHub 技能，见 [官方 FAQ](https://www.skills.sh/docs/faq)。遵守用户已有 `DISABLE_TELEMETRY`、`DO_NOT_TRACK` 等设置，不刷安装量，不为收录擅自打开遥测。
- 默认前台核查累计不超过两分钟；页面仍旧或不可见时报告“分发完成、索引待更新”，保留最后观测，不自动创建后台任务。

分别报告制包、GitHub 分发、公网安装、页面更新的结果，附版本、来源状态、摘要、提交或 PR 链接、实际检查及未完成项。仅本地制包时明确发布步骤未执行；结构检查不能替代实际 Agent 行为验证。
