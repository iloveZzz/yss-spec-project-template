# YSS 团队培训入口与协作分工

团队从用户当前目标、已有资料和已授权工程开展工作。产品 Home 汇总产品定义、业务规格、原型、交互说明和关联工程入口，技术方案、生产 API、源码与工程验证保存在各自工程。

首次使用阅读[用户手册](../../.template-spec/user-guide/用户手册.md)。组织授课、课堂演示和练习统一使用[全团队培训讲义](../../.template-spec/user-guide/培训材料.md)，其中包含建议安排、教学假设、演示步骤、实操验收与参考解答。

## 按任务分工

| 当前任务 | 主要负责方 | 交给协作方的内容 |
|---|---|---|
| 调查事实与来源 | 产品、需求、研究人员与 Agent | 原始依据、适用时间、已知限制和仍待核实事项 |
| 明确范围、规则与业务取舍 | 产品负责人、需求人员与业务负责人 | 角色、状态、权限、异常、验收和真实决定 |
| 制作规格、原型与交互说明 | Spec 与设计人员 | 同一主 Spec、采用版本、可操作场景、查看方式和模拟范围 |
| 完成服务端研发 | Backend | 适用技术方案、当前 API、实现位置、工程检查与运行说明 |
| 完成前端研发 | Frontend | 采用的设计、页面与组件、浏览器结果和真实接口状态 |
| 检查行为与交付范围 | 测试人员及任务负责人 | 可复现前提、实际操作、观察结果、未覆盖项与剩余依赖 |
| 协调多仓与续办 | 当前任务负责人及主 Agent | 工程身份、写入范围、采用输入、分工、逐仓结果与下一动作 |
| 核对跨仓集成与整体验收 | 本次明确接手的集成负责人 | 真实依赖、采用版本组合、整体 AC 结果及未完成范围 |
| 接续发布与运行反馈 | 实际发布执行者及运行反馈接收人 | 环境与制品/配置/迁移组合、恢复依据、观察对象与时机、反馈入口及下一责任人 |

完整 Spec 交付业务规格、高保真交互原型及交互说明。核心操作与状态变化可实际操作，纯展示可采用高保真静态设计，无 UI 使用业务逻辑或状态原型。业务票按明确拆票请求组织。技术设计与研发由相应任务授权承接，责任说明见[技能地图](../../.template-spec/agents/profile-skills.md)。

## 一起工作时保留哪些上下文

开始前读取实际工程入口、相关资料与根 CONTEXT.md，复用有效决定。进入工程时核实 Git 身份、工作树、适用规则与有效技能，明确本次允许修改的路径。缺少关键业务决定时定点澄清，其余有依据的独立工作继续。

跨仓任务沿实际调用关系分工。共享 API、生成客户端、锁文件和共享组件指定一位整合者，分别核实路径、端口、测试数据与运行资源。Home 地图记录稳定关系，当前工作树、采用版本和进度保留在本次任务上下文。方法见[Spec / Home 教程](../../.template-spec/user-guide/cli/tutorial-spec.md)。

收到明确的复杂研发请求时，研发主动检查独立责任、跨仓依赖和跨会话接续需要，复用足以承载目标的最少工作项；已有目标与对应操作授权时直接维护。集成与发布责任写到实际人员或接手的 Agent，一人可兼任多项责任。小修复按原目标直接完成，业务拆票沿明确拆票请求组织。

工作台答复由 Agent 回写原问题、规则、验收与相关产物，核对一致后记录解决依据和真实答复 ID。延期保留原因、影响、排除范围与复查条件，当前仍依赖该决定的工作保留待处理状态。Wiki 维护回到原始依据，来源变化时检查已知派生页面，保护人工内容。

交付说明实际修改、采用材料、已执行命令及结果、未验证范围与下一动作。模拟运行、构建、真实联调和部署分别记录实际结果。提交、推送、对外发送、部署和发行沿用对应动作的真实授权。

涉及环境交付时，在已有任务或部署记录中接续实际版本与环境组合，分别保留部分成功、失败和未知结果，并交代恢复依据、下一责任人、观察对象与时机及反馈入口。无 Issue 时继续使用现有记录。具体方法见 [Issue 工作项协作与回流](../../.template-spec/agents/issue-tracker-operations.md) 的环境交付与运行反馈部分。
