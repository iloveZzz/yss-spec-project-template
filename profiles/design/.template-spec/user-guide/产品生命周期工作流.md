# 战略设计工作流

从用户问题形成业务方案及战略交接；不在本仓冻结工程 API、生成后端/前端工程或实施代码。

`机会与目标 → 业务故事与责任边界 → 规则/反例 → Spec → 所需原型与视觉基线 → 业务级 Ticket → 批准交接`

1. 收集真实用户问题、目标与限制，区分已确认决定和待确认假设。
2. 核对根词汇与业务边界，形成 Spec；有 UI 时准备页面、状态和当前视觉基线。
3. 按本仓政策完成用户决定与适用批准，准备业务级 Ticket 及交接描述。
4. 形成 Handoff v5 描述，按 `delivery_kind: strategic-handoff` 执行只读交付预检，再导出完整战略包、独立验包并记录版本摘要；把研发待决项和影响范围交给下游。

战略交接完成不等于产品发布。下游需要重新对账并准备其工程契约。

本页为阅读导航，不复制定义阶段或批准政策。权威是本仓 .template-spec/process/lifecycle-registry.yaml、.template-spec/process/harness-profile.yaml 与 .template-spec/agents/digital-human-roles.yaml。

完整操作见[战略设计子项目用户手册](战略设计子项目用户手册.md)；输入、输出和命令见[设备借用案例](设备借用贯穿案例.md)。
