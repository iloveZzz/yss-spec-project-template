# 外部输入问卷

当前工作单元在信息掌握于他人时使用本合同。复用已知接收人和目的，仅询问影响问卷的缺口；草稿不授权对外发送。

明确接收人的角色、专业背景、与提问者关系，以及需要取回的具体事实或决定。围绕信息缺口起草问卷，重要问题优先，一个问题只问一件事，每题留答案位置。超过少量问题时按主题分组，说明答案用于哪个决定。允许部分回答和“不知道”，不把沉默视为批准。

## 问卷模板

在获准的当前阶段资产目录保存 `external-input-<slug>.md`：

- 标题、目的、发起人、接收人、答案用途。
- 一段必要背景，避免假定对方读过当前对话。
- 截止时间、预计耗时与不确定答案的标注方式。
- 分主题的问题、必要时一句原因、每题答案位置。
- 最后一个补充问题：还有哪些影响决定的信息未被覆盖？

## 暂停与恢复

未收到答案时保持 `pause.reason_code: external-input-required`，保存 `questionnaire_ref`、`recipient_role`、`requested_outputs` 和 `resume_route`。答案回流后保存 `response_ref`、`reclassified_impact`、`updated_authoritative_asset`，重算 stale、门禁与 frontier，再由编排器恢复原工作单元或合法的 Spec 入口。收到回复不等于自动批准；原门禁与真实用户决定规则仍适用。
