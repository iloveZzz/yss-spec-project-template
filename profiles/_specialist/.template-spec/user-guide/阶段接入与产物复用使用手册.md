# 既有成果复用与项目接续

已有需求、原型、API 或代码都可以作为本次工作的入口。告诉 Agent 要完成的结果、采用哪些材料，以及允许修改的位置，Agent 会核实当前事实并接着完成受影响的工作。

本文适用于 CLI 3.8.0 与 Template 5.8.0 的工作方式。来源采用依据、项目验证入口接续的方法在当前主干 `536f6eee` 增强，使用时核对实际安装内容。模板源码、已安装 Bundle 和会话采用的技能分别维护，升级方法见[统一 CLI 说明](unified-cli.md)。

完整工作路径见[用户手册](用户手册.md)，团队演示与练习见[培训材料](培训材料.md)，研发职责见[技术设计用户指南](技术设计用户指南.md)。

## 先说明要接着完成什么

开始时给出已有信息即可，缺少的工程事实由 Agent 调查。

| 信息 | 可提供的内容 | Agent 接着核实什么 |
| --- | --- | --- |
| 目标 | 修订某条规则、还原选定页面、接入 API、修复故障、完成指定需求 | 本次可观察结果与完成范围 |
| 材料 | 文件、Issue、原型入口、OpenAPI、提交或工作树位置 | 内容是否可读、采用版本、实际适用范围 |
| 工程 | 仓库链接、目录、Home 中的工程名称 | Git 根、remote、分支、worktree、源码和构建入口 |
| 允许动作 | 只读分析、改指定文件、实现需求、运行本地验证，或已有提交与交付授权 | 各仓允许读写路径及外部动作范围 |
| 已有结果 | 已确认决定、运行记录、尚未解决的问题 | 哪些结果仍对当前文件成立，哪些需要复查 |

可直接使用下面的请求。方括号替换为实际内容。

```text
继续完成[目标]。采用[规格或材料位置及版本]，工程使用[目录或仓库]。
允许修改[范围]，已有决定沿用[位置]。请先核实当前工作树和输入，
复用有效成果，完成受影响工作，并说明实际验证及剩余事项。
```

## 从不同成果进入

| 已有成果 | Agent 的动作 | 本次应得到的结果 |
| --- | --- | --- |
| 业务想法、需求或会议资料 | 核实目标、来源与已确认规则，调查事实，定点澄清真实业务取舍 | 当前请求需要的分析或规格修订，保留来源和未决项 |
| 已有 Spec | 沿原规则、FR/AC/OQ 增量维护，检查关联交互与原型 | 同一主 Spec 的一致更新，原确认仍绑定其实际范围与版本 |
| 高保真原型或页面代码 | 核对选定页面、状态、设计规范、交互和模拟范围 | 产品改稿交设计方法，工程落地交前端应用方法，分别报告成果 |
| OpenAPI 或既有服务 | 读取真实契约、参数、错误、权限、分页与调用方 | 按授权完成契约维护、客户端接入或实现，并报告真实联调范围 |
| 已有代码或故障 | 读取实际入口、调用方、配置和日志，沿工程结构定位问题 | 本次实现或修复，以及对应的行为与回归证据 |
| 已安装 YSS 的旧项目 | 核实程序来源、项目收据、已安装技能和本地定制 | 按本次目标继续工程工作，升级同步任务另按实际差异处理 |

完整产品 Spec 交付业务规格、高保真交互原型及交互说明。局部修订按受影响范围进行。业务拆票在明确要求时组织，技术设计与实现按研发请求承接。详细能力衔接见[Profile 技能地图](../agents/profile-skills.md)。

### 只有原型时

先区分页面已经表达的行为与仍需决定的业务规则。模拟数据、模拟请求和演示状态保留其用途，真实 API 由后端或契约仓维护。前端可先完成已明确的布局和交互，并在交付中标明模拟运行及待联调部分。

```text
按[原型入口和版本]实现[页面范围]，沿用[目标前端工程]。
先核对规格、交互说明、资源和模拟边界，完成可独立验证的前端工作。
接口采用[契约位置]。缺失部分请具体列出，涉及业务取舍时定点澄清。
```

### 只有接口或代码时

从实际行为与本次目标核实差距。既有实现可以证明当前代码怎样处理请求，已部署行为还需对应环境证据。业务规则有冲突时保留各处来源及影响，已有明确规则继续用于研发。

```text
阅读[工程或API位置]，核实[具体行为]。本次目标是[结果]，允许[分析或修改范围]。
请检查实际调用方、错误与权限边界，区分代码观察、运行结果和待确认规则。
```

## 核对材料版本与缺口

1. 采用用户指定的提交、原型版本或工作树。使用当前文件时保留相关路径、未提交差异和观察时点。
2. 在依赖材料开始工作、交付前及收到来源变化时，复读真正消费的规则和契约。
3. 将变化定位到受影响页面、接口、调用方和验证，只更新这些部分。其他仍有效的成果继续复用。
4. 关键事实缺失时先调查。只有业务方能决定的结果、权限或验收取舍，才向业务方澄清。

| 核实结果 | 接着如何处理 |
| --- | --- |
| 材料可读、规则清楚 | 直接完成已授权范围 |
| 材料暂时不可读 | 说明具体缺口与影响，继续有依据的独立工作 |
| Spec 与原型冲突 | 定位两处来源，澄清影响业务结果的分歧 |
| 工程技术细化保持业务结果 | 在工程内判断并记录依据 |
| 上游实质修改已消费规则 | 更新受影响实现和检查，保留旧观察的原版本含义 |
| 必需接口或运行环境缺失 | 完成可独立部分，列出尚未验证的路径及其前提 |

## 从 Home 进入一个或多个工程

Home 保存产品目标、业务规格、原型和仓库导航。Agent 从已有 `REPOSITORIES.md`、README 索引或用户明确路径定位工程，再核实实际 checkout。一个产品可以关联多个 Backend、Web、Mobile 与共享组件，同仓多工程用仓库身份加子路径定位。

1. 读取目标工程的 AGENTS、局部规则、构建资料和适用技能，命令在目标工程执行。
2. 优先采用目标工程有效技能及相对资源，再按任务使用 Home 或宿主中来源可核实的共享内容。
3. 明确各仓允许修改的路径、采用输入和接口依赖。共享 OpenAPI、客户端、锁文件及共享组件安排一名整合负责人。
4. 独立任务在路径和运行资源可隔离、宿主支持且有收益时并行，其余依赖顺序完成。
5. 逐仓说明实现、检查和上下游影响，必要集成完成后再判断整体目标。

切换 shell 目录后仍需显式读取目标规则。worktree 共享的端口、数据库、输出目录和运行程序要分别核实。涉及子模块时沿真实 Git 边界处理。详细方法见项目中的 `implement` 仓库范围参考，以及 `setup-yss-harness` 的跨工程接续参考。

```text
从[Home目录]继续完成[跨仓目标]，后端使用[目录]，Web使用[目录]。
规格采用[位置及版本]，API以[后端或契约仓位置]为准。
允许修改[各仓范围]。请核实各工作树和规则，按实际依赖分工，
由一人整合共享契约，最后逐仓汇总检查与必要联调结果。
```

## 新会话继续已有工作

把上一轮任务说明、交付回复或已有实施记录交给 Agent 即可。记录中可继续定位这些内容即可，无需额外创建统一状态文件。

| 需要恢复的内容 | 新会话实际核对 |
| --- | --- |
| 目标、完成条件与授权 | 本次仍需完成什么，哪些动作已获授权 |
| 工程与输入 | 当前工作树、规则、规格、契约及相关未提交内容 |
| 已完成事项 | 实际文件、命令结果、浏览器操作与证据 |
| 运行现场 | 服务对应工作树、端口、数据和输出归属 |
| 剩余事项 | 具体依赖、未决决定、受阻验证及下一动作 |

当前主干 `536f6eee` 补充了来源冲突和验证入口接续方法。遇到同名技能或来源更新时，核对实际采用的正文、资源与读取依据。需要运行时，优先从已有技能、README、运行说明和用例找到真实启动、就绪、正常异常路径与清理办法。中断后先核实现场，清理前再次确认本任务资源归属。

```text
依据[上一轮记录位置]接续[目标]。先检查实际工作树、输入变化和运行资源，
保留已有有效结果，只补受影响工作。请说明采用的技能来源、
实际运行结果、残留资源及未完成事项。
```

## 查看交付是否覆盖本次目标

交付应能定位实际材料，解释完成了哪些行为、检查了哪些范围，以及仍依赖什么。源码实现、模拟运行、构建、测试、真实联调和部署分别报告。涉及新版本材料时，核对检查对应的是本次采用内容。

需要 PR/MR 交付时，在请求中明确接收方、目标仓库与选定产物，Agent 使用 `handoff` 组织真实文件变更并回读平台结果。提交、推送、合并、部署和发行继续沿各自动作的已有授权执行。
