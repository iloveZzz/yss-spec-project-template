# YSS 全团队培训讲义

本讲义面向产品、需求、设计、前后端研发、测试和项目协作人员。通过虚构的“团队设备借用”案例，练习从需求澄清、规格与原型到研发、验证、交付和后续维护。讲师可按演示顺序授课，学员在各自临时训练项目完成练习。

操作基线为已核实的 CLI **3.8.0** 与 Template **5.8.0**。模板当前 `main` 的补充方法单列在文末，使用时核对实际技能与必要资源，CLI 受管安装同时核对 Bundle 来源。日常操作从[用户手册](用户手册.md)和[CLI 导航](unified-cli.md)进入。

从空目录串讲完整项目时，使用[客户跟进项目全生命周期 Demo](客户跟进项目全生命周期Demo.md)，沿同一项目学习技能选择、产物衔接、问题修复和测试环境交付。本页提供设备借用的分角色演示与练习。

## 课程目标

完成训练后，学员能够完成以下任务。

- 根据目标选择 Spec、Backend、Frontend，以及 `project`、`skills` 安装范围。
- 从已有资料继续工作，交付可核对的规则、原型和交互说明。
- 将工作台答复回写原问题、规则与验收，保留真实答复关联。
- 从产品 Home 定位实际工程，完成一个小范围研发任务并逐仓说明结果。
- 记录原型模拟、工程检查、真实联调和部署各自取得的结果。
- 更新有来源的 Wiki，并在同步冲突或中断后保留现场、诊断和续办。

## 建议安排

建议安排 **240 分钟**，含演示和分组实操。时长为授课建议，可根据学员经验调整。程序下载、依赖安装和训练工程预热宜在课前完成。

| 环节 | 建议时长 | 学员当场产出 |
|---|---|---|
| 目标、角色和案例规则 | 15 分钟 | 本组练习范围 |
| 演示一，安装与接续已有工程 | 25 分钟 | 临时 Home、安装来源与工程入口 |
| 演示二，规格、原型和工作台答复 | 45 分钟 | 主 Spec、可操作场景与答复回写 |
| 演示三，Home 多仓研发与验证 | 45 分钟 | 一个研发切片、逐仓检查与交接说明 |
| 演示四，Wiki 证据维护 | 30 分钟 | 主题综合及来源变更处理 |
| 演示五，同步冲突和中断恢复 | 30 分钟 | 现场诊断、受影响文件与续办动作 |
| 练习、互查和答疑 | 50 分钟 | 练习结果与未完成项 |

## 角色路径

全员先参加环境准备与案例讲解，随后主做本职任务，并参与一次相邻角色的检查。

| 角色 | 主做内容 | 交给下一位的具体材料 |
|---|---|---|
| 产品、需求、业务负责人 | 澄清取舍，核对范围、权限、状态与验收 | 采用版本明确的主 Spec、已答复与仍待决定的问题 |
| 设计、原型制作者 | 将规则落实为页面、状态、动作和反馈 | 原型入口、运行与重置方式、规则对应和模拟范围 |
| Backend | 完成领用行为及服务端保护 | 当前接口、实现位置、权限与竞争处理、实际检查结果 |
| Frontend | 还原交互，接入实际接口并处理错误 | 采用的设计版本、页面与组件、浏览器结果、联调状态 |
| 测试、质量人员 | 检查成功、拒绝、竞争与恢复 | 测试前提、操作、可观察结果、未覆盖项 |
| 项目负责人、技术负责人 | 明确工程和写入范围，协调依赖、汇总结果 | 各仓采用版本、完成范围、剩余依赖与下一责任人 |

Spec 保存业务规则与产品设计，生产 API、技术方案、源码和工程验证留在其所属工程。能力与衔接见[技能地图](../agents/profile-skills.md)。

## 准备训练环境

### 讲师课前准备

1. 核对程序的 `version --json`、来源与 Bundle，确认 CLI 3.8.0、Template 5.8.0。首次安装交给 Agent 按正式发行资产、平台和摘要完成，方法见[安装与升级](cli/install-and-verify.md)。
2. 每组准备一个独立临时父目录，其中使用 `equipment-home`、`equipment-api`、`equipment-web`。个人工作台数据放在独立 `workbench-data`，位于所有训练项目与 Git 工作树之外。
3. 准备可运行的训练版后端、前端，提供启动说明、虚构数据重置方法、当前接口和训练账号。框架、数据库与依赖以训练工程实际声明为准。
4. 需要展示从零生成时，在另一全新目标演示脚手架，然后按需要接入对应 Profile。Java 参数与版本见[Backend 教程](cli/tutorial-backend.md)，Vue 生成与启动见[Frontend 教程](cli/tutorial-frontend.md)。
5. 每组使用独立端口、测试数据和输出位置。课前跑一次正常、无权限与已占用路径，保留执行结果和环境限制。

本讲义提供演示方法与练习输入。课堂训练工程、依赖和数据由讲师准备，缺项写入本次安排，并调整受影响的实操范围。

### 开场核对

讲师展示程序实际路径，后续沿用同一程序。学员读取训练工程入口和工作树，核对本组可写目录。以下命令形状须先用所装版本帮助核实，尖括号替换为真实值。

```text
yss version --json
yss help
yss init --help
yss attach --help
yss sync --help
yss workbench --help
```

课堂写入限定在本组临时项目及工作台数据目录。提交、推送、对外发送、部署与发行分别沿用对应动作授权。讲师只停止本组创建的进程，清理前核实路径、进程与数据归属。

## 教学案例与验收

以下规则全部为**教学假设**。真实产品沿用已有业务决定，教学内容保留在训练项目。

### 故事与本次范围

员工申请借用设备，指定审批人审批，设备管理员办理领用与归还。本次详细制作和实现“已批准申请领用设备”，其他环节采用讲师提供的训练数据。采购、维修、费用、通知、代领和超期处罚列在本次范围之外。

| 编号 | 教学规则 |
|---|---|
| FR-01 | 申请人可查看自己的申请。指定审批人可处理分配给自己的申请。设备管理员可查看并办理本组训练申请的领用。 |
| FR-02 | 申请状态包含待审批、已批准、已驳回、已领用、已归还。指定审批人只能对待审批申请作出批准或驳回。 |
| FR-03 | 批准只改变申请状态。管理员办理领用时，申请须为已批准且设备可借。成功后申请变为已领用，设备变为借出。 |
| FR-04 | 同一设备在任一时点最多有一张已领用申请。两张已批准申请竞争领用时，只允许一张成功，另一张保留已批准并提示设备已被领用。 |
| FR-05 | 对同一已领用申请再次领用，反馈已领用，保持现有记录。无权限操作被拒绝，申请与设备状态保持原值。 |
| FR-06 | 管理员可办理归还，使申请进入已归还、设备恢复可借。重复归还反馈当前状态并保留原记录。课堂只观察该转换，新增归还界面留待后续独立任务。 |
| FR-07 | 领用请求超时后，界面提示结果待核实，并查询当前申请与设备状态恢复。查清结果后再决定下一动作。 |

训练设备为 `E-001`、`E-002`，申请 `A-001`、`A-002` 均已批准且关联 `E-001`，初始设备可借。每个独立验收场景执行前按训练工程的方法重置，保留执行中的实际结果。

### 本次可观察验收

| 编号 | 初始状态与操作 | 预期结果 | 依据 |
|---|---|---|---|
| AC-01 | 管理员打开 A-001 并确认领用 | A-001 已领用，E-001 借出，能查询对应记录 | FR-03 |
| AC-02 | 普通申请人尝试办理 A-001 领用 | 显示无权限，申请和设备状态保持原值 | FR-01、FR-05 |
| AC-03 | 两个管理员会话竞争领用 A-001、A-002 | 恰好一张已领用，另一张已批准并提示冲突，同设备只保留一个有效领用 | FR-04 |
| AC-04 | 对已领用的 A-001 再次提交 | 显示当前已领用，记录数量与状态保持原值 | FR-05 |
| AC-05 | 模拟领用提交后超时 | 显示结果待核实，查询后按真实状态恢复显示和操作 | FR-07 |

澄清演示先将 FR-03 的“批准时是否占用设备”暂记为 `OQ-01`，其余假设照常给出。由扮演业务负责人的学员答复后，补齐 FR-03、AC-01、AC-03 和对应原型。

## 演示一，安装与接续已有工程

### 新建训练 Home

讲师给 Agent 以下任务，并补充本组真实目录。

```text
请在指定的临时父目录中创建 equipment-home，使用 Spec / project。
先核对已安装 CLI 的版本、来源、Bundle 和实际帮助，再完成安装。
本次允许修改这个新 Home，结果请说明目录、来源、技能和尚未配置的关系。
```

Agent 可先展示同一操作的预览，再直接执行已授权写入。

```text
yss init --root <训练Home绝对路径> --profile spec --installation project --dry-run
yss init --root <训练Home绝对路径> --profile spec --installation project
yss skills list --root <训练Home绝对路径> --json
yss doctor --root <训练Home绝对路径> --json
```

学员观察预览与安装结果，核对默认技能和真实文件。安装提供方法和入口，真实工程关系在后续配置。完整参数见[命令参考](cli/command-reference.md)。

### 接续讲师提供的工程

1. 展示已有后端、前端的 README、AGENTS、Git 身份、工作树和启动说明，指出一处用户定制。
2. 普通已有工程使用对应 Profile 的 `attach --installation skills`。已有受管工程沿原 Profile 和安装范围使用 `sync`，先读取收据与帮助。
3. 核对原源码、依赖、业务资料和定制内容，再检查技能、必要资源与入口。冲突按演示五处理。
4. 旧 Go 格式或旧家族收据保留原目录，在新目录准备 Rust 接入，按实际诊断决定后续工作。

```text
yss attach --root <普通已有后端绝对路径> --profile backend --installation skills --dry-run
yss attach --root <普通已有后端绝对路径> --profile backend --installation skills
yss attach --root <普通已有前端绝对路径> --profile frontend --installation skills
```

**当场核对**，说清每个安装根的 Profile、范围与采用来源，找到一处原有定制和对应技能入口。方法见[既有成果复用](阶段接入与产物复用使用手册.md)。

## 演示二，规格、原型和工作台答复

### 形成小范围规格与原型

在 Home 会话提供案例表、范围与临时项目位置，保留 `OQ-01` 等待课堂答复。

```text
请按本讲义教学假设完善“已批准申请领用设备”的业务规格、
高保真可操作原型和交互说明。读取训练项目已有资料，复用有效内容。
批准是否占用设备记为 OQ-01，当场说明它对两张申请竞争领用的影响。
本次仅修改训练 Home。原型使用模拟数据，覆盖成功、无权限、
已占用、重复操作和超时恢复。交付查看与重置方法、规则对应、
实际操作结果和未覆盖项。
```

1. 学员检查问题、范围、角色、FR、AC 与 `OQ-01`，定位它对 FR-03、AC-01、AC-03 的影响。
2. 新需求无已有约定时，采用首次创建日期和具体主题的固定 key，例如 `2026-11-16-equipment-checkout`。同需求续改沿用 key、文件和规则编号。
3. 主 Spec 关联交互说明与实际原型。正文链接相对文档，工作台 `resources.target` 相对项目根。
4. 分别操作成功、无权限、占用冲突、重复与超时场景，重置后核对 AC。制作与运行方法见[Spec 教程](cli/tutorial-spec.md)。

### 登记同一主 Spec

先核对实际 `workbench register/request/respond --help`。本组所有工作台命令沿用同一独立数据目录，主文件路径取实际保存结果。

用于独立演示的最小元数据如下。Agent 将该 JSON 对象放入主 Spec 唯一的 `<!-- yss-spec {JSON} -->` 注释块，再补充正文规则与验收。这里的空资源数组表示尚未关联原型，产物实际保存后再填入真实路径。

```json
{
  "schemaVersion": 1,
  "scope": "教学演示，已批准申请领用设备",
  "contentStatus": "draft",
  "resources": [],
  "questions": [
    {
      "id": "OQ-01",
      "title": "批准时是否占用设备",
      "kind": "decision",
      "impact": "影响领用条件和同设备两张申请的竞争结果",
      "recommendation": "批准不预占设备，领用成功时占用设备",
      "blocking": true,
      "affectedScope": "FR-03、AC-01、AC-03",
      "status": "open",
      "resolution": "",
      "appliedDecisionId": null
    }
  ]
}
```

```text
yss workbench --data-dir <训练工作台数据绝对路径> register --root <训练Home绝对路径> --source <主Spec项目相对路径> --json
yss workbench --data-dir <训练工作台数据绝对路径> --no-open
```

打开实际返回的本地地址，展示同一主 Spec 的范围、资源与 `OQ-01`。保留登记返回的真实 Spec ID，原型资源引用已存在且可核对的项目内产物。当前 web 资源在确认前需替换为项目内已核验快照，原链接可留在正文来源。

### 保存答复并回写

1. 业务负责人在聊天或工作台明确答复“批准不预占设备，领用成功时占用设备”。
2. Agent 读取当前问题摘要与已有答复。聊天已答时按实际接口保存答复，取得真实返回 ID。
3. Agent 更新原 FR-03、AC-01、AC-03、交互说明与原型，回读核对一致。
4. 保留原 `OQ-01`，填写解决依据、`status: "resolved"` 与真实 `appliedDecisionId`，再次登记同一主文件。
5. 学员核对当前产物与问题处理结果。用户要求确认且内容具备条件时，记录其对展示范围与版本的明确确认，后续实质变化再核对受影响内容。授权研发按当前任务继续开展。

```text
yss workbench --data-dir <训练工作台数据绝对路径> request --spec-id <真实SpecID> --json
yss workbench --data-dir <训练工作台数据绝对路径> respond --spec-id <真实SpecID> --question-id OQ-01 --question-digest <当前问题摘要> --kind answer --answer "批准不预占设备，领用成功时占用设备" --json
```

**当场核对**，保存答复后观察待回写状态，再观察回写完成结果。沿原 FR、AC、问题 ID 与真实答复 ID 还原决定。参数和元数据见[命令参考](cli/command-reference.md)。

### 处理延期

追加问题“超期是否自动通知”。业务负责人明确将通知排除出本轮，说明原因、影响与复查条件。Agent 保存延期答复，原问题保留 `status: "deferred"`、非空 `resolution` 和真实 `appliedDecisionId`，核对本次范围已排除通知。

再将问题换成“领用时是否允许设备已经借出”。学员应指出它直接决定 AC-01、AC-03，当前领用范围仍依赖该决定，需完成澄清后才能确认。延期参数与日期时区沿[命令参考](cli/command-reference.md)处理。

## 演示三，Home 多仓研发与验证

### 核实工程关系

明确本次允许修改训练 Home、API、Web。Agent 读取已有地图或 README 索引，核实实际工程。需要独立地图时在 Home 创建 `REPOSITORIES.md`，记录稳定身份、职责、资料入口和关系。本机路径、当前分支和端口保留在任务上下文。

| 训练工程 | 保存内容 | 本次负责范围 |
|---|---|---|
| equipment-home | 业务规则、原型、交互说明与工程导航 | 采用版本和研发发现的业务回写 |
| equipment-api | 技术方案、真实 API、实现与工程验证 | 领用条件、权限、竞争与查询恢复 |
| equipment-web | 页面、组件、接口调用与浏览器验证 | 领用界面、错误反馈与超时后查询 |

一个安装根使用一个 Profile。同仓多工程按仓库身份与不重叠子路径定位，父子安装根的物理文件所有权、运行资源分别核实。方法见[Spec / Home 教程](cli/tutorial-spec.md)。

### 从分析交接到明确研发

先演示只读分析请求。

```text
请阅读训练 Home 中选定的 Spec、原型与交互说明，以及 equipment-api、
equipment-web 的实际入口和代码。分析领用切片涉及的规则、接口、权限、
竞争处理、前后端调用和验证方式，给出文件位置与缺口。本轮任务只读。
```

随后明确授权实现。

```text
请在训练 API 和 Web 实现领用切片，采用刚才核对的材料版本。
沿用实际架构与组件，服务端保证权限和同设备最多一个有效领用，
前端接入实际接口，按规则处理占用、重复与超时恢复。
允许必要的本地工程检查和训练数据重置，保留他人修改。
共享 API 由一人维护，依赖明确后安排可隔离的工作。
交付实际修改、命令与结果、浏览器操作和剩余事项。
```

1. Backend 沿实际 DDD 或 MVC 结构确定条件检查、事务或并发保护、失败语义与查询入口，维护生产 API 和数据实现。
2. Frontend 沿选定原型与实际接口还原，接口未就绪时完成独立部分，记录模拟范围和待联调点。
3. 并行前确定共享契约、生成客户端、锁文件和共享组件的整合者，核实各写入路径、端口、数据与输出。
4. 新的业务取舍定位到原 FR/AC 反馈 Home，等义技术细化沿已确认要求继续完成。

后端方法见[Backend 教程](cli/tutorial-backend.md)和[技术设计](技术设计用户指南.md)，应用工程见[Frontend 教程](cli/tutorial-frontend.md)。

### 验证与交付

采用实际工程支持的检查命令，后端优先根 `./mvnw`，前端优先 `pnpm`。本次竞争规则需观察并发请求及最终状态，权限规则需检查服务端拒绝。

| 检查层面 | 课堂观察 | 记录内容 |
|---|---|---|
| 原型 | 按 AC 操作模拟页面 | 场景、进入和重置方法、实际结果 |
| 工程检查 | 执行适用构建、类型、静态或测试命令 | 实际命令、结果和失败原因 |
| 服务端 | 成功、无权限、重复与两申请竞争 | 身份、初始数据、响应与最终状态 |
| 浏览器与接口 | 同视口、数据、主题和状态对照原型，操作实际接口 | 页面反馈、请求来源、服务版本和联调覆盖 |
| 超时恢复 | 在训练环境制造受控超时，再查询当前状态 | 待核实提示、查询结果与恢复后的操作 |

逐仓交付文件、采用输入、实际执行、剩余问题和运行方式。后端完整交付更新有源码依据的构建部署说明，未知平台、健康入口和回滚条件保持未知。课堂交付本地材料，对外发送或发布核对目标与动作授权。

**当场核对**，测试人员从 FR-04 找到实现和 AC-03 的结果，前端人员指出请求实际 API 来源。模拟部分明确待联调，尚未执行的检查保留未验证状态。

## 演示四，Wiki 证据维护

明确调用 `llm-wiki`，创建或复用训练 Home 的 `wiki/`。将主 Spec、业务负责人实际答复和已读工程结果作为来源，整理“设备领用规则与实现情况”。

```text
请使用 llm-wiki，在本组训练 Home 的 wiki 整理设备领用规则与实现情况。
复用已有主题和导航，分别记录教学规则、真实答复与工程执行观察。
关键结论给出来源位置、采用版本或读取时间，保留人工编辑。
```

1. 读取索引、相关主题与来源，综合批准、领用占用与单设备有效领用的关系。
2. 规则引用 Spec 的 FR，实现结论引用实际仓库、提交或工作树、路径与检查时点。派生摘要沿证据链回到原件。
3. 加入一段学员人工说明，明确标为人工所有，后续刷新保留该段正文。
4. 给出新教学决定“仅 E-002 由指定管理员领用”。核实对象与范围后，更新原 Spec 及受影响验收、原型和工程任务。
5. 先只读巡检 Wiki 中仍声称“所有设备管理员均可领用 E-002”的旧主张，给出位置、旧新来源、影响和建议。
6. 再明确授权更新受影响的主张与导航，复查已知派生页面和来源链接，核对人工正文及当前规则。

**当场核对**，从主题回到两条原始依据，解释结论的有效范围和时间，找到仍待工程验证的主张。

QMD 为可选检索工具。课堂默认沿文件和来源链接完成，明确启用时再核对集合、知识根和专用派生状态目录，按所装版本帮助操作。工具安装、查询和索引更新各依实际授权，知识正文与 SQLite、缓存等派生状态分别核查。方法随实际安装的 `llm-wiki` 提供。

## 演示五，同步冲突和中断恢复

### 受控同步冲突

在课前准备的受管训练副本保留一处本地定制，选用会触及同一路径的新 Bundle。新旧内容、收据和原始用户文件留在训练目录。仅改本地文件时 CLI 可能安全保留变化，讲师按实际输出讲解。

```text
yss doctor --root <受管训练副本绝对路径> --json
yss sync --root <受管训练副本绝对路径> --dry-run --json
```

1. 阅读诊断，区分受管差异、来源变化、冲突与未完成事务，定位具体文件。
2. 对照本地定制、旧基线与新内容，说明可合并部分和需任务所有者决定的部分。
3. 在明确范围处理冲突，复读目标后重试同步，核对用户定制、业务材料和收据。
4. 同步已报冲突时先解决，再检查缺失技能与后续接入。保留控制文件和备份。

### 中断后续办

未完成 CLI 事务演示采用讲师预先准备的隔离现场，展示 `doctor`、`recover --help`、恢复预览和实际结果。缺少该现场时完成诊断题，注明事务恢复尚未实操。

```text
yss recover --help
yss recover --root <隔离事务现场绝对路径> --dry-run --json
```

`recover` 处理未完成事务或已提交事务的安全清理，按诊断与授权执行后核对文件、收据和残留项。方法见[维护与恢复](cli/tutorial-maintenance.md)和[错误处理](cli/error-index.md)。

研发中断后，重新核实采用 Spec、工作树、运行服务、配置与数据，识别已完成与待处理部分。规则实质变化时只重做受影响工作，保留先前版本的真实结果及适用范围。

**当场核对**，指出冲突文件和本地定制，说明失败步骤、保留内容、重试入口与仍待验证的结果。

## 实操练习与参考解答

建议每组 3—5 人，轮流承担业务负责人、Agent 操作者、研发与验证者。每项保留材料位置和观察结果，按下表互查。

| 练习 | 学员任务 | 可观察验收与参考解答 |
|---|---|---|
| A，接续已有工程 | 为含定制 README、已有源码的普通训练工程选择接入方式 | 选对应 Profile 的 `attach skills`，核对冲突和保留内容。受管目录用 `sync`，新目录或空目录用 `init`。给出 Profile、范围、程序来源和定制位置。 |
| B，答复回写 | 将聊天中对 OQ-01 的答复应用到 Spec、AC 与原型 | 沿同一主文件和 OQ-01，使用当前摘要保存真实答复并取得 ID，回写 FR-03、AC-01、AC-03 和相关产物，核对后标 resolved 并关联 `appliedDecisionId`。再次 request 可定位记录。 |
| C，局部延期 | 延期超期通知，保留领用主范围 | 原因、影响、排除范围和复查条件齐备，原问题保留 deferred、非空依据与真实答复 ID。通知从本轮排除，领用验收可执行。 |
| D，多仓领用 | 从 Home 协调服务端与前端改动，执行 AC-01 至 AC-05 | 实际来源、工作树和输入可定位，共享接口有整合者。竞争只成功一张，无权限被服务端拒绝，超时查询后恢复。缺项说明具体条件。 |
| E，来源变化 | 更新 E-002 指定管理员规则与 Wiki，保留人工正文 | 新旧依据可追溯，检查相关摘要、主题与保存答案，范围准确、人工段落保留，越出授权或失去唯一支撑的主张有处理说明。 |
| F，冲突与续办 | 分析 sync 冲突输出和研发中断现场 | 指出失败位置、用户内容、采用版本和下一动作。事务按 recover 范围处理，研发按工作树与运行现场续办，区分实际恢复与尚未实操。 |

讲师可追问以下三题。

1. 工作台已保存答复，原型仍按旧规则工作，如何交付。参考处理为沿原问题完成规则、AC、交互说明和原型回写并核对，保留当前未完成情况。
2. Vue 构建成功，API 尚未启动，如何写结果。参考表述为前端已完成实际检查的部分，当前采用模拟或尚待接口验证，列出启动与联调条件。
3. Home 记录五个工程，本轮只涉及 Web 和客户 API，如何分工。参考处理为核实调用链后调整受影响工程，其余关系继续作为查找入口。

### PR/MR 持续跟进补充练习

当前 main 的 `c8c61688` 另加入 PR/MR 持续跟进方法。授课时读取本工程有效参考，使用讲师提供的脱敏 PR/MR、讨论和 CI 记录完成桌面推演。

1. 记录目标、完成条件、源 head、目标分支和已有动作授权。
2. 给出一条旧 head 的绿色检查和一条新 head 的失败，学员定位新检查的真实对象并调查原因。
3. 给出一条过时位置的讨论，学员根据当前代码和规则判断问题是否解决，说明证据与待处理项。
4. 给出自动合并入队结果，学员记录服务端状态和仍需观察的版本、检查与反馈，直到目标条件有实际结果。
5. 模拟一次写入响应超时，续办时先核对实际结果，再决定后续操作。

验收时应能从记录找到目标版本、检查对象、反馈处理依据和最后结果。真实评论、推送、CI 重试或合并按各自动作授权在训练仓操作，课堂推演只记录方案和未知项。

## 讲师收尾

每组用五分钟展示一条规则从来源、Spec、原型到实现与验证的对应，再演示一次问题回写或冲突续办。讲师记录实际完成练习、环境限制和下一待办，在现有材料中保存必要结果。

课程结束后核实本组运行资源，停止本组创建的服务，按训练约定处理临时数据与工作台目录。需要保留成果时先确认位置、来源和共享范围，再执行已授权的保存或交付。
