# Backend Plan 旧资产接入

本说明适用于 Backend Profile。以 `.template-spec/process/harness-profile.yaml`、`.template-spec/process/lifecycle-registry.yaml` 和当前 `.template-spec/process/orchestration-contract.yaml` 判断本端职责、Plan 入口与退出条件，不套用其他 Profile 的阶段或门禁。

旧需求、Plan、事实和决定可作为来源，按当前 `.template-spec/plan/templates/plan-template.md` 整理本端目标、范围、业务规则、证据、验收及未决项；注明来源、当前版本、适用范围和复用理由。影响后端关键规则或当前决定的未决项先解决；允许延期的非关键项须记录依据、责任人、解决时点和接收方。

历史冻结文档、批准记录及摘要保持原字节；旧状态不直接恢复当前流程，新草案不继承旧批准。需要继续正式工作时，按现行政策核验当前资产、真实授权和适用门禁；输入缺失、身份不支持或证据失效时阻断受影响工作，不补造批准或接收结果。

显式上游战略交接按 `.template-spec/process/strategic-handoff-package.md` 核验来源和接收记录。本端已有的批准资产可按当前合同复用，不为本地来源补造外部接收回执；前端实现由独立规格处理。
