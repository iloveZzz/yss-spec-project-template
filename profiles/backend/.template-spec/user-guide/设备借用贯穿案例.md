# 设备借用：后端交付职责案例

本文是虚构教学材料，不是已批准合同或真实环境证据。目标是实现“已批准申请领用设备”的后端切片，并向前端交付可核验接口、构建和部署身份。

## 1. 接收战略输入

```sh
node scripts/strategic-handoff verify --bundle <战略包目录或ZIP>
node scripts/strategic-handoff import --bundle <战略包目录或ZIP> --target-root .
```

```text
请读取导入收据、源规则和关键场景，完成目标 CONTEXT.md 对账。
逐项说明“已批准申请领用设备”的承接、冲突和依赖；规则含糊时回交战略方。
```

导入成功不批准本地设计。审批是否预占设备、重复领用结果等业务决定必须来自上游当前资产。

## 2. 固定工程与合同

已有 Java/Maven 工程应提供 repository registration、engineering baseline 和 observation manifest，绑定实际 Git commit、POM、源码范围、架构身份和验证命令。

```sh
node scripts/preflight-delivery --input <后端预检输入.json> --stage prepare --json
```

然后用 `yss-technical-design` 设计设备占用不变量、状态、事务、并发和幂等；API 有影响时完成 OpenAPI Draft/Freeze。Slice Contract 必须绑定“批准申请领用”这一窄路径、允许写范围、公开测试 seam 和回滚点，并取得当前批准。

## 3. 实现与验证

```text
请复验战略、工程身份、技术设计、冻结接口和 Slice Contract 仍然当前。
在登记后端工程实现领用切片，使用项目根 ./mvnw 验证。
覆盖成功领用、未批准、无权限、并发占用和重复请求，保存实际命令、退出码和日志。
```

构建记录必须绑定实际源码提交和制品摘要；部署记录绑定同一制品、环境和原始验证日志。不能用单元测试结果推断服务已部署，也不能把数据库驱动存在写成真实数据库已验证。

## 4. 导出 Backend Delivery

形成交付源记录并完成 export 预检：

```sh
node scripts/preflight-delivery --input <后端预检输入.json> --stage export --json
node scripts/backend-delivery export --source-root . --delivery <交付描述相对路径> --output <新包目录> --preflight-input <后端预检输入.json> --zip
node scripts/backend-delivery verify --bundle <包目录或ZIP>
```

交付包应绑定战略摘要、规则/场景、冻结 API、批准合同、源码、构建制品、部署和测试数据。账号密码不进入包；离线验包不证明真实服务当前可达。

本仓完成结论是 `backend-deliverable`。前端必须重新验证包和真实服务，统一管理方再汇总端到端业务证据。
