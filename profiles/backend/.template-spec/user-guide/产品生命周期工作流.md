# 后端专职工作流

消费批准战略，负责后端设计、冻结接口、后端实现及交付包；前端页面和整体业务验收由对应责任方负责。

`战略接收与对账 → 战术/API设计 → 后端合同批准 → 实现与验证 → 构建部署证据 → 后端交付`

1. 导入战略快照并完成目标词汇/规则/场景承接；未知依赖和冲突回交。
2. 执行 prepare 只读交付预检；既有工程固定三份架构身份原始证据，再按影响准备技术设计、OpenAPI Draft 及 Freeze。
3. 合同获准后在登记后端工程实现窄业务切片，优先根 ./mvnw，验证成功和失败场景。
4. 形成当前切片的交付描述，绑定战略摘要、冻结接口、合同批准、构建、部署、数据和验证证据。
5. 执行 export 只读预检，导出并验包，向前端提供可核验真实环境；本端只记录 `backend-deliverable`。

验包不会检查实时服务可用性；前端联合接收重新探测。整体切片需要统一管理方汇总两端证据。

本页为阅读导航，不复制定义阶段或批准政策。权威是本仓 .template-spec/process/lifecycle-registry.yaml、.template-spec/process/harness-profile.yaml 与 .template-spec/agents/digital-human-roles.yaml。

完整操作见[后端子项目用户手册](后端子项目用户手册.md)；输入、输出和命令见[设备借用案例](设备借用贯穿案例.md)。
