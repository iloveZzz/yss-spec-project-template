# 后端子项目用户手册

Backend 承接明确需求，负责必要技术设计、实现切片、代码与验证。向 Agent 提供目标、已有依据和允许修改的工程，已有信息足够时可以直接开始实现或维护。

本手册说明后端团队日常使用路径。全团队协作见[用户手册](用户手册.md)，演示练习见[培训材料](培训材料.md)，方案职责见[技术设计用户指南](技术设计用户指南.md)，技能组成见[Profile 技能地图](../agents/profile-skills.md)。

版本基线为 CLI 3.8.0 与 Template 5.8.0。当前主干 `536f6eee` 增强了技能来源采用、验证入口和新会话接续方法，需要核对实际安装内容后使用。新建 Backend 的平台默认组合见[Backend 与脚手架](cli/tutorial-backend.md)，工程运行与真实部署结果按目标环境另行验证。

## 每天从当前工程开始

1. 给出本次目标、Spec/票据/错误来源、工程位置和允许动作。已有决定沿原材料复用。
2. Agent 核实 Git 根、remote、分支、worktree 和受影响文件，读取本仓 AGENTS、局部规则、POM、配置和必要技能。
3. 将业务行为对应到真实调用链，找全相关调用方、持久化、接口、测试和配置。
4. 按需补充设计，完成授权实现，选择与本次影响相称的验证。
5. 返回实际修改、采用依据、执行结果和剩余事项。提交、推送、PR/MR、部署和发行按各自动作授权执行。

```text
在[工程目录]完成[需求或修复目标]，依据[Spec/票据/日志位置]。
允许修改[路径范围]，沿用当前架构、版本和已确认规则。
请核对实际调用方，完成必要设计、实现与回归，报告执行结果和未完成项。
```

任务可以从 Home、工程聊天或已有材料进入。Home 协调产品目标与关联工程，后端仓保存技术方案、源码、实际 API 和验证结果。进入另一仓时重新读取其规则，并核实写入范围。跨仓输入与恢复方法见[既有成果复用](阶段接入与产物复用使用手册.md)。

## 按职责选择日常路径

| 读者及任务 | 先给 Agent 什么 | Agent 的主要动作 | 查看哪些结果 |
| --- | --- | --- | --- |
| 产品与需求负责人交付需求 | 规则、验收、原型与模拟边界、未决项 | 沿原 FR/AC 或章节承接，定位业务缺口，已有决定直接用于研发 | 实现对应、规则差异、需要业务决定的具体事项 |
| 技术负责人评估方案 | 行为目标、工程和实际约束 | `yss-technical-design` 分析调用、事务、兼容性与恢复，DDD 聚合按需细化 | 方案依据、影响、验证办法及尚未确定条件 |
| 开发者实现需求 | 明确规则、目标仓和允许修改范围 | `implement` 协调必要设计与分层技能，完成相关调用方 | 源码、配置、接口兼容处理和实际回归 |
| 测试与开发者补测 | 行为、实际代码、现有测试与可用环境 | `yss-backend-testing` 选择层次与场景，读取真实 Maven 执行配置 | 实际运行、失败、跳过和未覆盖范围 |
| 评审者检查改动 | PR/分支/工作树及比较基线 | `code-review` 阅读候选与相关调用链，给出可证缺陷 | 文件位置、触发条件、影响和修复建议 |
| 维护者排障 | 症状、日志、环境、复现和发生版本 | `diagnosing-bugs` 定位共享根因，按授权修复和回归 | 已确认原因、代码推断、实际运行结果及限制 |

完整研发需要细化时，Backend `to-tickets` 将同一可观察行为贯通所需技术层，保留原验收和依赖。独立小改动直接完成受影响部分。设计、审查、测试均可作为单独请求进入。

## 保持工程职责一致

| 范围 | DDD 工程 | MVC 工程 |
| --- | --- | --- |
| 业务规则与状态 | Domain 的聚合、行为和不变量 | 既有 Service 的用例规则和状态行为 |
| 事务、幂等与协作 | Application 的用例编排 | Service 边界 |
| 数据与外部依赖 | Repository、Gateway 的实际适配 | Repository 和既有外部适配器 |
| HTTP 与传输模型 | Controller、DTO/VO 与映射 | Controller、DTO/VO 与映射 |

保留当前分层、POM、包结构和平台线。按实际需求使用校验、异常、映射、缓存、用户上下文、审计、Excel、分布式 ID 或熔断等组件技能，精确 API 从工程解析依赖和对应源码核实。

实现中保留认证、权限、输入校验、SQL 参数绑定、错误脱敏和事务语义。写入限定在本次授权工程与路径，保护未提交内容、未知文件和子模块边界。

### 数据库与 API 变更

数据库结构审查、说明书和 DDL 使用 `database-analysis-docs`，元信息采集限制在已授权对象定义范围。设计说明区分现状、建议和业务未决项，多格式维护采用同源模型。实际迁移按目标数据库、既有工具及对应执行授权处理。

API 变化读取真实 OpenAPI、参数、错误、权限、分页及调用方。后端或契约仓维护生产 API，前端消费选定版本。跨仓调整由一人整合共享契约与生成输出，分别报告契约检查、模拟验证和真实联调。

```text
修改[接口或数据行为]以满足[规则位置]。请核对现有调用方和历史数据，
说明兼容窗口、迁移或发布顺序、失败恢复和验证前提，
完成授权范围内的改动，外部执行按已有授权处理。
```

## 测试怎样真正运行

先读取工程的测试目录、POM、Surefire/Failsafe、模块、Profile、选择器和跳过参数。后端命令优先使用根 `./mvnw`，具体命令从实际配置确定。`test`、`package` 或 `verify` 覆盖哪些检查，需要结合插件绑定与本次日志判断。

| 当前改动 | 重点检查 |
| --- | --- |
| 领域或 Service 规则 | 初始状态、成功、拒绝、边界、重复执行和不变项 |
| 事务、并发与幂等 | 真实边界、竞争结果、部分失败及重试后的状态一致性 |
| SQL、分页和映射 | 查询参数、排序、空值、分页边界及目标数据库行为 |
| HTTP、身份与权限 | 实际请求响应、输入约束、错误体、授权和数据范围 |
| 外部消息或服务 | 提交与投递时点、超时、重复、失败恢复和实际副作用 |
| 多项工作集成 | 集成后的接口、配置、生成文件、测试库、端口与输出目录 |

普通补测和集成验证使用测试方法，明确要求 TDD 或测试优先时采用 `tdd`。运行后检查本次退出码、日志和结果文件，确认目标测试被发现并执行。测试数为零、跳过、环境不可用和业务失败各自说明。实际方法见项目中的 `yss-backend-testing`。

```text
为[已有行为]补充集成验证，沿用当前测试工具和[授权测试环境]。
请先核实Maven插件与Profile，选择能覆盖[具体风险]的场景，
执行后说明目标测试是否运行、结果、跳过项和真实外部依赖覆盖。
```

## 出现故障时怎样排查

| 现象 | Agent 先查什么 | 接着如何处理 |
| --- | --- | --- |
| 构建失败 | 失败模块、首个有效错误、POM 与解析版本 | 定位实际编译或依赖问题，修复后重跑受影响检查 |
| 测试命令成功但目标行为没覆盖 | 测试发现、选择器、插件阶段、跳过项和旧报告 | 修正实际测试入口或范围，报告本次运行证据 |
| 本地正常、集成环境失败 | 启用配置、服务地址、数据库、权限与部署版本 | 比较环境事实，区分代码与环境原因 |
| 重复请求、部分失败或状态异常 | 公共入口、事务边界、幂等处理和真实副作用 | 修复共享根因，核对重试与并发后的状态 |
| 分页、缓存或组件行为不符 | 工程实际版本、配置、调用路径和组件源码 | 使用对应技能定位，保留未知兼容性 |
| 运行了错误工作树的服务 | PID、启动目录、端口、配置和业务响应 | 保护已有服务，使用本任务独立资源重新验证 |

症状明确时直接给出日志和复现条件。原因已有充分依据时做最小修复，原因未定时选择能区分假设的观察。性能结论使用实际测量，日志中的凭据和个人数据脱敏。

```text
[工程目录]在[条件]出现[症状]，相关日志位于[位置]。
允许修复[范围]并运行[授权环境]验证。请读取代码和环境事实，
定位根因、处理调用方并验证原问题及相关回归。
```

## 多人研发与新会话接续

任务可独立推进、依赖明确、路径和运行资源可隔离且宿主支持时，`implement` 可以并行并负责集成。共享 POM、OpenAPI、锁文件、客户端和组件明确单一整合责任。子任务结果在主控实际集成后验证，跨仓按当前版本逐一核对。

新会话先恢复当前任务、工程/worktree、输入版本、已有改动、真实结果、剩余依赖和下一步。使用当前主干 `536f6eee` 方法时，特别核对以下内容。

1. 同名技能、工程切换或来源更新时，核对实际采用正文、必要资源和可见读取依据。
2. 优先从项目已有技能、README、运行说明和用例找到验证入口，复用其中的身份、启动、就绪、正常异常路径与清理方法。
3. 启动后核实工作树、端口、配置与业务可用条件，记录本次创建进程、数据和输出归属。
4. 入口漂移时修订原说明，环境缺失时说明受阻路径。中断和清理失败保留现场及恢复动作，清理前重新核对资源身份。

## 工程接入、同步与交付

首次安装、项目接管、同步与事务恢复使用[统一 CLI 说明](unified-cli.md)，具体参数见[命令参考](cli/command-reference.md)。新工程走[Backend 与脚手架](cli/tutorial-backend.md)，受管旧项目走[维护与恢复](cli/tutorial-maintenance.md)。每次操作先核实实际版本、帮助、Bundle 与项目收据，保护本地定制和未提交文件。

源码生成、skills 安装、Git 接入和业务实现分别报告。新建平台默认组合描述生成选择，构建、测试、启动、外部组件和真实部署各自需要实际证据。完整研发交付按需更新已有 README 或运维说明，写明适用版本、构建运行、配置、迁移、健康检查及恢复前提。

交付至少说明本次行为与文件、采用规则和版本、实际执行命令及结果、模拟或环境限制、剩余事项及上下游影响。详细运行说明维护在工程原入口，便于下一次直接接续。
