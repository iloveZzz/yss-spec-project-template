# 业务 Ticket 拆分

仅用户显式调用。读取已有 Spec、有效决定、适用设计和已有票，复用稳定 ID；Context 存在时沿用业务词汇，不重复生成已存在的票。

Spec 模式按用户行为和可验收结果拆分业务票，参考 `.template-spec/templates/business-ticket-template.md` 的业务内容。每票说明结果、范围、规则/AC 来源、设计对应、成功与失败恢复、业务前后依赖和未决项。可以在现有 tracker、文档或授权草稿中表达，不强制每票一个文件、集合 YAML 或摘要批准包。只有已存在业务集合时才同步其引用及覆盖关系。

不要按 Controller、Service、Repository 或数据库表分票，也不机械地一条 FR 一票。拆分不能新增业务规则或改变原 AC；影响范围、权限或验收的真实取舍回到原决定。无实现仓、API 或构建命令不阻断业务拆票。

研发场景消费这些业务票，按用户当前授权细化贯通必要技术层的窄实现 Slice，保留原业务票和 AC 引用；技术设计与实现选择由研发承担，不回填为 Spec 已确认事实。

展示各票结果、依赖、覆盖与缺口。发布、评论、改标签、分配和关闭使用对应授权，拆票不自动关闭父票或宣布功能完成，不增加主控审批前置。
