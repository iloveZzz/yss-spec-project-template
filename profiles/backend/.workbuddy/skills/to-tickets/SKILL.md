# 按行为拆分研发实现切片

Backend 承接已有 Spec、业务 Ticket 或明确需求，只细化研发实现 Slice。复用已确认讨论、现有票、稳定 ID 和适用设计，不重新访谈、生成平行业务票集或要求先补业务票。

读取实际工程、技术栈和适用设计，再细化需要的实现约束。必要技术方案缺失时，在本次授权范围内使用 yss-technical-design 等研发能力处理；没有依据的 DDL、接口或选型不能写成已确认方案。缺失事实列为未决项并说明影响，继续整理已有依据的行为范围，不要求统一冻结、集合 YAML 或阶段合同才能起草。

Slice 参考 `.template-spec/templates/vertical-slice-ticket-template.md`。模板仅提供内容结构，字段按实际来源填写，没有业务票或集合就省略相应引用，不为填字段新建票集或伪造 ID。已有集合继续维护同一引用与覆盖情况。

一票描述一个完整可观察行为，保留真实业务来源与 FR/AC，不按 Controller/Service/Repository 横向分票，也不机械一条 FR 一票。实现 Slice 只贯通当前行为命中的技术层；纯后端不引入 UI。产品规则、流程或异常未定时说明业务缺口及解除条件，不代替产品决定或补造原型。

研发 Slice 同时写明实际仓库与路径、接口依赖及适用技能，沿用已有验收和稳定 ID。DDD 按领域/用例/持久化职责拆解实现，MVC 沿用 Service/Repository，不因为缺登记或合同编译结果阻止起草，也不将另一仓库的可读资料当作写入授权。

机械重构按 expand → migrate → contract 排序；能独立验证时说明各票验收，不能独立保持绿色时明确共享集成边界，不虚称每批已独立完成。

tracker 沿用明确配置和对应操作授权。远程父子/阻塞关系使用真实 ID，支持时用原生关系，无能力才用文本；已存在原生关系不维护另一套阻塞清单。完整读取相关分页与实际状态，未知状态不当成已解决。普通分析仅在对话给出拆分；只有授权保存/发布才修改条目。

返回每票业务结果、范围、验收、依赖、未决项和实际保存状态。实质改变范围/规则/验收时明确缺少的业务决定；等义细化复用已有授权，不新增审批节点，不强制主控回交、关闭父票或宣布功能完成。
