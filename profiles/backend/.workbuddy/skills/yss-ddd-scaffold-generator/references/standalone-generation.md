# CLI 能力缺口与资产使用边界

新建默认 YSS `4.0.0-SNAPSHOT` / Boot `4.1.2` / Java `17`。五项必填参数、3.2 选择与完整自定义见 [命令示例](command-examples.md)，补全与歧义规则见 [平台选择](platform-selection.md)。

新建空工程优先使用现装 CLI 支持的 `scaffold ddd/mvc`。CLI 缺失时先使用 `setup-yss-harness` 安装，再核对版本、catalog 和帮助。

现装 CLI 缺少用户要求的目标能力时，先记录具体缺口和适用版本。只有保留资产确实覆盖所需结构、版本和依赖，且手工创建属于用户授权范围时，才可由 Agent 评估资产 fallback。资产含教学业务场景，按需参考其实现思路，空工程只创建当前需要的骨架。无法确认兼容性时说明待解决输入。

fallback 继续核对精确平台与 Maven 坐标、路径授权、符号链接、Git 子模块和用户文件保护。目标工程目录须不存在，包括空目录。CLI 因输入无效、已知不兼容、目标已存在或路径保护而拒绝时，先处理拒绝原因。已有工程沿现有架构增量维护。

按 [架构说明](ARCHITECTURE.md) 或 MVC 技能组织模块，Wrapper 使用标准工具或真实已有文件。来源说明记录实际采用的资产与操作。`.yss/scaffold.json` 由 CLI 生成，手工创建时保留真实来源。

按当前任务需要使用工程根 `./mvnw` 验证，文件创建、构建和运行结果分别报告。
