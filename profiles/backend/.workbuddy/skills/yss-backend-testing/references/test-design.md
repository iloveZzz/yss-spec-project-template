# 从行为选择测试

把 Spec 的可观察验收与当前实现对应起来，从实际风险选择正常、边界、拒绝、异常和恢复案例；不为每次小改动建立追踪台账。预期值来自业务规则、已知样例或独立推导，不复制被测实现作为断言。

## 测试层次

| 要验证的行为 | 合适的证据 |
|---|---|
| 规则、计算、状态转换、不变量 | 通过公共接口的单元测试，断言结果与可观察状态 |
| 依赖装配、MapStruct 映射、持久化或事务 | 使用工程实际配置的集成测试，确认真实参与的组件 |
| HTTP 请求校验、认证授权、序列化、分页、错误和兼容性 | 运行对应接口路径并核对协议；DTO 字段或编译不证明 HTTP 行为 |
| 缺陷回归 | 原复现路径及受影响调用方；拒绝/失败后的状态同样检查 |
| 并发、性能、真实数据库方言 | 有明确需求时用对应环境和负载验证，说明测量条件 |

mock 放在真实外部边界，不 mock 被验证的核心规则、事务或映射。如果问题正是外部集成，单元 mock 只能验证调用方逻辑，不能替代真实协议或服务验证。沿用现有框架，不因选择测试层次自动引入新依赖。

## 拒绝后状态示例

库存初始 5，预留 2 成功后应为 3；再预留 4 应拒绝且仍为 3。只断言抛异常会漏掉“先扣库存再校验”的缺陷。分别断言成功结果、拒绝结果和拒绝后的状态；数据库事务场景还需核对实际回滚及事务边界，内存样例不能证明数据库一致性。

从调用链判断失败是否可能导致部分写入、重复副作用或丢失补偿；只为当前命中的风险增加案例。权限拒绝不能仅验证状态码而遗漏敏感数据泄漏；分页要核对实际 wire 协议与排序边界。

## 覆盖说明

需要解释上游验收、来源变化或业务差异时，按项目根读取 `.agents/skills/implement/references/spec-feedback.md`。沿原 FR/AC 或章节说明实现、实际验证与缺口，区分原型模拟和真实环境结果；不另建编号或验收台账。

说明这次验证了哪些行为，哪些受环境或范围限制尚未验证。普通补测沿用已有实现；不要求为获得红绿过程回退正常代码。明确测试优先请求才采用 `tdd`。
