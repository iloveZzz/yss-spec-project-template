# 从行为选择测试

把 Spec 的可观察验收与当前实现对应起来，从实际风险选择正常、边界、拒绝、异常和恢复案例；不为每次小改动建立追踪台账。预期值来自业务规则、已知样例或独立推导，不复制被测实现作为断言。

## 测试层次

| 要验证的行为 | 合适的证据 |
|---|---|
| 规则、计算、状态转换、不变量 | 通过公共接口的单元测试，断言结果与可观察状态 |
| 依赖装配、MapStruct 映射、持久化或事务 | 使用工程实际配置的集成测试，确认真实参与的组件 |
| HTTP 请求校验、认证授权、序列化、分页、错误和兼容性 | 运行对应接口路径并核对协议；DTO 字段或编译不证明 HTTP 行为 |
| 缺陷回归 | 原复现路径及受影响调用方；拒绝/失败后的状态同样检查 |
| 并发、性能、真实数据库方言 | 有明确需求时用对应环境和负载验证，说明测量条件 |

mock 放在真实外部边界，不 mock 被验证的核心规则、事务或映射。如果问题正是外部集成，单元 mock 只能验证调用方逻辑，不能替代真实协议或服务验证。沿用现有框架，不因选择测试层次自动引入新依赖。

## 拒绝后状态示例

库存初始 5，预留 2 成功后应为 3；再预留 4 应拒绝且仍为 3。只断言抛异常会漏掉“先扣库存再校验”的缺陷。分别断言成功结果、拒绝结果和拒绝后的状态；数据库事务场景还需核对实际回滚及事务边界，内存样例不能证明数据库一致性。

从调用链判断失败是否可能导致部分写入、重复副作用或丢失补偿；只为当前命中的风险增加案例。权限拒绝不能仅验证状态码而遗漏敏感数据泄漏；分页要核对实际 wire 协议与排序边界。

## 数据库、提交与并发

持久化或事务行为采用工程目标数据库及实际支持的版本，记录驱动、schema、字符集/排序规则、时区和事务隔离级别等影响当前断言的配置。H2 即使使用兼容模式，也不能代表 MySQL/PostgreSQL 的方言、锁或隔离行为。沿用现有测试环境，容器可用且确需临时数据库时可选 Testcontainers，不默认新增依赖或要求容器设施。

- 用工程真实迁移链初始化隔离测试库/schema。涉及升级时，既验证空库初始化，也从相应旧版本结构与代表性历史数据执行增量迁移，覆盖空值、重复值及转换失败，核对结构、数据和应用兼容性。自动建表无法替代迁移链验证。
- 共享数据库时按运行/案例隔离 schema 或数据标识，确认连接目标与清理范围。并行用例避免共用可变数据和全库清理，提交型测试需显式清理自己写入的数据。回滚型测试不能清理其他线程或独立事务已提交的数据。
- 从真实 Application/Service 公共代理入口进入事务，注入中途失败后通过独立事务核对持久状态，确认部分写入回滚。测试自身的外层事务可能改变生产提交时点，验证传播语义时按真实调用边界安排。[Spring 测试事务说明](https://docs.spring.io/spring-framework/reference/6.2/testing/testcontext-framework/tx.html)
- 提交后事件、缓存失效或异步通知使用真实提交，再以有界等待读取可观察结果，同时覆盖回滚不触发、提交后发送失败及重复处理。可沿用工程已有 `TestTransaction` 或程序化事务结束测试事务，单纯 flush 或默认回滚不能证明提交后行为。YSS 审计的正常返回采集、内存入队、事务提交和下游持久化分别核验，按实际组件能力断言。
- 并发冲突用独立连接/事务构造真实竞争，通过屏障或锁存器协调重叠，避免仅凭固定 sleep 假定冲突发生。覆盖当前依赖的唯一键、乐观锁、悲观锁或幂等裁决，断言各调用结果、最终数据和副作用次数。死锁/超时按已有重试策略验证有界重试和最终结果。

执行后核对本次测试确实被发现、运行且使用目标环境。零测试、跳过和旧报告仅记录实际状态，不能算作这些行为已验证。数据库不可用时继续可独立完成的单元验证，并明确真实方言、提交及并发范围尚未验证。

## 覆盖说明

需要解释上游验收、来源变化或业务差异时，按项目根读取 `.agents/skills/implement/references/spec-feedback.md`。沿原 FR/AC 或章节说明实现、实际验证与缺口，区分原型模拟和真实环境结果；不另建编号或验收台账。

说明这次验证了哪些行为，哪些受环境或范围限制尚未验证。普通补测沿用已有实现；不要求为获得红绿过程回退正常代码。明确测试优先请求才采用 `tdd`。
