# 执行测试并解释结果

先读项目 README、POM、测试目录、插件与 Profile，确认实际测试入口和范围。已有根 `./mvnw` 优先使用它；命令、模块参数与 Profile 由工程配置决定，不能凭惯例声称 `test` 或 `package` 已执行全部集成测试。

## 执行前

确认测试数据与外部服务属于本次授权范围，区分隔离测试库和生产库。数据库、消息服务或凭据缺失时记录影响，继续能独立执行的单元验证；不绕过权限、复制真实秘密或改为生产环境。

检查 Surefire/Failsafe 等实际插件的绑定阶段、测试命名/选择器、模块、激活的 Profile 和跳过参数。配置可能将集成测试放在后续阶段，甚至没有绑定执行；选择真实支持的命令，不自动改 POM 让表面命令变绿。

## 判读实际结果

同时检查退出码、执行日志和实际生成的结果文件：目标测试是否被发现并运行、运行数量、失败与跳过、所用模块和环境。读取本次产生的结果，不能把旧报告当本次证据。

- 退出码 0 但 Tests are skipped、测试数为 0 或选择器没命中：只说明命令成功/未运行目标测试。
- 只执行编译：只报告编译成功；没有测试通过证据。
- 单元测试通过但数据库环境不可用：报告单元范围与集成未执行，不概括为全部通过。
- 测试失败：保留失败名称、关键原因和复现条件；区分业务回归、断言问题、环境与不稳定测试，不静默跳过或放宽断言。

启动应用与部署是另外的动作和证据；测试命令成功不能推导它们成功。测试本身有外部副作用时，未知结果先回读真实状态，再决定是否重试。

## 汇报

在当前任务中说明实际命令、执行范围、通过/失败/跳过和未覆盖的限制即可，不强制生成单独报告。必要修改后运行能覆盖本次影响的验证；只有观察到的结果可标为已验证。
