# 产品仓库地图模板

配置 Home 时先检查已有 README、地图和交接说明；已有等价入口就沿用。需要新文件时，以以下结构创建项目根 `REPOSITORIES.md`，将标题换为实际产品名，并只填写核实过的信息。地图是项目资料，不进入 CLI 安装收据或模板覆盖范围。

## 仓库与资料

| 仓库标识 | 职责 | Git 身份 | 资料入口 | 关联 | 查找提示（可选） |
| --- | --- | --- | --- | --- | --- |

- 标识在本产品内稳定且不重复，以“仓库身份 + 仓内子路径”区分同仓工程。职责说明产品边界、实现端或只读参考用途，不从角色名推断所有端都需要修改。
- Git 身份使用已核实的远程仓地址；地址不得含凭据。没有远程或暂时未知时明确注明，不把同名目录认作同一仓。
- 资料入口写明所属仓及仓内实际相对路径，按需引用工程入口、技术说明、API、上游规格、实际技能目录及技能来源说明；不复制另一仓的技术事实，不维护重复的全量技能索引。
- 关联只记录有依据的上游、调用或共享关系。未知关系明确说明，缺少关系不阻止目标已清楚的任务。
- 查找提示可以是常用目录名或相对布局，仅用于查找候选。个人绝对路径、当前分支、worktree、未提交状态、任务版本及进度不放进共享地图。

## 使用约定

Agent 按当前任务核实实际 Git 根、remote、工作树和允许范围，再读取目标仓规则与必要资料。多个位置都符合身份但无法按本次任务消歧时，只暂停相关写入并询问位置；缺失 checkout 时说明缺口，不自动克隆全部关联仓。

地图中的用途和链接不扩大用户授权，不自动触发安装、研发、提交或发布。关系发生实质变化时，沿本文件或既有地图更新，不创建并行索引。

## 多工程填写示例

以下是虚构布局，实际使用时核实并替换，未核实的 remote 不填成示例地址。独立仓的子路径为 `.`；同仓工程填写自己的子路径。

| 工程标识 | 职责 | Git 身份与子路径 | 资料入口示意 | 已知关系示意 |
| --- | --- | --- | --- | --- |
| product/spec | 产品 Home、规则与原型 | 已核实产品仓；`spec/` | `AGENTS.md`、主 Spec、`.agents/skills/` | 为各实现工程提供业务依据 |
| product/customer-api | 客户后端 | 同产品仓；`services/customer-api/` | `AGENTS.md`、实际 API、`.agents/skills/` | 供 Web 与 Mobile 查询客户 |
| product/order-api | 订单后端 | 同产品仓；`services/order-api/` | 工程入口与实际 API | 仅按真实调用确定影响 |
| product/web | Web 应用 | 同产品仓；`apps/web/` | 工程入口、接口消费代码、技能目录 | 消费客户 API、共享 UI |
| product/mobile | 移动应用 | 同产品仓；`apps/mobile/` | 工程入口与接口消费代码 | 消费客户 API |
| shared-ui | 共享 UI | 独立仓，remote 待核实；`.` | 组件入口与使用说明 | 被实际引用的应用消费 |

此表不保存当前 worktree 或执行进度，也不要求所有工程安装 YSS。实际技能来源和运行路径在任务中按当前 checkout 核实；完整协调方法见本包 [Git 接入与 Skills 共享](project-portability.md)。
