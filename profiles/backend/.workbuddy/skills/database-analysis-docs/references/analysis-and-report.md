# 分析与报告

## 证据和输入

先确定用户要求审查现状、设计目标，还是两者都做；已有上下文能够回答时不重复提问。建立资料清单，写明时间／版本和定位方式：文件路径及章节、工作表及范围、代码符号／行号、官方文档 URL 或用户本次明确答复。截图只证明可见内容；ORM 和旧设计稿不自动等于实际库结构。输入不全不代表对象不存在。

发现冲突时保留两方来源，说明采用哪个口径及为什么。用户明确更正可替代旧规则；代码与新要求不一致是需要报告的差距。技术细节涉及具体数据库版本时查官方依据，不能将通用经验描述成该版本的已验证行为。

## 从动作找数据需要

围绕用户真正操作的流程检查：

| 业务动作 | 要核对的内容 |
|---|---|
| 创建、编辑、导入 | 必填、合法值、身份、判重范围、默认值、创建时机 |
| 关联、转移、共享 | 两端数量、是否可不关联、归属来源、对象与字段操作资格 |
| 状态推进、结束、恢复 | 允许动作、终态、原因与时间、不可丢失的历史 |
| 列表、筛选、详情、统计 | 所需字段与关系、数据范围、汇总口径、查询形态 |
| 配置、通知、分配 | 配置与执行结果、接收对象、失败与重试、是否真的有执行器 |
| 删除、更正、撤权 | 原记录与审计、关联数据处理、历史与当前访问资格 |

按适用性分析，不为凑齐清单发明业务模块。索引建议依据查询、排序和关联场景；没有实际数据量和执行计划就不宣称性能收益。按照已确认规则设计主键、非空和必要的唯一约束或唯一索引，仅凭字段名不能推断必填或唯一。租户、软删除、审计字段不是所有表的默认义务。

对判重和历史等关键规则，结合实际数据库及版本核对：唯一约束的作用范围、复合列及顺序、可空值、排序规则和软删除条件；CHECK 的空值语义及是否实际生效；时间字段的时区、精度与历史保留。索引存在不等于规则完整，数据库约束也不自动覆盖应用权限或并发路径。敏感字段按业务证据识别，说明存储、展示和访问范围尚需确认之处，不凭字段名断言合规。

## 关系的反例

“每张订单只选一个客户，同一客户可以多次下单”：客户到订单是 0..多，订单到客户是 1..1。不能给订单的客户引用加单列唯一约束。是否允许同一客户同一商品重复下单是另一条规则，不能自行推断。

“一个订单可选多个服务”未回答是否允许零个服务，也未回答同一服务能否被多个订单引用。保留未知；不能把“多”写成“至少一”。业务引用是否采用物理外键、删除策略、旧数据修正属于单独的设计决定。

数据库中声明的外键、需求明确的逻辑关系和仅凭字段命名或类型推测的候选分别标注来源与置信情况。候选关系不能当作已实施约束或确认的业务基数。

新设计默认用逻辑关系表达关联：记录引用字段、是否必填、创建与删除策略及维护责任。没有物理外键时，应用先查后写不能单独保证并发下的引用完整性；根据业务需要列出待研发确定的事务、锁或对账措施，不声称已经实现。明确的业务唯一规则仍应按其范围设计必要唯一约束或唯一索引，普通查询判重不能单独保证并发唯一性。

## 比较现状与基线

需要比较多份结构时，注明每一端的来源、环境或版本、采集时间、对象范围和已知可见性限制，按同一范围列出新增、缺失、变化及无法比较项；名称或表达式不同先核实是否语义差异。差异可能来自有意的现场修复或版本不同，不能自动认定错误或覆盖现场。单凭前后结构不能可靠推断重命名、数据转换和迁移顺序；有疑问列为待确认，不自动生成修复或迁移。

## 报告结构

以用户需要为准，可合并章节，不强制生成多个报告。

1. **结论和范围**：哪些场景支持、不支持、部分支持或无法判断；实际取得了哪些证据。
2. **业务对照**：需求／页面动作、表字段／关系、约束与权限、支持程度、依据。
3. **具体问题**：定位、触发例子、用户影响、现状证据、建议、依赖或未决决定。优先处理会造成错误关系、丢数据或越权的问题。
4. **调整方案**：保留／新增／变更／取消的设计及理由；现状与目标分别标注。说明历史数据和依赖需要核对，不据此执行迁移。
5. **确认与验证**：已确认、建议、待确认分开；检查方式、实际结果和未执行事项分开。

推荐对照行：

| 需求／动作 | 数据对象与字段 | 约束／权限 | 支持情况 | 依据／缺口 |
|---|---|---|---|---|
| 同客户多次下单 | order.customer_id | 不应单列唯一；非空与外键另核对 | 示例：冲突 | 指向现有唯一约束和需求来源 |

不要用没有证据的数字评分、空泛“最佳实践”或“全部满足”代替具体结论。一个关键缺口即可影响该业务，不按表数量计算通过率。

## 未知与技术事实

- 已有库缺少某项声明：写“提供的资料未包含”，不要断言线上不存在。
- 只确认采用人工验证：写“待人工验证”，不能记为通过。
- 来源表达未知可空性：模型写 null；模型建议暂定可空时写 true 并在建议和待确认区说明，不将它写成事实。
- SQL CHECK 与业务校验分开；字段权限配置不等于对象访问授权。
- 未支持的视图、过程、分区或索引表达式保留定义；没有取得定义就明确未提供，不编造 SQL。
