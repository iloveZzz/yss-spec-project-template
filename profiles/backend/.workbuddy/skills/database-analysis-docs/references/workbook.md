# 工作簿生成与核对

仅在用户需要 Excel 时读取。使用宿主已有的表格技能或能力，遵循其依赖发现、导出与渲染要求；如已安装 `openpyxl` 也可使用，不为本技能安装新依赖。输出简洁明亮、跳转可靠、文字精炼的数据库说明书。缺少表格能力时可先完成 Markdown 并明确说明 Excel 未生成；用户提供模板时优先沿用适用规范。

## 1. 引用与内部跳转硬性规范（必守）

1. **内部页签跳转必须使用 OOXML 原生 `location`**：
   - 目录页跳往各表详情页、以及各表详情页「`← 返回目录`」跳回目录页，必须生成工作簿内部定位（XML `<hyperlink ref="..." location="'页签名'!A1"/>`），**严禁生成外部关系（`TargetMode="External"`）**。
   - 以 `openpyxl` 为例，**禁止**直接写 `cell.hyperlink = "#'页签名'!A1"`（这会把值写入 `hyperlink.target` 并在 `_rels` 中创建失效的外部链接）；**必须**显式构造：
     ```python
     from openpyxl.worksheet.hyperlink import Hyperlink
     escaped_sheet = target_sheet.replace("'", "''")
     cell.hyperlink = Hyperlink(
         ref=cell.coordinate,
         location=f"'{escaped_sheet}'!A1",
         display=str(cell.value),
     )
     ```
     注意：`location` 字符串**不带 `#` 前缀**，页签名用单引号包裹（若页签名含单引号则双写转义 `''`），且 `cell.hyperlink.target` 必须保持为 `None`。
   - 跳转单元格应为**独立未合并单元格**（或合并区左上角主单元格），不要把链接绑在被合并的尾部单元格上。
2. **禁止在静态说明书中使用动态 Excel 公式**：
   - 表总数、总字段数、索引数、关系数等汇总数字在生成时已由模型精确算出，**必须直接写入真实整数（`int`）**。
   - **严禁**写入 `=COUNTA(...)`、`=SUM(...)`、`=HYPERLINK(...)` 等公式：无头生成工具不会运行 Excel 公式计算引擎，公式单元格缺少缓存值 `<v>`，在 IDE 预览、macOS QuickLook 或只读解析中会显示为空白或引用失效。
3. **页签名 31 字符安全截断与确定性映射（防超链接断裂）**：
   - 生成工作簿前，先按 `tables` 顺序建立确定性的 `sheet_map: dict[table_id, sheet_title]`，预留目录和其他固定页签名：
     - 替换非法字符 `\ / ? * : [ ]`，去除首尾单引号；空白名称使用非空占位名称，保留表的完整真实名称。
     - 清理后的名称最多 31 字符，不与已有页签重名（不区分大小写），且不使用保留名 `History`。
     - 超长、重名或命中保留名时，用 `suffix = "_" + 序号`，按 `31 - len(suffix)` 为名称主体预留长度，逐次避重并复查长度与合法性；同名跨 schema 的表也按稳定表 ID 分配。
   - 目录页的表名链接、「查看明细 →」链接以及关联表的源表／目标表链接，**必须传入 `sheet_map[table_id]`**，严禁直接拼接未截断的原始表名。
4. **文本与特殊字符保护**：
   - 页内顶部展示完整真实表名（不受 31 字符限制）。
   - 默认值、SQL 片段、标识符、长整数 ID 按纯文本写入（`data_type = 's'`），防止以 `=`、`+`、`-`、`@` 开头被误判为公式，或被自动转换为科学计数法／日期；汇总计数仍使用数值。

## 2. 内容精炼与去 AI 味规范

1. **隐藏机器内部元数据**：
   - `database-model.json` 保存稳定 ID、来源编码和基数字段；Excel 仍展示实际关系基数及非空的未覆盖对象、原始定义或来源定位与影响。
   - **Excel 页面只展示对研发和业务审阅有价值的信息**：
     - 不设与表名重复的「稳定 ID」列；
     - 不在字段、索引、规则行逐行刷屏 `SRC-PG-DDL, SRC-SPEC...` 等来源代号；
     - 若所有表均位于默认 schema，省略全列重复的 `"" (默认未限定)`，仅在跨 schema 时展示 Schema；
     - 若无 `unsupported_objects`，**不渲染**「未覆盖对象清单」空表；不在目录页堆放十几行代码文件路径表。
     - 来源集中展示环境／版本、采集时间、范围与必要定位；已确认、建议、待确认分开。隐藏逐行编码不删除来源证据。
2. **字段属性与关系表达直白化**：
   - **必填**：用「必填」列直接填 `是` / `否`（未知填 `待确认`），不写冗长的 `否 (NOT NULL)`、`是 (NULL)`。
   - **默认值**：未声明填 `-`，空字符串填 `''`，其余按字面量填 `0`、`FALSE`、`'DRAFT'`、`CURRENT_TIMESTAMP`，不写 `未声明` 或 `"" (空字符串)`。
   - **表间关系**：表头采用自然中文（`序号 | 源表 | 目标表 | 关联字段 | 关系基数 | 业务与维护说明`），基数按源表:目标表顺序写为 `0..1 : 0..N` 或 `1 : 0..N`，方向遵循 [模型约定](model-and-validation.md)，未知写「待确认」。逻辑关系与物理外键以中文标明，不暴露 JSON 键名。
3. **注释、索引与规则「三不写」**：
   - **不写代码实现细节**：字段说明只写业务含义、枚举取值与关联目标（如 `状态：DRAFT 草稿 / COMPLETED 已完成 / ARCHIVED 已归档`），不塞入 `FieldStrategy.ALWAYS`、`*GatewayImpl`、`@Version` 拦截器类名等代码细节。
   - **不写万金油套话**：每条索引说明必须指出具体查询条件或唯一性规则（如 `按分类+生命周期筛选笔记`、`名称小写唯一`），严禁统写「支撑列表查询/关联/排序场景」。
   - **不写「无」占位废话行**：逐表页的「主键与索引」表只列出真实存在的 PK、UK、IDX、FK；某表没有普通索引或没有物理外键时，**绝不输出**「普通索引 | 无 | 当前表未声明额外普通索引」之类的占位行。
4. **100% 同源模型驱动（零脚本硬编码）**：
   - 表职责、字段说明与备注、索引用途和关联字段均直接读取同源模型，严禁在生成逻辑中硬编码业务字典。可选字段缺失按 [模型兼容规则](model-and-validation.md) 展示，不补造内容。

## 3. 简洁明亮视觉模板规范（Light & Clean）

采用清爽、克制、明亮的现代工程表格风格，避免深黑蓝大色块、刺眼红绿灯背景和错位合并单元格。

### 3.1 配色方案

| 元素 | 背景色 (Fill) | 文字颜色 (Font) | 字号与字重 | 边框与修饰 |
|---|---|---|---|---|
| **页签主标题栏** | 极浅蓝灰 `#F1F5F9` | 深灰黑 `#0F172A` | 13pt 加粗 | 底边框 `#CBD5E1` 中粗线 |
| **顶部概览条 / 元信息** | 纯白 `#FFFFFF` 或 `#F8FAFC` | 标签 `#475569` / 值 `#0F172A` | 9.5pt（值加粗） | 细灰框 `#E2E8F0` |
| **分节小标题** | 纯白 `#FFFFFF` | 深蓝 `#1E40AF` | 10.5pt 加粗 | 底边框 `#BFDBFE` |
| **表头行 (Header)** | 明亮浅蓝灰 `#E8EEF5` | 深石板灰 `#1E293B` | 10pt 加粗 | 上下 `#CBD5E1`，左右 `#E2E8F0` |
| **数据行 (奇数行)** | 纯白 `#FFFFFF` | 正文 `#1E293B` | 10pt 常规 | 四周细灰线 `#E2E8F0` |

### 3.2 页面结构与列网格对齐

同一工作表内的各子表应**共用同一套列网格**，避免跨不同列结构的区域滥用合并单元格：

- **页签 1：`目录`（共 8 列 `A..H`）**
  - **Row 1（主标题）**：`A1:G1` 合并写文档标题，`H1` 写更新日期。
  - **Row 2（概览指标条）**：直接展示目标数据库、表数量、总字段数、唯一约束数、普通索引数、逻辑关系数（全部为真实整数/文本，不用公式）。
  - **分节 1：数据表清单**（列 `A..H`）：
    `序号(A) | 表名(B, 内部链接) | 中文名称(C) | 主键(D) | 字段数(E) | 索引数(F) | 核心说明(G) | 跳转(H, "查看 →" 内部链接)`
  - **分节 2：表间关联关系**（复用 `A..H` 列网格，仅将「说明」合并 `F..H`）：
    `序号(A) | 源表(B) | 目标表(C) | 关联字段(D) | 关系基数(E) | 关联与维护说明(F:H)`
  - **分节 3：核心设计约定与待确认项**（复用 `A..H` 列网格，将「内容」合并 `C..H`）：
    `序号(A) | 类别(B: 已确认 / 建议 / 待确认) | 说明内容(C:H，精炼单句)`

- **页签 2..N：各表详情页 `<表名>`（共 7 列 `A..G`）**
  - **Row 1（表头栏）**：`A1:F1` 合并写 `[序号/总数] 表名 — 中文名称`（如 `[3/6] kb_note — 知识库笔记`），**`G1` 独立单元格写 `← 返回目录`**（绑定 `location="'目录'!A1"`）。
  - **Row 2（表级摘要）**：展示主键与表职责说明（直接读取 `table.comment`）。
  - **分节 1：字段明细**（列 `A..G`，零合并单元格）：
    `序号(A) | 字段名(B) | 数据类型(C) | 必填(D) | 默认值(E) | 字段说明(F, 读取 field.comment) | 约束与备注(G, 读取 field.note)`
  - **分节 2：主键与索引**（仅列实际存在的键与索引，复用 `A..G`，说明合并 `F..G`）：
    `序号(A) | 类型(B: PRIMARY KEY / UNIQUE / INDEX) | 名称(C) | 包含字段(D) | 唯一(E: 是/否) | 用途说明(F:G)`，保留复合列次序。
  - **物理外键**（存在时单列区域，复用 `A..G`）：
    `序号(A) | 名称(B) | 本表字段(C) | 目标表(D) | 引用字段(E) | 删除动作(F) | 更新动作(G)`，读取 `foreign_keys` 的真实属性，不以逻辑关系替代。
  - **分节 3：表级业务规则**（仅当存在跨字段或表级规则时渲染，复用 `A..G`，规则合并 `C..G`）：
    `序号(A) | 规则类型(B) | 规则说明(C:G，精炼单句，不重复字段表已写内容)`；SQL CHECK 与业务条件分别标注，实际 SQL 定义完整保留，不用摘要替代。

### 3.3 字体、行高与自适应列宽细节

- 字体统一使用 `PingFang SC`（或 `Microsoft YaHei`）；
- 开启网格线（`ws.views.sheetView[0].showGridLines = True`）；
- 行高克制紧凑：主标题 `30pt`，分节标题 `24pt`，表头 `25pt`，单行数据 `22pt`；多行文本按实际字数与列宽动态计算（每行约 `15pt` + 上下留白 `8pt`），禁止固定设置 `50pt+` 造成大面积空行；
- **列宽上下限自适应公式**：
  - 标识符列（表名、字段名、类型、索引名、关联列）：宽度按最长视觉字符数计算 `clamp(max_visual_len + 4, min=10, max=32)`；超长标识符换行并增高行，不裁切完整名称；
  - 短属性列（序号、必填、唯一、主键）：固定紧凑宽度 `6~12` 并居中；
  - 长文本说明列（核心说明、字段说明、约束与备注、用途说明）：控制在 `30~44` 宽度并开启 `wrap_text=True`。

## 4. 实际文件核对清单

生成 `.xlsx` 后用独立读取能力核对实际保存的文件（已有库、连接器或临时核对均可），不能只检查内存对象或日志；缺少能力时明确对应检查未完成：

1. **链接可点击性核对**：遍历全部工作表的超链接，确认每条内部跳转的 `cell.hyperlink.location` 格式为 `'目标页签'!A1`、目标页签在 `wb.sheetnames` 中存在，且 **`cell.hyperlink.target` 为 `None`**（确保 `.rels` 中无 `#` 开头的 External 假链接）。
2. **零未求值公式核对**：遍历全部单元格，确认不存在 `cell.data_type == 'f'` 的未求值公式单元格，汇总数字全部为真实数值。
3. **内容核对**：比较表集合、完整名称、字段顺序、类型、必填、默认值、复合键／索引、物理外键及动作、CHECK、关系基数、来源与未覆盖项；确认与同源模型一致。新写说明去除套话和占位行，原始定义与注释保真。
4. **视觉检查**：查看实际渲染的目录、代表性详情页和长文本／多行区域，确认行高、换行、合并单元格和完整标识符没有裁切；仅重读文件不能证明视觉正确。缺少渲染能力时明确未完成。
5. 如实报告实际执行的核对结果；文件结构、读回核对和渲染不替代真实数据库执行验证。

页签合法性依据：[Microsoft 工作表命名规则](https://support.microsoft.com/en-us/excel/rename-a-worksheet)。
