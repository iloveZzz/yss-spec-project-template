# 后端测试

从当前 Spec/验收和实际代码确定可观察行为与受影响调用方，选取能发现真实缺陷的验证。使用工程已有工具，不为普通工作建设统一测试门禁或报告体系。

- 选择案例、测试层次与 mock 边界时读 [测试设计](references/test-design.md)。
- 执行命令和解释通过、失败、跳过或环境缺失时读 [测试执行](references/test-execution.md)。
- 只有用户明确要求测试优先、TDD 或 red-green-refactor 时才采用 `tdd`；调查失败根因时按需使用 `diagnosing-bugs`。

只操作本次授权的工程、测试数据和环境。普通本地测试不授权生产数据变更或外部付费调用；需要真实服务时先核对已有环境和操作范围。编写测试、编译成功、测试通过、服务启动、部署成功分别说明，只报告实际观察到的结果及未覆盖内容。
