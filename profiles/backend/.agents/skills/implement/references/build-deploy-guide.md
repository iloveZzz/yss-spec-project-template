# 构建部署手册

完整研发交付或用户要求构建部署说明时读取；局部修改只更新受影响内容。优先增量维护已有 README/运维文档，缺少结构时参考实例根 `.template-spec/templates/build-deploy-guide-template.md`，不重复建立另一套手册。

## 依据实际工程

读取真实构建文件、模块/Profile、运行配置、已有部署说明和本次命令结果。已有根 `./mvnw` 优先使用；其他工程沿用已有工具。把已确认事实、建议执行步骤和未确认环境分清楚，命令与产物名称必须可追溯到工程配置或实际输出。

完整交付按适用程度说明：

1. 适用源码版本/工作树状态、Java/Maven 等前提和必要外部服务；避免把本机绝对路径当公共前提。
2. 构建命令、模块、Profile、产物名称与位置，以及本次是否实际构建。
3. 配置项/环境变量、用途与安全注入位置；示例只保留变量名和占位符，不复制真实密钥、生产地址或用户数据。
4. 依据既有运行方式描述安装、启动、停止和配置步骤。部署环境未知时写清缺口，不替用户选择 Docker/Kubernetes/systemd。
5. 涉及数据变更时说明迁移顺序、备份需求和兼容限制；没有可逆依据就说明不可保证数据回滚，不编造回滚 SQL。
6. 实际健康入口、日志位置及排障办法；工程没有探针就标明未知/未提供，不编造健康 URL。
7. 旧产物和配置的恢复前提与步骤，区分应用回退与数据恢复；没有已验证路径时说明限制。
8. 分别列明编译、测试、启动、部署的已验证与待验证状态，不从构建成功推导部署成功。

## 操作边界

本方法只编写手册；其中的命令不授予执行部署权限。构建和本地测试按实际研发任务授权进行，未执行的步骤写为待验证。手册不要求新增 CI/CD、部署脚本、集群配置、云资源或凭据。

事实缺失时继续整理有依据的内容，指出影响后续操作的具体未知项；不为填满模板制造事实或固定批准包。
