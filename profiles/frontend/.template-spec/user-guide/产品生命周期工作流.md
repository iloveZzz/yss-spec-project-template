# 前端专职工作流

联合接收战略与后端交付，承担前端工程设计、页面实现和验收。后端代码、API和业务规则缺口回交维护方。

`验包与诊断 → 词汇/场景/真实服务联合接收 → 前端工程设计 → 计划与合同批准 → 前端实现 → 独立验收`

1. 用 `backend-delivery import` 导入 Backend Delivery 及其 Handoff v5 战略依赖，读取接收草稿；不把导入成功当批准。
2. 完成根词汇对账和规则/场景、API、既有 UI baseline 与视觉用例映射；执行 `node scripts/preflight-delivery --input <前端接收预检输入.json> --stage accept --json`，再运行前端交付验证检查真实服务身份。
3. `inputs-verified` 仅允许准备 `frontend_implementation_plan` 与当前 Slice Implementation Contract；由当前用户批准后再编码。
4. 在登记前端工程用 pnpm 验证，保存截图/视觉、状态交互、console warning、失败恢复和真实联调证据。
5. 独立审查本端结果，形成 Frontend Acceptance 并向统一管理方提供 `frontend-accepted` 证据；不自行宣布整体业务完成。

后端新版本、战略/视觉变化或服务身份不符会要求重新接收和合同重编译；恢复任务时重新检查。

本页为阅读导航，不复制定义阶段或批准政策。权威是本仓 .template-spec/process/lifecycle-registry.yaml、.template-spec/process/harness-profile.yaml 与 .template-spec/agents/digital-human-roles.yaml。

完整操作见 [前端专职指南](前端子项目用户手册.md)；输入、输出和命令见 [贯穿案例](设备借用贯穿案例.md)。
