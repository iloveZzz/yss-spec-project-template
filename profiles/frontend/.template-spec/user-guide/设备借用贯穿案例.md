# 设备借用：前端接收与验收职责案例

本文是虚构教学材料，不是已批准合同或真实服务证据。目标是联合接收“已批准申请领用设备”的战略与后端交付，完成前端实现和验收。

## 1. 导入并诊断

```sh
node scripts/backend-delivery import --bundle <后端交付目录或ZIP> --target-root .
```

```text
请读取战略与后端导入收据，完成目标 CONTEXT.md 对账。
把领用规则、成功和拒绝场景映射到冻结 operation ID、页面状态和恢复动作。
核对部署、源码、接口、构建、测试数据和真实服务版本；缺口回交对应责任方。
```

导入成功只生成接收事实，不批准前端实现。重复领用、无权限和设备已占用的返回行为必须来自上游当前规则与冻结 API。

## 2. 确认 UI 依据

Handoff v5 必须选择一个 UI 分支：

- 页面有变化：消费当前且已批准的 prototype / visual baseline。
- 页面无变化且复用既有工程：使用 `existing-ui-baseline`，绑定固定源码、锁文件、构建、浏览器动作、截图及实际 API 交换。
- 确实没有 UI 影响：记录有理由的 `not-applicable`。

不能用旧截图代替当前源码和真实浏览器捕获，也不能在前端接收时把既有基线改写为原型。

## 3. 联合接收和实现许可

```sh
node scripts/preflight-delivery --input <前端接收预检输入.json> --stage accept --json
node scripts/verify-frontend-delivery --root . --slice <切片ID> <接收记录相对路径>
```

成功结果仍是 `inputs-verified`、`ready_for_agent: false`。随后准备 `frontend_implementation_plan` 和当前 Slice Contract，让用户确认页面行为、写入范围和验收标准；合同获准前不写代码。

## 4. 实现与 Frontend Acceptance

```text
请复验战略、后端、API、真实服务、UI 基线、前端计划和 Slice Contract 仍然当前。
在登记前端工程实现领用页面，使用 pnpm 执行实际测试、type-check 和构建。
记录成功领用、未批准、无权限、设备已占用和重复请求的页面状态、截图、console 与恢复结果。
```

独立 Reviewer 核对页面、网络请求、真实服务版本和异常恢复。后端包、服务部署、OpenAPI 或 UI 源码任一变化，都使受影响接收与合同失效并要求重验。

本仓完成结论是 `frontend-accepted`。统一管理方仍需绑定同一战略、后端部署和前端版本，完成端到端业务验收与发布决定。
