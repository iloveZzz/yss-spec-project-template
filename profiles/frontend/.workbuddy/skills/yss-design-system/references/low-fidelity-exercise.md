# 低保真完整演练：资料审批组织方式

这是维护教学 fixture，不是产品需求或用户批准。本文明确允许单项、批量、按编号队列审批同一组三条虚构资料；三条资料均已具备审批条件。确认通过后仅从本地待处理集合移除；首次失败保留输入和选择，再次操作成功。

## 输入与保持项

用户任务是核对编号、名称、负责人、状态后处理三条资料。三候选共享 scenarios.json、文案、数据、失败状态、Token 和相同低保真深度；允许变化只有任务组织、选择粒度和上下文展示。不能删除字段或跳过失败处理来制造优势。

## 事前标准与任务脚本

硬约束：每条资料可定位、可核对；只处理明确选择的资料；失败保留上下文；重置恢复原始三条。权衡项：列表全局对照能力、重复选择成本、逐条核对负担。没有人为规定的完成秒数或点击达标门槛。

1. 正常场景：找到 M-002 的负责人，再处理全部资料；记录实际操作与结果。
2. 失败场景：执行处理，核对失败后行与选择未丢失，再重试；确认剩余资料集合。
3. 每个候选完成后重置，再切换到下一候选，从同一初始数据开始。
4. 在桌面和窄屏执行；填写现有交互说明的观察、代价及落选理由。

| 候选 | 差异轴 | 适合条件 | 需要观察的代价 |
|---|---|---|---|
| 逐项处理 | 全列表中逐条提交 | 经常需要横向比较资料 | 重复动作，逐条定位 |
| 批量处理 | 选择集合后统一提交 | 允许批量且资料同质 | 误选风险、选择集合理解 |
| 引导队列 | 系统按顺序给出下一条 | 每项需要集中核对 | 看不到完整列表上下文 |

## 教学选择示范

在本 fixture 的“同质资料、允许批量、需要整体核对”假设下，示范推荐批量处理。代价是必须看清所选范围；逐项方案保留全局上下文但重复提交；队列适合逐项仔细核对但牺牲全局对照。若真实需求禁止批量或每项审核负担更高，应重新比较。此段是条件推演，不是用户选择、实测效率结论或批准记录。

运行后将实际观察与本段假设对照，不用教学推荐替代证据。教学结果不替代真实产品决定；按共同复核方法检查实际产物与验收条件。

按 [Vue 准备](shadcn-vue-prototype.md) 组装 `assets/vue-business-patterns/` 中的草稿：

| 模式 | 配置/入口 |
|---|---|
| 单项 | `approval-draft-single.config.json` / `approval-draft-single.ts` |
| 批量 | `approval-draft-batch.config.json` / `approval-draft-batch.ts` |
| 队列 | `approval-draft-queue.config.json` / `approval-draft-queue.ts` |

三者复用 `ApprovalDraft.vue`、`draft.css`、既有 Workspace 和 `approval-draft.scenarios.json`；后者包含 primary/failure 的相同三条 `{id,name,owner,status}`。所有资料都能处理，包含 M-002；不要套用 `Approval.vue` 的权限与部分成功规则。首次失败保留全部资料/选择，再试成功；重置重新挂载并恢复初始状态。

场景包装见 [产品原型](product-prototype.md)。低保真以既有 appearance 的 `draft` 值简化装饰，保留语义色、焦点和错误。后续在同一页面改用 standard 并完善内容，不复制业务逻辑，不提供最终用户的保真度切换器。Vite 的 HTML 挂载页正常保留；不承诺 file:// 双击运行。只有实际运行后才报告演练结果。
