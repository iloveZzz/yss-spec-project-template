# 产品设计方法

结合任务确认目标用户、内容、操作、关键状态和设备；会实质影响结果且无法从材料确定的问题需澄清，不要求固定表单。方向不清且存在实质取舍时比较少量可审阅方向，已有方向或局部任务不强制多方案。先确认当前产品问题：视觉层级、信息密度、表单反馈、操作可见性、状态提示或特定显示条件。已有模式能解决就复用，不要求为每个需求重建完整设计系统。

先读取目标项目已有 DESIGN.md、主题、页面与组件约定，以及实际相关 Token；不全量加载所有主题。用户要求与已有约定矛盾时说明冲突并由用户决定。没有基线时结合任务提出可审阅建议，企业后台默认采用 YSS 标准亮色主题，项目明确需求可覆盖风格、颜色和密度，不假定已安装其组件，也不把 YSS 示例主题当项目事实。

文字或流程可用文字和流程图；信息结构不清时用标明内容分区、关键操作与必要状态的线框探索。新项目高保真默认使用 [Vue + shadcn-vue 浏览器页面](shadcn-vue-prototype.md)，后台工作台且缺少设计基线时默认采用 [YSS 标准亮色主题](high-fidelity-default-theme.md)；用户可要求图片或其他形式；既有项目继续遵循其实际合同。页面设计表达真实或代表性内容、关键操作与风险相关状态，默认使用模拟数据。完整有 UI 的 Spec 需高保真原型及说明，核心操作或状态变化须实现并验证相关闭环；纯展示可用高保真静态稿，无 UI 使用业务逻辑或状态原型。线框或低保真草稿不能单独算完整交付。普通查询或局部修订仅完成当前范围，不要求预先定义生产组件、API 或实现代码。

高保真须提供可评审的完整页面或指定区域，以真实或代表性内容呈现结构、层级、排版、主题、组件状态与主要操作；占位骨架、组件堆叠或仅改色不足以证明完成。用户提供参考时说明借鉴范围和允许差异；无参考时根据场景提出方向。长标题、长字段与不同数据量应可读，不能靠缩小正文或隐藏必要内容解决布局。

先明确主要任务、入口、动作、结果和返回/取消；需要用户判断流程时提供可实际操作的最小闭环，仅展示的入口须标明示意，不以可点击外观暗示功能。按页面风险选择正常、空、加载、错误、权限、禁用、校验、危险操作或部分成功状态，记录未覆盖的关键状态与待确认规则，不机械要求每页全部实现。[页面组合](page-composition.md)按需提供门户、工作台、列表和表单模式，模拟行为不代表真实业务规则。

交互说明需要关联页面、状态或动作时，按 [图解表达](../../i-have-adhd/references/visual-explanation.md) 选择必要流程、标注或动作反馈表。产品设计负责入口、输入、操作、反馈、离开与恢复的实际含义；界面显示状态与业务状态分开，图表引用同一规则和验收。图文冲突交回业务所有者，说明图不代替原型操作验证。

按 [设计评议](design-review.md) 记录观察、发现与未验证范围。检查与声明相称：静态稿核对内容层级、动作可见性和视觉约定；原型实际操作承诺路径，按当前风险检查窄屏、键盘、焦点、对比度等条件。图片工具、浏览器或网络不可用时记录未验证项；关键问题依赖缺失验证时保持阻断。可使用本地方法继续设计，不要求固定档位、六轴矩阵或独立审批。

发现权限、异常、恢复或范围问题时回流需求及验收；真实取舍交给用户。设计文件保存到项目已有或用户指定的设计位置，无约定时在当前任务目录新建清晰目录，不覆盖既有成果。附目标、来源、页面与状态范围、实际检查、差异和未覆盖条件；不自动修改生产页面、主题或业务代码。
