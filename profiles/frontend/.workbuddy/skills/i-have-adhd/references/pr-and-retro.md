# PR / MR 与复盘方法

适用于当前文档任务。复用真实需求、改动与执行记录，不为写描述建立额外治理材料或运行无关检查。

## PR / MR 描述

先写具体问题和最终可观察变化。小改动用一两段及验证说明，复杂改动沿用仓库模板，按需要展开：

- **问题与 Before/After**：谁在何种条件下遇到什么问题，改动后怎样表现。实际复现、预期目标和已验证结果分别表达；只有 After 证据时说明 Before 的来源与未复现限制，不补造历史输出。
- **范围与依据**：引用实际请求、Ticket、Spec 或相关约束，说明影响理解所需的边界。标题和正文围绕最终改动，不记录无关会话过程或弃用方案。
- **实际验证与限制**：说明执行了什么、实际结果及未覆盖范围。需要复现时附工作目录、命令和证据位置；普通小改动不强制完整证据表。环境失败、代码失败与未运行分别说明，不能统称通过。
- **影响与恢复**：根据真实改动说明剩余风险、依赖及恢复方式。未验证回滚如实写明；数据迁移、外部副作用不能凭空承诺可逆。

已有 Before/After 对照能解释行为时引用它；图示只在帮助理解时使用。写描述不自动提交、推送、发评论、创建 PR 或请求审核。

## 复盘中的改进与沉淀

用户要求复盘，或本次实际出现返工、漏检、资料难找或工具阻碍时，读取已有输入、差异和结果，做与影响相称的回看。没有具体信号就省略，不生成空表或自动复盘任务。

区分已观察现象、已确认机制和待验证假设。信息难找先修现有导航；输出过长先缩小查询范围；已有检查没接入时核实调用路径与真实执行结果。只提出证据支持的最小修订，不把没有 CI、hook、脚本或套件本身当缺陷，也不因复盘自动建设它们。

单次现象不直接形成通用禁令。需要验证的改进说明下一项能区分假设的观察；有既有工作项则沿用，没有就说明实际结果和剩余事项，不要求新建追踪资产或关闭流程。

## 真实任务观察与反馈关闭

使用实际任务、原始消息、失败日志和修复差异；不创造业务任务凑样本。没有完整消息不统计重复澄清，没有时间记录不估算耗时，没有后续样本不声称不再复发。

按实际取得的证据分别报告：

| 证据 | 能说明什么 | 不能推导什么 |
|---|---|---|
| 源码、引用与有效树核对 | 正文、元数据、覆盖和资源一致 | 宿主实际发现或调用正确 |
| 指定 CLI / Bundle 的临时安装 | 该组合分发了哪些内容 | 其他版本、既有实例升级或新源码已生效 |
| 实际宿主中的可见读取与执行 | 该宿主、版本和请求使用了哪些方法 | 所有宿主、所有任务都可靠 |
| 真实项目任务的结果 | 该场景的效果、限制和纠正 | 整体成功率或普遍效率提升 |

在当前任务或已有维护说明保留输入与来源版本（无版本时用读取时点）、profile/宿主、可取得的模型信息、预期行为、实际观察、人工纠正及限制；简单任务用一段即可。没有真实任务时可以演练代表场景，但必须标明演练，不能冒充项目结果。观察只使用已授权的目录、数据和真实宿主能力，不为此改全局配置或新建用户可见聊天。

旧 Bundle 安装成功不能验证本轮新源码；给 Agent 粘贴正文后回答正确仅说明该次方法演练。没有可见读取轨迹时，不从最终回答或模型自报反推已自动调用技能；实际读取了同名全局技能也不证明本地修改被使用。发布、安装、调用和实例效果分别说明。建议或已提交代码不证明消费者已经改善；已有工作项的关闭仍需对应授权和实际依据，不强制建立新关闭机制。

少量维护样本不能推导整体准确率或效率提升；缺失指标保留未知，不填零或虚构改善比例。
