# 执行与验收结果

完成本轮研发或专项验证后，按实际受托范围和终点交付结果。范围内仍有失败、受阻或待验收项时，把已取得的证据与尚需处理的事项一并交付。

## 选择交付形式

按以下顺序选择一种主要载体。

1. 用户指定报告文件时，在获准位置交付该文件，引用已有摘要和原证据。
2. 审计、归档或跨权限交接需要独立材料时，优先使用接收方可读的已有材料，确有缺口再按授权保存一份。
3. 执行本轮完整 Spec 范围、跨仓联调、指定环境验收、兼容迁移或需要持久交接时，汇总到一个可回读的原任务、工作台或团队交付记录。其他入口引用该记录。没有可写的持久载体时，先在当前任务交付并说明交接限制。
4. 其余任务在原任务或当前回复说明实际改动、检查、结果和相关限制。依据完整 Spec 只修一处且本轮仅需局部验证时，仍用短摘要。

## 逐项关联实际结果

完整汇总写明本轮范围、实际达到的终点、所用 Spec 和相关材料、工程候选及验证环境。共用版本和环境只写一次。使用实际提交、工作树摘要、快照或制品标识，仅知读取时点时注明限制。

- 沿用原 AC 或验收章节。没有编号或章节时，用原工单条款、用户请求的原文和位置定位。预期缺失时，写出观察结果及尚无法判定的项。
- 每项写验证层级、实际观察、凭证位置及剩余缺口。涉及权限、重试、状态或迁移时，补足可重放的初始条件、公开入口、预期与实际结果及数据副作用。需要展示复杂差异时，可在相关条目旁引用已有反例或局部图。
- 分别说明未执行、失败、跳过、阻塞及仅模拟的实际范围。单仓和模拟验证按实际层级报告，组合验收使用参与工程的实际版本及目标环境。CI 结果对应实际候选和检查项。共享凭证覆盖多条验收时，指出每条观察所依据的断言。
- 核实接手人可读取的证据及其版本。证据受限时按授权提供可共享的最小摘述或脱敏材料，注明哪些结果仍无法独立核实。按已有授权写入或分享。

## 已登记的工作台目标

需要上报时，读取实际工程适用的 `.template-spec/agents/workbench-progress.md`，按其中的「上报验证结果」和所装 CLI 帮助操作。沿用原数据目录、Spec、实际目标版本、规格摘要、阶段和参与工程。指南、登记、接口或权限缺失，或者回写失败时，在原任务交付实际结果并记录具体回写缺口。恢复后先核对已保存的结果和原候选是否仍可读，再决定是否补报。

上报前对照原验收逐项核对必验范围与所需层级。部分通过在报告中保留实际凭证，阶段按真实进度填写。跨工程整体仍有必验缺口时，先按指南保存并回读整体缺口，再登记可能触发整体验证完成的分仓结果。完成报告仅把有对应凭证且达到要求层级的条目列入通过范围。

用户或项目明确要求人工业务验收时，在原任务保留待签收范围及接收方，并按实际签收条件收尾。工作台已有自动核实时，注明其来源。收到部分决定时在原任务记录实际范围和依据。整目标确认或退回沿工作台指南处理。其他任务遵循现有自动核实流程。

## 换版与迟到结果

分别核对目标版本和工程候选。回读原规则、实际输入、候选组合和环境，注明受影响的验收以及哪些证据仍有效。对独立的本地验收，能证明相关规则、输入及环境仍适用时，沿用原证据和版本并说明依据。合并、环境和集成验证沿实际候选组合及既有复验要求取得凭证。

旧报告和确认保留原范围及版本。迟到结果可核实且接口接受时，按原目标版本和实际测试候选上报，按原 `goalVersion` 和报告 ID 回读历史。收到旧输入或版本冲突时，在原任务保留原证据、候选及实际错误，标明待同步。另核对当前目标的阶段与确认来源，当前轮次按本轮适用的凭证判断。
