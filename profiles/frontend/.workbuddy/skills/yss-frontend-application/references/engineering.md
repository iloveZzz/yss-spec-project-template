# Vue 应用工程约定

在新增页面、状态逻辑、接口联调或工程问题修复时按需读取。沿用项目已有分层、组件和命名；以下是缺少约定时的起点，不是统一重构要求。

## 结构与状态归属

- 工程采用 Vue 3、TypeScript、ESM、Vite、pnpm；组件使用 Composition API 与 `<script setup lang="ts">`。迁移范围内直接使用当前 API 并移除旧支持分支，局部任务不顺带迁移全站。
- 新工程及新增页面执行 [目录规范](project-structure.md)，页面入口组合区块与上下文，页面私有组件负责呈现/交互，页面 hook 负责独立状态流程，页面 schemas 存放声明式字段与校验；service 负责接口输入输出与业务映射，transport 负责网络通信。三个页面目录必须存在，内容按真实职责创建，简单组件局部行为仍可在组件内实现。
- 新工程统一 `hooks/`；它与 `composables/` 都表示组合式逻辑，但不并行创建两套。存量页面局部修复沿用现状，明确迁移时才移动受影响代码，不擅自全量合并。
- 用户提到的“Vue hooks”先理解为 Vue 组合式函数。未指定包名时，VueUse 是通用 hooks 的建议来源，不能宣称用户已确认某个同名 npm 包。
- 组件内局部状态用 `ref`/`reactive`，派生值用 `computed`；纯计算用普通函数。仅需局部状态时不创建 store；跨页面共享且需要统一生命周期的状态再沿用或引入 Pinia。
- 分享、刷新、前进后退后仍应恢复的筛选、排序、页码等由 URL 承载；读取时校验类型与范围。表单草稿、弹窗状态和敏感输入不因方便而写入 URL。
- props 向下、事件向上；可复用状态逻辑返回调用方需要的状态和动作。DOM 监听、定时器与请求副作用随其所有者清理，勿把全页逻辑堆进万能 `usePage`。
- VueUse 15 适合监听、尺寸、媒体查询、防抖等通用交互，按 [VueUse 规则](vueuse.md) 检查实际函数/类型、状态归属与生命周期；普通响应式仍用 Vue，纯布局优先 CSS。不能以库的通用清理约定替代具体 pending 工作的取消验证。

## 路由与会话

- 新增路由同时考虑直接输入地址、刷新、前进后退、参数无效和资源不存在；不要依赖“必须先访问列表”才能进入详情。
- 使用既有认证、权限与会话来源。前端隐藏按钮或守卫用于交互，服务端仍负责授权；不要凭参考工程发明 token、Cookie、角色或租户协议。
- 区分未登录/会话失效与已登录无权限。认证恢复保留合法的站内目标，避免重定向循环；403 给出无权限状态，不反复重新登录。
- 编辑页按业务需要处理未保存离开、详情刷新与返回列表后的状态恢复。失败或认证跳转不能静默清空草稿；持久化草稿时遵循数据敏感性与保留范围。

## transport 与 service

- 先找已有 HTTP 客户端及调用方，复用 fetch 或 Axios。统一 base URL、超时、凭证、必要头、取消和错误转换；不要让组件直接散落不同的请求实现。
- 只实现有来源的接口契约。service 的参数、返回值与映射有类型；网络响应仍是不可信输入，TypeScript 类型断言不代替运行时校验。复用已有校验能力，在实际消费边界核对关键结构、枚举与可空字段。
- fetch 路径显式处理非成功 HTTP 状态、无内容响应和解析失败；沿用 Axios 路径时核对拦截器是否已经解包响应，不重复取 `data`。
- 保留网络失败、取消、未认证、无权限、字段校验失败、业务冲突与服务端异常的区别。按真实协议提取安全提示和追踪标识，不假定所有后端都有统一 `code/message/data`。
- 错误提示只由约定的一层负责，避免 transport 与页面重复 toast。不要把异常转换成空数组或成功结果掩盖失败；日志不包含凭证、敏感表单或完整响应。
- 支持以真实 OpenAPI 3 契约和 Orval 8 建立生成链，按 [OpenAPI 接入](openapi.md) 使用普通异步函数与 DTO。生成代码与手写适配分开，修复生成来源或手写边界；service 通过生成函数的 options 传递 AbortSignal，`useRequest` 管理页面状态。不因缺少契约而自创生产接口，也不要求先建设接口平台。

## vue-hooks-plus 的请求状态

先核对项目锁定的 vue-hooks-plus 版本及其类型/源码。在线文档可能领先于安装版本，并发、回调与取消行为不能仅凭示例推断。

- `useRequest` 负责 `loading/data/error` 等请求状态；service 仍是普通异步函数，通过已有 transport 通信。VueUse 通用 hooks 不应再为同一请求维护另一份状态或缓存。
- `manual` 默认是 `false`，初始化会发起请求。查询在参数、认证与租户上下文就绪后选择一个触发入口；自动执行、`onMounted`、立即执行的 watch 不得同时发起同一次请求。
- 创建、修改、删除等写操作使用 `manual: true`，由明确动作触发。不要把写操作放进自动查询、窗口聚焦刷新、轮询或无条件重试配置。
- `run` 的错误由 hook 的错误路径处理；`runAsync`/`refreshAsync` 返回 Promise，调用方必须处理 rejection，并保留草稿与错误反馈。不能以存在 `onError` 为由省略调用方的 catch。
- `cancel()` 取消的是结果处理，不等于终止网络请求，更不能回滚服务端写入。要中断传输，显式把 `AbortSignal` 从请求所有者传入 service，再传到 fetch/支持该能力的 Axios；不要臆造 hook 自动注入 signal。
- 上述触发与取消语义见 [useRequest 基础文档](https://inhiblabcore.github.io/vue-hooks-plus/hooks/useRequest/basic)。并发规则以安装版本验证为准。
- 搜索、切换记录、换租户时防止旧响应覆盖新页面：核对库的竞争处理是否覆盖实际回调；必要时用当前请求标识/上下文版本约束结果落地，并取消可取消的旧传输。
- 超时、断网或取消后的写入结果可能未知。只有契约保证幂等或已确认未执行时才重试；否则保留输入、说明待确认状态，通过现有查询能力确认结果，不能自行发明幂等键协议。
- 需要缓存时只保留一个缓存所有者。键包含影响数据范围的参数及用户/租户身份；注销、身份或租户切换时清理相关缓存并使旧请求失效，避免迟到响应重新填入旧数据。

## 表单与可访问性

- 客户端处理格式与即时反馈，业务校验按现有规则落实；服务端校验结果映射回字段或表单级区域。不要把后端尚未定义的规则当成事实。
- 提交中阻止重复动作，成功后再按业务约定清理或离开；失败保留用户输入、字段错误和重新提交入口。编辑草稿与服务端已保存值分开，后台刷新不覆盖正在编辑的输入。
- 原生标签、控件名称、错误关联、键盘操作和可见焦点随组件交付。弹窗需处理初始焦点、关闭及焦点返回；不要为了视觉覆盖 shadcn-vue 原语的交互语义。
- loading、空数据、加载失败、无权限和局部保存失败分别呈现；不能把失败画成“暂无数据”。具体页面与设计衔接见 [设计交接](design-handoff.md)。

## mock、环境与基础发布行为

- mock 使用显式开发/演示入口，和真实 service 保持可区分的来源；使用合成或去敏数据，生产接口失败绝不自动回退到 mock。
- 环境变量只保存对应环境的配置。进入客户端产物的变量都是公开信息；密钥、私钥及服务端凭证不放入前端源码、`VITE_*` 或构建产物。
- 按真实部署路径核对 Vite `base`、路由 history base 与资源地址；history 模式需由宿主提供应用路由回退，不能把 API/静态资源错误也改写为页面。
- 部署更新后懒加载 chunk 失败要有可恢复反馈；避免无限强制刷新，也避免丢失未保存输入。按宿主能力采用旧资源保留或受控重新加载，不为此默认引入发布平台。
- Qiankun、微前端、动态菜单平台与复杂鉴权体系仅在本项目已有或用户明确需要时使用。参考工程的可迁移边界见 [参考工程适配](source-adaptation.md)。
- 验证按本次变化选择 [验证参考](verification.md)，不要求每个工程或每轮修改遍历所有场景。
