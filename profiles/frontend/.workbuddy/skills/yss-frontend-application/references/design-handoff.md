# 设计交接与还原

用于把既有设计、原型或页面代码接入应用。局部修改只处理相关页面；缺少一种文件格式不阻断已有充分输入，不要求建立额外交接系统。

## 找到真正的基线

优先读取用户指定材料及目标项目已有说明；按需要补齐以下信息，可以用链接代替复制：

| 输入 | 要读取的事实 | 工程使用方式 |
|---|---|---|
| 业务规格 / 交互说明 | 字段含义、操作条件、权限、状态转换、错误恢复、验收例子 | 决定行为；不能根据一张截图发明业务规则 |
| `DESIGN.md` / 设计稿 | 信息层级、尺寸、密度、字体、色彩、断点、保持项 | 决定视觉基线；记录设计链接、画面或现有文件位置 |
| 可运行原型 / Vue 源码 | 页面入口、组件、事件、依赖、资源和可操作状态 | 可选择复用，不把所有演示实现一并迁入 |
| CSS / token / 图标图片 | 变量定义、语义映射、字体资源、许可、实际加载顺序 | 形成完整主题链；保留资源路径和来源 |
| 组件来源 / manifest / 锁文件 | 本地修改、来源版本、依赖与许可 | 判断兼容；保留已有来源清单，不虚构摘要或版本 |
| 服务资料 | 已确认 API、认证方式、分页/错误/权限语义 | 真实接入的依据；缺失时标为接口待确认 |

区分提交中的基线与包含用户未提交改动的工作树。若采用工作树设计，记录实际文件及当前改动情况，不能只写 HEAD 作为完整依据。复制到隔离目录时包含实际依赖的未提交资源；禁止重置、覆盖或清理原产物。

本次选定的规格与交互说明约束行为，选定的原型与设计规范约束呈现；目标工程已有目录、组件、状态和服务约定约束实现方式。沿用已确认的取舍，不把原型演示代码的目录或状态写法变成工程规范。已有排序、分页、错误处理等工程新增行为先识别并保留，确与选定设计冲突时列明影响；当前实现或旧截图不能自动覆盖任务输入。

文字规则与画面冲突时指出具体冲突；只有会改变业务或已选视觉方向的未决问题需要用户决定，其他页面和无关部分继续实施。任务已明确要求的变更无需再次审批。输入确实缺失时只标明受影响状态，不发明规则、不把整个工程一并停下。

## 轻量映射

每个受影响的核心任务至少能追溯到设计、实现和检查。可以写在既有 README 或 PR 描述，不强制独立文件。

按本次范围列出实际需要的默认态、弹层打开态、编辑/校验态、提交结果与恢复动作；只检查有设计依据或由本次工程行为产生的状态。一个弹层的默认截图不能代替取消、失败保留输入与关闭回焦的验证。

| 设计 / 规则 | 页面与实现责任 | 数据或演示边界 | 如何验证 |
|---|---|---|---|
| 客户列表：输入后查询，空结果可清除条件 | 页面编排、查询 composable、列表组件 | 查询 service；后端缺失时固定合成 fixture | 连续输入后仅展示最新结果；空结果与请求失败可区分 |
| 编辑弹层：保存失败保留输入，成功才关闭 | Dialog 负责焦点与草稿，service 负责写入 | 模拟保存不等于持久化完成 | 失败后字段不丢；成功后关闭并更新列表；焦点回触发按钮 |

实际项目使用实际路径、设计链接和检查结果替换例子。没有运行的检查写“未执行”，不能把“如何验证”当已取得证据。

## 选择性复用代码

- **保留**：经确认的布局、排版、图标资源、tokens、shadcn-vue 本地组件及已验证的组件交互。先看 props、emits、slots、依赖和本地定制，再移植。
- **适配**：把页面中有独立职责的业务交互接入 composable；把需要后端的动作接入目标工程 service；处理路由参数、错误和权限边界。
- **隔离或替换**：随机数据、假成功 toast、仅内存保存、模拟上传、场景切换器、演示 hash/query 页面分发、硬编码当前用户。演示分发不能无条件转换成新的业务路由；已有 Router 就接入既有路由表。
- **待真实输入**：未定义的鉴权协议、分页协议、上传限制和业务校验，写为待接入项，不依据原型自创生产 API。前端为测试定义的 service 类型须注明其临时用途。

保留原型中的取消、重试、禁用原因、加载、错误及空状态。按当前规则决定是否需要未保存离开提示、删除确认、部分成功反馈；不为每个按钮机械套用同一弹窗。

## 主题与组件链

1. 找到真实 token 定义及其消费者。YSS 原型常见链为 `tokens.css`（值）→ `prototype-theme.css`（布局/密度）与 `theme.css`（shadcn 语义映射）；文件名以实际项目为准。只复制消费变量的 CSS 不算完成主题。
   若拿到的资产只有映射文件，继续从原型实际 CSS 入口、项目 `DESIGN.md` 或设计技能的 `assets/DESIGN.md` 找到值源；按本页所需投影时记录来源和覆盖范围。找不到值就明确标记缺口，不用猜测值或默认主题冒充设计基线。
2. 同一语义 token 保持一个权威定义，必要适配发生在语义映射层。保留既有字号、行高、控件高度、表格密度、圆角、阴影与焦点环，避免靠局部大量覆盖来补偿丢失的全局主题。
3. 定义和主题作用域覆盖 Teleport：放在文档根或弹层实际祖先，核对 Dialog、Popover、Select、Tooltip。放在 `.app` 或 SFC `scoped` 内不保证传送到 `body` 的内容继承变量。
4. 检查 Tailwind 主版本、CSS layers/导入顺序、语义类映射、动画依赖与扫描范围；跨 package 组件或动态拼接 class 可能构建成功但没有样式。使用实际可扫描类或该版本支持的明确来源配置。
5. `components/ui` 是项目持有的源码。已有组件先复用；新增组件按目标版本和来源取得其完整依赖闭包。CLI 不覆盖已定制组件；组件 API、Reka 和图标 import 以实际版本为准。
6. 交互控件直接使用已有 shadcn-vue 对应组件。允许语义布局标签、链接和组件内部原生 DOM；不以“长得像”的原生按钮/输入替换组件契约。不为 Form 名称自动引入新表单库。

## 实际还原检查

先在相同视口、缩放、数据、主题和状态下比较设计与实现；稳定异步数据和动画后截图，并记录对应的来源画面与实现画面。字体、浏览器或操作系统不同造成的比较限制应说明。已有自动截图设施才复用，不为单次局部任务建设一套视觉平台。

先核对旧快照的来源、状态和覆盖范围。迁移前工程的快照只证明相对该工程基线的回归，不能替代与本次选定原型的对比；实现截图不能自证还原。不得通过更新基线、遮罩核心控件、扩大容差或跳过失败用例掩盖偏差。任务已明确改变设计时，可在对照新依据后更新受影响基线，说明变化依据与范围，不新增例行审批。

- 默认画面检查层级、对齐、列宽、密度、文本截断及资源；弹层单独检查主题、尺寸、定位和滚动。
- 按设计目标验证窄屏/断点、长文本、溢出和页面滚动，不把整页截图相似误当所有尺寸通过。
- 操作关键路径：键盘到达、标签/可访问名称、焦点进入与返回、取消/提交、失败保留输入。仅组件自带 ARIA 不证明页面可访问。
- 差异记录包含“设计依据、实际结果、影响、修正或未解决原因”；重要业务未决项返回业务说明，工程实现不静默改规格。
