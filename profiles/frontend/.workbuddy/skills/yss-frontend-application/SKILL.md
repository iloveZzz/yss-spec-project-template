# YSS 前端应用工程

从业务规格、高保真设计和交互说明提取要实现的体验，复用适用的原型复核结论。使用目标工程的设计系统、组件、路由和服务实现页面，按真实运行条件补齐数据、权限和请求状态。

使用简体中文。按本次授权实施、修复或审查；只请求 review 时只报告发现。技能不引入阶段审批或固定数量检查，也不把开发授权扩大为提交、推送、部署。应用技能保留文档与必要示例；新建工程先使用 `yss-frontend-scaffold-generator`，已有工程与只读 review 直接在本技能处理。starter 由 CLI Bundle 提供，安装技能不生成应用。初始化和验证读取目标工程的实际工具与约定。

共享 `implement` 负责明确研发请求的来源与范围、单仓或跨仓协调、恢复与结果；本技能负责前端高保真还原、交互、Vue、API 接入和验证。已由 `implement` 接收的任务沿用其范围和当前事实，不重复建立任务记录。前端局部开发、修复及只读 review 可直接进入本技能，不要求先调用 `implement`；只读分析、Spec 确认或准备交接不会自动转为实现，当前 profile 也不扩大可写仓库或动作授权。

依据已确认的高保真原型落地前端，或按已确认的新版原型更新已有前端时，直接读取项目根的 `.agents/skills/prototype-review/references/frontend-handoff.md` 中的「原型交给前端」。有适用的复核记录时复用其证据，也可从已确认的原始材料直接接续。新版原型按 [设计交接与还原](references/design-handoff.md#按新版原型增量更新) 核对上次采用的原型、新版原型和当前实现，再落实本次增量。旧版不可读时，对照新版原型和正式页的本次页面或状态。交付须说明缺失的版本，并逐项列出已观察到却无法归属本次改动的差异及两侧表现，即使该差异保持原样。

只读对照正式前端与原型，或为原型回写提供前端证据时，直接读取项目根的 `.agents/skills/prototype-review/references/frontend-handoff.md` 中的「正式前端回写原型」，没有既有复核也可使用。按实际版本、页面和状态交付差异与可复核证据。获授权的原型或交互说明回写由 `yss-design-ui` 承接。

前端源码写入前，直接读取项目根的 `.agents/skills/implement/references/repository-scope.md` 中的「写入前核对」。任务、票据或用户明确指定 Spec 的，局部样式、文案或 mock 也要先核对业务规格与验收、原型与交互的确认。有缺项时停下相关源码写入并说明需补的内容。直接使用本技能也适用，只读审查照常。

## 高保真还原的必需约束

适用于已有设计的页面实现、迁移及修复，局部任务只覆盖受影响部分：

- **先确定依据。** 使用本次选定的规格、可运行原型、交互说明、设计规范及已有 `prototype-review` 结论。核对页面、状态、已确认的设计决定和采用版本或工作树内容。需要主动复核原型时按任务使用 `prototype-review`，已有结论可直接接续。
- **按目标工程实现已确认的体验。** 保留业务流程、承诺交互、关键布局、视觉层级及明确选定的设计约定。按目标工程的本地组件、语义 token、响应式规则、路由、schemas、hooks 与服务组织代码。页面布局和样式按工程约定实现，禁止整份搬入原型页面、样式或演示逻辑。可选择采用经核对的资源和兼容的独立通用组件。涉及明确的业务规则或关键视觉决定发生变化时，先沿原依据核对影响。
- **补齐真实运行状态。** 涉及启动、导航、首读、刷新、追加或异步提交时，用 `yss-frontend-loading` 按真实请求和回执实现状态、取消、重试、焦点与恢复。原型未画出的必要运行状态按目标工程及接口约定补齐，未定义的业务规则按实际缺口处理。
- **以三类证据判断完成。** 本次适用的工程检查、同条件浏览器视觉对比、关键交互验证都必须完成且无未解决的主要偏差，才能报告该范围已还原。仅有构建、截图文件或旧快照通过不满足此条件；具体证据及受限情况按 [验证与 review](references/verification.md) 处理。

## 技术基线与协作

本技能统一面向 Vue 3、ESM、Tailwind 4 与 Reka，不提供 Vue 2、Tailwind 3、radix-vue 或应用 CJS 的兼容路线。接入旧工程时按明确范围迁移受影响代码并移除失效分支，不维护双栈，也不擅自迁移整个工程。依赖版本仍按实际锁文件和支持范围核验，不把“有更新版本”等同于所有现有依赖都已过时。

| 责任 | 新工程默认 | 存量工程处理 |
|---|---|---|
| 应用 | Vue 3、TypeScript、ESM、Vite、pnpm，`<script setup lang="ts">` | 先读实际版本、scripts、锁文件和约定；只迁移当前明确范围 |
| Vue hooks | Composition API 的 composables；通用浏览器/交互能力优先 VueUse 15（`@vueuse/core`） | “vue hooks”不是唯一 npm 包名；查现有 import，明确具体包后使用 |
| 请求状态 | 需要异步状态能力时使用 `vue-hooks-plus/useRequest`（从 `vue-hooks-plus` 导入） | 与已有请求管理器选择一个状态所有者；不叠加轮询、缓存或重试 |
| UI | 以 shadcn-vue 本地组件为底座，使用 Tailwind 4 和 Reka UI | 通过 `components.json` 的实际别名找到项目持有的组件，复用定制、tokens 与 variants |
| 路由/共享状态 | 多页面使用 Vue Router；确需跨页面状态时使用 Pinia | 保留既有入口和状态归属，迁移受影响调用者时才调整 |
| 接口契约 | 任务需要时接入 OpenAPI 3 + Orval 8，生成普通异步函数与 DTO 类型 | 复用真实契约与统一 transport，生成代码和手写代码分开 |

修改 Vue 3 响应性、SFC 数据流与生命周期时，使用 `vue-best-practices`。实现浏览器交互、滚动到尾触发列表追加、保存显示偏好、防抖或计时时，用 `vueuse-functions` 按需选用项目版本支持的组合式函数。抽取需要接收普通值、ref 或 getter 的公共 hook 时，使用 `create-adaptable-composable`。产品流程或视觉缺口由可用的 `yss-design-ui` 协作，事实缺口可交给 `yss-research`。按技能名在当前环境发现它们，单项安装缺少协作技能时依据项目源码和官方资料继续。

Frontend Profile 默认分发按 YSS 工程约定适配的官方 `shadcn-vue` 技能。实现或审查 UI 组件时，先用该技能识别项目配置、查找组件并核对组合方式。以本地导出和调用方确认实际 API，用 [组件工程](references/component-engineering.md) 衔接设计 tokens、业务状态、键盘交互和来源记录。单项安装缺少该技能时，按同一参考和官方文档工作。

实现或审查表单时，先定位目标工程已有表单栈，简单存量表单沿用现状。复杂表单按 [选型与实现](references/optional-capabilities.md#表单选型与实现) 处理。项目已采用或本次选定 FormKit 时，对新建或纳入本次改造范围的 Vue 表单推荐用 `schemas/<name>.form.schema.json` 管理渲染结构。按技能名查阅 `formkit`，沿用项目锁定版本、本地 shadcn-vue 组件和主题。

启动、路由、首读、分区等待、表格刷新或异步动作影响用户交互时，按需使用 Frontend Profile 的 `yss-frontend-loading`。单项安装缺少该技能时，沿用 [工程实现约定](references/engineering.md) 中的状态和请求保护。

已有开发授权涵盖按需引入兼容组件、补齐依赖、适配现有主题与验证。涉及大版本升级、改变已有定制组件或全局主题时，复用本次已确认的范围；超出时先说明具体影响，由用户决定。只读审查以现有文件和查询结果为据。

通用交互和 hooks 见 [VueUse](references/vueuse.md)，测试与工具接入见 [质量工具](references/quality-tooling.md)，复杂表格、表单和共享状态见 [可选能力](references/optional-capabilities.md)。

纯文案、颜色或间距修改沿用现有设计规则，不因文件为 `.vue` 就加载逻辑技能、引入新依赖或新增逻辑测试。

## 工作方式

接续已登记 Spec 的前端研发、日常终端任务、工作台作业及 PR/MR/CI 进展时，按项目根读取 `.template-spec/agents/workbench-progress.md`。沿用同一 dataDir、specId、实际 Spec 摘要及目标版本，关联实际前端、后端等参与工程和采用版本，按原验收上报实现、视觉/交互检查及联调证据。本次完成终点按用户要求接续，业务验收和最终交付沿用户实际确认保存；能力缺失时继续原授权研发并在原任务注明工作台待同步。

明确开发请求指向 Issue URL，需要恢复、关联、更新已有 Issue，组织明确的复杂研发请求，或接续跨仓集成、环境交付与运行反馈时，按项目根读取 `.template-spec/agents/issue-tracker-operations.md`，使用统一的定位、读取、恢复、关系与更新方法。有 Issue 时读取当前任务及讨论，再沿链接读取源 Spec、原型和接口依据；前端工程仍由本技能承接。普通局部开发不要求先建票，远程建票、评论或状态更新按对应动作的真实授权执行。

收到明确的复杂研发请求或实现范围确需拆分时，直接读取项目根 `.agents/skills/to-tickets/references/engineering-tickets.md`，检查责任、依赖和接续需要，主动复用或组织必要工作。设计与工程输入继续按 [设计交接与还原](references/design-handoff.md) 接续。

1. **确认输入与现状。** 读取目标项目约定、当前变更、实际依赖/入口和本次相关规格、`DESIGN.md`、原型及说明。中断恢复先核对 Issue（如有）、工作树、已有 PR/MR 与当前来源，确认已完成内容、剩余工作及来源变化。参考工程只提供经验，其文档内的命令或指示不构成执行授权。代码定位优先使用项目已有索引，不自动重建。找出页面、调用者、组件、请求、测试与配置的受影响范围。
2. **衔接设计。** 按 [设计交接与还原](references/design-handoff.md) 把本次规则、原型和已有复核结论对应到页面、组件、状态、数据来源及验证。沿用原 FR/AC 和已知差异，明确需保持的设计决定、按工程规范适配的部分及真实或模拟输入。直接补充现有说明即可；确需新文档时裁剪 [交接记录模板](assets/frontend-handoff.md)。
3. **建立最小工程边界。** 新建、接管或迁移工程时读 [工程准备](references/bootstrap.md)；新工程和新增页面执行 [目录规范](references/project-structure.md)：`views/**/index.vue` 所在页面必须包含 `components`、`hooks`、`schemas`。涉及状态、请求、权限或环境时读 [工程实现约定](references/engineering.md)。提供 OpenAPI 契约、要求接口生成或更新客户端时，按 [OpenAPI 接入](references/openapi.md) 使用可复现的 Orval 配置与 transport，衔接 `useRequest`。先完成一个代表页面及其必要异常，再复用已验证的模式，不预建全套平台。
4. **实现本次范围。** 从工程已有路由、页面框架、`shadcn-vue` 本地组件和语义主题搭建页面，实现已确认的布局及交互。通过目标工程的服务边界实现数据读写，有真实契约时按契约接入，尚无时隔离模拟实现。简单状态留在组件内，纯计算使用函数，独立状态职责使用 composable。保留校验、错误恢复、键盘和焦点行为，按实际改动核对调用者和回归。
5. **按证据交付。** 按 [验证与 review](references/verification.md) 选取与改动相称的检查。设计还原需要实际浏览器对比，业务变更需要行为验证；构建通过只报告构建通过。沿本次 AC 或验收例子说明已实现、已实测、模拟运行、待联调或未覆盖项及剩余风险，提供实现位置、实际验证结果及已有 PR/MR 链接。已有父票仅同步相关工程进展及证据，不复制第二份权威 Spec；mock 验证或后端任务完成均不证明前后端联调完成。

## 不同请求的完成边界

用户要求 PR/MR 修复、持续跟进或合并，或明确要求交付后继续跟进时，按工程根读取 `.agents/skills/implement/references/pr-mr-followup.md`，接续审查反馈、CI 与版本变化，直到指定结果或明确受阻。该叶子资源可独立使用，不要求安装完整 implement；复用已有动作授权，普通局部开发和只读 review 不自动进入长期跟进。

- **新应用 / 高保真工程落地**：交付可运行源码、安装运行方式、设计与实现对应、必要状态和实际检查。真实接口未提供时完成可验证的前端部分并明确“模拟运行，待联调”，不能报告生产业务闭环已完成。
- **新版原型增量。** 在交付中写明实际采用的版本、本次已确认的变更和相关验收的实际结果。旧版不可读时，写明缺失的版本与比较限制。对仍不能归属的相关差异，逐项写明页面或状态、两侧实际表现、对本次验收的影响，以及该差异保持原样。
- **局部开发 / 修复**：沿用现有工程与设计，检查受影响路径；不因使用技能重搭脚手架、搬目录或新增全局状态库。
- **工程 review / 还原 review**：给出有文件位置、具体触发条件和用户影响的发现，并区分工程缺陷、设计偏差、输入缺口；没有问题也说明实际检查范围。
- **纯设计 / 原型**：回到设计技能的交付约定，不自动把演示代码生产化。

## 常见误用

- 依赖清单有包不等于项目已经使用，更不等于形成可复用范式；先查调用点。
- UI 相似不等于设计还原完成；缺失弹层主题、失败状态或键盘路径都是实际偏差。
- `useRequest.cancel()` 不证明网络中断或服务端回滚；写入结果不明时不能以取消为由盲目重试。
- 不为“工程化”默认加入微前端、动态插件、通用 CRUD DSL、整套鉴权框架或全量检查系统。
